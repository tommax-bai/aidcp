### 3.1 `interactionApi` —— 前置已扫清，但**顺序不能反**

原估「新开 2 个端口 8 个方法」。**那个估算的前提已经不成立**，因为查出来：

> **互动能力自物理拆库起就整体没组装。** 自动化的能力自检里断言了
> `interaction_reply_configs`，而那张表按 §5.1 **归 api 属主**、拆库后在 api 库里；
> 自检跑在 automation 池上 ⇒ 永远为假。而本进程**从不读写那张表**。
> **已修**（`aidcp-automation@28f96be`），能力现已组装、离场路由实测正常返回。

**动手前必须先做这一件（否则会造出本仓代价最高的错误）**：

**互动域的错误类跨进程后 `instanceof` 恒 false。** 后果不是报错，是
`INTERACTION_SEND_AMBIGUOUS`（409 / **不可重试**，语义是「已发出但核不到」）
被兜底成 500 + `retryable:true` ⇒ **客户端会去重投一条可能已经上墙的命令**。
这条**在只点亮 reader 通道的阶段就会中招**，不是写通道才有。

修法有先例可抄：`aidcp-transport/src/transport/api-direct-http-common.ts` 的
`translateReadFailure`（registrar 侧带上 `httpStatus`/`retryable`/`details`，
client 侧还原成具名错误）。判别**按 `name` + 具名字段**，MUST NOT 用 `instanceof`。

**四个不可重试的提交点**（`dispatchQueued` / `requestSync` / `requestAuthReopen` /
`requestBrowserControl`）：transport 层 **MUST NOT 加任何重试**，
`timeout` / `transport_error` 两个码意味着**可能已发出**，必须映射成 409 不可重试那一族。

**另外三件与通道无关、但同批该做的**：
- api 侧给 `auth_reopen` / `browser_control` / `sync` 补 `!claim.fresh` 守卫
  （`test_reset` 已有，其余三处没有；跨进程后失窗从「进程崩溃」放大成「一次网络超时」，
  重投 `auth_reopen` 会把用户正在扫的二维码顶掉重开）。
- 恢复循环 `drainInteractionRecovery` **从没搬进 automation**，全仓零调用方 ⇒
  `void dispatchQueued(...).catch(()=>{})` 失败后今天没有任何东西会再派发那条 queued。
- `generate` / `edit` 会跑 LLM（最坏 3×20s），而内部 HTTP 默认超时 15s ⇒ **必然超时**，
  而属主侧会照常把 job 推进状态 —— 「看起来失败其实成功」，比失败难查。**要分档超时。**

**分阶段判断**：只点亮 reader 通道 **用户可见收益为零**（构造式是 5 个 `&&` 的全或无，
缺 workflow/sender 则整片路由仍 404）。它值得先做，理由是铺作用域与提前逼出二态，
不是「点亮功能」——**别把阶段一汇报成功能可用**。

## 4. 会咬人的坑（都**不报错**）

按踩到的顺序记，每条都是「照着最自然的写法做就会中」：

1. **稿件编辑走裸存储**：稿子真改了，但不推预览刷新 ⇒ 桌面端还显示旧的，用户以为没保存上。
   必须走发布台账的**权威层**。
2. **审批走边缘发布端口**：那个端口形状里**没有 actor** ⇒ 审批成功、但台账署名退回默认值，
   认不出是哪个客户操作的 —— 而那正是审批台账存在的理由。
3. **人设自助补齐只接一处**：握手权威的第二个参数是 `waiting_binding` 的**唯一唤醒源**，
   而 `resume()` 明确不管这一态。少接它：编译过、201 成功、状态合法，**人设永远补不上**。
4. **给平台能力投影传空值**：它不报错，回落成「保持现状」而保留 collect 那一格 ⇒
   Facebook 账号重新看到「收藏 0/N」，正是 change `platform-honest-usage-metrics` 除掉的谎。
   ⇒ **所以「今日进展」必须由属主域算完整块再给，不能递原料。**
5. **可选依赖的存储不传 pool**：会自建一个连默认库的池 —— 物理拆库后那库不存在，
   **启动期不报错、第一次写才炸**。
6. **模板字符串里的反引号**：SQL 注释里写了一个反引号，当场截断字符串（TS1005）。
   与 CLAUDE.md §5 记的 heredoc 那条同型。

后者值得单独立项 —— 它是 dev 停摆那次的真根因，也是本轮三次「靠用户报障才发现」的共同原因。
