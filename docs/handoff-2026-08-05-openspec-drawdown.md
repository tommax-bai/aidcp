### 3.4 那条随机变红的用例：修好了，而台账对根因 / 对用例 / 对修法**三样全判错**

- **不是它点名的那条用例**：红的是 `facebook_reel_follow_uses_one_pointer_write_and_same_author_postcondition`。
- **不是超时**：失败的断言是 `assert!(mouse_dispatch_count > 3, "点击必须逐帧移动")`。
- **不是预算**：把两处真正封顶的量（会话超时 + 命令截止期，`command_timeout_ms_for` 取二者与平台天花板的 min）
  一起抬到宿主单命令上限 45s，**实测毫无变化**（4 路并发下改动前后同为 4 红 / 24 跑）。
  **这一步正是排除预算的证据——没有它，"改完全绿"会把一个错误修法记成正确修法。**
- **也不是「偶发」**：实测 4 路 **17%**、16 路 **16%**。

**真因是跨用例污染进程级全局状态**：指针「上一次落点」是 `input.rs` 的进程级静态量，
注释写着成立前提「引擎进程同一时刻只服务一个会话，故按进程持有即会话级」——
**代码里没有任何东西让这个前提成真**。测试二进制里几十条用例并发跑在同一进程、各开各的会话，
落点互相污染；继承来的起点一旦落在新目标的退化距离（2px）内，轨迹**正确地**塌成单帧
（那一支本就是对的：目标已在脚下），于是本该逐帧移动的点击变成瞬移，而降级枚举报 `None`。
**「两态压成一态」又发生了一次，且发生在专为区分两态而建的地方。**

修法：开会话时清掉落点（`aidcp-edge 2cea703`），放在开会话而非关会话——进程被杀时关会话路径根本走不到。
归因实测（`scripts/flake-probe`，两侧同一套负载、二进制先 `cmp` 确认不同）：
**4 路 4 红/24 → 0 红/24；16 路 10 红/64 → 0 红/64。**

**生产可达性**：需要「一个引擎进程先后服务两场会话」，比测试里罕见得多，但**不是不可能**
（运行时按 owner 缓存会话、有丢弃重开路径）。**未观察到生产实例，登记为可达而非已发生。**

## 5. 别再踩的坑（★ 是本轮新踩或新证实的）

- ★ **★★ 登记的根因可能是错的，而且不止一处错。** 本轮三条登记与实测不符：
  配图「没实装」（其实已实装）、flaky 用例（根因/用例/修法三样全错）、
  11.4「无法取样」（其实两分钟就能取到）。**动手前先自己量一遍。**
- ★ **抬预算不是修法，而且「改完全绿」证明不了任何事。**
  必须先证明**旧代码在同一套负载下会红**（`scripts/flake-probe`，两侧二进制先 `cmp`），
  再看**是哪条用例变红的**。本轮正是靠「抬到上限仍毫无变化」排除掉预算这个假设的。
- ★ **在退役模块上实装 = 零生产效果，且没有任何东西会警告你。**
  判据是「核心入口到不到得了」，不是「有没有人 import 它」。
  事实源＝`aidcp-edge/scripts/native-engine-inventory.cjs` 的 `RETIRED_DIST_MODULES`，
  再加一道从核心入口出发的可达性剪枝（名单外但无人可达的同样会被删）。
  全景见 `docs/architecture.md` §2.2 / §3.2 / §3.3（本轮据实重写过）。
- ★ **只改一侧不算改完。** 协议改动要同时管三份副本，派生仓那份走 `scripts/sync-split-repos --apply`；
  且同步器读的是 **origin 上的云端头**，所以必须先提交推送云端那一半。
  （新闸第一次跑就抓住了我自己只改一侧。）
- **协议是热点单写文件**（`CLAUDE.md` §2 / §7），改它必须与 fleet 串行。
- **canonical checkout 里有并发 session 的未提交改动是常态**：
  `git add` 只写自己那几个路径，**绝不 `-A`**；rebase 撞「有未暂存变更」时，
  先看 `git rev-list --count HEAD..origin/master`，为 0 就直接 ff 推、不要动别人的脏文件。
