## 判据（收进来的标准，宁严勿宽）

- 写完不回头验证业务结果，或验证了但判据不成立（点完睡一觉就报成功）。
- **两态压成一态**：「探针读不到」与「读到了、确实没发生」被折成同一个失败值；或「读不到」被当成好消息。
- **自证循环**：后置校验读回的证据，正是本命令自己刚写进页面的那段内容。
- **判据过宽**：宽松子串匹配类名、或单个汉字作文本兜底来判「已生效」。
- **静默降级**：走了降级路径但回执照样说成功，且降级痕迹到不了人眼前。

### E1. 评论提交的后置判据只剩一条宽松子串扫描，并丢掉了切换前的结构必要条件「编辑器已被平台清空」——判据过宽 + 丢结构证据（自证循环目前未坐实，是潜在退化风险而非现行事实）：native/page-engine/src/xhs-input-targets.js:205-209 + native/page

- **类型**：自证循环　**落点**：`native/page-engine/src/xhs-input-targets.js:208`　**体量**：medium
- **今天回报什么**：提交点击后固定停一拍，再在详情容器内取所有类名含 comment 的元素做整段文本包含判断，命中即 appeared=true → 回执 action='comment' / ok=true / 相位 confirmed；不命中回 submitted_unconfirmed，读不到回 submitted_ack_unreadable（后两态已分开，是好的）。
- **为什么是错的**：评论输入框（富文本形态）本身及其外层容器的类名就含 comment，而提交失败时输入框不会被平台清空——于是「证据」正是本条命令自己刚写进页面的那段文本，等于没有后置校验。真机上一次没提交成功的评论会被判成已发布：云端据此写去重、不再重投，这条评论永久丢失，且运营侧看到的是一条成功记录。并行 change 的 5.10 明令禁止「对整段编辑器文本做包含判断」，这正是它点名的形态，只是实现点已从注入路由搬到了这块判据分片。
