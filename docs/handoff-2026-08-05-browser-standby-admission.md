## 1. 用户在本轮定下的编址分层（**别再重新讨论，尤其别再提"上收云端"**）

| 层 | 编址单位 | 权威 | 例子 |
| --- | --- | --- | --- |
| 宿主层 | 机器 | **本地** | 槽位调度、内存推算、启动队列、等待门槛 |
| 环境层 | 分身 | **本地** | 浏览器开关、登录协调、指纹、代理、阻断浮层 |
| 翻译层 | 环境 → 账号 | **本地** | 身份确立、身份守卫、身份翻转 |
| 账号层 | 账号 | **云端** | 浏览、互动、发布、风控、配额、审批 |

由此推出的、**本轮已经拿来做决定**的几条：

- **槽位调度权在宿主层，不上收云端。** 车队跨机器，**槽位不跨机器**，且环境绑死本机分身、
  不可迁移 ⇒ 不存在任何"云端能做而宿主做不了"的槽位决策。
  > 本轮我（助手）先前推过"把判断权上收云端"，**那是错的，已当场收回**。新 session 别再走回去。
- **今天的病根是云端下发的字段名叫 `eligible`——那是个决策词。** 两层各出一个决策 ⇒ 必然漂移。
  云端在这件事上只该给账号层**事实**（这个账号到 T 之前没有活干）。
- **验证码按"翻译层是否完成"分类，不按"浏览期 / 登录期"**：
  - 身份确立**之前**（登录验证码 / 首登 checkpoint）＝环境层。此时账号还不存在，
    账号层**结构上没有可裁决的对象**——这是最硬的论据。
  - 身份确立**之后**（浏览期风控浮层）＝账号层，属风控事实，云端单写。
  - 运行期掉登录 / checkpoint ＝翻译层事件：检测与恢复在本地，"该账号当前不可操作"归云端。
  - **三类共有：检测与上报永远在本地**（云端看不见页面）；分歧只在分类与后果。
- **让位决策 = 宿主层拿两条事实做的判断**：云端的"没活干到 T" + 本地的"这个浏览器此刻是不是人机接口"。
- 宿主层拥有决策权的**代价是必须向上可见**——否则就退化成本次故障。可见性是遥测，**不是审批权**。

分层表与推论已写进 change `admit-browser-standby-on-live-facts` 的 `design.md`，
归档后会随 delta 并入 `browser-cold-standby` 规格。

## 2. 触发本轮的真机故障（已定位、已修，未出包）

**现象**：2026-08-05 18:18，账号 `Lê Thảo Hân`（`ads-k1fd38qw`，Facebook，Native 引擎）
小时浏览配额跑满。云端每 60 秒推一次 `eligible=true`（等待约 33 分钟 ≫ 门槛 5 分钟）。
客户端**连续 32 分钟每次都拒绝**，浏览器一直占着两个槽位之一，界面与日志**零痕迹**。
同机另两个账号 18:08 收到同类提示后**在同一毫秒内**让位——机制与配置本身正常。

**根因两半**：

1. **准入读了一个已无写入方的标签。** 准入要求会话轴 ∈ {running, resting}，
   而写会话轴的那几句中文只有**已退役的 TypeScript 浏览循环**会打印
   （`src/browse/browse-session.ts`）。Facebook 与现役小红书都跑 Native 引擎，
   发的是结构化会话事件，外壳**零处理分支**。实测本机全部日志历史里那几句话出现 **0 次**。
   该轴自核心 spawn 被写下一次之后再无人维护，只会被各种失败路径单向改坏、永不复原。
2. **拒绝完全无痕。** 除"最短持有时长未满"外的所有拒绝理由都是直接 return——
   不写状态、不写日志、不计次数。于是锁死半小时在磁盘上零证据，
   连"是哪一次写把会话轴改坏的"都**无法回溯**（我确实没查出来，也不必了，见 §3 的 D1）。

**顺带挖出的、更急的一个坑**（原属 `browser-slot-scheduling` §5.6，本轮接管）：
核心侧"进入待机被拒"原本复用无参的 `onCloseFailed`，外壳当成"运营要关浏览器但没关成"，
于是收敛自动化意图、把环境写成暂停态 = **永久占槽且被踢出等槽位队列的砖**。
而 `enterStandby()` 的五个失败出口里，**三个是拆除动作之前的无害拒绝**
（最常见的是 `task_lease_active`＝正在发帖 / 评论），两个才是 `session.detach()` 之后的真失败。
本次改动的全部目的就是让待机尝试频繁发生 ⇒ 不修这条等于把低频隐患放大成高频故障。

## 4.1 探索结论（2026-08-06，已在代码里取证；**立项按这一节，别按上面那五条**）

上面五条已按下述结论修订：**第 3 条作废，剩下四条并成三个 change。**

### 第 3 条为什么删掉

按 §1 的分层规则：**登录前的验证码＝环境层（本地说了算）；登录后浏览期的阻断浮层＝账号层（云端单写）**。
浏览期验证码正是账号层的事，所以那道云端否决**放对了地方**，不是「账号层回答环境层问题」。

代码与规则完全对得上，连边界情况都对：那份待机提示是**按账号**产出的
（`aidcp-cloud/src/server.ts` 的 `buildBrowserStandbyForAccount`），**身份确立前根本没有账号、也就不会有提示**，
那种情况天然落回本地判——正是 §1 说的「账号层结构上没有可裁决的对象」。

### 四条剩余项的取证结果

| 项 | 结论 | 关键事实 |
| --- | --- | --- |
| 云端决策词降级成事实 | 成立，但**比「删个布尔」大** | 那个布尔确实可由「等待时长 ≥ 门槛」推出、纯冗余；但真正带信息的是原因串，而边缘今天只把它当**不透明展示文本**。要让宿主层自己判，得先给账号层定一套**有类型的事实词汇**，让本地分得清三种今天长得一样的情况：有人卡住了 / 算不出恢复时刻 / 本来就有活干 |
| 等待门槛权威还给宿主层 | 成立，但是**正面反转一条刚合并的规格** | `openspec/specs/browser-cold-standby/spec.md` 的 `Cloud SHALL be the single standby wait-threshold authority` 明写边缘不得掺入本地默认值 / 持久化设置 / 环境变量；且边缘现在会**主动删掉**配置文件里那条历史设置。提案里须写明是**有意反转**，别看着像没读过规格 |
| 会话轴接结构化会话事件 | 成立，但**仍是读日志** | Native 引擎那两个会话事件是打进**日志行**的（形如 `session.event event=session_ready platform=…`），不是进程间消息；且**外壳今天完全不解析它**（全仓零命中）。好处是格式机器可读、各平台通用、写入方还活着——满足新规格「每个准入输入都要有可证写入方」那条。**但本项仍只修界面显示，MUST NOT 回准入闸** |
| 让位决策向上回执 | 成立，**且比 §4.5 说的更硬** | 不只是那一条通道不能用（只认 `absent`/`ready`，且云端处理函数第一行就是「状态没变直接返回」——让位被拒时浏览器一直是 ready，永远送不到）；我把**整张消息表**扫了一遍，**边缘→云端没有任何通用遥测通道**。确认要新增一条协议消息 |

**发现一条 §4.5 没提的旁路，但不推荐**：桌面外壳里有一个带鉴权的 HTTP 客户端可直接调云端
（customer-auth 那条出口），走它能完全绕开协议改动。**不推荐的理由**：那套接口两端是手工维护的双份契约、
**零路径级测试、已经断过两次**；而且它是**客户侧**接口，拿来送运维遥测是层次错位。

### ⚠️ 一条会一次性搞挂全部在跑客户端的硬约束（贯穿三个 change）

边缘收到待机提示时**先验格式**：只要「是否够格让位」不是布尔、或「门槛值」小于 1 秒，
**整条提示当场判无效丢弃**（`aidcp-edge/src/electron/browser-cold-standby.cjs` 的 `normalizeBrowserStandbyHint`）。

⇒ **云端一旦停发这两个字段，所有在跑的客户端会立刻集体停止让位——不是降级，是整条链路死掉。**

所以：**协议只能加、不能减**，新语义走**能力位协商**（机制现成，握手时边缘声明、云端按 edge 查）。
**且不能靠版本号灰度**——用户会从源码重新编译装机而不抬版本号（本轮实证），版本号认不出装的是哪份代码。

### 建议拆成 3 个 change，顺序不能换

1. **修边缘外壳本地两件事**（不动协议，最小，自身即安全修复）
   - 阻断浮层标记的清除条件里**摘掉「浏览会话结束」**。浏览停了**证明不了验证码解了**。
     注意这不是为了撤云端那道闸（那条已作废）——**登录前那一半本来就归本地管，本地这面旗子是那时唯一的权威**。
     判据早有先例：同一段代码里已经按「清除是判断、不是副作用」删掉过「成功互动顺带清除」那条兜底，
     `session_end` 是**同一类不成立的推断，当时漏了**。
   - 会话轴接上结构化会话行，**只修界面显示**。
   - *两件合并的理由*：改的是同一个状态推导块里相邻的十几行，分开做必撞车。
2. **新增让位决策的向上回执**（协议改动，四~五处同步 + 新能力位）
   - 排在 3 之前：**§1 说宿主层拿决策权的代价是必须向上可见——先装眼睛，再动权。**
   - ⚠️ 要动两份 `protocol.ts`，按 CLAUDE.md §7 属**热点文件、必须标记需串行**，不与他人并行。
3. **决策词降级成事实 + 等待门槛权威回本地**（原第 1、2 条合一）
   - 合并理由：是同一件事的两半，且**共用同一套线上兼容手法**，分开做要做两遍。

**为什么不合成一个**：三件的风险等级差好几档（一件只修显示、一件新开协议通道、一件反转已上线规格）。
合成一个，真机上出问题分不清是谁干的。
