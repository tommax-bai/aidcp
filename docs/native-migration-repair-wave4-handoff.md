## 3. 这一波真正的产出不是代码，是方法

代码只是结果。**值得带走的是这套流程**，因为它反复奏效：

### 3.1 每一轮都要有一个「不信前一轮」的独立复验者

首轮实装完，4 路对抗审查抓出 **2 个阻断 + 10 个重要**；修完，复验抓出**修复自带的回归**；
再修，复验又抓出**新的漏网**。**六轮下来每一轮都有实质产出**，而且严重度在稳定下降。

关键不是「多审几遍」，是**复验者被要求把实装报告当供词读，不当事实读**。多次证明实装报告的
自我评估是乐观的——包括「我扫过同族问题了」（漏了一条）、「连跑 9 次全绿」（复验跑 22 次红 2 次）。

### 3.2 唯一算数的判据：**把修复回退掉，有没有用例会变红**

这条判据消灭了本批工作最核心的病：**闸装了、判据算了、日志打了，但它不拦**。

实测证据（都是真跑出来的，不是推理）：
- 三处「诚实失败闸」删掉整块 → 全仓测试 **0 失败**（因为钉它们的用例测的是已不可达的死码）。
- 把拒绝那句 `throw` 删掉、判据留着 → **26 条用例零红**（源码扫描只能断言「判据出现了」「顺序在前」）。
- 一整块保护逻辑**位置挪一下**（不是删）→ 全绿，而之前修好的症状**完整复活**。
- 把逐字输入的每字间隔改成 0（= 拟人化整个关掉）→ **全绿，回执照样诚实**。

**「源码文本扫描」对这一族无能为力**，别指望往扫描里加更多正则。正确做法是把「判据 + 动作」
整段搬进可注入实现、宿主只剩一行接线，让用例驱动**真实现**而不是自己复制一份的闭包。

### 3.3 打补丁打到第三轮还在出新回归，就该换打法

A 流前三轮是「报一条、修一条」，主项每次都真修好，但**每轮都带出新分岔**。
第四轮改成**把源头收掉**（「核心运行态 → 界面呈现」收成一处权威映射，所有入口必须经它），
回归就停了。判断信号很明确：**同一族问题反复以不同面貌出现 = 打法错了，不是运气差。**

## 4. 本波新增的坑（都付过代价）

### 4.1 「注释说一套，代码干另一套」出现了三次

- 注释写「不能把『读不到』和『不匹配』当一回事」，代码里正好这么写了。
- 注释写「冷待机唤醒等价于一次真重立」，而那条路**只在特定条件下才通**。
- 注释声明某个判据是「核心与外壳共用」，实际两侧判的根本不是一件事，而且那个符号**零调用方**。

**没有任何机械手段会提醒你。** 现在有一条扫描断言专门禁止其中一句被坐实为假的话再出现在源码里。

### 4.2 一句错误的「没有路可走」比一个 bug 更贵

有一轮裁定「协议上没有拒绝回执的形状，所以不发」。**前提是假的**——形状早就存在，
云端收到会立刻处理、不等 200 秒超时，边缘自己的协调器本来就在用它。

**结论（不伪造回执）是对的，理由是错的。** 而错误的理由会让下一个人以为无路可走、从而永远不去补。
现在代码里写的是真实情况 + 可执行配方（见 P1）。

### 4.3 验证抖动**必须跑全量、跑够次数**

历史上多次「这条不抖」的结论，都是**单独跑那个文件**得出的——那样永远全绿。
真实情况：主干自身 8 次全量红 4 次。**单独跑单文件 = 自证一个假的无抖动。**

### 4.4 合并时「文本不冲突」的地方最危险

本波三处（侦察提前测出来了，否则一定中）：
- 提交窗口预算被钉在一个**主干刚好改掉**的常量上 ⇒ 合完窗口比命令短 15 秒 ⇒ 已发出的评论被当成没发出 ⇒ **重发一遍**。
  正解不是抄新数字，是**从常量派生**。
- 回执结构在一侧多了一格，另一侧新增的字面量缺它。**编译器会抓，但为了「让它编译」把那一格删掉，
  整套取证就静默消失了。** 按意图解，不按能编译解。
- 主干把一个条件从「有值就执行」改严成「值真被更新过才执行」，而分支是从改之前分叉的。
  机械选边会**把主干的改进悄悄回退掉**，两边看起来都合理。

## 5. 未完成 / 转出项

### P1 · 任务租约拒绝的负向应答（跨仓，等串行窗口）

**形状已存在**：`edge.task.released` + reason，云端 `onReleased` 对已知原因即刻 reject、不等 200 秒超时。
缺的只是「身份未落定」这一档 reason 取值没接线。配方：
两份 `protocol.ts` 的 reason 联合各加一个值 + 云端 `onReleased` 一个 `if` + 边缘把 `ack` 从 `'unwired'` 改成真发出。
**不新增消息类型、不动动作映射、不改协议文档计数、不进主动命令白名单。**
`protocol.ts` 是本仓明令的**串行热点单写区**，必须等窗口。

### P2 · 停摆 / 终局态在 IPC 丢失时缺持久红

现状兜底日志只顶**当下那一行**，下一行普通日志就把界面写回运行中。修法在外壳侧
（识别白名单措辞时也合成一个状态闩，让后续日志被压住）。性质是继承的，但残局态本波才补到同一水平。

### P3 · 指针原语在预算压力下静默退化成瞬移

剩余预算不足约 **64ms** 时帧数塌成 1 —— 也就是**瞬移到目标再按下**，正是这批工作要根除的机器特征。
**不报错、回执照样诚实**，全仓唯一会喊的是一条测试断言。
与 B 流刚做完的「逐字输入降级标记 + 记账」是同一族，指针这条还没有。**不是本波引入的。**

### P4 · 门禁抖动（**接手第一件该修的事**）

`native/page-engine/tests/fake_cdp.rs` 里三条 Facebook feed-recovery 用例**共用同一个落点坐标 (540, 330)**，
而 `input.rs` 的「上一次点击落点」是**进程级全局**、被并发测试互相污染：
谁后跑，起点就已经在目标上 ⇒ 距离为零 ⇒ 路径塌成单帧 ⇒ 「不得瞬移」当场红。

**实测频率：主干自身 8 次全量红 4 次（约 50%），本波分支同率 ⇒ 门禁在主干上就是坏的，不是本波引入的。**

三个修法，**主控倾向第二个**：
1. 给引擎加一个具名的测试用重置入口 —— 最小，但污染生产 API；
2. **让这几条用例各用不同的落点坐标** —— 纯测试改动、不碰生产、不污染 API；
3. 把「上一次落点」改成按会话隔离 —— 架构最正确，但要改 `input.rs` 签名与全部调用点。

**生产语义不需要改**：一个引擎进程只驱动一个浏览器、命令串行，「光标已经在那儿就不再移动」是对的行为。

> ⚠️ **一个 50% 红的门禁比没有门禁更坏**——它训练人无视红灯。修它优先于开新功能。

### P5 · 显式弃守的覆盖项（有理由，别当遗漏）

- 7 个 `unreadable` 原因码按「方向性」判据不补用例：折叠它们只会让回执**病因写错**，不会假成功。
- 逐字输入降级的「响亮痕迹」**上报通路根本不存在**（引擎 stderr 进了 2048 字符滚动缓冲、只在进程级失败时才被读，
  而降级是一条**成功**路径）。测住那行诊断存在 = 断言一个运营侧读不到的字符串确实存在，是自我安慰。
  真要做通得单独起 change。

### P6 · 两仓协议文件 4 处既有漂移

`ui.snapshot` 注释、某个错误码在三处枚举中的排序、一处连字符写法。
**均为本波之前就存在**，`npm run typecheck` 抓不到（都不影响消息类型穷举）。未触碰、未加剧。

## 6. 具名裁定（别再重新讨论）

| 事项 | 裁定 | 理由 |
| --- | --- | --- |
| §4 的落点层级 | **宿主 TS 层**，具名推翻 `design.md` 的否决 | design 的第二条理由与代码事实相反：宿主等待发生在死线计算**之前**、不占引擎预算；且平行 change 已把同形状落进主干并带 7 条测试 |
| 提交窗口 4s 打穿 | **抬预算（改成从命令上限派生），否决「把开窗挪到提交前一刻」** | 会话守卫的不变量是「提交窗口先于任何触碰页面的写动作」，而逐字打字就是写动作；挪过去等于亲手拆闸 |
| 运行期覆盖账号值 | 读不出 ⇒ **halt**；读出来但与覆盖值不一致 ⇒ **以实测为准** | 启动期覆盖是操作者逃生阀，运行期没有权威。读不出＝把不知道说成知道；读出来了还用请求值＝把动作记到别人头上 |
| 身份翻转时有活跃租约 | **照走 + 中止租约**，绝不静默等待 | 静默等待会让身份翻转无限期不生效；在已翻转的身份下跑完租约会把记账挂到错账号 |
| 残局态（身份好、自动化停了） | **单占一格 `automation_stalled`** | 折进健康＝外壳全绿的静默假成功；折进身份失败＝把运营推去重登+重启，而有效动作是点一次「恢复」。**处理办法不同才是分态依据** |
| 身份未落定时的服务链路 | 拒绝重绑 + **写动作过闸**；读 / 救援 / 收尾**放行** | 写动作会在平台上留下该账号名下的新痕迹；拦掉读和救援只会让节点救不回来 |
| 富文本评论框 + 联系方式串码 | **诚实失败（零派发结构性拒绝）**，接受能力回退 | 评论框里的裸回车就是提交，按形态分派会把只写了一半的评论发出去，比丢一条换行严重一个量级 |
| §8 页面判据的承载方式 | **新增本 change 独有的混淆分片**，不改注入路由那份 | 与仓内已跑通的同构；注入路由是并行 change 的单写区 |
