## 2. 那 36 项真活里，风险最高的两块

**优先做这两块**：

1. **重连后可能连错浏览器**（运行时契约 6.2 / 6.3）。引擎断线重连时不重新确认「我连的是不是本环境自己的浏览器」。
   同机多开时端口被系统回收再分配，**可能连到别人的号上、把动作记到别人账下**。
   判据代码已写好但**没接到真实附着路径上**——这是整批唯一一条会造成「张冠李戴」的。
   - **勘察结论（2026-07-31）：这是接线活，不是设计活。** 判据整套已在端点选择层写成、单测 10 条全过、
     连危害都在注释里写明白了，但**零生产调用方**——附着路径（开会话与重连两处）走的仍是老判据。
     身份证据的载体也已定：浏览器级调试地址里的实例标识，换浏览器进程必换值、端口回收带不过去。
   - **宿主那边已经算出过这个证据然后原地扔掉**：认领失联浏览器时会拿本地标记文件与浏览器自报值交叉校验，
     校验通过后函数只返回地址与端口，标识被丢弃；指纹浏览器的启动接口本来也返回它，同样在取数时丢掉。
     所以不用新造证据，把已有的接上即可。
   - **实装边界（决定改动面大小）**：开会话时**不要**新增网络往返去自读身份——13 个测试假服务端都是单次应答、
     不按路径分发，加一次读会把它们全打坏。正确做法是身份由宿主随开会话参数传进来，重连时才实读比对。
     真正走重连路径的用例只有一条，改动面很小。
2. **后置判据会错报成功**（拟人化 5.9 / 5.10 + 小红书动作诚实化 H.2 / H.3 / H.4）。宽松子串匹配、
   读回自己刚写进去的内容当证据。逐条清单见 `docs/edge-honesty-gap-inventory.md`。
   - **勘察结论（2026-07-31）：扇出点是 7 个决策点**（早先说的 5 处漏数了；穷举核对过，本文件之外零扇出）。
     两个共享判据里，类名那一支是不带词边界的子串匹配，**连否定形也读成正证据**——
     「未选中」「未点赞」「非激活」这类类名今天一律判成「已生效」。
   - **同一个文件里已经有正确写法**：点赞 / 收藏 / 关注三条各有硬判据（读图标状态位 + 有界轮询等翻转），
     注释里白纸黑字写了为什么类名和「已」字不能当证据。偏偏兼容路径把这三个动作又送回了那个弱判据。
   - **三条原清单没有、但更狠的**：① 发布选项设成「关」时，控件读不出状态 = 判定本来就是关的 = 直接回成功、**连点都不点**
     （没有证据被当成了证据）；② 设封面的判据会命中轮播「当前正在显示」的状态类，于是连「设为封面」都不点就报成功；
     ③ 搜索筛选误判时连筛选都不点，直接把**未筛选**结果当作已筛过送上去，回执里没有任何字段记录筛过什么。
   - **这 7 个点零测试覆盖**——现在的错误行为没有任何断言钉着，改起来不会打坏别人，但也意味着必须自带用例。

其余 27 项可按线推进，不急——它们的失败方向都是诚实的。

## 3. 本轮已定的口径（别再重新讨论）

| 事项 | 裁定 | 出处 |

| 定位第三道闸（锚点暂存 / 反污染） | **不做，需要重新设计**。当前引擎根本没有「学」这一环节 —— 没有非确定性定位来源，就没有可暂存 / 可晋升的东西 | 对应 change 的 7.16 已结案，结论写回其 design.md |
| 边缘「诚实回执 / 后置校验」缺口 | **要做**。同日曾短暂定为「按 case 处理」，随后改口径为要做，**以后者为准** | `docs/edge-honesty-gap-inventory.md` |
| 跨平台打包资源解析 | **按 case 处理**。已验证推迟是安全的：在 macOS 上打 Windows 包会**响亮失败**、不会静默发错包 | 产物门禁 9.1–9.3 |
| 真机验收 | **不单独排期**，由用户在日常测试中逐步覆盖 | `docs/real-machine-acceptance-backlog.md` 顶部 |

> **真机那条要清醒**：日常测试的覆盖是**不均匀**的，冷门分支（异常态、降级路径、失败回执）可能长期没人碰。
> 清单上没勾的项＝**至今无人验证**，不因所属 change 归档就变成「验过了」。
> 小红书侧自 Native 迁移以来真机零覆盖，改成日常覆盖不会自动改善这一点。

## 4. 本轮不做的（**只是我不做，不是对别人的指令**）

用户口径：**这些多是此前 JS 侧没做完的功能，与「迁移到 Rust 引擎」这批没有关系**，不该混在这一轮排期。

云端拆仓（3 条）、验证码协助基址自证、视频号存储与熔断、发布认领改判、风控目标跟随会话、
自包含指纹浏览器运行时、Facebook 帖子身份两条、发布授权入库、发布触发与执行、
Facebook 发帖填充时限、以及几条差 1–2 项收口的。

**它们的 `tasks.md` 我一个字都没改**，立论仍然成立、缺陷仍然存在。其中三条值得下一个排期的人知道：

- **Facebook 发帖填充时限**：一天前引入的**线上回归**，正文改逐字输入后是 O(长度)，
  云端仍用固定 30s 窗口，约 175 字即中位数超时、200 字几乎必爆，dev 上每篇自动生成的 FB 帖都踩。
- **发布认领改判**：「资源暂时被占」被判成失败，且是 2 秒内烧光预算那种 —— 与本仓
  「失败判定必须是结构性的、资源暂时被占绝不算失败」这条铁律直接冲突。
- **验证码协助基址自证**：基址是进程内验不了的声明，可能**跨环境错投**。

另有两条的**立论已过期**（不是排期问题）：`facebook-join-actuation-decouple` 与
`facebook-consent-structural-detect` 的实装落点在 Native 切换后已不进生产，
**照原文实装等于给永不运行的代码加固**。
判据是「从核心入口到不到得了」，不是「有没有人引用」。**这只是事实登记，处置权在其属主。**

**2026-07-30 处置更新（用户裁定）**：`facebook-join-actuation-decouple` 已删除，全文存 git 历史。
删前复核订正了本节原先的措辞——加群执行器的源文件**并非不存在**，它更名为
`aidcp-edge/src/facebook/join-executor.ts` 仍在仓里；真正成立的判据是它**运行时不可达**：
全仓对 `FacebookJoinExecutor` 只剩两处 `import type`，类型导入编译后被抹除，
`join-executor.js` 从核心入口不可达、随生产剪枝移出产物。`classifyCtaLabel` 亦无任何调用方。
`facebook-consent-structural-detect` **未删**（文件在、被剪枝，且近日仍有改动），维持事实登记、处置权仍在其属主。
