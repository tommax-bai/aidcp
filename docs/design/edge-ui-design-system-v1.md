# AIDCP Edge Design System v1.0

> 状态：Baseline<br>
> 生效日期：2026-07-15<br>
> 适用范围：`aidcp-edge` Electron 客户端，包括主窗口、环境栏、运行进展、发布结果、今日进展、活动流、设置与账号人设浮层。<br>
> 配套速查板：[edge-ui-design-system-v1.svg](./edge-ui-design-system-v1.svg)

## 1. 这份规范解决什么问题

这是一套可复用的设计系统，不是一张固定页面模板。后续设计可以改变信息组合和页面结构，但必须遵守本规范的视觉语义、组件关系、状态诚实性和交互层级。

应用效果图只用于说明一种组合方式，不是唯一答案。规范优先级如下：

1. 状态和业务事实必须真实。
2. 颜色、文案和动效必须遵守各自的语义边界。
3. 组件应复用本文定义的尺寸、字重、圆角和交互状态。
4. 页面可以创新，但不得重新制造已经明确禁止的冲突模式。

文中的“必须 / 应该 / 可以”分别对应 MUST / SHOULD / MAY。

## 2. 设计目标

Edge 是一个长期驻留的桌面运营伴侣，不是后台报表，也不是开发调试台。整体体验应满足四个目标：

- **安静可信**：长期打开不制造持续告警感，不用高饱和色争抢注意力。
- **结果优先**：先说明正在做什么、为什么有价值、取得了什么，再按需展示内部步骤。
- **状态诚实**：停止、失联、无目标、等待和失败必须明确表达，禁止用动效或乐观文案伪装成功。
- **紧凑可扫读**：适配约 `820 × 720` 的真实桌面窗口，不依赖大屏后台布局。

## 3. 四类视觉语义

四类颜色不得互相替代。

| 语义 | 用途 | 主色 | 禁止用法 |
|---|---|---|---|
| 交互 | 当前选择、焦点、链接、主要进度 | Interaction Blue | 不用于平台身份或成功状态 |
| 品牌 / 智能能力 | 吉祥物、人设功能、智能提示 | Mascot Teal | 不代替运行成功绿 |
| 平台身份 | 小红书、Facebook、飞书等来源 | Platform Colors | 不铺满卡片或标题栏 |
| 运行状态 | 成功、等待、失败、离线 | State Colors | 不表示当前选择 |

### 3.1 基础色与交互色

| Token | 值 | 用途 |
|---|---:|---|
| `--edge-bg` | `#F4F7FB` | 主窗口背景 |
| `--edge-surface` | `#FFFFFF` | 卡片、面板、浮层 |
| `--edge-surface-soft` | `#EEF3F9` | 次级中性表面 |
| `--edge-surface-blue` | `#F2F7FF` | 进展汇总等轻蓝表面 |
| `--edge-ink` | `#172238` | 主文字 |
| `--edge-muted` | `#56657E` | 次级说明 |
| `--edge-faint` | `#8B9AB2` | 时间、辅助数据、占位说明 |
| `--edge-border` | `#DFE6F0` | 常规边框 |
| `--edge-border-strong` | `#CFDAE8` | 分组和可交互容器边框 |
| `--edge-blue` | `#3478F6` | 当前选择、焦点、链接 |
| `--edge-blue-soft` | `#E8F0FF` | 蓝色浅底 |

### 3.2 吉祥物与人设功能色

| Token | 值 | 用途 |
|---|---:|---|
| `--mascot-teal` | `#1496A5` | 人设主操作、智能能力标记 |
| `--mascot-teal-dark` | `#087482` | Teal 表面的文字和图标 |
| `--mascot-teal-soft` | `#EAF7F7` | 人设选中态、轻提示 |
| `--mascot-teal-line` | `#B8E0E4` | 人设选项边框、步骤连接 |
| `--mascot-gold` | `#F4B63D` | 温和提醒、待确认 |
| `--mascot-coral` | `#F05A3D` | 小面积庆祝和小红书身份点缀 |

吉祥物色系只在“智能能力、人设、陪伴反馈”语境中成为主色。主窗口的选择和键盘焦点仍使用 Interaction Blue。

### 3.3 平台色

| 平台 | 色值 | 允许范围 |
|---|---:|---|
| 小红书 | `#FF365D` | 账号头像、平台徽标、极小身份提示 |
| Facebook | `#1877F2` | 账号头像、平台徽标、极小身份提示 |
| 飞书 | `#3370FF` | 飞书来源或审批去向标识 |

平台色不得作为选中边框、运行中状态、成功状态或整张卡片背景。

### 3.4 状态色

| 状态 | 前景 | 浅底 | 使用规则 |
|---|---:|---:|---|
| 成功 / 完成 | `#0E8058` | `#E6F7F0` | 已完成、已发布、计划完成 |
| 平静暂停 | `#2F6F78` | `#E8F4F6` | 暂停、自然间隔 |
| 待处理 | `#9A6413` | `#FDF1DC` | 等待用户确认、需要关注 |
| 失败 / 风险 | `#991B1B` | `#FEE2E2` | 失败、风控、阻塞 |
| 离线 / 未开始 | `#64748B` | `#EEF3F9` | 已停止、未连接、未开始 |

失败和风险不得只用颜色表达，必须同时出现清晰文字或图标。

## 4. 字体系统

### 4.1 字体栈

```css
font-family:
  -apple-system,
  BlinkMacSystemFont,
  "PingFang SC",
  "Hiragino Sans GB",
  "Microsoft YaHei",
  "Segoe UI",
  system-ui,
  sans-serif;
```

不加载远程字体，避免桌面包体、离线和跨平台差异。

### 4.2 字体层级

| 层级 | 字号 / 行高 | 字重 | 典型用途 |
|---|---|---:|---|
| `Title/L` | `20 / 28` | `600` | 浮层主标题、完成反馈标题 |
| `Title/M` | `16 / 23` | `600` | 运行价值标题、区块标题 |
| `Title/S` | `14 / 20` | `600` | 账号名、卡片小标题 |
| `Body/M` | `13.5 / 21` | `400–500` | 价值说明、引导文案 |
| `Body/S` | `12.5 / 18` | `400–500` | 选项、活动记录、状态说明 |
| `Label` | `11 / 15` | `500–600` | 徽标、控制、分组名 |
| `Metric` | `16 / 18` | `700` | 今日进展数字 |
| `Caption` | `10 / 14` | `500–600` | 时间、配额、元信息 |

规则：

- 页面中大多数文字使用 `400–500`，不要用粗体制造全部层级。
- 选中态优先通过颜色、浅底、边框和指示器表达，字重最多提升一级。
- 同一区块最多同时出现三档文字层级。
- 数字使用 tabular numerals，避免计数变化时宽度跳动。

## 5. 空间、尺寸与形状

### 5.1 间距

采用 4px 基准网格：

| Token | 值 | 用途 |
|---|---:|---|
| `space-1` | `4px` | 图标和文字微间距 |
| `space-2` | `8px` | 控件内部、同组元素 |
| `space-3` | `12px` | 卡片内部常规间距 |
| `space-4` | `16px` | 区块内主间距 |
| `space-5` | `20px` | 相邻区块 |
| `space-6` | `24px` | 大分组切换 |
| `space-8` | `32px` | 内容章节边界 |

### 5.2 圆角

| Token | 值 | 用途 |
|---|---:|---|
| `radius-xs` | `5px` | 平台小徽标 |
| `radius-s` | `8px` | 图标按钮、轻控件 |
| `radius-m` | `10–12px` | 选择项、分段面板 |
| `radius-l` | `14–16px` | 主卡片、摘要区 |
| `radius-pill` | `999px` | 健康 pill、极少量状态 chip |

一块内容只能有一个主圆角层级。禁止卡片内每一项继续使用同等强度圆角，形成“框套框”。

### 5.3 边框与阴影

- 常规边框：`1px solid var(--edge-border)`。
- 强分组边框：`1px solid var(--edge-border-strong)`。
- 主页面卡片默认不使用明显阴影，依靠背景、边框和留白区分。
- 浮层可以使用 `0 14px 40px rgba(15, 23, 42, 0.14)`。
- 任何长期驻留卡片不得使用发光、彩色投影或多层阴影。

## 6. 页面层级

主窗口默认阅读顺序必须是：

1. 当前账号与整体健康。
2. 当前正在做什么。
3. 为什么这件事有价值、当前取得了什么进展。
4. 最近一次发布或待确认结果。
5. 今日进展与生命周期控制。
6. 活动记录和开发者详情。

### 6.1 内部步骤采用渐进披露

七段内部流程可以存在，但不得以面包屑形式常驻主界面。主界面只保留：

- 用户能理解的三阶段摘要。
- 真实进度，例如 `165/300`。
- 轻量文字入口“查看运行步骤”。

展开后才展示详细步骤。详细步骤仍必须按真实当前阶段点亮。

### 6.2 生命周期控制归属

启动、暂停、恢复、关闭必须位于“今日进展”的操作上下文中。禁止使用覆盖活动流的全局悬浮按钮。

## 7. 核心组件规范

### 7.1 环境栏与账号行

环境栏有展开和收起两种模式：

- 展开宽度约 `176px`，显示昵称、平台身份和状态文字。
- 收起宽度只容纳头像与必要状态点，不保留昵称。
- 头像始终使用平台色。
- 运行状态使用头像右下角小状态点。
- 当前选择使用浅蓝容器和单层短蓝侧标。
- 需处理数字徽标独立存在，不用多层头像环替代。
- 人设入口使用吉祥物 Teal，但不得覆盖平台色头像。

禁止同时叠加平台底色、状态外圈、选中外框和浏览器抬前外框。

### 7.2 标题栏

- 高度基准 `46px`。
- 正常状态使用中性白色表面。
- 账号身份位于左侧；云端、健康、设置位于右侧。
- 标题栏只有真正异常时才使用警戒浅底。
- 平台色只出现在头像和平台徽标。

### 7.3 在场感行

在场感由“状态点 + 当前动作 + 新鲜度”组成：

- 当前动作是主信息，使用 `Title/S` 或 `Title/M`。
- 新鲜度使用 `Caption` 和 Faint 色。
- 动效只能由真实新事件驱动。
- 已停止时必须显示终态，不得继续显示“正在处理”。

### 7.4 运行价值卡

卡片必须同时回答三个问题：

1. 正在做什么？
2. 为什么这样做？
3. 已经取得什么进展？

结构建议：

- Kicker：当前意图。
- Title：面向用户的阶段结果。
- Value：对账号的价值解释。
- 三阶段 Flow：当前推进关系。
- Progress：真实计数、目标和查看详细步骤入口。

运行态吉祥物应紧凑，建议占位 `56–72px`。阶段完成、等待或庆祝场景可以使用 `72–96px` 静态吉祥物。不得让吉祥物成为主视觉背景。

### 7.5 三阶段 Flow

- 图标、标题和连接线必须共享同一状态色。
- 当前推进使用 Blue → Teal 的轻连接动效。
- 已完成连接使用稳定 Success Green，不播放“仍在执行”的动效。
- 说明文字保持中性灰，避免整块都变成彩色。
- 连续动效周期建议 `2.0–2.4s`，只表达真实推进。

### 7.6 发布结果

- 历史发布默认可以收起为单行薄条。
- 待确认稿件必须明显高于历史结果，但不得伪装成已发布。
- 发布、取消等动作在稿件预览内完成；点击后立即关闭抽屉，失败时重新打开并显示原因。
- 所有文案必须区分“已生成、待确认、已批准、已发布、失败”。

### 7.7 今日进展

- 六项数据使用一个分段容器，不使用六张独立 KPI 卡。
- 主数字为 `Metric`，标签为 `Caption`。
- 当前进度使用 Blue，完成使用 Success Green。
- “展开 / 收起”使用文字 + 几何 chevron，无圆形描边和白色底盘。
- 生命周期控制与更新时间位于同一标题区。
- 进度分母必须使用真实账号今日目标；缺少真实目标时不得显示虚假默认值。

### 7.8 人设选择项

- 选项高度基准 `40–44px`。
- 文字使用 `12.5–15px / 500`。
- 未选项使用弱边框和中性文字。
- 选中项使用 Teal 浅底、Teal 边框和勾选指示器，字重不超过 `600`。
- 单选建议三列网格，多选建议两列网格。
- 自定义项使用同尺寸虚线边框。
- 加号必须用 CSS / SVG 几何线条绘制，不能依赖 CJK 字体中的 `＋`。
- Facebook 和小红书只改变平台头像与徽标；通用人设操作仍使用 Teal。

### 7.9 按钮

| 类型 | 用途 | 基本样式 |
|---|---|---|
| Primary | 一个区块的最终动作 | 实色 Blue 或人设语境 Teal，文字白色 |
| Secondary | 取消、返回、辅助动作 | 白底、弱边框、中性文字 |
| Ghost | 展开、查看步骤、编辑 | 透明背景、无边框、Hover 浅底 |
| Warning | 暂停、仍要执行 | Amber 描边或浅底，不使用危险红 |
| Danger | 删除、终止不可逆动作 | Red，必须配清晰动词和确认 |

主按钮文案必须是明确动作，例如“创建环境”“预览人设”“发布”，不得只写“确定”。

## 8. 图标

- 统一使用 `16px` 视觉尺寸、`1.8px` 左右描边、圆角端点。
- 图标颜色跟随组件语义，不单独使用随机颜色。
- 简单 `+`、`−`、chevron、check 优先使用 CSS 或内联 SVG 几何绘制。
- 不使用 Emoji 或系统字体符号承担关键交互图标。
- 不引入远程图标库；新图标应进入现有内联 SVG 体系。

## 9. 动效

| 类型 | 时长 / 周期 | 使用范围 |
|---|---|---|
| Hover / Focus | `120–180ms` | 按钮、选择项、链接 |
| 抽屉开合 | `180–240ms` | 设置、稿件预览 |
| 进度变化 | `240–360ms` | 进度条、计数 |
| 状态呼吸 | `2.2–2.6s` | 真实运行中状态点 |
| Flow 推进 | `2.0–2.4s` | 真实运行中的步骤连接 |
| 吉祥物轻动作 | `3.6–4.5s` | 低频运行陪伴 |

规则：

- 动效必须解释状态，不得只为“显得智能”。
- 完成态停止运行型动效。
- 所有持续动效必须遵守 `prefers-reduced-motion: reduce`。
- 减少动态时仍要通过颜色、文字和图标传达同等信息。

## 10. 文案与情绪

### 10.1 先解释价值，再暴露内部动作

推荐：

> 正在缩小创作方向。<br>
> 刷首页不是漫无目的，而是在寻找目标人群已经验证过的方向。

不推荐：

> 执行 browse loop stage 2，等待 selector 结果。

### 10.2 状态必须可验证

- “已发布”只用于真实发布完成。
- 没有目标时显示“未找到合适目标”，不得显示“已完成”。
- 浏览器关闭、核心停止、云端失联必须显示终态。
- 等待用户确认时使用“待确认”，不得暗示系统会自动完成。

### 10.3 文案层级

- 标题：一句人话结果。
- 说明：为什么对用户有价值。
- 元信息：真实数字、时间、来源。
- 开发者详情：默认隐藏，按需展开。

## 11. 响应式与桌面约束

- 基准窗口：`820 × 720`。
- 最小窗口：`640 × 520`。
- `> 700px`：环境栏可展开，六项进展单行。
- `520–700px`：环境栏优先收起，标题操作可换行。
- `< 520px`：三阶段 Flow 和六项进展允许横向滚动或两行重排。
- 不允许主要动作被裁切到窗口外。
- macOS 红绿灯与 Windows 标题栏控件必须预留安全区。

## 12. 可访问性

- 交互元素必须支持键盘焦点和可见 `focus-visible`。
- 常规文字与背景对比度目标不低于 `4.5:1`；大字不低于 `3:1`。
- 颜色不是唯一状态信号。
- 图标按钮必须有 `aria-label` 和 tooltip。
- 展开控件必须同步 `aria-expanded`。
- 可点击桌面控件最小视觉尺寸建议 `30 × 30px`，主要动作建议高度 `36px` 以上。
- 被隐藏的面板不得继续占据键盘焦点顺序。

## 13. 明确禁止的模式

- 平台色、状态色和选中色叠在一个头像上形成多层套圈。
- 把内部执行管线做成常驻面包屑。
- 六项指标分别做成六张强卡片。
- 用大吉祥物填补信息空白。
- 标题、选项、标签全部使用粗体。
- 用圆形独立按钮承载“展开 / 收起”，让用户猜图标含义。
- 用 Emoji、全角 `＋`、书名号等字体字形承担关键图标。
- 把暂停、失败、无目标包装成“运行顺利”。
- 在同一页面混用多套圆角、阴影和按钮高度。
- 用悬浮控制遮挡活动记录。

## 14. 工程落地

推荐在 Edge renderer 逐步收敛到以下全局令牌：

```css
:root {
  --edge-bg: #f4f7fb;
  --edge-surface: #ffffff;
  --edge-surface-soft: #eef3f9;
  --edge-surface-blue: #f2f7ff;
  --edge-ink: #172238;
  --edge-muted: #56657e;
  --edge-faint: #8b9ab2;
  --edge-border: #dfe6f0;
  --edge-border-strong: #cfdae8;
  --edge-blue: #3478f6;
  --edge-blue-soft: #e8f0ff;
  --mascot-teal: #1496a5;
  --mascot-teal-dark: #087482;
  --mascot-teal-soft: #eaf7f7;
  --mascot-teal-line: #b8e0e4;
  --platform-xhs: #ff365d;
  --platform-facebook: #1877f2;
  --state-success: #159a68;
  --state-warning: #d97706;
  --state-danger: #dc2626;
}
```

新组件落地时：

1. 先确认它属于交互、品牌、平台还是状态语义。
2. 从现有 token 选择颜色，不直接写新的近似色。
3. 使用现有按钮、选择项、状态点和分段容器结构。
4. 补充 hover、focus、disabled、loading、error、empty 状态。
5. 补充窄窗口和 reduced-motion 验证。
6. 用户可见行为变化通过 OpenSpec 记录；只调整视觉但改变信息层级时也应说明影响。

## 15. 设计与评审清单

每个 Edge UI 设计稿和实现至少通过以下检查：

- [ ] 一眼能看出当前账号和平台，但平台色没有占据主画面。
- [ ] 一眼能看出当前状态，且状态文字与真实运行一致。
- [ ] 当前最重要任务只有一个主视觉焦点。
- [ ] 用户能理解系统为什么做这件事，而不只是看到内部步骤。
- [ ] 详细流程默认按需展开，不重复制造第三套进度。
- [ ] 生命周期控制在正确上下文中，不遮挡内容。
- [ ] 字体层级主要由字号、颜色和空间建立，不靠全局粗体。
- [ ] 选中、平台和状态三类颜色互不覆盖。
- [ ] 所有数字、目标、时间和完成状态都来自真实数据。
- [ ] 空态、失败态、等待态和离线态均有明确设计。
- [ ] 键盘、焦点、窄窗口和减少动态偏好可用。
- [ ] 新色值、新圆角或新控件形态有明确必要性，而不是临时发挥。

## 16. 维护规则

- 本文版本采用 `major.minor`：破坏语义边界或核心组件结构时升 major；新增兼容组件或 token 时升 minor。
- 设计规范更新与 Edge 实现可以分阶段进行，但 PR / OpenSpec 必须记录“仅规范”或“已实现”的边界。
- 视觉示例与规范冲突时，以本文文字和 token 为准。
- 当前代码中的历史近似色可以渐进迁移；新代码不得继续扩大颜色漂移。
- 吉祥物资产的选择和使用方式参见 [mascot-transparent/README.md](./mascot-transparent/README.md)。
