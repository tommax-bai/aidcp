### 1.1 假红那族：修法与「为什么不是抬预算」

被修的是四条断言「截止期在流程第 N 步被跨过」的用例。它们用 25–250 毫秒的**绝对墙钟**表达这件事，
并发负载下跨期位置会漂到更早的探测，断言从「已派发但未确认」翻成「未开始」。

修法是**把两个量级分开**，不是把预算调大（调大只是把赌局挪个位置）：

- `DEADLINE_HEADROOM_MS = 1200`：给「不该被跨过」的前置步留出远超调度抖动的余量。
- `SLOW_PROBE_DELAY_MS = 2500`：让「该被跨过」的那一步由**假服务端自己的睡眠**跨过——睡眠只会随负载变长，
  方向永远站在断言这边。
- `const _: () = assert!(SLOW_PROBE_DELAY_MS > DEADLINE_HEADROOM_MS)`：防止后人把两个数一起调回去。

台账子项④预警的坑（提交那条给 50ms 预算，帧预算被算成 1，**它今天能过正是因为踩中了指针静默降级路径**）
随之解除：现在跑正常多帧手势，仍只派发一次抬起。

## 4. 块① 重连认错浏览器 —— 设计已定，是接线活

**危害**：同机多环境并行时，指纹浏览器释放的调试端口会被另一环境复用。引擎重连只按
「目标类型 + 平台域名 + 端口」挑目标，于是**可能附着到别的分身的浏览器上，随后一切动作落在别人账号里**。

### 4.4 实装边界（这条决定改动面大小，别搞反）

**开会话时不要新增网络往返去自读身份。** 13 个测试文件里的假服务端都是**单次 accept、不按路径分发**
（见 `tests/fake_cdp.rs` 的 `serve_target_listing_for`），开会话多读一次就会把它们全打坏。

**正确做法**：身份由宿主随开会话参数传给引擎（引擎侧只记下来），**重连时才实读并比对**。

- `protocol.rs:39-45` `SessionOpenParams` 带 `deny_unknown_fields`，加字段要用 `Option` + `#[serde(default)]`；
  引擎与宿主同包发布，兼容性只需照顾「旧宿主 + 新引擎」。
- 宿主链路：`src/cdp/browser-provider.ts` 捕获 → `src/main.ts:263/269/1473` 的可变端点三元组 →
  `main.ts:340` 的 `getEndpoint` 闭包 → `src/native-page-engine/runtime.ts:171-172` →
  `src/native-page-engine/client.ts:923`（开会话线上参数是**封闭的四字段形状**，没有自由袋）。
- **两半必须同批落**：只落引擎那半会让所有重连直接失败（没有基线 → 按 6.3 诚实拒绝）。

**真正走重连路径的用例只有一条**：`tests/fake_cdp.rs:60`
`read_only_command_reconnects_once_without_replaying_a_write`。改动面很小。
新增用例至少覆盖：端口对上但身份不一致 → 拒绝且零命令执行；无基线 → 诚实拒绝。
