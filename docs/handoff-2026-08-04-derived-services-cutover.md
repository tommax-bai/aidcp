## 2. 为什么 automation 不能跟单体并存（这条决定了切换只能是原子的）

自动化写者锁**按 target 单实例**，且在**构造期**就抢（远早于业务放行），抢不到就 fail-closed
退出。dev 那把锁在单体手里 ⇒ 派生 automation 起不来。这是设计，不是缺陷：两个实例同时持写权，
合计放行的真实平台动作会翻倍。

⇒ **不存在「先让 automation 陪跑一阵子」这个选项**。要么不动，要么切。

## 4. 几条会让人白花时间的（都实测过）

- **`npm install <包名>` 会把 pin 规格从 `git+ssh://` 重写成 `github:`**，对账脚本从此报「未 pin」；
  且本机实测跑了 **37 分钟**。要刷新装机用 `rm -rf node_modules/<包> && npm install`（17 秒）。
- **ECS 上没有 GitHub 私钥**，但 `ssh -A` 转发可用 ⇒ 服务器上不留钥匙也能装私有共享包。
  ECS 的 npm registry 是公网 npmjs，**没有本机那个 @types 劫持问题**。
- **systemd unit 用未加引号的 heredoc 写时，正文里不能出现反引号**——会被 shell 当命令替换执行，
  实测把 `systemctl status` 的输出写进了 unit 文件，systemd 报 `Missing '='`。
- **新加的派生仓私有文件要登记进 `scripts/sync-split-repos` 的私有清单**，否则对账报「多出」、
  `--prune` 会**删掉它们**。
- **门禁写完要变异测试**：本批那道 AC-OWN-07 第一版恒绿（把数组当对象读、表全集为空），
  注入违规仍然全绿，只有变异测试才发现。

## 7. 这一批修掉的（都是「只有真切过去才现形」那一类）

1. **人设解析收成一份**：纯解析提进共享包，内容段编解码器 + 两个组装根按引用共用；
   「解析 / 归一 / 解不出来算什么」三件事收在同一个函数里。载荷与单体当初发的逐位相同。
2. **自动化漏注册第七族**（Facebook 群组操作面，12 个方法）。它比前六族更阴：
   面板那侧依赖是注入了的 ⇒ 不答具名 503，而是被顶层 catch 兜成 500。
3. **接口进程漏注册七族内部路由**（内容进程要用的六族 + 配置镜像失效信号落地端）。
   实测自证：内容进程重启后，日志从「取图片模型失败，沿用保守默认」变成「模型镜像已就绪：真值」。
4. **两条写口漏推配置镜像版本** —— 这条把 dev 干停了 18 分钟，见 §8。
5. **同步读重发周期 == 新鲜期**：每周期末尾都有空窗，多条流「同时新鲜」几乎不成立，
   接口进程的业务入口一次都开不了。改成新鲜期的三分之一。
6. 两道新门禁 + 两条按引用断：接口进程的路由清单闸（两个方向）、
   「写 Facebook 策略必须同事务推版本」（按事务判，不按文件判）、重发周期与新鲜期的比例闸。

## 8. 那 18 分钟：一个新环境把 dev 干停了

**顺序**：11:19 某客户端建了个新 Facebook 环境 → 那笔事务写了两张策略表但没推镜像版本 →
同步读那条流「同游标、不同载荷」→ 消费方按设计永久拒收 → 11:23 切流时自动化就绪不了 →
判定回滚 → **单体也起不来**（启动期那次 apply 同样 fail-closed）→ dev 停摆。

**两条要记住的**：

- **单体从 08-02 起就每天在报这条错**，只是平时不致命（挡刷新、不挡运行），**没有任何人在看**。
  真正的债是这个，不是那条 bug。
- **恢复不能用裸 SQL 改库**：那会把「版本落后」变成一次没人知道的手改。用的是产品自己的写口
  —— 面板「保存全局运营策略」把刚读出来的同一份值原样写回去，语义空操作，只让版本各进一格。
