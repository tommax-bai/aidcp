托管自动化运行时（Managed Automation Runtime）分期实施方案

一、整体框架

这套系统要统一回答四个问题：为什么启动任务、按什么步骤推进、由谁占用账号、如何证明外部动作的结果。

对象模型（六层）

ManagedPlan（长期经营计划，用户授权的边界）
  └─ ManagedCycle（一个运营周期，如每日一轮，分配预算）
      └─ Task / TaskRevision（一件要做的事，修订产生新版本，旧版本不可改）
          └─ ExecutionPlan（编译后的执行图，冻结即不可变）
              └─ TaskRun（一次执行实例：排队/运行/等待/终态）
                  └─ StepRun（执行图中的一步，带检查点可恢复）
                      └─ ExecutionAttempt（一次外部动作尝试，有平台证据才算确认）

四个入口操作

操作语义特点
CreateTaskProposal“现在帮我做……”仅为建议，由 API 鉴权后产生权威 Task
ReviseTaskProposal“接下来改成……”产生新 TaskRevision + 新执行计划，旧的在安全点停
CancelTaskProposal“停掉，别继续了”请求取消，已派发的动作仍如实回执
QueryTaskRequest“进度怎么样了？”只读投影，不产生任何新工作

九个模块，三层职责

层模块职责
L1 决定何时做trigger-registry、managed-cycle-runtime事件/定时/手动触发，周期编排与预算分配
L2 决定怎样推进task-runtime、account-work-arbiter、policy-risk编译执行计划、驱动执行；账号排队仲裁；风控/配额/授权两阶段准入
L3 执行与证明execution-ledger、edge-gateway、reconciler、decision-trace动作账本；边缘派发与能力协商；未知结果对账；全程决策留痕

五条核心原则

  1. 计划不可变：改需求 = 出新版本，绝不原地改，杜绝“改了一半”的中间态；
  2. 两阶段准入：编译时查一次授权预算，每次不可逆动作派发前再实时重读风控/配额/冷却；
  3. 账号单车道：同一账号同一时刻只有一件事在执行，按优先级排队，安全点才能换人；
  4. 平台证据才算数：只认平台稳定 ID/URL/回执，浏览器“点了”不等于“成了”；
  5. 诚实的未知：结果查不清就是 submitted_unknown，交给对账器证明，绝不猜成功或失败。

二、整体能力（全部完成后）

  • 用户一句话（创建/修改/取消/查询）→ 受控、可审计的自动化任务；
  • 全托管日常运营：按周期自动研究、创作、发布、互动，预算受控；
  • 每个外部动作可证明、可追溯、可对账，风控口径全局唯一；
  • 完整取代现有 delegated-task，且切换过程逐能力灰度、可回退。

三、三个阶段

阶段一：地基 + 只读闭环（人类 2–3 周）

目标：把地基打死，跑通第一条端到端链路，全部可演示。

范围

  • 类型契约全量冻结（含阶段二三要用的，只是不实现）；旧 11 态 → 新模型映射文档 + supersession map；
  • 核心 7 张表：tasks、task_revisions、execution_plans、task_runs、step_runs、execution_intents/attempts、decision_traces；
  • 三个入口操作：Create / Cancel / Query（Revise 契约预留、实现延后）；
  • task-runtime 最小版：线性执行图编译 + TaskRun/StepRun 执行 + 检查点恢复；
  • 一条只读纵切：persona 研究任务（搜索→浏览→评估，无平台写入）；
  • decision-trace 从第一天记录。

框架形态：入口层(3/4) + 最小执行引擎 + 只写账本 + 留痕。不含仲裁、对账、周期、预算。

能力：创建一个研究任务 → 编译 → 账号上执行只读研究 → 随时查询进度和结果。总开关默认关，现网零影响。

阶段二：写动作 + 仲裁与对账（增量约 4–6 周人类）

目标：让系统敢做“不可逆的事”。

范围

  • ReviseTask 完整实现（安全点切换、进度继承）；
  • account-work-arbiter 完整版（6 级优先级、抢占、锁顺序）；
  • policy-risk 两阶段准入完整版；edge-gateway 能力协商与版本锁步；
  • reconciler（submitted_unknown 对账：唯一匹配 / 证明不存在 / 多候选留人工）；
  • 三条写纵切：publish（意图冻结+指纹对账）、comment（prepare/commit 两段占用）、reply（api_only 路由）。

框架形态：九模块中八个成型（缺 managed-cycle 完整版），四操作齐全。

能力：发布、评论、回复端到端可托管执行；改任务不丢进度；断网断电结果不糊涂账。

阶段三：全托管 + 切换退役（增量约 4–6 周人类）

目标：从“能执行任务”到“能托管经营”，并完成新旧交接。

范围

  • trigger-registry 完整版（事件/定时触发、幂等派生、latest_wins）；
  • ManagedCycle + 三类独立预算（平台配额 / 执行资源 / AI 成本）；
  • 客户端投影完善、周期总结聚合；
  • legacy delegated-task 适配层、逐能力 OpenSpec delta 生效、影子对标、灰度切换、旧路径退役；
  • （可选并行）迁出到独立 automation 服务仓。

框架形态：九模块全量 + 切换设施。

能力：日常运营全自动按周期跑、预算受控；旧 delegated-task 正式退役，系统只有一套任务模型。

分期逻辑一句话：阶段一打地基且零风险可演示；阶段二攻下“不可逆写动作”这个深水区；阶段三把单任务能力升级成经营能力并完成交接。每一期的产出都是下一期的地基，无返工。
