## ADDED Requirements

### Requirement: 判为阻断的那一刻必须采集现场可见容器的结构

当边缘的阻断探针把当前页面判为阻断态（验证码 / 未知阻断）时，边缘 MUST 在同一次探测内额外采集页面上**视口内可见的对话框 / 浮层容器**的结构化现场，并随既有阻断上报送达云端。

采集的入选口径 MUST 覆盖：具备对话框语义（`role="dialog"` 或 `aria-modal="true"`）的可见容器，以及定位为 fixed / absolute 且面积超过阈值的可见容器。该口径 MUST NOT 要求容器带 iframe，MUST NOT 要求容器缺少关闭控件，MUST NOT 要求容器达到判定通道所用的尺寸阈值——真实的平台限流弹窗普遍不满足这三者中的任意一项。

采集 MUST 为只读：MUST NOT 点击、MUST NOT 修改页面、MUST NOT 触发导航。

#### Scenario: 标准限流弹窗被采到

- **WHEN** 页面上出现一个带对话框语义、不含 iframe、面积约占视口三分之一、右下角带确认按钮的阻断弹窗，且探针已将页面判为阻断态
- **THEN** 上报载荷 MUST 包含该容器的结构化现场，MUST NOT 因该容器不满足判定通道的候选筛选阈值而报出空的现场

#### Scenario: 采集不点击不改页

- **WHEN** 采集在某个含可点击子元素的阻断容器上运行
- **THEN** 该容器及页面的状态 MUST 保持不变，MUST NOT 因采集而发生点击、导航或 DOM 变更

### Requirement: 每个采到的容器必须携带足以复现动作的三层信息

对每个入选容器，采集结果 MUST 同时包含下列三层信息：

1. **结构特征**：标签名、id、class、role、无障碍属性、`data-testid`、有界的层级路径、相对视口的位置与尺寸、定位方式与层叠序、是否位于 iframe 内。
2. **可点击子元素清单**：容器内部每个可点击子元素的可见文字、无障碍标签、role、标签名，以及**相对视口的位置与尺寸**。位置与尺寸 MUST 采集，MUST NOT 以「有文字即可定位」为由省略——同一平台上不同部位所需的点击方式不同（部分部位只有元素点击有效，部分部位只有坐标点击有效），事先无法判断新形态属于哪一类，故两种方式所需的信息都必须留存。
3. **容器 HTML 原文**：容器的 `outerHTML`，按上限截断。

三层信息 MUST 同时存在。MUST NOT 以「结构特征已经够用」为由省略 HTML 原文——原文的作用正是覆盖字段设计未预料到的后续需求，缺失它会使每一次字段遗漏都必须等待下一次真机复现。

#### Scenario: 可点击子元素带坐标

- **WHEN** 某阻断容器内含一个确认按钮
- **THEN** 采集结果中该按钮的条目 MUST 同时包含其可见文字 / 无障碍标签与相对视口的位置尺寸

#### Scenario: 容器原文被保留

- **WHEN** 某阻断容器被采集
- **THEN** 采集结果 MUST 包含该容器的 HTML 原文（截断至上限内）

### Requirement: 采集必须有界，且超限必须显式标记

采集 MUST 受下列硬上限约束：入选容器数上限、每容器可点击子元素数上限、每容器 HTML 原文字节上限、单次采集总字节上限。任一上限被触及时，采集结果 MUST 显式标记该项已被截断。

MUST NOT 静默截断后将结果呈现为完整样本。

本要求的理由：阻断探针按固定周期反复运行且受命令超时预算约束，而探测超时的处置是保持上一状态——无上限的采集会把探测拖至超时，等于使阻断监测失明。这是本能力唯一可能反向损害生产行为的路径。

#### Scenario: 超限被标记

- **WHEN** 某容器的 HTML 原文超过字节上限
- **THEN** 采集结果 MUST 只携带截断后的原文，且 MUST 带有该项已被截断的显式标记

#### Scenario: 采集不拖垮探测

- **WHEN** 页面上存在大量可见浮层容器
- **THEN** 采集 MUST 在上限内结束，MUST NOT 使该次阻断探测超过其超时预算

### Requirement: 采集结果必须区分「采到了」「确实没有」「没能采到」三态

上报载荷 MUST 能区分下列三种结果，且三者 MUST 有不同的取值：

- 采集成功且采到至少一个容器；
- 采集成功但页面上确实没有符合入选口径的可见容器；
- 采集本身未能完成（求值抛错、超时、或结果不可用），并 MUST 携带原因。

MUST NOT 用同一个空结果同时表示「确实没有」与「没能采到」。

#### Scenario: 没能采到不伪装成没有

- **WHEN** 采集因页面求值抛错而未能完成
- **THEN** 上报载荷 MUST 标记为采集失败并携带原因，MUST NOT 呈现为「页面上没有可见容器」

#### Scenario: 确实没有被如实标记

- **WHEN** 采集正常完成，但页面上不存在符合入选口径的可见容器
- **THEN** 上报载荷 MUST 标记为「确实没有」，MUST NOT 标记为采集失败

### Requirement: 采集失败不得影响既有阻断上报与判定

采集是既有阻断上报的加法。采集失败、超时或被截断时，边缘 MUST 照常发出既有的阻断上报（含阻断类别与既有证据文案），其内容与行为 MUST 与本能力引入前一致。

采集结果 MUST NOT 参与阻断判定：判定的输入 MUST 仍只是既有的页面文本与既有判据。放宽采集入选口径 MUST NOT 导致任何页面被判为阻断态。

#### Scenario: 采集失败仍照常上报

- **WHEN** 某次阻断被判出，而现场采集抛错
- **THEN** 边缘 MUST 照常发出阻断上报，其阻断类别与证据文案 MUST 与采集引入前一致

#### Scenario: 采集口径不改变判定

- **WHEN** 某页面上存在符合采集入选口径但不命中任何阻断判据的良性浮层
- **THEN** 该页面 MUST NOT 被判为阻断态，MUST NOT 因采集口径较判定口径更宽而产生任何上报

### Requirement: 云端必须为每次带现场的上报留存一条可查询样本

云端每收到一次携带现场采集结果的阻断上报，MUST 原样留存一条结构化样本，其内容 MUST 保留采集结果的结构（MUST NOT 在留存前拍平为供人阅读的文本）。

样本留存 MUST NOT 受告警去重冷却的影响：留存动作 MUST 在冷却判定之前完成，使冷却窗内被抑制告警的上报同样留下样本。

样本 MUST 可按平台、来源页面地址与文案指纹查询。

#### Scenario: 冷却窗内的上报仍留样本

- **WHEN** 同一边缘在告警冷却窗内再次上报同类阻断，其告警按既有规则被抑制
- **THEN** 该次上报的现场样本 MUST 仍被留存

#### Scenario: 结构不被拍平

- **WHEN** 一条携带多个容器与可点击子元素清单的现场被留存
- **THEN** 留存内容 MUST 保持其结构化形态，MUST 可按容器与子元素逐项读出

### Requirement: 每次采集必须带边缘生成的采集标识，且告警必须据此可回溯到样本

每次现场采集 MUST 携带一个**由边缘生成**的采集标识，该标识随阻断上报送达云端，并 MUST 满足：

- 云端 MUST 以该标识作为样本的唯一键，使同一次上报被重复投递时 MUST NOT 产生第二条样本；
- 该标识 MUST 出现在边缘的诊断记录中，使同一次采集可从边缘侧与云端侧双向对上；
- 该标识 MUST NOT 由页面内容派生（如文案哈希）——同一形态的弹窗会反复出现，内容派生的标识会把多次独立采集折叠为一条。

由该次上报触发的告警，其正文 MUST 展示该采集标识，使收到告警的人 MUST 能据此直接定位到对应样本。

#### Scenario: 从告警定位到样本

- **WHEN** 一次携带现场的阻断上报触发了告警
- **THEN** 该告警正文 MUST 展示本次采集标识，且按该标识 MUST 能在样本留存中查到唯一一条对应记录

#### Scenario: 重复投递不产生第二条样本

- **WHEN** 同一次采集的上报因重投而被云端处理两次
- **THEN** 样本留存中该采集标识对应的记录 MUST 仍为一条

### Requirement: 样本留存失败时告警必须如实说明未存住

当采集标识已产生、而样本留存失败时，告警正文 MUST 仍展示该采集标识，并 MUST 显式标注该样本未能存住。

MUST NOT 在留存失败时把采集标识从告警中省略——省略会使该次现场既查不到样本、也无从得知曾经采到过，是静默假失败。

#### Scenario: 留存失败仍给出标识与实情

- **WHEN** 某次采集成功但样本写入存储失败
- **THEN** 告警正文 MUST 仍展示该次采集标识，且 MUST 标注该样本未存住

### Requirement: 样本留存不得改变既有告警与风控行为

引入样本留存 MUST NOT 改变：阻断上报触发的风控状态迁移、按边缘暂停下发的行为、告警的类型 / 优先级 / 标题 / 去重冷却窗、以及告警落库行为。

告警正文的变更 MUST 限于新增采集标识相关的展示；其余既有正文内容 MUST 逐字不变。

样本留存失败 MUST 被记录且 MUST NOT 静默吞没，同时 MUST NOT 阻断风控迁移、暂停下发或告警投递。

#### Scenario: 样本写入失败不阻断告警

- **WHEN** 样本留存因存储故障失败
- **THEN** 该失败 MUST 被记录，且风控迁移、暂停下发与告警投递 MUST 照常完成

#### Scenario: 告警面貌除标识行外不变

- **WHEN** 一次携带现场的阻断上报被处理
- **THEN** 其告警的类型、优先级、标题 MUST 与本能力引入前一致，正文除新增的采集标识展示外 MUST 逐字不变

### Requirement: 采集实装必须落在生产路径上

现场采集的实装 MUST 落在实际参与生产运行的阻断探测路径上。MUST NOT 实装于已从生产构建中剪除的模块，也 MUST NOT 实装于其消费方均已退役的模块。

页面规则部分 MUST 遵循既有的防反编译约束，MUST NOT 以明文形式进入生产构建产物。

本要求的理由：退役模块中已存在一份形似的候选筛选实现，在其上实装会通过全部本地测试与发布流程，而运营机上的行为不变且无任何告警。

#### Scenario: 采集在生产探测路径上生效

- **WHEN** 运行生产构建的边缘遇到阻断弹窗
- **THEN** 其上报 MUST 携带现场采集结果，MUST NOT 因实装落在非生产路径而仍为空

#### Scenario: 页面规则不进明文产物

- **WHEN** 生产构建产物被扫描
- **THEN** 采集所用的页面规则 MUST NOT 以明文形式出现在产物中
