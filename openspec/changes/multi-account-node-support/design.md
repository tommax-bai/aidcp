## Context

云端编排器今天是**单租户单体**：一套 `RoleDispatcher` + 一个 `SessionContext` + 一个 `EventBus`，`currentAccountId` 钉死 `'default'`（`role-dispatcher.ts:157-164`），下行指令广播给所有连接（`server.ts:568-572` → `ws-server.ts:154-168`），握手事件丢账号身份（`handler.ts:282`）。这套结构在「全机一个 edge 一个账号」下正确，但运营要**一台机器多节点、各跑不同账号**，于是它在三处坍塌：串号（按 A 算的指令发到 B）、连接互相重置会话、限频闸看 `default` 而记账看真实账号致限频失效。

姊妹 change `account-persona-config`（接近完成）已建好按账号人设：PG `persona_config`（`account_id` 主键，迁移 0011）、`PersonaStore`（落库 + 内存镜像 + 热加载）、解析器 `createPersonaResolver(accountId)`、后台人设页与设置 API（JWT）。**它的解析器对未绑账号刻意回落打包默认（绝不 brick）**，且决策器的账号仍是 `default`。本 change 接力：把云端改成**按连接多租户**，让那套按账号解析真的按真实账号生效，并补一条产品规则的诚实闸。

约束（项目铁律）：边轻云重、状态单写、**绝不静默假成功/绝不静默啥也不干**、协议 v2 改动须四处同步、DOM-first 定位三闸与 CdpClient 重连不可破。

## Goals / Non-Goals

**Goals:**
- 一台机器多个 edge 节点各驱动**不同账号**，互不串号、互不重置、限频按真实账号生效。
- **同一账号被多个节点并行驱动**也安全：N 节点**共享该账号单一风控/配额控制器**（额度合并不翻倍）、**不对同一笔记/作者重复动作**、记账串行。
- 每个 edge 节点驱动**自己独立的 Chrome**，绝不静默接管别的节点的浏览器。
- 落实规则：**原有账号**连上即复用其已绑人设；**新账号没设人设则诚实拒绝启动**并在后台标出，绝不以默认人设偷跑。

**Non-Goals:**
- **同机不同账号的防关联**（不同设备指纹 / 独立 IP / 指纹浏览器）——**本 change 不做**，edge 仍一机真实指纹；该能力由后续 change `adspower-browser-provider` 以显式 opt-in 的可插拔浏览器 provider 接入。
- 重写 DOM 定位 / 浏览闭环逻辑——只动「谁来路由、谁的上下文、用谁的账号、同账号怎么协调」。

## Decisions

### D1. 每连接一束独立运行时 + 私有事件通道（决策 ①，含看板改造）
**选择**：握手时为该连接创建一束独立运行时 = **私有 `EventBus` + `RoleDispatcher` + `SessionContext`（信息流状态/预算/待评论/当前账号）+ SessionMonitor**，按 `sessionId/edgeId` 持有；该连接的入站消息只灌进它自己的私有通道、出站指令只发回自己的 `edgeId`；断连即拆除。**连带改造后台看板**：实时看板原本订阅那条单一全局总线，现改为**跨所有连接的私有通道聚合**成对外仍是单一全局流（`console-panel-api` 的扇出适配）。
**理由**：私有通道让隔离从结构上成立——连接之间不可能互相收到对方事件，**无需逐事件打标再过滤**，「新连接重置老会话」「两账号串味」从根上消失，也不留「漏打标即串台」的纪律债。代价是看板扇出要从「订阅一条总线」改成「聚合 N 条通道」，这是已知且可控的一处改动。
**取舍/备选**：① 共享总线 + 逐事件打标过滤——不动看板但留串台纪律债，**否决**（用户选私有通道、接受改看板）；② 单体内部按 edgeId 取键——要把 edgeId 穿进所有共享可变状态、易漏，**否决**。**全局仍共享**：per-account 风控控制器注册表（同账号 N 连接天然共用一个 → 额度按账号合并，见 D7）、`PersonaStore`、PG 各 store。**[内存]** 每连接一束运行时 + 一条私有通道，少量账号无虞；规模化再评估对象复用/上限。

### D2. 指令路由：每连接运行时让路由「免费」
**选择**：因 D1 每个 `RoleDispatcher` 属于某个连接，其 `sendCommand` 闭包直接捕获自己的 `edgeId`，调 `pushToEdges(env, edgeId)`（原语 `ws-server.ts:160` 已支持按 edgeId 过滤）。
**理由**：不必给 `EdgeCommand` 加目标字段（`role-dispatcher.ts:129-133` 不变）；广播路径（`server.ts:568-572` 无 edgeId）被「带本连接 edgeId」取代。单 edge 下「发给唯一连接」与原广播等价——**非 BREAKING**。

### D3. 诚实人设启动闸 = 解析器之外的独立判据（与 account-persona-config 不冲突）
**选择**：会话启动前，用 `PersonaStore.getForAccount(accountId) !== null` 作**独立**「绑没绑」判据；**绑了**照常 `startSession`；**未绑**则不开循环、不发巡刷信号、**在角色重订阅/指令翻译重连之前短路**（`role-dispatcher.ts:492-494` 之前），账号置 `needs_persona_setup` + 飞书告警。**`default` 账号硬豁免**：`if (accountId !== 'default' && getForAccount(accountId) === null) 拒绝`。握手缺/空 `accountId` **当未绑处理，绝不映射成 `default` 偷跑**。
**理由**：`account-persona-config` 的解析器刻意对未绑回落打包默认（never-brick + prompt 注入安全网），**那条语义不能动**否则会 brick `default`。把「能不能启动」与「启动后用哪份 soul」拆成两件事：闸在解析器之前决定前者、只对真实未绑账号拒绝，解析器后者语义原样保留。这样「没绑人设」是一个**可观测的明确拒绝**，永远区别于「绑到默认」、永远不是「静默用默认跑」。
**备选**：复用解析器的回落作为「绑定」信号——否决，因为它本就会回落，无法区分「绑了 default」与「没绑」。

### D4. 账号身份穿透与新账号自动登记
**选择**：`handler.ts:282` 的 `edge.hello` 事件载荷加 `accountId`（`event-bus/types.ts:126`），创建/选取该连接运行时时设入其 `currentAccountId`；握手时 `account-store` `ensureAccount(accountId)` upsert 一行「未配置」账号，使新账号在后台 `GET /api/accounts` 即时可见、等设人设。绑定状态以 **`persona_config` 行存在**为准；死列 `accounts.persona_ref`（`account-store.ts:25`）留着不用。

### D5. 边缘每节点独立 Chrome + 堵静默接管
**选择**：编排（端口/目录/身份分配、拉起 N 进程）放在 **edge 之外的启动器**（`scripts/`），每节点 `AIDCP_CDP_PORT=base+N`、`AIDCP_CHROME_PROFILE=~/.aidcp-chrome-profile-<accountId>-<节点号>`、真实 `AIDCP_ACCOUNT_ID`/`AIDCP_EDGE_ID`。edge **唯一核心改动**：`chrome-launcher.ts:502-521` 探测到端口上已有 Chrome 时**默认拒绝复用、诚实报错**，除非显式 `AIDCP_CDP_ALLOW_REUSE`；崩溃残留单例锁仅在确认无活进程持有时清。
**理由**：保持边缘薄（编排不进 edge 核心）；「默认拒绝复用」直接消灭「静默接管陌生浏览器还报成功」红线，也使「只换端口共享目录」这类误配诚实失败而非静默挂死。**本 change 不引入指纹浏览器**（YAGNI，防关联非本 change 目标；后续由 change `adspower-browser-provider` 以可插拔 provider 接入）。

### D6. 被拒 / 需配置 → 飞书通知 + 后台状态（决策 ③，不动协议）
**选择**：被拒（未绑人设 / 缺账号身份）经**飞书通知 + 后台 `needs_persona_setup` 状态**呈现，运营据此去后台设人设；**不新增 cloud→edge 命令、完全不动边-云协议**。被拒节点本次**接受空转**（看门狗按 idle 收尾后或重连再被拒），由飞书把人叫去处理。
**理由**：用户取舍——「让节点自己停」要动协议四处（含 typecheck 抓不到的白名单），成本/回归面大；改用飞书通知把运营叫去补人设，更轻、且不碰协议红线。残留：被拒节点会空转/churn，靠飞书及时通知 + 运营动作收敛（接受）。

### D7. 同账号并行（N:1）安全（决策 ②，本次纳入）
**选择**：允许同一账号被多个节点并行驱动；安全由三件事保证：① **共享单一 per-account 控制器**——D1 里每连接运行时按真实账号经控制器注册表取控制器，同账号 N 连接**天然拿到同一个**，故互动计数按账号合并、N 节点**共用该账号每日额度（不翻倍）**，几乎零额外代码；② **互动前按账号去重防双动**——云端在把互动决策下发为指令前，按账号查「该笔记/作者是否已被本账号在途或已完成同类互动」，是则跳过；点赞/收藏已有 per-note 落库去重，**关注/评论/评论赞无 per-note 去重，尤须此闸**；③ **记账串行化**——同账号控制器的计数读改写串行（队列/锁），防并发竞争重复扣减。**重连区分**：同 `edgeId` 重连**顶替**旧连接（不算并行第二节点），仅「同账号 + 不同 `edgeId` + 旧连接仍活」才视为真并行。
**理由**：① 几乎免费（注册表本就 per-account 单例）；② 是同账号并行**唯一真正新增**的硬骨头——两节点各刷各的 feed，多数时候看到的笔记不同，但一旦撞同一篇/同一作者，关注/评论会真重复，必须按账号去重；③ 防边界并发竞争。**备选**：「硬拒第二连接」——用户否决，要求真支持并行。

## Risks / Trade-offs

- **[迁移回归] 上线诚实闸瞬间，现存「靠默认人设静默在跑」的真实账号会突变「未绑定、拒启动」** → 上线前**预种 `persona_config` 行**给所有已知真实账号，或把拒绝**先限定在新账号/非 `default`**；`default` 永久豁免（D3 硬分支）。
- **[同账号双动残窗] 同账号并行已纳入（D7：共享 per-account 控制器 + 互动前去重 + 记账串行）**，但去重若只看「已完成」而漏「在途」，两节点近乎同时对同一笔记/作者动作仍会双发 → 去重 MUST 含 **in-flight 声明**（下发即占坑、回执或超时释放），并对**关注/评论/评论赞**（无 per-note 去重）确保兜底。
- **[看板扇出改造] 改私有通道后，实时看板须从「订阅一条总线」改为「聚合 N 条私有通道」**（对外仍单一全局流、不漏不重） → apply 阶段须核实概念池 / SessionMonitor 等是否依赖单一全局总线做跨连接协调，私有化后不破坏既有单账号行为。
- **[DTO 漂移] cloud `panel/types.ts` ↔ console `types/api.ts` 手工镜像** → 加字段时两处同步，PR 自检。
- **[并行 change 撞车] 与 `safety-quota-config` 共改 `interaction-risk-gating`、与 `account-real-nickname` 共改 `account-store.ts`/panel DTO** → 错峰、加性改动、先确认对方落点。

## Migration Plan

1. **预种人设**：为所有已知真实账号在 `persona_config` 写入有效 soul 行（否则被诚实闸拒）。`default` 无需（豁免）。
1b. **默认账号显式声明身份**：给现存默认账号的 edge 启动器显式设 `AIDCP_ACCOUNT_ID=default`——上线「拒绝缺 accountId 握手」后，不显式声明会被拒（决策 4）。
2. **cloud 部署**：按连接私有运行时 + 路由 + 闸 + 账号 upsert + 同账号去重/串行 + 看板聚合；先测两不同账号（两套上下文、指令不串、限频各按账号、未绑被拒并入后台），再测**同账号两节点**（共用一个控制器、额度合并不翻倍、撞同一笔记/作者不双动、断线重连顶替不并列）。
3. **console 部署**：账号列表「需设置人设」状态标 + 链接。
4. **edge 启动器**：发布每节点端口/目录/身份分配 + 拒绝复用；两节点不同账号验证两 PID/两端口/两目录、登录各自持久。
5. **回滚**：核心多租户路由对单 edge 向后兼容；风险集中在「诚实闸」——以「闸限定非 `default` + 预种迁移」兜底；必要时可临时放宽闸为「仅告警不拒」回滚。

## Open Questions（已决策 2026-06-24，用户拍板）

1. **隔离形态** → **每连接一条私有事件通道**（决策 ①，见 D1）；连带**改造后台看板**为跨连接聚合。取代原「共享总线打标」倾向——用户接受改看板换取无串台纪律债。
2. **同账号并行** → **本次纳入、要做**（决策 ②，见 D7：共享 per-account 控制器 + 互动前按账号去重防双动 + 记账串行）；不再「硬拒第二连接」。同 `edgeId` 重连顶替、仅「同账号 + 不同 `edgeId` + 旧连接仍活」算真并行。
3. **被拒呈现** → **飞书通知 + 后台状态**（决策 ③，见 D6）；**不新增 cloud→edge 命令、不动协议**；被拒节点接受空转，靠飞书把人叫去补人设。
4. **缺 `accountId`** → **拒绝握手**当配置错误（决策 ④）；连带迁移：现默认账号的 edge 须**显式声明 `AIDCP_ACCOUNT_ID=default`**。

> 残留待 apply 时定：D7 去重的 in-flight 声明粒度（笔记级 / 作者级 / 动作级）与超时释放时长；看板聚合的具体接法。
