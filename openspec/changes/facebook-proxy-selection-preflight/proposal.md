## Why

Facebook 环境目前要等浏览器启动后才暴露代理类型配置错误或代理已不可用，用户点击启动后才失败，自动唤醒也会浪费一次浏览器启动。客户端已经能在主进程读取 AdsPower 保存的完整代理配置，因此可以把一次轻量检测提前到用户选择离线环境时，并让后续启动复用结果。

## What Changes

- 选择未启动的 Facebook 环境时，在 Electron 主进程后台执行一次不启动浏览器、不占浏览器槽位的代理预检。
- 在短时内存有效期内复用同一环境的检测结果；手动启动或冷待机自动唤醒仅在结果缺失或过期时补做一次。
- 已确认代理不可用时停止本次浏览器启动或唤醒并显示直白原因；无法读取配置或检测器自身不可用时保持“无法确认”，不把未知冒充代理失效。
- 代理密码只在主进程单次检测调用中使用，不进入 IPC、日志或持久化缓存。
- 保留现有浏览器代际出口观测和现有冷待机失败退避，不新增浏览器重建阻塞门禁或独立重试状态机。

## Capabilities

### New Capabilities
- `facebook-proxy-preflight`: Facebook 离线环境选择时的后台代理预检、短时结果复用、启动/唤醒闸与安全状态投影。

### Modified Capabilities

## Impact

- `aidcp-edge` Electron 主进程：AdsPower profile 代理配置的主进程内安全读取、代理预检、环境选择与启动/唤醒接入。
- `aidcp-edge` renderer：复用现有代理状态入口显示预检中、代理可用、代理不可用或无法确认。
- 新增小型运行时代理 Agent 依赖以覆盖 AdsPower 已支持的 HTTP、HTTPS 与 SOCKS5 类型。
- 不修改 Cloud、边云协议、浏览器槽位容量、任务重试策略或客户 HTTP 数据面。
