## Why

词汇蓝图批 3。三段对账的第③段今天缺位：命令带期望（批 4 起）、边缘报错两态（规格已立）之后，**云端没有任何命令能问「浏览器现在到底在哪个面、登着谁」**——报错之后没有出路。46 条里最近的是读登录身份（问登着谁，不问在哪页）；「在哪个面」只能事后从回执顺带的观察里读到，不能主动问。云端对当前页的推定是开环的（会漂、脱节无人上报），恢复链需要一个真相探针。

## What Changes

- **新增观察命令「问现状」**：cloud → edge 请求 + edge → cloud 应答一对消息类型（协议 93 → 95）。应答一次带回：当前面（结构化枚举，绝不裸字符串）+ 当前登录身份观察 + 采集时刻。按语法：观察族、**无平台段**（翻译层/环境层观察，不编址平台）；登记类别用批 2 新增的 `page_observation`（已协调，批 2 并行中）。
- **纯读**：MUST NOT 触发任何导航、点击、滚动；页面读不出来时如实回「没能确认」（与「确认到在 X 面」两态分开）。
- 边缘实现走引擎既有的页面分类与身份读取能力（FB 已有面分类器；XHS 按引擎现有观察路径），不新造探测。
- 协议四处同步纪律全走：两份 protocol.ts 逐字一致、登记表 ×2、**edge-client 主动命令路由白名单**（第 4 处，漏了就是静默丢弃）、protocol.md 计数与表。
- 云端侧只落**命令与应答的通道**（发得出、收得到、能关联）；把它接进恢复决策链（何时问、问完怎么改航向）是阶段四（观测决策上移）的活，本批不做。

## Capabilities

- `edge-state-observation`: 云端主动询问边缘浏览器现场（面 + 身份）的观察命令——三段对账第③段的载体。

### Modified Capabilities
（无）
