> 本 change 的实质是**让默认值有一个跟着版本走的落脚点**，而不只是把一个值改对。

## 1. aidcp-cloud

- [ ] 1.1 放开兜底的判据从「不等于关就是开」改为「等于开才是开」。注意这不是简单取反：新写法把配置缺失、为空、取值拼错三种情形一并归入严格侧，失败方向由宽松转为收紧。
- [ ] 1.2 就近注释改写：写明默认为严格、环境变量是显式临时放开、以及「默认值必须由代码承载」的理由（运行时配置不进版本库、部署被排除、静默失效）。

## 2. aidcp-cloud — 测试

- [ ] 2.2 断言只有显式开启才放开。
- [ ] 2.3 断言显式关闭仍为严格（dev 现存那一行的取值，改后必须仍然成立）。
- [ ] 2.4 跑 `npm run test:acceptance` → `npm test` → `npm run typecheck`。

## 3. 部署与验收（dev）

- [ ] 3.1 部署 cloud 到 dev（控制仓 §5 安全序列）。无数据库改动。
- [ ] 3.2 验收：把 dev 上那一行显式配置**临时移除**后重启，确认行为仍是严格（这才真正证明默认值生效，而不是靠那一行撑着）；确认后按需决定保留或删除该行。
