## Why

change `restore-native-facebook-feed-card-discovery`（edge `2a4752a`）把首页找卡从 0 张修到 4–5 张真卡，但**可上报卡仍是 0**——找得到卡，读不出帖子地址。2026-07-29 在真实账号环境（Xu Nu / `k1f4kcsv`，越南语首页）上逐项实测，原因已完全查清：

**Facebook 不再把帖子地址放进页面。** 一张卡里有 3–4 个链接指向站点根路径；其中只有**时间戳**那一个是真正的帖子链接，它的目的地被扣着，**只有经调试通道下发的可信指针移动落到它上面，Facebook 才把真地址换进 DOM**。

实测数据（同一账号、同一版式）：

| 手段 | 结果 |
| --- | --- |
| 什么都不做（对照） | 0/8 |
| 页面内合成 `pointerover`/`mouseover`/`mouseenter`/`mousemove` | **0/8** |
| 页面内 `focus()` | 3/25 |
| **经 CDP 下发的可信指针移动** | **5/5**（瞄准时间戳时） |

配套的其他事实（均为实测）：

- **视口外悬停无效**；目标必须真正落在视口内。
- **地址一旦换出就持久**：鼠标挪走 4 秒、再悬停、滚走两屏再滚回来，地址都还在。**不是一次性**。
- **前台 / 后台无关**：窗口停靠在边缘时页面自述仍是 `hasFocus:true` / `visible`，两种模式生效率无差异（2/13 vs 1/12，用的都是不可靠的 `focus()`）。
- **同卡多个候选可按形状区分**：时间戳是扁长文字链接（实测 124×15、位于卡顶部 3%、无无障碍标签）；「隐藏此帖」等是方块图标链接（36×36、含图标、带无障碍标签）且悬停后**不变**——后者是用链接形式实现的按钮，本就没有目的地。
- **时间戳的可见文字被打散**（人眼「3 小时前」，程序读到 `d n s o e t r p o S`），所以不能靠文案定位它。
- 整页范围内 `pfbid` 在任何属性、隐藏链接、内联脚本中出现次数为 **0**——悬停前身份根本不在 DOM 里，**没有免交互的替代路径**。

因此：**不引入可信悬停，Facebook 首页就永远读不出任何可操作目标。** 当前账号只能靠 Reels 兜底运转，首页浏览、首页点赞、首页评论、由首页发现的引流线索全部为零。

## What Changes

- **扫卡从「一次求值」升级为「引擎编排的多轮往返」**：页面侧负责找卡与读地址，引擎侧负责下发可信指针移动，两者交替进行。
- **新增一次「身份候选」探测**：对尚无地址的卡，按形状筛出候选链接（扁长、有文字、无图标、无无障碍标签，位于卡上部），返回其视口坐标与所属卡。
- **新增引擎侧身份采集回合**：对每个候选下发一次可信指针移动 → 有界等待 → 重扫卡列表；卡获得地址即视为命中，其余候选跳过。
- **有界与止损**：每张卡候选数上限、每轮处理卡数上限、整轮墙钟上限；任一上限触顶即停止采集、按当前已得结果继续，不重试、不延长。
- **坐标临用临取**：每次移动前重新读取坐标，禁止复用上一次探测的坐标（懒加载会在上方插入内容使坐标过期）。
- **跳过已解析的卡**：地址持久，已有地址的卡不再参与采集。

## Capabilities

### New Capabilities
- `facebook-feed-post-identity-acquisition`: Facebook 信息流帖子身份的交互式采集——何时采集、用什么手段采集、边界与止损、以及采集失败时的诚实终态。

### Modified Capabilities
（无）

> **刻意不改 `native-facebook-behavior-parity`**：该能力的「Native Feed scanning preserves stateful continuation truth」已被两条**尚未归档**的 change 各自持有 delta（`restore-native-facebook-feed-scroll-continuation` 修改了它、`restore-native-facebook-feed-card-discovery` 在同一能力下新增了两条）。再叠一份对同一条要求的修改会在归档合并时撞车。故本 change 把「扫卡可以产生有界只读指针移动」这条义务写进新能力自身，不去动那一条。

## Impact

- **代码**：`aidcp-edge` 的 Native 引擎——注入脚本（候选筛选、地址回读）+ Rust 侧编排（指针移动、轮次与预算控制）。cloud / 协议 / console 零改动。
- **时长**：单次滚动命令最坏从约 10 秒升到约 30 秒（取决于上限取值）。云端闲置看门狗为 240 秒，余量充足；且这只发生在「有卡待解析」的路径上。
- **反检测方向为正**：引擎当前的指针停在视口中央不动、只发滚轮；改后光标会随阅读在帖子之间移动，更接近真人轨迹。
- **红线不变**：MUST NOT 静默假成功。采集不到地址的卡一律不上报、不猜、不借用邻卡或作者 / 图片 / 动态地址。指针移动**只移动、不按下**，不得产生任何点击。
