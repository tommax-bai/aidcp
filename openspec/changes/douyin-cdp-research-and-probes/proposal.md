## Why

AIDCP 目前没有经过真实抖音网页验证的浏览、互动或发布编排能力，也不能把 TikTok 的页面结构、目标标识和成功语义直接套到抖音。需要先以本地 AdsPower 环境建立默认只读、动作显式授权、结果不假报的独立 CDP 探针，再决定是否进入正式平台接入；正式内容发布优先评估抖音开放平台，而不是依赖网页最终提交。

## What Changes

- 新增抖音网页端 CDP 调研探针，识别登录、可见安全验证、访问限制、页面形态和可滚动容器，并以抖音 `data-aweme-id` 等页面证据建立稳定作品标识。
- 新增有界浏览探针：分别适配精选卡片流与单作品详情，不缓存跨滚动 DOM 节点；每次滚动或导航后重新确认作品标识和目标唯一性。
- 设计一次性点赞探针：默认仅观察，真实动作必须同时满足显式动作开关、精确 profile 确认、已登录、目标唯一和动作前后同一作品；已点赞时不得反向取消。
- 设计评论输入探针：只定位并填写唯一评论编辑器，代码路径不拥有发送按钮、回车提交、表单提交或发送开关，并回读输入结果。
- 新增一次性关注与收藏探针：默认 shadow，只有各自动作开关、精确 profile 确认、唯一作品和可读未动作状态同时满足时才执行；已关注或已收藏绝不反向取消。
- 新增已知交互提示探针：动作控件被新手提示遮挡时，只允许精确匹配并关闭唯一可见的“我知道了”按钮，关闭后重新做坐标命中与状态预检，不把落在遮罩层的输入当作动作成功。
- 新增一次性私信回复探针：只选择一个可证明为私聊、最近消息入站且可回复的会话；群聊或会话类型不明必须阻断，只允许发送“好的”或“ok”，不输出会话正文或对方身份。
- 新增直播探针：只在一个明确直播间发送一次普通发言“1111”；只有能唯一定位具体直播评论及其回复入口时，才定向回复一次“666”，不得把普通发言冒充评论回复。
- 设计发布调研双路径：网页端只读识别创作者/上传编排器结构且不提交；正式发布能力优先采用抖音开放平台 OAuth、视频上传/创建和发布后查询能力，并保留每次发布前的用户明确感知与批准。
- 所有探针输出最小化、脱敏的结构化证据，不读取或记录 cookie、token、手机号、请求正文、评论内容或账号敏感标识。
- 使用本地 AdsPower profile `k1evgky5` 做受控验证；用户已明确授权一次关注、一次收藏、一次私聊回复“好的”、一次直播普通发言“1111”、一次直播评论定向回复“666”以及后续新增的一次点赞。每类动作仍须独立运行门和同目标 UI 回查；不执行普通作品评论发送、文件上传或发布。此前一次 DM 因缺少会话类型判定误发到群聊，必须作为偏差记录并由私聊-only fixture 防回归，不得把它计为有效私聊验收。
- 本变更只交付研究/验收探针，不注册抖音为生产平台，不修改 Cloud 协议、自动运营调度、发布队列或风险计数。

## Capabilities

### New Capabilities

- `douyin-cdp-research-probes`: 规定抖音网页端安全连接、登录与阻断识别、有界浏览、受控点赞、评论只输入不发送、一次性关注/收藏、一次性私信/直播回复、发布路径调研和脱敏证据的探针行为。

### Modified Capabilities

无。

## Impact

- 预期代码：`aidcp-edge` 新增独立的抖音调研探针、手动 runner 和聚焦测试；不接生产 command router。真机验证会产生最多一次点赞、一次关注、一次收藏、一条私信和两条直播消息的真实外部动作。
- 运行环境：本地 AdsPower API、明确绑定的 `k1evgky5` profile 和其动态 CDP endpoint；不访问 Cloud，不部署到 dev/ol。
- 官方接入：后续生产发布若获准，将另行设计抖音开放平台应用审核、OAuth token 托管、`video.create` 权限、用户批准和发布状态回查；不纳入本探针实现。
- API/数据：本变更无生产协议、数据库或第三方依赖变更。
- 风险：抖音页面会因登录状态、页面形态、灰度实验和安全策略变化而诚实失败；目标歧义、登录失效、可见验证、访问受限或确认超时均必须中止，不得推断成功。
