## ADDED Requirements

### Requirement: OL 更新通道由打包元数据固定

系统 SHALL 只在已打包的 macOS 客户端内、且该客户端的打包元数据明确标记为 `ol` 更新通道并提供合法 HTTPS 更新基址时启用自动更新。更新通道 SHALL 由打包时的元数据决定，MUST NOT 由运行时选择的 dev / ol / custom 云端地址、环境变量或 cloud 消息推导。未标记为 OL 的客户端、开发态客户端及 Windows 客户端 MUST NOT 请求或下载 OL 更新。

#### Scenario: OL 包即使切换运行时云端仍使用 OL 更新通道
- **WHEN** 一个带有效 OL 更新元数据的已打包 macOS 客户端把运行时云端选择改为 dev 或 custom
- **THEN** 客户端仍只从其烘焙的 OL HTTPS 更新基址检查更新，且不从运行时云端地址推导更新源

#### Scenario: 非 OL 或开发客户端不访问线上更新源
- **WHEN** 一个开发态、未带 OL 更新元数据或 Windows 的客户端启动
- **THEN** 客户端 MUST NOT 对 OL 更新基址发起检查、下载或安装请求

### Requirement: 更新检查和下载须由用户可见且可控

OL 更新客户端 SHALL 在主窗口可用后延迟检查一次更新，并且后续检查频率 MUST NOT 高于每六小时一次。已启用更新的客户端 SHALL 提供可由用户点击的“检查更新”入口；手动检查 MUST 复用同一检查服务、不得并发请求、不得自动下载或自动重启，并在没有更新时给出“当前已是最新”的明确反馈。发现更高版本时，客户端 MUST 显示当前版本、可用版本及“下载更新”“稍后提醒”入口；客户端 MUST NOT 在用户确认下载前下载更新，也 MUST NOT 在用户确认安装前重启应用。没有更新时不打扰用户。

#### Scenario: 发现可用更新但用户暂不下载
- **WHEN** 检查结果包含高于当前版本的有效 OL 更新且用户选择“稍后提醒”
- **THEN** 客户端保持当前版本和正在运行的环境不变，且在下一次合规检查前不重复下载该更新

#### Scenario: 用户确认下载并获得进度
- **WHEN** 用户在可用更新提示中确认下载
- **THEN** 客户端开始下载、显示可理解的下载状态或进度，并在下载成功后提示“立即重启更新”或“稍后”

#### Scenario: 用户手动检查且已是最新
- **WHEN** 一个已启用 OL 更新的客户端用户点击“检查更新”，且 stable manifest 没有更高版本
- **THEN** 客户端发起一次不与现有检查并发的检查，并明确显示当前版本已是最新，且不下载或重启应用

#### Scenario: 更新检查失败不影响当前工作
- **WHEN** 更新基址不可达、manifest 无效或检查过程发生错误
- **THEN** 客户端 MUST 如实记录并以非阻断方式提示检查失败，保持当前版本和所有运行环境继续可用，MUST NOT 伪报“已是最新”

### Requirement: 更新安装必须在所有 edge 子进程有序停止后发生

用户选择“立即重启更新”时，客户端 MUST 明确告知该动作将停止所有受监督 edge 环境，并取得确认。确认后客户端 SHALL 请求所有运行中的 edge 子进程有序停止并等待有界收尾；只有全部子进程已确认退出时，客户端才 MAY 调用更新器的安装重启。更新安装流程 MUST NOT 仅依赖普通 `before-quit` 事件触发停机。

#### Scenario: 没有运行环境时安装更新
- **WHEN** 更新已下载且用户确认立即安装，且没有 edge 子进程在运行
- **THEN** 客户端调用更新器安装并重启，且不额外伪造任务停止状态

#### Scenario: 有运行环境时先明确停机再安装
- **WHEN** 更新已下载、存在一个或多个运行中的 edge 子进程且用户确认立即安装
- **THEN** 客户端先显示停止影响，随后有序停止全部子进程；全部确认退出后才安装并重启

#### Scenario: 子进程未能在有界时间内停止
- **WHEN** 更新安装前的任一 edge 子进程未能在规定的有界停机流程内退出
- **THEN** 客户端 MUST 取消本次安装重启、如实告知未完成停机，并保持当前应用可继续操作；MUST NOT 把该结果显示为已更新

### Requirement: 更新完成、取消与失败状态必须诚实可见

客户端 SHALL 将更新检查、下载、准备安装及失败记录到本机诊断日志。下载失败、校验失败、用户取消或安装前停机失败 MUST 保留当前版本并显示对应事实；客户端 MUST NOT 把“已下载”显示为“已安装”，也 MUST NOT 把下载取消显示为更新成功。

#### Scenario: 下载成功但尚未重启
- **WHEN** 更新文件已完整下载但用户选择稍后重启
- **THEN** 客户端显示更新已就绪但当前运行版本未变，并在用户后续明确触发安装或正常退出后按更新器语义应用
