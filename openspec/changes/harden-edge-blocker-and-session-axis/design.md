## Context

外壳的环境状态由一个状态推导块合成，其中两根轴各自被一个**证明不了它的信号**驱动。

**取证结论（2026-08-06 实读代码，立项前完成）：**

| 事 | 结论 |
| --- | --- |
| 阻断浮层标记在**现役平台上有没有写入方** | **有。** 现役 Native 引擎在阻断检出时发结构化 `popup`、在复检确认解除时发 `popup_cleared`（`aidcp-edge/src/native-page-engine/browse-session.ts`）。**本改动因此有真实生产效果，不是在退役路径上空转。** |
| 退役路径 | 中文日志那两句（`检测到X弹窗，暂停操作` / `阻断弹窗已清除，恢复浏览`）的唯一发射点在**已退役**的 `src/browse/browse-session.ts`。壳侧那两条中文正则今天已无人触发，属死规则 |
| 摘掉 `session_end` 后**会不会永远卡在「需要处理」** | **不会。** 清除路径在产（同上），且环境启停会重置该标记 |
| 本地清除与云端清除**会不会分叉** | **摘掉后不会。** 二者由**同一个函数**先后发出：先向云端发验证码解除、再发界面清除事件。`session_end` 正是今天唯一那条只清本地、不通知云端的旁路——**摘掉它，两侧从此同源** |
| 会话轴 | 已退役 TypeScript 浏览循环是其唯一写入方；现役引擎发的是结构化会话行（`session.event event=session_ready` / `session_stopped`），**外壳零解析分支**（全仓零命中） |

分层依据：`edge-addressing-layers` 规格。冷待机准入现状与红线：`browser-cold-standby` 规格。

## Goals / Non-Goals

**Goals:**

- 阻断浮层标记回到 `edge-fleet-console` 已规定的行为：**只认显式解除**。
- 让本地阻断态与云端暂停集合**在清除侧同源**，消灭唯一那条只清一边的旁路。
- 会话轴重新获得**在产写入方**，界面上「这个号在不在跑」不再是陈旧值。
- 把「会话轴即便有了写入方也不得回准入闸」写进规格——**这是本 change 自己制造的缺口**。

**Non-Goals:**

- **不动云端那道验证码否决。** 该计划已作废；浏览期阻断浮层按分层判据属账号层、云端单写。
- **不动协议、不动云端、不动发布链与风控。** 单仓 `aidcp-edge`。
- 不改用户主动关闭 / 暂停路径。
- 不扩大阻断检测的平台覆盖（见 R1）。

## Decisions

### D1 · 摘掉 `session_end`，而不是给它附加条件

**否决的替代方案**：保留 `session_end` 但要求「同时复检页面确无浮层才清」。

理由：**会话结束与阻断是否解除之间没有因果**，附加条件只是在一个不成立的推断外面再套一层，
并且引入**第二条清除判据**——而分叉正是要消灭的东西。摘掉之后，清除只剩一条路径，
且该路径与通知云端的信号**同处同源**（见 Context 表最后一行）。

判例已有：同一段代码里按「**清除是判断、不是副作用**」删过「任何成功互动顺带清除」那条兜底。
`session_end` 是同一类不成立的推断，当时漏了。本决策是把同一把尺子用完。

### D2 · 会话轴改读结构化会话行；这**不是**退回「解析日志」

结构化会话行与被淘汰的中文措辞推断有三点本质区别，缺一不可，实装时须逐条守住：

1. **token 化**——引擎侧对字段做过字符集收敛，不含页面正文，不会因文案改写而漂。
2. **平台中立**——各平台分片共用同一发射点，不是某平台专属措辞。
3. **写入方在产**——现役引擎每条会话都发。

因此本轴满足 `browser-cold-standby` 新条款「每个输入都要有可证写入方」。
**但满足该条款不等于可以进准入闸**，见 D3。

**回归断言沿用 `admit-browser-standby-on-live-facts` 的 D2 做法**：从壳侧解析器抽出匹配串，
逐个到引擎源码里找发射点。这条断言是那次事故的机械化教训，本 change **MUST NOT** 省略。

### D3 · 会话轴 **MUST NOT** 回到冷待机准入闸——理由是姿态，不是写入方

现行条款禁止的是「写入方已退役的生命周期标签」。本 change 一旦给它接上活写入方，
**该禁令就不再覆盖它**，日后完全可以有人「合规地」把它加回准入闸——这是本 change 自己开的口子，
必须当场堵上。

真正的理由在 `docs/stop-or-continue.md`：**这根轴描述的是目标周边处境（在不在跑），不是目标身份**
（换个结果不会导致被操作的是另一个对象）。姿态条件 MUST NOT 单独用来拒绝动手。
所以写进规格的措辞要落在**姿态 vs 身份**上，而不是「因为它以前坏过」。

### D4 · 两件合并为一个 change

改的是同一个状态推导块里相邻的十余行。分开做，第二个必然要 rebase 第一个的同一段。
风险等级也同档（都只在外壳内、都不动协议）。

### D5 · 与 `browser-slot-scheduling` 串行，不并行

该活跃 change（59/69，认领停滞）与本 change 共享这个状态推导块。按 CLAUDE.md §7
「热点文件单写者」，本 change **须标记需串行**。已核：其 tasks 无与本 change 重叠项
（其 5.8「需求驱动的让位 / 槽位借调」明确标为**不做**）。

## Risks / Trade-offs

- **[R1] 平台策略门可能让某些平台的旗子恒为假** → 阻断 UI 事件的两个发射点都在同一个
  `emitsCompanionUi` 平台策略门后面。**两侧对称**，所以不会产生「置得起清不掉」的偏态；
  但若某平台该门为关，本改动对其无效。**处置：本 change 只登记、不扩大覆盖**，
  实装时把实测结果写进 tasks 备注。
- **[R2] 摘掉一条清除路径 = 阻断态停留时间变长** → 这正是意图（真实阻断本就该停留到有人处理）。
  反向风险是误报滞留，由 D2 的清除路径在产 + 环境启停重置兜住。
- **[R3] 会话轴解析写成宽松匹配就白改了** → 若实装时用自然语言或宽正则去凑，等于把被淘汰的
  措辞推断换个地方重来。**判据：匹配串必须是引擎侧 token 化字段，且能在引擎源码里指出发射点**（D2 断言）。
- **[R4] 改完在运营机上不生效** → 本仓默认不打安装包。**本 change 的效果要到客户端重新编译装机后才存在**；
  且用户重编译**不抬版本号**，验收时 MUST NOT 用版本号判断装的是哪份代码。

## Migration Plan

单仓、纯外壳、无数据与协议变更，无迁移步骤。

- **上线路径**：合入 `aidcp-edge` 默认分支 → 客户端重新编译装机（用户显式触发）。
- **回滚**：`git revert` 该提交即可，无残留状态。**不需要**开关旗标——两处改动都不引入新配置。
