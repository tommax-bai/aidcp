## Why

运营希望账号「到点自动发帖」——按星期几 / 几点排期，让云端在指定时段自动生成帖子草稿、仍走飞书人审、通过才真发，而不必每次手动 `/publish`。今天发帖的自动扳机（概念积累 / 距上次时窗）只支持**恰好一个账号**、且无「星期 × 小时」的运营控制；「活跃时间设置」那张周历掩码只治浏览会话、不治发帖。缺一条「多账号 + 按时段 + 仍人审」的发帖排期通路。

本变更是「多账号内容排期」功能的 **Phase 1，只做发帖**；评论排期、群评排期是后续独立变更（群评还有前置门槛，见 Impact）。

## What Changes

- **【新·内容排期调度器】** 云端新增一个每分钟心跳的内容调度器：只决定「此刻对哪个账号试发帖」，命中后调用**现成**的发帖触发机器产草稿。它是**触发扇入、不是新发送通道**——绝不新增发送口、绝不自动发送（发布前人审 AC-PUB 全程保留）、绝不碰浏览活跃掩码、绝不碰风控最终态单写、绝不加边-云协议。
- **【新·全局「内容可自动时段」周历格】** 与浏览掩码**物理分开**的另一张 168 格（7 天 × 24 小时）'0'/'1' 掩码，治「何时允许自动发帖」。语义 **fail-closed**：缺失 / 非法 = 全 0 = 不自动（与浏览掩码「缺失 = 全天活跃」刻意相反，因为自动发送后果重）。
- **【新·每账号发帖排期】** 每账号一份排期：总开关（默认关）、发帖开关（默认关）、发帖日上限（默认 0）、可选的每账号时段覆盖（默认继承全局；**v1 留存储、不做编辑界面**）。**未配 = 完全不自动**（零回归）。
- **【新·后台「内容排期」页】** 控制台新页：顶部一张全局「内容可自动时段」网格（复用现有浏览掩码那张网格控件），下面每账号一行「开关 + 日上限」表；账号变多只加行、不加要画的格子。手动 `/publish` 完全不受时窗限制。
- **【新·多账号发帖能力】** 把现有发帖触发机器从「单账号自动扳机」泛化到「按显式账号触发」（新增排期触发入口，绕开单账号闸；persona 绑定 / 风控 normal / `canDo('publish')` / 人审全部不变）。发帖生成**全局串行**（避免全局账号槽被并发污染成本记账）。
- **【新·排期安全闸】** 分钟错峰（账号 × 日期 × 动作哈希，天天变、账号间错开）；发帖日上限做成**原子**（已发历史 + 在途未审草稿一起计，防重启 / 双扳机超发）；新调度器开启时**无条件关闭**旧的单账号自动发帖定时器（防错时双触发）；每次触发无论成功 / 诚实空槽（无素材本次不发）/ 失败都回一张飞书结果卡（绝不静默假成功）。

> 非 BREAKING：新表、新调度器、新页均为纯新增；所有开关默认关、未配即维持今天行为；旧单账号自动扳机在新调度器未开启时保持不变。

## Capabilities

### New Capabilities
- `content-schedule`: 「内容排期」域——全局「内容可自动时段」周历格 + 每账号发帖排期的**数据契约与 fail-closed 语义**；内容调度器的**触发扇入行为**（每分钟心跳、账号扇出、分钟错峰、发帖日上限原子性、风控 normal 闸、发帖全局串行、fire-and-forget、无条件关旧扳机、每次触发回结果卡、手动不受限）；本 Phase 仅发帖、发布前人审不变；多账号共用全局时段格的协同指纹**已知缺口**声明；评论 / 群评排期的后续前置声明。

### Modified Capabilities
- `console-write-operations`: 新增一条 Requirement——内容排期的写入（每账号 `PUT /api/content-schedule/:accountId` 与全局 `PUT /api/content-schedule/global`）经受 JWT 保护的一等单写通道，UPSERT-only、写前校验账号存在（防造幽灵排期行）、退役账号拒、非法整块拒不部分落库、写后回读真态、拒绝与成功可区分、绝不 raw UPDATE / 绝不乐观假成功；掩码 / 上限 / 开关的**默认与非法值一律 fail-closed（归不自动）**。与该 spec「写只经拥有者对象、诚实非乐观」核心不变量同构。

## Impact

- **aidcp-cloud**：新增内容调度器（云端单进程、命令式触发器，不进 `RoleDispatcher` 角色注册、不走 `EventBus`）；新增全局单例表 `content_schedule_global` 与旁挂 1:1 侧表 `account_content_schedule`（均 `CREATE TABLE IF NOT EXISTS` 自愈自建、无迁移器，伴随人审文档 `migrations/0028_content_schedule.sql`，编号避让 0026/0027 已占）；发帖触发机器加「按显式账号排期触发」孪生入口 + 全局串行只读闸 + 按账号「今日已发」计数；连接注册表加「在线账号」访问器；`server.ts` 装配调度器并在其开启时无条件短路旧单账号自动扳机。**复用不改**：发布管线的生成 / 发布前人审 / 发送（`publish-pipeline` 契约不变，仅多一个触发来源）；风控最终态单写；边-云协议。
- **aidcp-console**：先抽出浏览掩码那张周历网格为共用组件；新增「内容排期」页（全局网格卡 + 每账号策略表）；新增读写 `/api/content-schedule[/:accountId]` 与 `/api/content-schedule/global` 的查询与表单。
- **不触及**：浏览活跃掩码（`weekly-active-window` 一字不改）；边-云 WebSocket 协议 v2；`RiskController` 最终状态单写；dispatcher 角色注册数；同机 isales。
- **协同风险**：云端 `account-store` / `panel-server` / `panel/types` / `server` 现被多个未提交 change（`editable-account-group-label` + `account-group-chat-injection` + `role-thinking-mode-config`）交织占用；本变更用「新侧表 + 新写通道 + 新页」最大化避开交织，几乎不碰 `accounts` 表列与既有 `accountAttr` 通道；**落地时序**：等那摊解结、提交后再落。
- **已知缺口（写进 design）**：多账号默认共用同一张全局内容格 → 小时级活跃模式逐位相同、协同指纹残留（分钟错峰只在小时内打散）；本 Phase 记为已知缺口，缓解（hour-mask 打散 / 最小账号集）留后续。
- **后续变更前置声明**：评论排期需先做「搜索结果页有界翻页」边缘探针 + 评论在途草稿台账；群评排期需 `account-group-chat-injection` 在真机验证「审=发」+ 部署 + 归档之后，且把「一码一号」升级为硬阻断、群评日计数持久化、聚合层人审卡节流，并以 MODIFIED delta 正式重写其「仅命令式」spec 那一条。
