## ADDED Requirements

### Requirement: 迁移的属主归属必须由显式声明给出，缺声明一律失败

迁移执行器 SHALL 按唯一的解析顺序判定一条迁移属于哪个属主库：① 文件内属主头声明；② 历史迁移的封闭属主名册条目；③ 文件头对象声明能定位到的表的属主；④ 以上皆无 —— **MUST 失败并指名该迁移**。

MUST NOT 存在「无法判定归属时计入全部属主」的推断路径。归属判定 MUST NOT 由 SQL 文本反推表名。

#### Scenario: 新增迁移既无属主头也无可定位属主的对象声明

- **WHEN** 开发者新增一条迁移，文件头既没有属主声明，其对象声明也无法定位到任何一张已登记属主的表
- **THEN** 迁移状态查询与执行 MUST 失败并指名该迁移的版本 id，MUST NOT 把它计入任何属主，更 MUST NOT 计入全部属主

#### Scenario: 只声明索引的迁移

- **WHEN** 一条迁移的对象声明里只有索引名（索引名无法反推归属表）
- **THEN** 该迁移 MUST 由属主头或名册条目给出归属；两者皆无时 MUST 失败

#### Scenario: 归属由对象声明正常定位

- **WHEN** 一条迁移的对象声明包含某张已登记属主的表
- **THEN** 该迁移的执行范围 MUST 恰为这些表的属主集合，判定结果与本 change 之前逐字一致

### Requirement: 执行范围与账本范围必须分开

一条迁移的**账本范围** SHALL 为全部属主 —— 每个属主库都记一条「该版本已处置」，以免拆库后外域迁移被当作待应用重放、或被乱序闸判为失序而整批拒绝。

一条迁移的**执行范围** SHALL 由属主声明给出，MUST 是账本范围的子集。执行器 MUST 只在执行范围内的属主库里执行该迁移的 SQL；在执行范围外的属主库里 MUST 只写账本行、MUST NOT 执行任何语句。

执行器 MUST 在每次运行时把「记账但未执行」的版本清单原样打出，MUST NOT 静默。

#### Scenario: 单属主迁移在其它属主库

- **WHEN** 一条执行范围仅为某一个属主的迁移，在另一个属主的库上被处理
- **THEN** 该库的账本 MUST 新增该版本的行，且 MUST NOT 对该库执行该迁移的任何语句

#### Scenario: 迁移触及的表只存在于自己的属主库

- **WHEN** 一条迁移在自己属主的表上建索引，而该表在另外两个属主的库里并不存在
- **THEN** 在另外两个库上 MUST 不产生任何 SQL 执行，MUST NOT 出现「关系不存在」类错误，MUST NOT 中断整批

### Requirement: 历史迁移的属主声明走封闭名册，且名册只减不增

已经入过账本的迁移文件 MUST NOT 被修改字节 —— 校验和是整文件摘要，任何改动都会让已应用该迁移的库整批拒绝迁移命令。

因此本 change 落地前已存在的迁移，其属主声明 SHALL 记录在一份独立的封闭名册里，逐条给出版本 id、属主集合与判定依据。该名册 MUST 只减不增：条目只在其对应迁移被接替或删除时消失。名册 MUST NOT 接受本 change 落地之后新增的迁移 —— 新迁移一律用文件内属主头声明。

#### Scenario: 试图给已应用的迁移文件加属主头

- **WHEN** 开发者往一条已入账本的迁移文件里追加属主头声明
- **THEN** 该库的迁移状态查询 MUST 报校验和不一致并整批拒绝，MUST NOT 重跑、MUST NOT 覆盖账本里的校验和

#### Scenario: 试图把新迁移写进历史名册

- **WHEN** 开发者把一条新增迁移的版本 id 写进封闭名册
- **THEN** 门禁 MUST 失败并要求改用文件内属主头声明

#### Scenario: 名册条目对应的迁移已被删除

- **WHEN** 名册里某条目对应的迁移文件在目录中已不存在
- **THEN** 门禁 MUST 失败并指名该失效条目，要求同批清理

### Requirement: 记账不执行的迁移必须具名声明接替者

一条迁移的执行范围可以为空（在任何属主库里都只记账、不执行），但**仅限**历史名册中的条目，且 MUST 同时具名声明接替它的迁移。被点名的接替迁移合起来 MUST 覆盖它原本创建的全部对象。

执行范围为空且未声明接替者的条目 MUST 判失败。新增迁移 MUST NOT 使用该形态。

#### Scenario: 跨属主的历史迁移被拆分接替

- **WHEN** 一条历史迁移在两个不同属主的表上各建对象、在任何单一属主库里都无法执行
- **THEN** 它 MUST 在名册里声明执行范围为空并点名接替它的每条新迁移，且新迁移 MUST 用幂等形态创建对应对象，使已建成的库上重跑为空转

#### Scenario: 执行范围为空但没有接替者

- **WHEN** 名册里某条目的执行范围为空且未声明接替迁移
- **THEN** 门禁 MUST 失败 —— 否则该迁移创建过的对象会在全新库上被悄悄丢弃

### Requirement: 每条迁移在其执行范围内的每个属主库里必须可执行

系统 SHALL 提供一道静态闸：对执行范围含属主 O 的每条迁移，它引用的每一张表 MUST 由某条执行范围也含 O 的迁移创建。任一条不满足即失败并指名「迁移 / 属主 / 缺失的表」。

该闸用于判定表引用的 SQL 扫描 MUST NOT 参与归属判定 —— 它只有否决权，永远不得为任何迁移分配属主。扫描解析不了的语句 MUST 失败并指名，MUST NOT 静默跳过。该闸 MUST 进验收用例集。

#### Scenario: 新增一条引用了外域表的迁移

- **WHEN** 开发者新增一条迁移，它在自己属主的库里引用了一张由另一属主的迁移创建的表
- **THEN** 该闸 MUST 失败并指出这条迁移在哪个属主库里缺哪张表，验收用例集不通过

#### Scenario: 扫描器遇到无法解析的语句

- **WHEN** 迁移中出现该闸的 SQL 扫描无法解析的语句形态
- **THEN** 闸 MUST 失败并指名该迁移与该语句，MUST NOT 当作「没有表引用」放行

### Requirement: 派生仓的迁移命令必须可执行，且不得手工维护

三个派生业务仓 SHALL 各自具备可执行的迁移命令：其全部模块引用 MUST 解析到该仓中实际存在的模块（共享内核以包依赖形式取用，MUST NOT 相对引用一个只存在于事实源仓的路径）。

承载迁移命令的脚本目录 MUST 纳入拆仓同步的覆盖范围并逐文件点名，MUST NOT 靠手工搬运维护。同步 MUST 按既有规则把指向共享内核的相对说明符改写为包说明符。

#### Scenario: 派生仓执行迁移状态查询

- **WHEN** 在任一派生业务仓中执行迁移状态查询
- **THEN** 命令 MUST 正常启动并给出该仓属主的迁移状态，MUST NOT 因模块解析失败而无法启动

#### Scenario: 事实源仓改动迁移命令后未同步

- **WHEN** 事实源仓的迁移命令脚本发生改动而派生仓未同步
- **THEN** 拆仓同步的对账 MUST 报出该文件存在差异，MUST NOT 只对源码目录报账而对脚本目录失明

#### Scenario: 派生仓中已应用的迁移文件

- **WHEN** 某条迁移的执行范围收窄到不含某个属主
- **THEN** 该迁移文件 MUST 仍分发到该属主仓（账本范围不变），MUST NOT 因执行范围收窄而从该仓删除
