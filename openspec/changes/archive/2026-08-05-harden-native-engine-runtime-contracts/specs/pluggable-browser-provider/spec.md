## MODIFIED Requirements

### Requirement: CDP 接入层在 provider 之下保持不变

无论选用哪个 provider，其 `launch` SHALL 产出一个统一形状的浏览器实例句柄（含可连接的 CDP host 与端口、以及关闭 / 确认关闭能力）。CDP 附着及其下游的定位、拟人化操作、登录身份读取 MUST NOT 因 provider 不同而出现任何分支或改动——它们 SHALL 只依赖该统一句柄给出的 host 与端口。

该统一句柄 SHALL 在会话的整个生命周期内保持权威：任何下游消费方（含独立进程的页面执行引擎）在**重新建立**与浏览器的连接时，MUST 重新向该句柄解析当前 host 与端口，MUST NOT 把建会话那一次读到的值当成会话期内恒定的事实。指纹浏览器的调试端口是动态分配的，长时会话期内该值可能变化。

目标选择 SHALL 带分身身份证据：判据 MUST NOT 只有「平台 + 端口」。同机多环境并行时，一个环境释放的调试端口可被另一个环境取得，仅按平台与端口筛选可能接管另一个分身的浏览器，并在真实账号上留下平台可见行为。当无法取得可验证的身份证据、或无候选目标可被证明属于被准入的那一个浏览器实例时，消费方 MUST 诚实回报执行器健康类失败并交回宿主处理，MUST NOT 退化为「端口对上就接管」。

#### Scenario: AdsPower 的调试端口喂给现成接入层
- **WHEN** `adspower` 提供商启动浏览器并返回其标准 DevTools 调试端口
- **THEN** edge 用与 `self` 模式完全相同的 CDP 附着路径连上该端口，定位 / 拟人 / 读身份逻辑零改动地工作

#### Scenario: 重连时端点已变
- **WHEN** 被准入的浏览器实例仍健康，但其调试端点自建会话以来发生变化，下游消费方需要重连
- **THEN** 消费方重新向统一句柄解析当前 host 与端口并连回被准入的那一个实例
- **AND** 它不会因为建会话时缓存的旧端点不再应答而判失败

#### Scenario: 端口被同机另一环境复用
- **WHEN** 重连时那个端口已被同机另一个环境的浏览器占用
- **THEN** 身份证据不匹配，消费方拒绝附着并回报执行器健康类失败
- **AND** 该会话的任何命令都不会在另一个分身的浏览器上执行
