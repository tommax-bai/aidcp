## Context

Electron 主进程已经分别投影 `coreState`、`engineLinkState`、`automationState` 与 `browserState`，但环境栏仍把它们压回 `error / attention / launching / stale / running / offline` 六个视觉级别。结果是 `ready` 与 `running` 同组、`waiting_resource` 与真正启动过程同组、浏览器关闭但引擎在线的冷待机又容易落到离线含义。与此同时，权威槽位队列只把位次写进自然语言日志，渲染层没有结构化位次可用。

现有环境栏的头像底色表达平台、浅蓝容器和左侧短标表达选中/浏览器抬前、红橙左标表达需处理；这些语义已经稳定，不能被运行状态颜色复用。浏览器槽位队列和串行启动队列也已有既定调度策略，本变更只能投影其真态，不能重排它们。

## Goals / Non-Goals

**Goals:**

- 让用户在现有左栏中一眼区分正在执行、已占用浏览器等待任务、启动过渡、真实排队、关闭浏览器待唤醒、暂停和未启动。
- 所有环境栏主状态文案不超过三个汉字；需处理项保留独立的完整原因，不用含糊短词替代诊断事实。
- 仅显示主进程权威调度器可证明的排队位次。
- 让“全部启动”的 k/N 统计基于真实可执行状态，而不是核心子进程是否存活。

**Non-Goals:**

- 不改环境栏宽度、行结构、平台筛选、选中交互和右侧主区域布局。
- 不改变串行启动优先级、等槽位 FIFO、容量上限或冷待机策略。
- 不把本变更扩展为“先连引擎、确认需要后再打开浏览器”的启动链路重构。
- 不构建或发布桌面安装包。

## Decisions

### 1. 从四条生命周期轴推导单一环境栏状态

`fleetLevel` 继续是环境栏投影的唯一纯函数，但返回值增加 `state`、`railGroup` 与 `detail`：

| 环境栏状态 | 判据 | 分组 | 状态点 |
| --- | --- | --- | --- |
| `运行中` | `automationState=running` | 运行中 | 绿色实心 |
| `待任务` | 自动化 `ready`、引擎已连接、浏览器 `ready` | 待任务 | 绿色实心 |
| `启动中` | 自动化/浏览器正在启动 | 启动中 | 蓝色实心 |
| `连接中` | 浏览器已就绪但引擎首次连接中 | 启动中 | 蓝色实心 |
| `排队中` | `automationState=waiting_resource` | 排队中 | 蓝色空心 |
| `待机中` | 自动化 `ready`、引擎已连接、浏览器关闭 | 待机中 | 绿色空心 |
| `已暂停` | 自动化暂停 | 暂停 | 灰色实心 |
| `未启动` | 自动化停止且无更高优先级问题 | 离线 | 灰色实心 |

失联、异常和需人工处理继续优先于普通生命周期状态。需处理行只显示不超过三字的主标签，例如 `需登录`、`待配置`、`需处理`、`受限制`，完整原因放在结构化 `detail` 并进入行的悬停说明；右侧已有诊断与活动信息保持不变。

选择该方案而不是直接按 `edge/session` 判断，是因为核心在线、浏览器打开、自动化执行是独立事实；继续复用旧字段会再次把待机冒充离线或把核心存活冒充任务执行。

### 2. 复用现有分组 DOM，按 `railGroup` 分栏

渲染层仍使用现有 `RAIL_GROUPS` 与分组标题 DOM，只把组扩展为：需要处理、运行中、待任务、启动中、排队中、待机中、暂停、离线。空组不渲染；同组按花名册稳定顺序。全局只保留“需要处理永远浮顶”这一紧迫度规则，普通状态不再用粗粒度 `level` 交叉猜组。

这避免增加第二个队列面板或改动左栏框架，也消除了一个环境被多个条件同时归组的风险。

### 3. 排队位次由主进程结构化投影

主进程状态增加可选的 `queueStage` 与 `queuePosition`：

- 等浏览器槽位时，从当前严格 FIFO `slotWaiters()` 的排序结果计算一基位次。
- 位于串行浏览器启动队列时，由队列自身按当前优先级和 FIFO 规则返回待处理项位次。
- 位于前置生命周期串行队列时，由该队列按当前 FIFO 返回带环境键的待处理项位次。
- 当前项已被任一队列取出执行、或调度阶段无法证明位次时，`queuePosition=null`；渲染层不得猜测。

环境行把位次作为独立节点显示为 `#N`，不并入三字主状态，不解析 `lastMessage` 或日志。位次随权威队列变化更新，可能因更高优先级任务到达而改变；这比展示一个过期的初始批次序号更诚实。

### 4. 状态点只表达运行类别

头像底色继续表达平台，行左侧蓝/红/橙继续表达选中和需处理。运行与待任务使用绿色实心点；启动/连接使用蓝色实心点；排队使用蓝色空心点；待机使用绿色空心点；暂停/未启动使用灰色点。收起态头像右下角和展开态状态行共用同一 `state-*` 类，避免两套映射漂移。

### 5. 批量启动完成判据使用自动化与浏览器真态

渲染层以纯函数判断单环境是否完成本次启动：`automationState=running`，或 `automationState=ready && engineLinkState=connected && browserState=ready`。核心进程单独存活、处于排队、首次连接或关闭浏览器待机均不计入完成；明确的浏览器无关任务仍可真实投影为 `running`。旧版缺少结构化轴时仍由既有兼容投影补齐，但不再直接读取 `status.edge=running`。

`loopStage` 是当前核心投影的执行阶段，不是跨会话存档。外壳为它绑定产生该事件的生命周期操作代，并在结构化 `lifecycle.task_idle`、冷待机确认、主动关闭、核心退出和新启动操作代开始时清空。既有 `feed/read/write/interact` 等阶段默认需要浏览器，只有浏览器真实就绪时才投影 `automationState=running`；结构化事件显式携带 `browserIndependent=true` 时，才允许浏览器关闭仍为运行。控制面在线但没有当前可执行任务证据时投影为 `ready`；浏览器关闭则对应 `待机中`。所有阶段都必须属于当前操作代，不能从旧阶段推断。

### 6. 关闭与重新启动使用每环境操作代隔离

每个环境句柄维护单调递增的生命周期操作代。显式关闭、暂停以及从停止态发起的新启动都会推进操作代；前置准备、串行启动、冷待机唤醒和失败重试在入队时捕获当前操作代，并在每个异步边界后复核。旧操作代的回调只允许自身收尾，不得清除新操作代的排队标记、重挂定时器或重新打开浏览器。

“全部关闭”已经进入核心安全退出后，紧接着收到“全部启动”时不尝试复用正在关闭的核心，也不把 `stopRequested` 提前复位；它记录 `resumeAfterStop`，等旧核心真实退出后再从当前操作代进入统一启动队列。若旧浏览器无法确认关闭，则取消本次重新启动并保留真实失败原因，避免同一环境再开一个浏览器。尚未执行的旧启动/唤醒项由队列按环境键取消，已经执行的项由操作代闸在下一异步边界作废。

### 7. 区分真实排队与未入队重试

`slots_full` 且已经保留启动资格的环境进入权威 `slotWaiters()` FIFO，显示 `排队中` 与可证明的 `#N`。`start_queue_full` 表示本次没有取得排队资格；环境可先连接 browser-absent 控制面并按 60/120/300 秒有界退避重新申请，但状态保持 `待机中`，日志必须写明“本次未入队、稍后重试”，不得复用“仍在队列中，浏览器继续起”的文案。

### 8. 全量快照与增量状态共用完整投影

`statusOf(handle)` 是单环境对渲染层的唯一权威状态投影，负责合并原始核心状态、四条生命周期轴以及当前调度器可证明的队列阶段和位次。`fleetSnapshot()` 与每次 `status:update` 增量推送都必须使用这份完整投影，不能由增量出口直接展开 `handle.status`。

渲染层按 `envId` 用最新状态对象替换旧对象，因此主进程推送必须是完整快照而不是局部 patch。这样，`start_queue_full` 后保持浏览器关闭的环境在后续心跳中仍是 `待机中`，真实槽位 FIFO 成员也会持续保留 `waiting_resource` 与 `#N`，不会被原始 `edge/session` 兼容字段重新解释为 `运行中` 或 `启动中`。旧主进程版本缺少结构化轴时，渲染层仍可使用兼容投影；当前主进程不得依赖该降级路径。

## Risks / Trade-offs

- [普通状态组增多，长列表标题更多] → 空组不展示，收起态仍只显示头像与状态点；不增加横向宽度。
- [队列在不同调度阶段切换时位次短暂为空或变化] → 只展示可证明的当前位次，不缓存初始序号；悬停不承诺固定等待时间。
- [需处理主标签缩短后信息量下降] → 完整原因保留在 `detail`、悬停说明和右侧真实状态，不以短标签替代原因。
- [旧快照没有四轴字段] → 继续使用现有 `lifecycleView` 兼容投影，并用单元测试锁定降级结果。
- [旧异步项无法从正在执行的 Promise 链物理移除] → 队列取消尚未开始的同环境项；已经开始的项由操作代复核作废，二者共同保证不跨代写状态。
- [关闭后立即启动可能让用户短暂看到启动中但浏览器仍在关闭] → 详情明确显示“关闭收尾后重新启动”，浏览器真实关闭前不申请新槽位。

## Migration Plan

1. 先增加队列位置查询与主进程结构化状态字段，保持字段可选以兼容旧渲染层。
2. 再更新纯状态投影、分组和 CSS；旧主进程没有位次字段时仅不显示 `#N`。
3. 更新批量启动进度判据并补充纯函数、DOM 与调度队列测试。
4. 为关闭/暂停/重新启动增加每环境操作代，取消尚未开始的旧队列项，并补充完整的快速关闭再启动回归。
5. 将 `fleetSnapshot()` 与 `status:update` 收敛到同一 `statusOf(handle)` 完整投影，并覆盖增量心跳不改变待机/排队真态的回归。
6. 通过 focused、acceptance、full test 与 typecheck 后快进集成到 `aidcp-edge/master`；控制仓 OpenSpec 独立提交并严格校验。
7. 回滚时可整体回退 Edge 提交；新增句柄字段只存在于内存，不需要数据迁移。

## Open Questions

无。启动链路是否改为“先连引擎再按任务需要打开浏览器”属于后续独立调度变更。
