## Context

Edge 已有在场感、浏览循环、发布卡和今日进展。`dailyUsage.windows` 提供本轮、分钟、小时与今日的动作计数及释放时间；`presence` 只在真实事件到达时说明当前动作。当前界面能诚实展示完成，但没有解释首页浏览和自然间隔与用户目标的关系。

本次只改桌面端渲染层。用户已经确认主运行区只表达“正在运行、本轮间隔、小时间隔、今日完成”四种状态；评论、点赞、收藏等单项节奏不能被渲染成整个浏览停止。

## Goals / Non-Goals

**Goals:**

- 让用户在运行和等待时都能理解系统正在为内容创作积累什么价值。
- 将完成表达为阶段成果，不把正常节奏写成上限、告警或风险。
- 复用真实 `presence` 和 `dailyUsage.windows` 数据，不改协议。
- 保持发布卡、活动流和今日进展的现有布局职责。

**Non-Goals:**

- 不新增浏览、互动、洗稿、发布或审批动作。
- 不因单个互动动作达到节奏而停止浏览或显示全局间隔。
- 不引入图标库、远程资源或新的动态数据字段。
- 不在发布卡或今日进展重复展示吉祥物。

## Decisions

### 1. 用保守的阶段判定决定主运行说明

主运行说明由本地纯视图函数生成，优先级为：新鲜的运行事件、本轮浏览完成、小时浏览完成、所有今日计划项完成。只有 `view` 在本轮或小时窗口达到真实计划时，才可显示“本轮浏览完成”或小时级自然间隔；单项互动的完成继续留在今日进展详情。

今日完成要求所有已提供且有配额的今日行动均已完成，避免“收藏已完成”被误写成“今天全部完成”。如果数据不完整或没有实际完成动作，不显示全局完成状态。

替代方案是沿用原有“任意动作饱和即完成”的摘要。该方式会把评论节奏误解为浏览停止，故不采用。

### 2. 说明文案固定为结果、机制、进度三层

运行态表达“正在为你寻找更容易被看见的内容灵感”。间隔态依次展示：阶段结果标题、带星标的价值句、三步“浏览与互动 / 留出自然间隔 / 继续寻找灵感”。该结构先回答用户得到什么，再解释系统为什么要这样做。

实际数量只来自真实窗口计数；没有可用数量时使用不含数字的成果文案。预计继续时间只在后端给出未来 `releaseAt` 时显示。

### 3. 吉祥物只属于当前运行说明区

执行吉祥物用于新鲜运行，观察吉祥物用于本轮或小时间隔，庆祝吉祥物用于今日完整计划。它不出现在发布卡或今日进展，避免同一视觉角色同时表达多个状态。

持续动效只在运行且 presence 新鲜时启用；等待和完成使用静态图，避免用动效制造仍在执行的错觉。所有动效均受 `prefers-reduced-motion` 关闭。

### 4. 使用透明图标与现有色彩语义

流程图标没有色块背景：已记录使用绿色、当前自然间隔使用蓝色、下一步使用中性灰。星标使用蓝色轻量强调。正常阶段完成继续使用现有绿色；节奏间隔使用现有平静蓝绿；错误和人工协助仍沿用既有琥珀/红色语义。

## Risks / Trade-offs

- [窗口数据缺少或滞后] → 隐藏运行价值说明，回退到既有在场感与今日进展，绝不推断完成。
- [本轮定义中包含非浏览动作] → 只用 `view` 触发本轮与小时的全局间隔说明。
- [吉祥物资源未被打包] → 将 PNG 放进 renderer 静态目录，并由 DOM 集成测试确认路径存在。
- [频繁状态推送导致动效反复开始] → 只让运行态的 CSS 动效持续存在；等待和完成态保持静态。

## Migration Plan

1. 将三个已定稿透明背景吉祥物拷贝到 renderer 静态资源目录。
2. 在渲染层新增纯视图状态判定和紧凑 DOM 区域。
3. 扩展 DOM 与纯逻辑测试，覆盖运行、三种阶段和单项动作不升级为全局状态。
4. 完成 typecheck、单元测试和 OpenSpec 严格校验后合入 Edge `master`。

回滚只需移除 renderer 说明区与资源引用；既有 presence、发布卡和今日进展不依赖新数据。

## Open Questions

无。当前数据可以支持保守实现；未来若云端提供明确的“整轮浏览已结束”事件，可替换 `view` 计数推断。
