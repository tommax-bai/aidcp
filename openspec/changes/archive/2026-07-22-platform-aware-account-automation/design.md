## Context

Cloud 已用 `account_content_schedule` 保存账号总开关、三类内容动作、日上限和账号周历覆盖，Console 的 `ContentSchedulePage` 则固定渲染三类动作。账号目录行目前没有平台字段，Cloud 写入口也不知道动作是否适用于该账号平台。已有 `PLATFORM_REGISTRY` 是平台能力的权威词表，但现有 `capabilities.group_join` 只服务客户端指标投影，明确不能充当自动化调度闸。

本变更横跨 Cloud 与 Console，但不改变 Edge/protocol，也不引入数据库迁移。它为后续 Facebook 自动加群提供平台化容器；自动加群本身由后续独立变更实现。

## Goals / Non-Goals

**Goals:**

- 让同一“账号自动化”入口可以按平台筛选，并只编辑平台真实支持的动作、模式和上限。
- 让 Cloud 成为平台动作能力的唯一权威，Console 只消费投影。
- 对绕过 Console 的不支持动作写入 fail-closed，且不破坏既有关闭/清理能力。
- 保持现有总开关、三态周历、错峰、日上限和审批语义不变。

**Non-Goals:**

- 不在本变更新增 Facebook 自动加群配置或执行逻辑。
- 不改变现有内容动作的执行管线、审批规则、风险闸、Edge 命令或协议。
- 不把各平台专属配置塞入一个无限扩张的通用排期表。

## Decisions

### 1. 在平台注册表增加有真实消费者的排期动作声明

新增全覆盖的 `ScheduledAutomationAction` 声明，至少覆盖 `post`、`comment`、`contact_comment`。每个平台逐项声明是否支持、允许的非关闭模式和日上限；Cloud 目录投影与写校验共同消费它。这样新增平台或动作时由 TypeScript 全覆盖检查逼迫明确表态。

不复用 `capabilities.group_join`：该字段现有唯一消费者只控制客户端指标是否显示，并被明确禁止作为准入闸。也不从 `noteActions` 或 `delegatedActions` 推导，因为“单帖可评论”“用户委托可发布”与“账号排期可自动执行”不是同一能力。

### 2. 目录返回规范化平台和服务端权威动作描述

`GET /api/content-schedule` 的每行增量返回：

- `platform`: 通过现有平台规范化函数得到的稳定平台 id；
- `availableActions`: 当前平台支持动作的有序列表，每项包含动作 id、允许模式和服务端日上限。

旧平台别名继续走现有规范化规则；未知平台不伪装成可配置动作，目录对其投影空动作并保留可诊断平台值/错误处理。Console 不维护第二份平台动作矩阵。

### 3. “全部平台”是摘要视图，单平台视图才可编辑专属动作

页面保留现有 route/tab，卡片文案升级为“账号自动化”。顶部平台筛选默认“全部平台”，筛选和表格行使用同一份规范化平台值：

- 全部平台：展示平台、账号、账号分组、总开关、时段来源、已启用动作摘要和更新时间/异常提示，不渲染三平台动作列的并集；
- 单个平台：仍显示公共字段，并按每行 `availableActions` 生成动作列；只有服务端声明的动作可以编辑。

当前变更没有通用批量写；未来新增批量操作时必须以同一过滤结果为作用域，不能只做视觉筛选。

### 4. 写校验按动作字段簇执行，并允许安全关闭遗留配置

Cloud 在单账号 UPSERT 前读取账号平台，并把 `post*`、`comment*`、`contactComment*` 视为三个动作字段簇：

- 支持动作：模式必须在平台注册表允许集合中，上限不得超过平台注册表上限；
- 不支持动作：任何启用、非 `off` 模式或正上限写入均整块拒绝为 `unsupported_automation_action`；
- 显式 `enabled=false`、`mode=off`、`dailyCap=0` 可用于清理历史脏配置；
- 公共字段（总开关、周历覆盖）不因某动作不支持而被误拒。

校验发生在数据库写入前，失败不部分落库。已有库中不受支持的历史值不由迁移静默修改；目录摘要不把它声称为可执行能力，运营可通过安全关闭值清理。

## Risks / Trade-offs

- [平台注册表声明与真实执行路径漂移] → 目录与写校验共用同一声明，并增加平台注册表、目录和写入测试；本变更不改变调度器，因此声明只覆盖当前已有真实路径。
- [未知/旧别名平台导致页面丢账号] → 复用既有规范化规则；未知值保留行但无可编辑动作并显示诊断提示，不并入任一已知平台。
- [旧配置含不再支持的动作] → 不批量清库；允许只写安全关闭值，且服务端不把旧值投影成“受支持”。
- [全部平台列过多导致不可读] → 全部平台只做公共摘要，单平台才展示动作细节。

## Migration Plan

1. 先部署 Cloud 增量字段和服务端写校验；旧 Console 忽略新增字段，现有合法写继续工作。
2. 再部署 Console 平台筛选和动态动作列。
3. 在 dev 用小红书、Facebook、视频号各一条目录数据验证投影、过滤和拒绝语义。
4. 回滚 Console 不影响 Cloud；如需回滚 Cloud，可回退代码，无数据库回退步骤。

## Open Questions

- 无。本变更只建立当前三类内容动作的平台化契约；Facebook `join_group` 将由独立 OpenSpec 变更加入同一目录投影。
