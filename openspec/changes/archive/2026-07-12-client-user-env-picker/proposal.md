# Proposal: client-user-env-picker

## Why

后台「客户端用户」现有的「环境归属」抽屉只能**手填 env ID（profileId）**逐条新增——运营要先去别处查到 profileId 再粘进来，既易错又看不到全貌：不知道系统里有哪些环境、某个环境已经分给了谁、哪些还没分出去。同时页面标题「客户端用户」对运营语义偏长，实际是「端用户」。

底层数据模型（`client_env_scope` 复合主键 `(user_id, env_key)`，`env_key` 单列不唯一）**已经支持一个环境分配给多个用户**，但后台既没有可选列表、也没有暴露「一环境被多客户共享」的信息，这个能力对运营不可见、不可用。

## What Changes

- **改名**：后台「客户端用户」显示名改为「**端用户**」（导航标签 + 页面标题 + 相关文案；不改路由路径 / 组件 / 接口）。
- **环境选择列表**：环境归属抽屉从「手填 env ID」升级为「**从已知环境列表里勾选加入**」。列表来自云端新增的**管理侧全局环境注册表**（内部 JWT 保护），每个环境带「已分配给哪些客户」信息。手填 env ID 作为兜底保留（云端尚未见过的新环境仍可手动登记）。
- **待分配 / 已分配筛选**：抽屉内一个筛选开关，相对**当前端用户**：待分配 = 该环境尚未归属当前端用户（可加入）；已分配 = 已归属当前端用户。**默认待分配**。
- **一环境多分 + 「多人」标识**：允许把同一个环境加入多个端用户（数据层本已支持，UI 放开）；对已分配给 ≥2 个客户的环境，后台显示「**多人**」标识（悬浮可见具体客户名）。

## Impact

- **cloud（aidcp-cloud）**：`ClientUserStore` 新增一个**管理侧**读法 `listAllEnvironments()`（聚合 `client_env_scope` 的 distinct env_key + 各自被分配的客户清单）；panel 新增受内部 JWT 保护的 `GET /api/client-environments`。**不碰客户鉴权服务、不新增客户可达读口**——N2（客户侧结构性无泄漏）不受影响。不改表、不改协议、不碰 accounts 热点表。
- **console（aidcp-console）**：`ClientUsersPage` 的环境归属抽屉重做为「可勾选列表 + 待分配/已分配筛选 + 多人标识」；新增类型 `ClientEnvironmentView` 与查询 `useClientEnvironments`；页面 / 导航显示名改「端用户」。
- **edge**：零改动（端侧本就按云端权威 `/my-environments` 过滤、且多分对端侧透明）。
- 涉及 spec：`client-customer-auth`（新增「管理侧全局环境注册表与一环境多分」要求）。
