## Context

浏览闭环里，一条笔记深读完后并行展开若干云端评估；其中「是否进作者主页 / 进主页后是否关注 / 看完主页返回信息流」构成主页子链。当前实现里：

- 「关注评估」决定关注后，统一出口在风控放行时下发关注命令；
- 「返回信息流」由专门角色负责，其触发器有二：决定不关注（直接返回）、或关注的执行回执到达（`action.completed{action:'follow'}`）后返回。后者刻意等回执，是为保证「关注先点、再返回」，避免返回抢在关注前下发导致按钮已不在、关注必败。

**缺陷**：当关注被风控/限频拦截时，统一出口诚实跳过、不下发关注命令 → 边缘永不回关注执行回执 → 「返回信息流」死等一个永不到来的回执 → 会话卡死在作者主页（本机监测 2026-06-24 真机两次复现，困住期间靠空转看门狗原地滚动、把主页笔记宫格误当信息流卡片继续开图）。

**已确认的关键事实**：边缘是**严格 FIFO 串行命令队列**——单消费循环逐条取命令、`await` 其完整执行（点击 + 校验 + 回报）后才取下一条；关注与返回信息流命令走的是同一条队列。因此「先入队的先执行且执行完才执行下一条」由边缘天然保证，云端无需用回执来排序。

## Goals / Non-Goals

**Goals:**
- 关注被风控/限频拦截时，会话仍能干净返回信息流，消除主页卡死分支。
- 关注与返回信息流在同一决策点按序下发，靠边缘 FIFO 队列保证「关注先点、再返回」。
- 主页子链所有分支（关注且放行 / 关注被拦 / 不关注）都收敛到恰好一次返回信息流。
- 保持拟人：关注后在主页停留片刻再离开。

**Non-Goals:**
- 不改边缘原子动作、不改命令队列实现、不改协议（无新增/修改消息类型）。
- 不改关注配额按真实回执扣减口径、不改关注的诚实成败回报。
- 不处理「已关注作者不进主页」的去重（那是独立的 `skip-profile-visit-if-followed`）。
- 不改空转看门狗（它是兜底，不是本修的主路径）。

## Decisions

### 决策 1：返回信息流不再死等关注回执，改由「单一时序点」按序下发

在「主页关注评估完成」这一个决策点上顺序执行：
1. 若决定关注且风控放行 → 下发关注命令（入队）；
2. **无条件**发出一个「主页子链结束」的单一信号 → 由返回信息流角色据此返回（构造 back 命令时携带 `dwellMs` 与 `targetPage`、做当前笔记上下文清理，沿用现有逻辑）。

因为信号在「下发关注命令之后」才发出、且二者在同一处理逻辑内顺序执行，所以返回命令必然在关注命令之后入队；边缘 FIFO 队列再保证返回必然在关注执行完之后执行。被拦时第 1 步跳过、第 2 步照常 → 直接返回，无卡死。

### 决策 2：返回信息流角色改为「单一信号」触发，移除其分散订阅

返回信息流角色原先订阅「不关注分支」与「关注回执」两个触发，现改为只订阅决策 1 里那个「主页子链结束」信号。这样：
- 主页子链的返回**有且仅有一个触发器** → 杜绝重复返回；
- 关注与返回**不再分散在两个各自响应「主页看完了」的地方** → 杜绝返回抢在关注前下发的竞态（这正是原先用「等回执」绕开的坑，现在用「同一处顺序下发」从结构上消除）。
- 该角色对「未进主页就要返回」的其它来源（质量否决 / 不互动 / 作者不值得访问）订阅**保持不变**。

### 决策 3：关注回执保留，仅卸下「触发返回」职责

关注回执仍照常回来，继续用于：关注配额按真实新关注扣减、关注成功/失败/已关注 no-op 的诚实记录。只是它不再被用作返回信息流的触发器。

### 决策 4：返回命令携带主页停留时长（dwellMs）

原先「等回执」的往返时间天然提供了「关注后在主页停留一会儿」的拟人停顿。改为紧随入队后，需由返回命令显式带上 `dwellMs`（沿用现有按笔记量级取停留的口径），避免关注完秒退。

### 备选方案与不取的理由

- **A. 仅补救分支（保守）**：正常路径仍等回执，只在风控拦截分支额外补一个返回信号。优点：正常路径零改动、爆炸半径最小。缺点：留下「等回执 + 补信号」两套机制、未收敛逻辑。→ 不取，但作为可回退的最小修法备选。
- **B. 伪造一条关注失败回执**以复用现有返回触发。→ **否决**：为一个从未执行的动作伪造回执，违背「回执必须反映边缘真实发生 / 不静默假成功」红线，并污染动作计数与配额。
- **C. 让返回角色在「决定关注」事件上立即返回**。→ 否决：重新引入「返回抢在关注前下发」的 handler 顺序竞态——正是原设计要躲的。

## Risks / Trade-offs

- **改动了正常路径的返回时机**（由「等回执」改为「紧随关注入队」）→ Mitigation：边缘 FIFO 队列保证关注完整执行（点击+校验+回报）后才执行返回；真机回归专门验证「关注先于返回执行」。
- **同一处理逻辑必须保证「先发关注、后发返回信号」的语句顺序**，若被拆散则竞态复活 → Mitigation：在单一处理点内顺序编码，并移除返回角色的旧分散订阅，使返回触发器唯一。
- **关注执行期间出现验证码/阻断浮层** → 边缘每条命令执行前已有浮层闸门，返回命令会在闸门处等待至浮层解除，无需特殊处理。
- **关注与返回之间边缘掉线** → 既有 CDP 有界重连 + 续跑重报 + 空转看门狗兜底覆盖，不被本修削弱。
- **通知巡视软暂停窗口**：若主页关注评估恰逢通知巡视触发软暂停（browse 命令统一被暂停出口扣住），关注与返回会**一起**被丢——但二者同处一个同步时序点、同丢同放行，无顺序错乱；且巡视结束时恢复角色会先解除暂停再重发返回，back 被重新下发，端到端自愈。此窗口为既有机制（旧"不关注"分支同样暴露其下），非本修引入，新实现相对旧实现严格更优（旧的"关注被拦→等回执死等"在本修后已不存在）。
- **重复返回风险** → 通过「单一触发器」结构性消除（决策 2）。

## Migration Plan

- 纯 cloud 编排改动：无协议变更、无边缘改动、无数据模型变更。
- 部署走标准 ECS 安全序列（备份 → rsync → 重启 → healthcheck → 失败回滚）。
- 回滚 = 还原该 commit；与边缘版本无耦合（边缘命令队列与命令集均未变）。
