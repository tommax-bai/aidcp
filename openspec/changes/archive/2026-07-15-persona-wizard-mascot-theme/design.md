# Design: persona-wizard-mascot-theme

## Context

现有人设浮层已在 `edge-client-proxy-platform-persona-ux` 中完成三段式布局、两步向导与平台动态标签，平台来源取当前环境的 `platform` 字段。当前问题集中在视觉令牌和选择控件：

- `.kw-btn` 使用 `font-weight: 600`，选项文字与区块标题接近，阅读层级偏平。
- 选中、hover、focus 仍使用旧蓝色，与现有吉祥物青绿主体不一致。
- 未选内容项的 `+` 与自定义入口的 `+` 使用字体字符，受 PingFang / Microsoft YaHei / Segoe UI 字形基线影响。
- 人设浮层的平台文案已有动态逻辑，但缺少浮层级回归断言，视觉改造时容易把小红书样式误扩成通用样式。

## Decisions

### D1. 人设局部令牌，不全局换肤

在 `.persona-pop` 上定义 `--persona-accent`、`--persona-accent-soft`、`--persona-warm`、`--persona-coral` 等局部变量，仅影响账号人设浮层。客户端其他功能继续使用现有全局令牌，避免一次局部评审扩散成全应用换肤。

### D2. 功能色与平台色分层

- 功能交互：青绿蓝，用于步骤、选中、focus、主 CTA。
- 状态提醒：金黄，用于待确认、待更新。
- 平台身份：小红书使用珊瑚色，Facebook 使用既有 `--plat-fb` 蓝。

选择项不会因平台切换而改成交互红或 Facebook 蓝，避免同一功能在两个平台拥有不同操作语义。

### D3. 加号使用几何背景绘制

未选内容项的圆形指示器用两条居中的线性渐变绘制 `+`；自定义入口使用相同方法。选中态仍以圆形青绿底 + `✓` 表达。几何绘制不依赖字体字形，因此跨系统字体栈保持居中。

### D4. 不改变现有行为与数据结构

关键词按钮的 `.kw-btn`、`data-kw`、`aria-pressed` 与事件代理保持不变；仅把自定义入口的可见 `+` 字符移交 CSS 绘制，`aria-label` 继续提供可访问名称。人设生成、草稿环境锚定、确认回执和闸三态不变。

## Validation

- 补充平台浮层断言：Facebook 环境打开人设浮层时显示 Facebook 文案与平台类；切回小红书时恢复小红书文案与样式。
- 补充视觉契约断言：局部吉祥物色彩令牌存在，选择项不再使用旧蓝色和 600 字重，加号不再依赖 `content: "+"` / 文本字符。
- 运行 Edge 聚焦测试、全量测试与 typecheck；不构建桌面安装包。
