## Context

桌面客户端有两种环境来源语义：未启用客户鉴权时，AdsPower 列表是本机运维环境全集；启用客户鉴权时，同一出口先刷新 `/my-environments`，再把本机列表收窄为当前客户权威归属环境。现有 renderer 只在列表恰好一个、花名册为空且核心未运行时便利加入，多环境一律等待人工点选。

直接把多环境全部加入会破坏“手动移出”：每次刷新都会重新加入。客户端因此需要一个与运行花名册分离的、持久化的客户排除集合，并且必须防止该集合跨客户继承或在不完整列表上被错误清理。

## Goals / Non-Goals

**Goals:**

- 客户鉴权模式下，让完整、权威收窄后的本机归属环境默认全部进入运行花名册并显示为离线行。
- 让手动移出成为持久的 opt-out，并允许用户再次点选恢复。
- 保留现有租户隔离、物理孤儿判断和不完整数据不自残边界。
- 不自动启动、不重启、不暂停任何环境。

**Non-Goals:**

- 不改变 Cloud 归属 API、数据库或协议。
- 不把未启用客户鉴权时的本机 AdsPower 全集自动入册。
- 不改变管理员分配/撤权流程，也不自动删除 AdsPower 环境。

## Decisions

### 1. 仅以主进程确认的客户范围信号启用默认入册

`ads:listProfiles` 在完成有效会话检查、权威归属刷新和本机列表收窄后，向 renderer 返回 `assignmentScoped: true`。renderer 不从列表形状或 URL 猜测是否为客户模式。未鉴权模式返回 false，继续沿用唯一环境便利加入和多环境人工选择。

替代方案是无条件自动加入所有 AdsPower profile；这会把内部/运维机器上的本地环境全集全部入册，拒绝采用。

### 2. 用独立排除集合表达持久手动移出

设置增加当前客户的排除 envKey 集合。客户在归属列表中点击“移出”时，从运行花名册删除并加入排除集合；再次点击环境行加入时，同时移出排除集合。默认对账只加入“权威收窄后的本机 profile - 已入册 - 已排除 - 撤权清理中”的差集。

使用独立集合而不是把“花名册里没有”直接解释成手动排除，因为升级前多环境本来就都不在花名册，无法区分“尚未默认迁入”和“用户明确移出”。

### 3. 排除集合绑定当前登录客户并由主进程校验

设置同时保存排除集合所属的客户名。主进程进入有效客户会话时若身份变化，清空排除集合并写入新 owner；renderer 不得自行覆盖 owner。保存排除集合时，主进程只接受当前权威 `allowedProfileIds` 中的 envKey。这样同机换客户不会继承旧客户选择，renderer 也不能借设置写入他客户 envKey。

### 4. 只在成功、完整且非空的物理列表上对账

默认加入与陈旧排除清理只在 `ok && !truncated && profiles.length > 0` 时运行。失败、截断、会话失效或 success-but-empty 都保持现有花名册与排除集合不动。成功完整列表中不再出现的排除项可清理；物理孤儿仍使用主进程给出的安全物理 id 集合判断，不把归属撤销冒充物理删除。

### 5. 默认入册只创建离线 handle

renderer 一次性更新花名册并经既有 `settings:save -> syncEnvHandles -> broadcastFleet` 落盘和投影。该链只新增受监督 handle，不调用 start/restart/resume；已有运行环境保持不变。新加入项缺少人工平台覆盖时沿用本机列表的平台真态。

## Risks / Trade-offs

- [完整列表偶发空响应被误当客户无环境] → 空列表不做默认对账或清理，宁可延迟收敛，不批量自残。
- [写盘失败导致重启后默认入册丢失] → 沿用 `saveOk/saveError` 真态并在界面提示；当前进程只显示主进程实际接受的内存真态。
- [环境撤权但仍物理存在] → 不把它当孤儿删除；主进程现有权威范围仍阻止其显示和运行，后续再授权可重新对账。
- [同机切换客户] → owner 不同即清空排除集合；花名册的现有范围过滤与停机规则保持不变。

## Migration Plan

1. 先落 OpenSpec delta 并严格校验。
2. Edge 设置以 additive 字段加载；旧设置缺字段时视为空排除集合，首次完整客户列表自动迁入全部归属环境。
3. 运行 focused Electron tests、完整测试与 typecheck，提交并快进集成到 `master`。
4. Edge 行为通过后续客户端更新生效；本任务不构建安装包。

回滚旧二进制时新增设置字段被忽略，既有 `environments` 花名册仍可读取；已默认迁入的环境继续显示但不会自动启动。
