## Context

内容工作区复用同一套标题栏 DOM。当前 `configureHeader(page)` 只根据返回栈决定左侧返回按钮是否显示，而右侧关闭按钮始终绑定关闭整个工作区的 `close()`。打开精选正文详情时，返回栈已经保存灵感库页面及其列表状态，因此现有 `goBack()` 能正确回到灵感库并恢复滚动位置。

## Goals / Non-Goals

**Goals:**

- 只在精选正文详情卡隐藏左侧返回按钮。
- 让详情标题右侧 `×` 复用现有返回栈回到灵感库。
- 为详情态 `×` 提供“返回灵感库”的准确可访问名称。
- 移除隐藏返回按钮后残留的左侧空列，继续保持标题栏紧凑且不遮挡正文。
- 保持其它页面的关闭与返回行为不变。

**Non-Goals:**

- 不改变灵感库、创作页、稿件审核或其它内容工作区页面的导航结构。
- 不改变精选详情的双栏独立滚动、隐藏滚动条或窄屏布局。
- 不改变窗口级导航、协议或后端数据。

## Decisions

### 详情关闭入口按当前页面分流

为右侧关闭按钮增加统一处理函数：当前页面为 `detail` 时调用 `goBack()`，其它页面仍调用 `close()`。这样只改变精选正文详情，且复用现有返回栈和列表状态恢复逻辑，不引入另一套导航状态。

### 在标题配置阶段同步可见性与可访问名称

`configureHeader(page)` 在详情态强制隐藏左侧返回按钮，并将右侧按钮的 `aria-label` 设置为“返回灵感库”；离开详情后恢复为“关闭内容工作区”。这避免复用 DOM 时残留错误的可访问语义。

### 详情标题栏使用两列网格

精选正文详情模式将标题栏网格从“返回、标题、关闭”三列改为“标题、退出”两列。标题继续单行省略，右侧按钮保持固定宽度，标题栏仍处于正常布局流并吸顶，不覆盖正文。

## Risks / Trade-offs

- [关闭图形通常表示关闭整个区域] → 在详情态提供“返回灵感库”可访问名称，并限定行为只在正文卡内变化。
- [复用 DOM 可能遗留详情态标签] → 每次 `configureHeader` 都显式设置关闭按钮标签，并以测试覆盖返回灵感库后的恢复值。
- [返回栈异常为空时无法回库] → 详情只能从灵感库进入；测试覆盖标准进入路径和列表状态恢复。

## Migration Plan

纯前端渲染器变更，无数据迁移；回滚对应 JavaScript、CSS 与测试即可。
