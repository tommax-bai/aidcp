## Context

视频号收件箱是 Electron 渲染层的原生 JS 模块（无构建链、无框架）：静态骨架在 `src/electron/renderer/index.html`，全部动态渲染在 `src/electron/renderer/interaction-workspace.js` 里靠 `innerHTML` 字符串拼接，样式是 `styles.css` 里的 `.iw-*` 规则。

当前收件箱是 CSS grid 两栏（`.iw-inbox`：列表列 + 详情列），两列同屏。工作区容器用 `min-height: calc(100vh - 70px)` 而非固定高度，且标签排上方还有概览卡与设置卡，所以整个面板可以超出视口——两列的内部滚动条与文档滚动条并存，详情列常被挤到折线以下。

渲染层现状有两个与本次直接相关的性质：

1. **没有任何滚动/锚定逻辑**。整个模块唯一与滚动相关的代码是列表重绘后恢复焦点时的 `focus({ preventScroll: true })`——刻意抑制滚动。本次的锚定行为是全新代码。
2. **列表与详情内容每次渲染整段重绘**（`innerHTML` 覆盖），只有 `index.html` 里的静态节点（`#iw-tabs`、`.iw-inbox`、`#iw-list`、`#iw-detail`）跨重绘存活。锚定必须挂在这些静态节点上。

样张已与客户逐轮定稿（单栏抽屉、覆盖层遮挡、无默认选中、图标化控件）。

## Goals / Non-Goals

**Goals:**

- 收件箱在不改动取数、协议与云端的前提下，从两栏改为单栏两级。
- 覆盖层打开期间保住列表滚动位置。
- 两级切换时把标签排锚到视口顶部，让消息区一次露全。
- 详情控件图标化，且退回路径（关闭 / 返回 / `Esc`）齐备可达。

**Non-Goals:**

- 不改 WebSocket 协议、云端、`aidcp-console`。
- 不动读取能力门禁、回复卡与发送状态语义。
- 不引入前端框架或构建链——保持原生 JS + `innerHTML` 的既有形态。
- 不做响应式的「宽屏仍两栏、窄屏才单栏」自适应（见下方决策）。

## Decisions

### 决策 1：单栏抽屉，不保留宽屏两栏

客户明确要求关闭后「回到头像昵称那个列表」，该语义只有在详情遮挡列表时成立。曾提出宽屏保留两栏的替代方案（桌面屏宽，两栏可逐条扫读），客户在样张对照后仍选单栏。

**代价与接受理由**：单栏下逐条处理需进出各一次，扫读效率下降；但客户的实际痛点是「消息区看不全」，而非「扫读慢」，且两级 + 锚定组合消灭了手动滚动。不做双模式自适应是为了避免两套布局各自的状态与回归面。

### 决策 2：覆盖层用绝对定位铺满收件箱区，而非隐藏列表让详情顶上

替代方案是把列表 `display:none`、详情占满单列 grid。否决理由：列表一旦卸载或隐藏，其内部滚动位置在下次显示时不保证保留，且列表本身会被重绘链路重排。

采用：`.iw-inbox` 设 `position: relative`，单栏态下详情面板 `position: absolute; inset: 0`，盖在列表之上。列表始终在文档流里、不卸载，滚动位置天然保留。

### 决策 3：隐藏必须显式压过面板容器的 display（红线）

面板容器类带 `display: flex`，其优先级高于浏览器给 `[hidden]` 的 `display: none`——直接用 `hidden` 属性会**静默失效**：不报错、不白屏，覆盖层永久糊在列表上，客户无法选择任何互动。样张阶段已实证中招一次。

采用双保险：

1. 样式侧显式写 `.pane[hidden] { display: none }`（或等价的具名隐藏类），确保隐藏声明赢得层叠；
2. 逻辑侧在列表级**不渲染**详情内容，而非只靠样式藏。

任一层单独都不足：只靠样式，层叠一旦被后来的规则改写就复发；只靠不渲染，空容器仍可能因绝对定位挡住点击。

### 决策 4：锚定挂在静态的标签排节点上

`#iw-tabs` 是 `index.html` 里的静态节点，跨重绘存活，且正是客户点名的锚点（「滚动到让待处理/评论这一列的高度」）。用 `scrollIntoView({ block: 'start' })`，并读 `prefers-reduced-motion` 决定 `behavior` 取 `auto` 还是 `smooth`。给 `.iw-tabs` 加 `scroll-margin-top` 留出呼吸位。

不自行计算 `scrollTop`：面板高度依赖视口且上方卡片高度可变，硬算偏移会随内容漂移。

### 决策 5：退回路径给三个入口

关闭图标（客户点名）、左上角返回箭头（IM 惯例）、`Esc`（键盘）。三者收敛到同一个「清除选中 + 回列表级 + 锚定」的动作。返回箭头与关闭叉功能重复是有意的冗余——两种心智模型（「返回上级」与「关掉这个」）各自成立；若客户觉得视觉噪音过大，砍返回箭头即可，不影响其余。

### 决策 6：覆盖层打开期间的列表重绘不做暂停

后台拉到新数据会重绘底下的列表，客户关掉覆盖层后可能发现列表顺序变了。本次**不**引入「覆盖层打开时暂停重绘」的机制：暂停会引入一份待应用数据的暂存状态与失效时机，是新的复杂度来源，而现象本身不影响正在阅读的详情。若真机反馈明显，再单独提 change。

## Risks / Trade-offs

- **[覆盖层隐藏静默失效]** → 决策 3 的双保险；并在验收里明确「列表级下每一条都可点击」这一可观测判据，而非只看截图。
- **[呈现层重构波及既有要求]** → `edge-companion-ui` 已有的空态区分、未读标记与去重通知、非发送动作不被 send capability 拦截等要求都渲染在同一模块内；实装后需回归这些既有场景，spec delta 已声明其判据不变、仅呈现位置改变。
- **[锚定与详情内部滚动打架]** → 详情面板自身有 `overflow-y: auto` 且 `overscroll-behavior: contain`；锚定作用于文档滚动、目标是静态标签排，两者不同轴，但需真机确认在详情已滚到中段时关闭不会产生跳变。
- **[单栏降低扫读效率]** → 客户已在样张对照后确认接受（决策 1）。
- **[无自动化 UI 测试覆盖]** → 该渲染层无 DOM 测试基建，本次不新建；验收依赖真机手测，相关项登记到真机验收 backlog。

## Migration Plan

纯前端呈现层改动，无数据迁移、无协议变更。随 edge 客户端常规发版生效；回滚即回退这几个渲染层文件的提交。不需要云端配合，也不需要出安装包才能验证——本地 `electron:dev` 即可观察。

## Open Questions

- 返回箭头与关闭叉是否都保留（决策 5）：默认两者都上，等客户真机观感后再定。
- 覆盖层打开期间的列表重绘是否需要暂停（决策 6）：默认不做，视真机反馈。
