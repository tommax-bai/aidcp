## Context

当前 aidcp-edge 已有人设浮层和 `persona.generate` / `persona.persist` stdin/stdout 桥。渲染层用 `personaBound` 判断已绑状态：已绑显示绿卡，未就绪显示空态，已登录且连云但未绑显示向导。缺口是未绑状态只在用户点开左栏人设图标时可见，没有主动弹出；关键词选择仍是「垂类 / 兴趣 / 语气」三组，和用户要的两面板样式不一致。

浏览器授权方面，Electron 主窗口当前没有统一处理 `setPermissionRequestHandler`。被驱动的 AdsPower/Chrome 页面偶发地理位置等浏览器权限请求时，如果原生权限条停留在页面上，会干扰自动化执行；系统不应自动授权这些权限。

## Goals / Non-Goals

**Goals:**
- 未绑定人设账号一旦登录并连云，客户端主动弹出人设设置并发一次系统通知。
- 人设关键词 UI 改成「语气调性」和「内容偏好」两个面板，内容偏好按行业分组、多选兴趣，并支持每组自定义。
- 浏览器权限请求有明确默认策略：敏感权限拒绝并提醒用户，避免被权限弹窗卡住。

**Non-Goals:**
- 不改云端人设存储、判绑闸和 LLM 生成协议。
- 不把自定义偏好持久化为独立配置；本期只作为生成人设时的关键词输入。
- 不远程代替用户处理小红书/Facebook 业务授权或登录验证码。

## Decisions

**D1 未绑人设提醒在渲染层触发，系统通知在主进程发出。** 渲染层最准确知道当前选中环境、浮层状态和 `personaReady && !personaBound`，适合做去重和自动打开；主进程通过新增 IPC 做系统通知，复用已有 Electron `Notification` 能力。替代方案是在云端新增消息类型下发 `needs_persona_setup`，但现有 `personaBound` 已足够，不需要扩大协议面。

**D2 内容偏好仍折成关键词数组。** 云端 `PersonaGenerator` 已把 `keywordSelections` 作为宽松关键词集合使用，足以表达行业、兴趣和语气。结构化 payload 会带来协议和云端校验改动，本期不需要。

**D3 自定义兴趣以分组局部输入实现。** 每个行业标题右侧的「+」展开本组输入框，用户输入后以 chip 形式加入该组并参与多选。这样与截图的「每个内容偏好后面增加 + 号」一致，也避免单个全局输入无法知道属于哪个行业。

**D4 浏览器权限默认拒绝敏感能力。** `geolocation`、摄像头、麦克风、MIDI/HID/串口/蓝牙等权限对当前自动化浏览不必要，默认拒绝并通知。若未来某平台确有必要，再按平台和环境显式白名单补充；本期不做自动授权。

## Risks / Trade-offs

- [一次登录后频繁状态推送导致反复弹窗] → 按 envId + accountId 做去重，只在未绑状态首次进入时提醒；绑定成功或切换环境重置局部状态。
- [关键词过多触发云端 `input_too_large`] → UI 自定义输入限制长度，生成前仍走云端 24 项 / 40 字校验。
- [权限拒绝影响网站个别功能] → 目前自动浏览不依赖地理位置等权限；拒绝时有客户端可见通知，不静默吞掉。

## Migration Plan

无数据迁移。edge 客户端代码验证后构建/发布客户端包即可生效；回滚为 revert 该 edge 提交。
