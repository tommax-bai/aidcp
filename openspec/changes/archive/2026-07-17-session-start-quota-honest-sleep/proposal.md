# session-start-quota-honest-sleep

## Why

**日额度耗尽的账号，整夜每 4 分钟被叫醒一次去重新发现自己没有额度。**

2026-07-17 dev，Facebook 账号 `61591753702668`（edgeId `ads-k1ei3dbi`）。日额度在 17:02 已耗尽（慢启动第 1 天，view 上限 20）。真实日志（边缘 `edge.log` + 云端 journal）逐条对上：

```
18:24:24  边缘 lifecycle standby: browser closed, cloud connection retained   ← 让位机制正常
18:25/26/27  云端待机提示 eligible=true, reason=view_quota:day                ← 云端也知道该停
18:28:23  边缘「冷待机期间收到唤醒触发 (cloud_command:page.scroll)」          ← 云端把它叫醒了
18:28:23  云端 sendCommand action=scroll sent=1                              ← 空闲看门狗 240s nudge
18:28:2x  → 开浏览器（≈40s 冷启动）→ 扫卡 → 读昵称 → 2 次模型调用（1238 tokens）
18:28:36  云端「view 配额暂不可用 → 休眠浏览 19884s（reason=quota:day）」      ← 到这一刻才发现没额度
18:29:13  断连 → 18:29:23 重连 → 「边缘 hello → 会话已重置并重启」            ← 刹车没了，回到第一行
```

**从 18:24 到零点，这个循环约 67 轮。** 每轮：开一次浏览器（≈40s）、翻一次 feed、约 1.24k tokens，然后得出一个 8 小时前就已知的结论。

### 根因（两条，缺一不成灾）

**① 刹车从来没被带过重连。** 云端**每条连接都重造一整套会话调度组件**（`aidcp-cloud/src/orchestrator/connection-runtime.ts:194` 建、`:205-213` 断连即拆）。浏览额度休眠标记是那个对象的私有字段 ⇒ 重连后是个**全新对象、标记出生即 false**。

> 🔴 **这里有一个必须写下来的反直觉点**，因为它决定了修法形状：
> `restartSession()` 里那行 `cancelViewQuotaSleep(false)`（`role-dispatcher.ts:1556`）**在事故路径上什么都没取消**——它作用在一个刚出生、本来就没睡的对象上。
> ⇒ **「重连时不要无条件取消休眠」是个零效果补丁，它没有靶子。** 唯一可行的形状是**现问一次**。
> （那行在**同连接内**的重启路径——续场 / 面板手动——上是真取消，故本 change 保留它，见 design §3。）

**② 会话启动闸不问配额。** `sessionStartVerdict()`（`role-dispatcher.ts:1429-1436`）只判三件事：调度总开关 / 平台支不支持浏览 / 有没有绑人设。**这是有意的**——`:1394-1396` 的注释逐字写明「临时 view 配额耗尽不在这里拒签；它在 `open_note` 前进入浏览休眠」。

那个设计对**分钟窗**（睡 60s，拒开新场反造卡点）完全正确。**它只是没考虑日窗**：睡到明天，却仍要先开浏览器、扫卡、跑两次模型，才走到 `open_note` 前那道闸（`:2269-2273`）去发现这件事。

**①+② 合起来**：每次重连 = 一次全新的「不知道自己没额度」的会话。而边缘约每 5 分钟重连一次，空闲看门狗每 240s nudge 一次——两个周期共同把它钉成常态。

### 为什么值得修（不是省 tokens）

约 83k tokens 是本 change 三项代价里**最小**的一项，不构成立论。真正的理由是两条红线：

1. **权威事实与派生状态漂移**。配额账本是**按账号持久的、跨连接共用的**（`connection-runtime.ts:169-170` 注释逐字：「同账号 N 连接经注册表天然共用 → 额度合并不翻倍」）。而消费它的那个「知不知道没额度」的派生标记**每连接归零**。系统持有正确事实，却让一个每 5 分钟被抹一次的副本去驱动行为。
2. **静默丢弃**。休眠期扣命令的那一支（`role-dispatcher.ts:765-767`）**一声不吭地 `return false`**。本 change 会让这道闸从边角变成主刹车——不补日志，等于把「静默丢弃」从偶发扶正成常态，直接撞红线。

### 明确不作为立论的两条

- ❌ **「深夜反复开关浏览器有风控含义」**——仓内无任何代码或平台信号支持，纯猜测，不写进理由。
- ❌ **「67 次唤醒会饿死发布任务」**——已证伪：发布任务走独立唤醒路径且排队自然消化，唤醒预算 180s vs 浏览器冷启动 ≈40s，**4 倍余量**。

## What Changes

**只改云端一处 + 补一条日志。当天可部署 dev，不出安装包。**

1. **会话启动统一收口处现问一次配额，被拒即当场休眠**（`restartSession()`）。
   - 不区分窗口：分钟窗拒 → 睡 60s 后自动重驱（与今日净行为一致，只是提前）；日窗拒 → 睡到明天。
   - **MUST NOT 结束会话**——这条是既有规格的反向不变量（`interaction-risk-gating/spec.md:483-486`），一刀切加「会话级配额闸」会当场破坏它。
   - 插入点必须在 `feed.entered` 派发**之前**（同步 emit 竞态，见 design §2）。
2. **休眠闸扣命令时打一条节流日志**（`role-dispatcher.ts:765-767`），照抄同文件 `:778-782` 既有格式。
3. **保留 `:1556` 那行取消**——它在同连接重启路径上是真取消，删了会造回归。

### 三条被压测否掉的方案（记下来，别再走）

| 方案 | 判决 | 理由 |
|---|---|---|
| A：重连时「不要无条件取消休眠」 | **并入 1** | 没有靶子（见 Why ①）；可行的那半就是「现问一次」 |
| B：看门狗只在浏览过程中才发滚动 | **放弃** | 刹车一装上，那条滚动自己就被 `:765-767` 扣住，看门狗**一行不用改**；且看门狗「不受暂停影响」是 spec 级 MUST（`browse-loop-resilience/spec.md:32/106/116-118`）、是唯一的存活探针，动它风险最高；且 B 管不到 `:1457` / `:1781` 两条重驱滚动 |
| D：边缘唤醒带原因 / 认租约 | **另起 change** | 边缘侧、要出包；且它是**今天就存在**的独立缺口（配额耗尽期浏览器本来就是关的），不与本次止血捆绑。见 design §5 |

## Impact

- **代码**：`aidcp-cloud` 单仓，两处（`role-dispatcher.ts`）。edge / console / 协议 **零改动**，不碰 §2 热点文件（两份 `protocol.ts` / `command-bridge.ts` / `RoleName` / 风控状态机）。
- **规格**：`interaction-risk-gating` **ADDED ×1**（既有 `:501-506` 只覆盖 minute / hour，day 窗从未被规定）。
- **行为**：日额度耗尽的账号 → 浏览器保持停放至次日零点。发布 / 手动评论**不受影响**（不在 21 条 `EdgeCommand` 枚举内、走独立下发通道，结构性免疫）。
- **验收未知项**：边缘约每 5 分钟重连会重置空闲时钟 ⇒ 看门狗 1h 结束会话这条尾巴今天可能从未触发过。C 上线后若重连churn 仍在，行为不变；若停了，1h 尾巴会首次现形（→ 结束会话 → 休息 → 续场 → 重新现问 → 再睡，闭环安全）。
