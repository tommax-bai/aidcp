## Why

FB 与 XHS 搜索已经是平台可观察的真实页面动作，也已有 `search.execute`、单场预算与关键词限频，但成功搜索没有统一执行事实，且搜索未进入按账号持久风控计数、每日活动或配额看板。当前把“Cloud 已下发”同时当成预算消耗、关键词已搜和页面已搜索，既可能少记平台已经观察到的失败后动作，也可能把根本未提交的命令提前记成已搜。

## What Changes

- 将 `search` 提升为一级平台发现行为并纳入 `RiskAction`、分钟/小时/自然日配额、冷/慢启动夹逼、账号今日活动与配额看板，但保持在按笔记去重的 `InteractionAction` 与互动内容账本之外。
- 为自治发现、评论任务定位和运营命令增加明确的搜索目的与全站/容器范围；自治搜索继续由单场预算和关键词限频控制，任务搜索沿用任务授权，但任何平台已执行的搜索都如实计数。
- 扩展既有 `search.execute` / `action.completed` 契约：Edge 回报是否真正提交或导航搜索、结果是否就绪/为空/提交后失败及结果数；FB 与 XHS 使用同一事实语义、各自保留平台后置验证。
- 把搜索生命周期拆成请求、预闸、下发、平台执行和结果五层：下发只占用尝试预算，只有 Edge 证明 `actuated=true` 才写入持久风险事实；未提交不得计数或标为成功。
- 搜索成功事实驱动概念词 `markSearched`，避免仅下发即把未执行关键词永久标成已搜；被预算、限频或风控拦截继续发出诚实 `search.skipped`。
- 管理后台把“单场互动预算”校准为“单场行为预算”，并把搜索作为可配置风险动作展示在配额、今日账号活动及枚举漂移哨兵中。

## Capabilities

### New Capabilities

- `platform-search-activity`: 定义跨 FB/XHS 的一级搜索行为、目的/范围、平台执行事实、结果终态和诚实计数边界。

### Modified Capabilities

- `interaction-risk-gating`: 将搜索加入按账号持久风险动作、配额与冷/慢启动控制，同时保持其不进入按笔记互动去重。
- `concept-pool-search`: 将关键词已搜落态从“命令已下发”收窄为“Edge 已证明平台搜索实际发生”，并增加搜索风控预闸。
- `console-panel-api`: 在风险动作枚举、今日账号活动和配额视图中暴露搜索，并保持前后端枚举漂移检测。

## Impact

- `aidcp-cloud`: 协议镜像、事件总线、`RoleDispatcher` 搜索状态机、`RiskController` 动作/配额/冷启动、PG 约束迁移、面板与客户端概览计数、测试。
- `aidcp-edge`: XHS 搜索提交观测、FB 全站与容器搜索观测、成功/失败统一回执、协议镜像与回归测试。
- `aidcp-console`: 风险动作枚举/标签/排序、配额页文案、今日活动表及漂移测试。
- `aidcp`: `docs/protocol.md` 与上述 capability delta；不增加协议消息类型，只扩展既有可选 payload 字段。
- 运行时行为变化需部署 Cloud dev；Edge 源码会合入默认分支，但本变更不构建或发布桌面安装包。
