## Context

Edge 当前分别持久化短期客户 JWT 与最近一次成功登录的 `name + key`。两者都位于当前实例的 `userData`，并在 Electron `safeStorage` 可用时加密；加密能力不可用时凭据记忆不落盘。启动流程只恢复仍在本地有效期内的 JWT，过期后直接打开登录门，登录页虽会回填加密凭据，但不会自动提交。

Cloud 的 `/login`、`/auth/refresh` 与 `/my-environments` 已提供完整权威校验：每次受保护请求重新检查客户启用状态，环境范围不从本地推断。本变更只重排 Edge 启动鉴权，不改变这些服务端边界。

## Goals / Non-Goals

**Goals:**

- 启动时优先恢复并校验现有 JWT；确认无效后使用本机加密凭据自动登录一次。
- 自动登录成功后仍通过既有 `/my-environments` 权威范围刷新，随后才建立主界面和环境句柄。
- 自动登录没有凭据或失败时停止在登录门，不产生后台重试循环。
- 区分“客户显式退出”与“短期令牌失效”：前者清除全部记忆，后者保留加密凭据供下次启动恢复。
- 保持所有凭据只在主进程内解密和提交，renderer、日志与协议不接触自动登录明文。

**Non-Goals:**

- 不增加长期 refresh token、设备授权或系统自动启动能力。
- 不延长 JWT TTL，不改变 Cloud/Console/WS 协议。
- 不在客户端运行期间因令牌失效立即无限自动重登；运行期仍回登录门并停止环境。
- 不打包或发布新的 Edge 安装程序。

## Decisions

### D1 — 每个进程启动最多自动登录一次

新增一个无循环的启动鉴权编排器。客户鉴权禁用时直接放行；启用时按以下顺序执行：

1. 若本地 JWT 仍有效，完成临期续签与 `/my-environments` 校验。
2. JWT 本地过期或收到明确 401 时，清除旧 session 文件但保留加密凭据。
3. 读取一次 `safeStorage` 加密凭据并调用既有 `/login` 一次。
4. 成功则保存新 JWT 并进入既有启动流程；失败或无凭据则打开登录门。

编排器本身不设定时器、不递归、不因窗口事件再次触发，因此一次应用启动最多消费一次自动登录尝试。相比把登录页自动提交，这一方案不把 key 交给 renderer，也不会因页面重载重复请求。

### D2 — 只把明确鉴权拒绝当作凭据失效

自动登录返回统一 401 `invalid_credentials` 时删除加密凭据，避免旧 key 在以后每次启动重复触发限流。网络失败与 429 只停止本次自动登录并保留凭据，允许客户在登录门看到回填后手动重试。客户端不得把网络未知状态当作成功。

### D3 — 令牌失效默认保留凭据，显式退出清除全部

现有统一失效路径把 session 与凭据一起删除，使“保存以便下次自动登录”在运行期令牌过期后失去作用。调整为：

- session 过期、续签失败或受保护请求 401：停止环境、清除 JWT、保留加密凭据、回登录门；
- 客户点击“退出登录”：撤销 JWT，并明确清除 JWT 与加密凭据；
- 自动登录被 `/login` 明确拒绝：清除 JWT 与加密凭据。

服务端仍在每次请求检查客户启用状态；保留本机 key 不会绕过停用或范围变更。

### D4 — 手动登录与自动登录复用同一会话建立函数

把 `/login` 请求、结果映射、凭据保存和 JWT 保存收敛到主进程单一函数。IPC 手动登录与启动编排器都调用它，避免两条路径在 TTL、限流或错误语义上漂移。启动编排器用独立纯函数模块承载一次性决策，并通过依赖注入做无 Electron 副作用的单元测试。

## Risks / Trade-offs

- **[本机被解锁的同一系统用户可触发自动登录]** → 这是现有 `safeStorage` 凭据回填能力的同一信任边界；加密能力不可用时不保存、不自动登录，显式退出立即清除。
- **[被停用客户在启动时多发起一次 `/login`]** → 每启动最多一次，服务端限流与统一 401 仍生效；明确拒绝后删除本地凭据。
- **[启动时 Cloud 暂时不可达]** → 不把瞬时网络错误判成令牌无效；无法完成自动登录时停在登录门并保留凭据，不伪造已登录。
- **[启动验证增加一次范围请求]** → 复用 `/my-environments`，以获得服务端启用态和范围真相；请求失败仍沿既有 fail-closed 环境集合处理。

## Migration Plan

1. 在独立 Edge worktree 加入启动鉴权编排器及测试。
2. 接入 Electron 主进程，复用现有登录请求并区分清 session 与清全部凭据。
3. 运行 focused tests、完整 Edge tests 与 typecheck。
4. 快进集成并推送 Edge `master`；本变更不要求 Cloud 部署，也不生成安装包。

回滚仅需回退 Edge 提交；Cloud 数据与接口没有迁移。

无。用户已确认启动时使用加密保存的 `name + key` 自动登录一次。
