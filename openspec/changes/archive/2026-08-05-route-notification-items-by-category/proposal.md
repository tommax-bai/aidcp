## Why

已上线规格 `notification-monitoring` 第一条要求明写：点赞、收藏、新增关注这三类通知 **MUST NOT 发飞书**（「忽略」= 不发飞书，但仍要看一眼清未读）。

**今天挡住它的不是这条类别禁令，而是一条按文案写的正则。**

执行端在「赞和收藏」/「新增关注」两栏，除了清未读回执，还会**顺带回传一批发送者条目**。这批条目的本意是喂**通知联系人名册**（能力 `notification-contact-registry`）。但云端把到达的通知条目**无条件**当成「评论和@」的抽取结果，原样跑评论管线：分类 → 去重 → 发飞书 / 或直接发出「评论和@ 已处理」的收尾事件。

两个后果：

1. **多发一条导航命令**：同一轮里同一类产生两次收尾 —— 一次来自赞收藏浏览角色自己的回执（正确），一次来自被误当成评论批次的旁路条目（错误），于是「返回通知首页」被下发两次。
2. **规格禁令实际上是靠正文文案在守**：真正拦住这批赞/收藏/关注条目的，只有分类器里那条 `^(赞了你的(评论|笔记)|收藏了你的笔记|关注了你|…)$` 的固定说法正则。**分类器根本没有读条目自带的类型字段，更没有读「本趟巡视选中的是哪一栏」。** 只要某条赞/收藏/关注行的正文不长成那几种说法（平台改文案、多语言、正文位取到了笔记标题），它就会被当成评论推送飞书 —— 直接违反已上线的 MUST NOT。

dev 2026-08-05 15:29 实测（账号 `63e2ff0500000000260049ce`）：分诊选中的是 `likes`，从未选过 `comments`，日志里却出现了

```
[notification_classifier] 分类：0/20 条值得通知        ← 这 20 条来自赞和收藏栏
[notification_deduper]   无新项（全部已通知或为空），本类收尾
[notification_return_home] 分类 comments 处理完，返回通知首页   ← 从没选过 comments
[notification_return_home] 分类 likes 处理完，返回通知首页
```

这一次 20 条恰好全被文案正则滤掉，所以没误发。**它是运气，不是保证。**

### 判据为什么落在云端自己的状态上，而不是让执行端多报一个字段

云端**是它自己点名要看哪一栏的**：分诊角色选中某类 → 下发该类的浏览命令。「当前巡视正在处理哪一类」因此是云端的**已知事实**，不需要经执行端绕一圈回来。把它记进巡视状态即可定性到达的批次 —— 不改协议、不需要执行端配合、**对任何版本的执行端立即生效**（现网两条执行端实现路径都会回传这批条目）。

条目自带的类型字段只当**交叉校验纵深**：实读执行端两条实现路径可知，该字段**是按云端下发的命令类别推导出来的**（只有「赞 vs 收藏」用了行内文案），本质上是同一个事实经执行端转了一手 —— 它作唯一判据既不更可靠，还多一次可能出错的传递。两个判据打架时以云端自己选中的那一类为准，并留具名记录。

## What Changes

- **给巡视状态加一格「本趟当前选中的分类」**：由分诊在选中该类时单点写入（与它记尝试次数是同一处），随巡视开始 / 结束清空。写者唯一。
- **评论管线入口按类别路由**：只有选中分类为「评论和@」时，到达的条目批次才进入分类 → 去重 → 飞书 → 该类收尾；其余批次（选中的是赞收藏 / 新增关注，或本趟尚未选中任何分类）**不进评论管线**，但**仍照常到达**——联系人名册那条通路一个字节不动。
- **交叉校验做成纵深而非判据**：条目类型字段与选中分类不一致时（两个方向都算），按选中分类处置并留下具名记录；MUST NOT 静默取其一。
- **三态不压成一态**：「评论栏真的一条都没有」仍照常收尾该类（分诊得以进入下一轮）；「这批条目根本不是评论栏来的」一条收尾事件都不发。二者在日志与事件上可区分。
- **规格侧**：把「点赞/收藏/关注 MUST NOT 发飞书」从一句结果性禁令，收紧成可机械验证的路由判据（谁定性、依据什么、拒进管线后去哪、不一致怎么办、三态怎么分），并显式写下「每一类的收尾 MUST 由该类自己的证据产生」。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `notification-monitoring`: 修改「通知巡视——评论/@ 通知，忽略赞/藏/关注」——把已有的「点赞/收藏/关注 MUST NOT 发飞书」从结果性禁令收紧为可机械验证的类别路由判据。原有的「评论/@ 发飞书」「赞/藏/关注看一眼清未读」「评论栏覆盖到清零」三条保证不变、只增强。
