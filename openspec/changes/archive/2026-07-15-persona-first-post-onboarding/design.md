## Context

Edge 已有账号人设向导、现有启动/恢复按钮、运行价值说明和发布确认卡。Cloud 已有人设持久化、精选内容存储、参照创作管线和发布审批链，但这些能力没有“首次账号首作”状态把它们串联起来。现有运行价值逻辑也只能从普通日/场次窗口推断进度，无法诚实地区分新人首轮 `20` 与账号正常的今日浏览计划。

## Goals / Non-Goals

**Goals:**

- 只在账号第一次成功建立人设时展示一次完成引导，更新或重复绑定不展示。
- 让 `20` 成为首作新人状态专属的观察预期，而不是浏览配额或成功承诺。
- 第一条符合条件的精选源内容自动进入既有参照创作管线，最终仍由既有发布确认卡承接。
- 状态可跨 Cloud 重启恢复，并在并发/重复精选事件下只触发一轮首作生成。
- 新旧 Edge/Cloud 组合能安全降级，不因缺少可选字段崩溃或伪造成功。

**Non-Goals:**

- 不新建第二套 feed 浏览、筛选或发布逻辑。
- 不把 20 条写进风控配额、会话预算或今日计划。
- 不保证浏览 20 条必然产生 1 条精选灵感。
- 不绕过人设闸、发布容量闸、待审落库或发布确认。

## Decisions

### 1. Cloud 持久化账号级首作状态

新增账号级 `first_post_onboarding` 状态行。首次成功的 Edge 人设持久化以 `INSERT ... ON CONFLICT DO NOTHING` 建立 `searching` 状态；唯一账号键保证后续更新、解绑后重绑或重复请求不会再次成为“首次”。`persona.persist.result.firstPostOnboarding` 只在本次确实首次建行时为 `true`。

状态至少包含 `searching / generating / generated`、开始时间、认领的源内容和最后失败原因。精选命中使用条件更新从 `searching` 原子切到 `generating`；生成管线达到待审/草稿/已发布状态后切到 `generated`。容量拒绝、管线失败或超时会退回 `searching` 并记录原因，让后续真实精选内容仍有机会触发，绝不把失败染成完成。

### 2. 首轮 20 是真实状态投影，不是调度输入

`ui.snapshot.dailyUsage.firstPost` 仅在首作状态为 `searching` 或 `generating` 时出现，包含状态、从首作开始时间累计的真实 `view` 数、展示目标 `20` 和可选源内容标识。Edge 只有看到该字段时才固定展示 `/20`；字段缺失时继续使用账号真实的日/场次计划。

达到 20 但尚未命中精选时，界面只表达“已观察约 20 条，继续寻找”，不宣称已经找到灵感，也不停止浏览。Cloud 的风险配额、会话上限和浏览循环完全不读取该展示目标。

### 3. 精选入池复用参照创作管线

精选存储在非空源内容成功入池后发出窄回调。回调只处理 `image_text` / `video`，评论精选不作为首篇图文参照。Cloud 先原子认领首作状态，再调用现有 `PublishScheduler.tryBeginRewrite`，继续复用现有参照图归一、保真改写、待审落库、客户端预览和发布确认。

回调允许由模型准入或机器人收藏两条既有入池路径触发；账号级状态认领与发布调度器的同源 claim 共同防重复。

### 4. Edge 引导只负责解释与复用现有启动动作

弹窗沿用现有人设浮层 560px 骨架和旧版 `mascot-celebration-512.png`。内容区直接呈现三步线性图标，不增加嵌套卡片；CTA 点击先结束一次性引导，再点击现有 `session-fab` 的 `start` 或 `resume` 动作。账号已在运行时只关闭弹窗，让既有自动运营继续。

默认动效只有一次弱撒花和一次 `scale(1) → scale(1.09) → scale(1)`；命中灵感时主运行区可使用一次不超过 `1.12` 的缩放。所有相关动效在 `prefers-reduced-motion` 下关闭，不左右摆动、不上下漂浮、不循环。

### 5. 兼容与诚实降级

协议字段均为可选。新 Cloud 对旧 Edge 只多发可忽略字段；新 Edge 只有收到 `firstPostOnboarding:true` 才展示首作引导，旧 Cloud 的普通成功回执不具备账号生命周期真值，因而安全降级为不展示。只有带 `dailyUsage.firstPost` 的快照才启用固定 20 进度。首作状态存储不可用时 Cloud 不声称已建立自动首作链路。

## Risks / Trade-offs

- [Cloud 状态建表失败] → 人设仍可保存，但回执不宣称首作引导已建立，记录明确日志。
- [精选事件重复或并发] → 账号状态条件更新 + 发布调度器 claim 双重去重。
- [首次参照创作容量不足或失败] → 状态退回 searching，后续真实精选内容可重试；发布卡不出现假候审。
- [运行快照延迟] → Edge 点击 CTA 后可先以本次成功事件显示 0/20，后续以 Cloud 专属快照覆盖；普通账号不持有该本地首轮标记。
- [旧 Cloud 无首作字段] → 新 Edge 不展示无法保证“一生一次”的首作弹窗，主运行区也绝不把普通真实计划强行改成 20。

## Migration Plan

1. Cloud 幂等建立首作状态表并同步协议类型。
2. 接入首次人设持久化、精选入池回调和既有参照创作调度器。
3. Edge 同步协议并落地弹窗、CTA 和首作运行投影。
4. 运行 Cloud/Edge 定向测试、完整相关测试、typecheck 和 OpenSpec 严格校验。
5. 分别提交并快进合并到 `aidcp-cloud/master`、`aidcp-edge/master` 和 `aidcp/main`；Cloud 变更按默认策略部署 dev，Edge 不打安装包。

回滚时可停止写入/下发首作字段并移除入池回调；新增状态表保留不影响现有浏览与发布链。
