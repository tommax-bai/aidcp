## Why

桌面客户端当前把“与 Cloud 保持账号级控制会话”和“启动浏览器执行自动化”装进同一条环境启动生命周期，导致本应只依赖客户登录、可信账号绑定或 Cloud 的操作，仍可能要求用户启动环境并间接消费浏览器槽位。浏览器缺席不应是槽位不足时的降级模式；客户端核心应天然常驻，浏览器只是自动化动作按需取得、可释放的执行器。

## What Changes

- 客户登录并完成环境归属/绑定解析后，每个可用环境自动建立并维持客户端核心与 Cloud 的控制会话，不启动 AdsPower 分身、不附着 CDP，也不占浏览器槽位。
- 建立显式操作分类：客户登录、状态读取、配置、内容、人设、审批受理、草稿编辑、API-only 互动和清理类操作不得经过浏览器槽位或 CDP 准入；只有真实页面读取/写入、人工登录/验证和浏览器窗口控制进入浏览器执行域。
- 浏览器执行域改为客户端核心的按需资源：自动化任务先在控制面受理/排队，需要页面执行时再申请槽位、启动浏览器、附着 CDP、复核真实身份并取得页面任务租约；结束后可释放浏览器而保持核心在线。
- **BREAKING（桌面生命周期语义）**：客户端核心不再由“启动环境”按钮创建；客户端登录后即在线。“开始/暂停自动化”和“打开/关闭浏览器”成为独立意图，浏览器关闭不等于客户端或 Cloud 会话离线。
- 人设生成/保存、稿件审批受理/驳回和待审配图编辑不再依赖浏览器拥有型 Edge 子进程；批准只代表 Cloud 接受授权，真正平台发布在后续浏览器执行阶段完成。
- Cloud 切换重连、控制面异常重起和视频号 offboard 清理必须保持无浏览器形态，不得因复用普通环境启动队列而拉起浏览器。
- 客户端分别展示客户端核心、Cloud 会话、自动化状态和浏览器执行器状态；非自动化操作不得用“请启动浏览器/等待槽位”作为准入或失败原因。

## Capabilities

### New Capabilities

- `client-core-browser-executor-separation`: 定义客户端核心常驻、操作分类、浏览器按需执行器、独立生命周期与故障域，以及浏览器槽位只约束自动化执行的总合同。

### Modified Capabilities

- `client-customer-auth`: 已登录客户的已归属且可信绑定环境自动建立控制会话；非自动化客户操作只依赖逐请求归属/绑定校验，不依赖浏览器或页面身份在线。
- `edge-multi-environment-supervisor`: 将每环境客户端核心生命周期与浏览器执行器生命周期拆开监督，并在重连、重起和 offboard 清理中保持无浏览器形态。
- `edge-fleet-console`: 独立展示和控制客户端核心、Cloud、自动化与浏览器状态，移除非自动化操作的浏览器启动引导。
- `edge-task-execution-coordination`: 页面任务租约和浏览器槽位只适用于自动化执行；控制面/API-only 操作不得进入页面执行准入链。
- `persona-keyword-generation`: 人设生成与确认保存改为基于可信环境绑定和 Cloud 会话，不要求浏览器已启动或页面登录态在线。
- `publish-draft-client-edit`: 客户端待审稿编辑与决策受理改为浏览器无关的客户鉴权/控制面操作，平台执行继续由后续自动化任务承担。
- `edge-cloud-env-selection`: 切换 Cloud 后只重建客户端核心连接，并保持切换前的浏览器关闭/待机状态。

## Impact

- `aidcp-edge`: Electron 环境监督器、客户端登录后的启动流程、每环境核心/浏览器生命周期、IPC 路由、状态模型、UI 文案、人设与稿件请求桥、视频号 offboard 恢复。
- `aidcp-cloud`: customer-auth 环境级操作入口、控制会话/能力协商、非自动化操作受理与后续浏览器任务排队边界。
- 协议与合同：明确操作分类、核心在线与执行器就绪的独立状态；需要新增字段或能力位时保持可选并与旧客户端兼容。
- 安全边界：持久绑定只允许控制面和可撤销 Cloud 操作；任何页面读写前仍须启动浏览器并复核真实平台身份，绝不把历史绑定当作当前页面授权证明。
- 运维与资源：每个已绑定环境会多一个无浏览器核心进程，但不占浏览器槽位；需要度量核心进程总量、内存与重连退避，防止控制面常驻演变为重起风暴。
