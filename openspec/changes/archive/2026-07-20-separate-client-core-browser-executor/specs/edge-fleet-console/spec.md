## ADDED Requirements

### Requirement: 客户端 SHALL 独立展示核心、Cloud、自动化和浏览器状态

每个环境的 UI SHALL 分别投影核心、Cloud、自动化和浏览器四条状态轴，至少能区分核心启动/在线/重启/错误，Cloud 连接/重连/离线，自动化停止/排队/运行/暂停，以及浏览器关闭/排队/启动/就绪/回收/错误。浏览器关闭或自动化暂停 MUST NOT 显示为客户端断线；页面任务排队 MUST NOT 冒充自动化正在执行。

#### Scenario: 核心在线且浏览器关闭

- **WHEN** 客户端核心和 Cloud 均在线、自动化暂停且浏览器未启动
- **THEN** UI 同时显示“核心在线 / Cloud 已连接 / 自动化已暂停 / 浏览器已关闭”，不得使用“待启动”概括四者

#### Scenario: 浏览器错误但 Cloud 操作可用

- **WHEN** 浏览器启动失败而 core 与 Cloud 仍在线
- **THEN** UI 仅在浏览器/页面任务轴显示错误，并保持人设、草稿和配置入口可用

### Requirement: 自动化控制与浏览器窗口控制 SHALL 是独立用户意图

客户端 SHALL 分别提供“开始/暂停自动化”和“打开/关闭浏览器”意图；客户登录后的核心在线不再要求点击“启动环境”。非自动化入口 SHALL 只提示其真实绑定、客户鉴权或 Cloud 前置，MUST NOT 显示“请先启动浏览器”“等待浏览器槽位”或把打开浏览器作为修复动作。人工登录/验证等确需页面的场景 SHALL 明确说明其浏览器目的。

#### Scenario: 浏览器关闭时打开人设向导

- **WHEN** 客户已登录且环境绑定可信、浏览器关闭
- **THEN** 人设向导正常读取和提交，不显示启动浏览器引导

#### Scenario: 人工验证需要浏览器

- **WHEN** 平台 API 或页面身份明确返回需要人工登录/验证码恢复
- **THEN** UI 可提出“打开浏览器完成验证”，并 SHALL 将其标记为鉴权恢复，不得把所有非自动化操作一并阻塞
