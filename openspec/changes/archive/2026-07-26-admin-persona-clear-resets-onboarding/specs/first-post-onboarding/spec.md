## MODIFIED Requirements

### Requirement: 首次人设完成只展示一次首作引导

系统 SHALL 在账号首次成功建立人设时向 Edge 返回首作引导信号。Edge SHALL 在既有人设浮层内展示“看趋势 / 找匹配 / 开始创作”的紧凑说明，并明确“首轮观察约 20 条推荐内容，通常筛出 1 条创作灵感；找到后将自动生成第一篇作品”。更新已有人设、重复持久化或该账号已经建立过首作状态时 MUST NOT 再展示。唯一例外是管理员在受 JWT 守护的后台显式清空人设：该操作 SHALL 同时原子清除既有人设绑定与首作状态；账号下一次成功建立人设时 SHALL 重新创建首作状态并再次返回引导信号。普通更新、客户端重复绑定、自动补齐或非后台解绑 MUST NOT 获得该重置语义。

#### Scenario: 第一次确认人设成功

- **WHEN** 一个从未建立过首作状态的账号第一次成功持久化人设
- **THEN** Cloud 原子建立该账号的首作寻找状态
- **AND** Edge 展示一次人设完成后的首作引导

#### Scenario: 更新已有人设

- **WHEN** 用户为已经绑定人设的账号生成并确认更新
- **THEN** 人设按既有流程更新
- **AND** 首作引导 MUST NOT 再出现

#### Scenario: 重复请求或普通重新绑定

- **WHEN** 同一账号重复提交成功的人设持久化请求，或在没有后台初始化重置的情况下重新绑定人设
- **THEN** Cloud 不得建立第二条首作状态
- **AND** Edge MUST NOT 因该请求重复展示首作引导

#### Scenario: 后台清空后重新建立人设

- **WHEN** 管理员在后台显式清空账号人设且原子重置成功
- **AND** 该账号随后成功建立新的人设
- **THEN** Cloud 重新创建该账号的首作寻找状态并返回 `firstPostOnboarding:true`
- **AND** Edge 再次展示新人首作引导

#### Scenario: 后台重置后尚未重新建立人设

- **WHEN** 后台已经成功清空人设并复位首作状态，但账号尚未保存新人设
- **THEN** 系统保持未绑定且无首作状态，既有无人设入口闸诚实拒绝运行
- **AND** MUST NOT 提前宣称新人引导已经触发
