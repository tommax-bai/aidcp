# Tasks: seed-facebook-automation-defaults-on-registration

> **范围铁律**：只对**真正首次登记**的账号种入。存量账号一个不碰。
> 判据 MUST 是「本次写入真的插入了新行」，**MUST NOT** 写成「配置侧表没有该账号的行」——
> 后者对 37 个存量账号同样成立，写错了会静默把它们全部种上，且单账号测试看不出来。

## 6. 修订：评论审批模式改为免审（2026-07-29 用户裁决）

> 本节推翻初稿的 D6（评论需人审）。发帖不动——Facebook 排期发帖在既有要求里就必须走需人审。

- [x] 6.1 kernel 目录常量里评论模式 `review` → `auto_approve`；发帖保持 `review`，两者刻意不同值。
- [x] 6.2 可达性核实：环境级评论审批策略只能把来源模式**升**成免审（缺省时逐字沿用来源模式），只有读取失败才 fail-closed 回需人审。故种一个免审来源模式即可，**不得**去绕过该策略。
- [x] 6.3 规格 delta 的「种入取值」与「审批模式」两段同步；新增一条场景，锁住「策略读取失败时仍回落需人审」。
- [x] 6.4 测试：断言评论为免审、发帖为需人审，且两者取值必须不同——最后这条专挡「把两个模式一起改掉」的误编辑。
- [x] 6.5 后果如实写进规格与设计：新账号绑上人设并过完其余各闸后，自动评论直接发到平台、无人过目；发帖不受影响。
- [x] 6.6 部署到 dev 并复核存量计数仍为零波及。 <!-- 2026-07-29 部署健康、错误 0。计数变化全部来自两个**真实新增**账号（FB 40→42、排期行 10→12、加群行 2→4、系统种入 0→2+2），存量三行原样未动 -->
