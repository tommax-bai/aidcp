## Why

Facebook 规则模式的账号如果没有配置联系方式，今天整条「加群 + 联系评论」在**加群之前**就整段不启动：联系方式闸位于命令式评论任务机器的入口，早于加群，因此既不入群也不评论，规则轮次直接以「加群未启动 / 评论未启动」终结。规则模式的开关写入侧又**只校验平台、不校验联系方式**（内容排期侧有这道配置期闸，规则模式没有），所以「开着规则模式但没配联系方式」的账号可以长期存在，其加群与评论产出恒为零。

运营决定：这类账号不应静默零产出，而应退而发一条**不带联系方式的普通评论**，让入群与内容互动继续发生。

## What Changes

- **BREAKING（具名放弃已上线安全保证）**：在 Facebook 规则模式的加群联系评论链路上，为「账号无联系方式」引入一个**范围化**降级——不再 fail-closed，改为按普通评论发出。这直接放弃两条已并入主 spec 的保证：`group-chat-injection` 的「缺联系方式时 fail-closed，绝不静默发无联系方式评论」与 `facebook-group-comment-coverage` 的「contact string missing MUST fail closed (no post, no silent downgrade to a no-contact comment)」。放弃是运营的显式决定，本变更具名登记，不作为实现细节顺带发生。
- **降级范围严格限定为规则模式的加群联系评论一条链路**。其余五个入口 MUST 保持 fail-closed 不变：飞书 `/comment --contact`（操作员显式要求带联系方式，降级即违背指令，正是既有判例本身）、内容排期的联系评论、精选定向联系评论、引流热帖联系评论、委托任务联系评论。降级意图 MUST 由调用方显式传入，共用闸的默认值 MUST 仍是 fail-closed。
- **降级后走普通评论的审批车道，不得沿用联系评论的免审授权**。联系评论与普通评论的审批模式是两个独立字段，运营可以只给前者免审。降级产出的是一条普通评论正文，其审批模式 MUST 取普通评论的配置，MUST NOT 继承联系评论车道的授权（含账号级全局免审对该车道的强制拉升）。
- **一切「是否带了联系方式」的对外表述 MUST 按实际注入值渲染，不得按请求意图**。当前合并结果卡与触发回执按请求意图渲染，降级后会对一条不带联系方式的评论宣称「已发出一条带联系方式的评论（服务器已确认）」；同一次动作的人审卡按实际值渲染，两张卡会自相矛盾。三处口径 MUST 统一到实际值，并新增可辨识的「已降级为普通评论」话术。
- **降级会新增今天不会发生的真实平台写动作**：加群将真正下发，消耗加群的风控日配额与会话预算，并在平台上留下真实入群事实。这是行为扩张，MUST 在规格与运营说明中显式声明，不得作为副作用出现。
- **正文来源不变**：仍是账号模板优先、账号模板为空时回落群组区域模板；两级都取不到时 MUST 继续诚实停止并给出具名原因，MUST NOT 为提高成功率回退到生成式撰写、跨区域取模板或任何默认文案。降级解决的是「没有联系方式」，不解决「没有模板」。
- 规则轮次的评论段投影 MUST 能区分「联系评论已确认」与「降级普通评论已确认」，后台 MUST NOT 把后者显示为联系评论已完成。
- 规则模式开关的写入侧增加联系方式**提示**（非硬拒）：开启时若账号无联系方式，回读中带出「该账号将按降级发普通评论」的具名说明，使运营在配置当刻就知道会发生什么。

## Capabilities

### Modified Capabilities

- `group-chat-injection`: 「缺联系方式 fail-closed」新增一个范围化具名例外（仅 Facebook 规则模式加群链路），其余触发入口保持原保证；并要求对外表述按实际注入值而非请求意图渲染。
- `facebook-group-comment-coverage`: 联系评论车道的「contact string missing MUST fail closed」新增同一范围化例外，并裁定降级产出归属普通评论审批车道。
- `facebook-rule-mode`: 规则轮次的评论段结果须区分联系评论与降级普通评论，并明确降级会真实执行加群。

## Impact

- **前置依赖**：`facebook-rule-mode` 能力尚未并入 `openspec/specs/`，仍活在未归档的 `facebook-rule-mode-cadence` 中；本变更对它的 delta MUST NOT 先于其归档生效。
- **并行冲突**：`facebook-rule-mode-without-persona` 已裁定「规则轮次评论 MUST 走模板；账号显式选生成式时评论段如实标为不可执行」。本变更与它同改规则轮次评论段语义，MUST 串行并对齐；两者不冲突（一个管正文来源、一个管联系方式缺失），但落地顺序需确认。
- **Cloud**：命令式评论任务机器的联系方式闸改为按显式意图分流；「本次实际是否注入」成为独立事实向下传递；触发回执、合并结果卡、免审通知三处口径统一；规则模式触发处决定降级意图与审批模式来源；规则轮次结果映射新增可辨识终态。
- **Console / 客户端**：规则轮次评论段的展示需容纳「降级普通评论」这一新结果；枚举漂移会整页白屏，须同步。
- **Edge**：零代码改动。边缘评论执行器对联系方式本就按「有值才追加」处理，协议中联系方式字段本就可选。**但原生页面引擎路径的正文与联系方式拼接方式与 JS 路径不等价，且该路径正在切换中**，实装期 MUST 两条边缘路径分别核验。
- **运行现实（2026-07-28 部署前实测修正）**：先前依据 `facebook-global-group-regional-comment-templates` 的实装记录写着「区域模板目录真态为空 ⇒ 降级后大概率仍评不出来」——**那条已过期**。实测 DEV：区域模板 5 个区域各 13 条，1864 个群目标**全部**带区域标注。因此降级产出的正文有来源，不会普遍卡在缺模板。
  - 受影响面比预期大得多：DEV 上开着规则模式的 21 个账号**全部**没有配联系方式，即降级不是边角情形而是当前的全部人群——这也正好解释了规则模式此前为什么产出为零（这条链对它们全都在加群之前整段停住）。
  - 其中 1 个账号有自己的评论模板，其余 20 个靠群组区域模板兜底。
  - 仍然成立的口径：降级**不承诺**一定评得出来。缺模板时 MUST 继续以具名原因诚实停止。
- **Out of scope**：不改正文来源解析链、不改评论校验器、不改联系评论的日额度台账、不改规则模式节奏（由 `facebook-rule-mode-two-tier-cadence` 承接）、不改其余五个入口的 fail-closed 行为。
