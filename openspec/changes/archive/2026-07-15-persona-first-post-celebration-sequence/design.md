## Context

现有 renderer 已通过 `showPersonaGrowth()` 为引导根节点添加一次 `.play`，CSS 同时驱动吉祥物与撒花。无需增加计时器或新的 JavaScript 状态；第二段文字强调可以在同一个 `.play` 生命周期中使用 animation delay 编排，避免弹窗关闭后仍有异步回调改 DOM。

## Decisions

### 1. 保留单次放大后归位，只提高可感知峰值

吉祥物使用 840ms 的 `scale(1) → scale(1.12) → scale(1)`。峰值采用既有动效体系允许的最大值，增强可见度但不造成布局重排；仍禁止左右摆动、上下漂浮和循环。

### 2. 撒花围绕吉祥物爆开

粒子起点从弹窗中部移到右上吉祥物中心附近，并从六粒增加到十粒。所有粒子只播放一次、在 900ms 内淡出，颜色继续复用青蓝、绿色、暖色与克制珊瑚色。

### 3. 第二段用纯 CSS 延迟编排

“首轮观察约 20 条推荐内容 → 通常筛出 1 条创作灵感”在首段约 840ms 结束后停顿约 240ms，于 1080ms 时开始 640ms 的一次性轻抬升、缩放与背景聚焦，结束后恢复静态透明背景，不形成常驻嵌套卡片。

### 4. 减少动画偏好直接静态展示

`prefers-reduced-motion: reduce` 同时关闭吉祥物、撒花和预期文字动画，并显式恢复文字的正常透明度、位置与背景，保证信息不依赖动画才能出现。

## Risks / Trade-offs

- [放大造成裁切] → 保持现有 82px 布局尺寸，只使用 `transform`，以底部中心为原点，峰值限制为 1.12。
- [文字强调看起来像嵌套卡片] → 聚焦底色仅存在于动画中，最终回到透明且不增加边框。
- [关闭弹窗后计时器继续工作] → 不使用 JavaScript timer，动画随 `.play` 节点生命周期自然结束。
