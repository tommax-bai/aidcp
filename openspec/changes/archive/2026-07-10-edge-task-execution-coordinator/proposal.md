## Why

边缘端目前只有浏览命令自己的 FIFO 队列，发布原子命令、按需评论接管和浏览动作分别由独立异步链驱动，却共享同一个 CDP 会话。云端停止 `RoleDispatcher` 只会停止后续浏览决策，不会等待边缘正在执行的动作真正静止；因此发布可能在 `navigation.back` 尚未完成时开始，随后被旧浏览动作重新导航回信息流，产生 `select_mode no_target` 一类执行冲突。发布与评论也没有跨任务互斥，任一任务先结束都可能过早恢复浏览。

需要把“单条动作排队”提升为“任务级执行权”：云端拿到边缘确认的执行租约后才能发第一条写页面命令，边缘在安全点完成当前动作、取消未开始的陈旧浏览命令，并保证整个发布或评论提交阶段不被其他写任务插入。

## What Changes

- 在 protocol v2 新增边缘任务租约的申请、确认、释放与释放确认消息；所有独占任务以 `taskId` 关联，边缘确认 `acquired` 同时代表 CDP 已进入 quiesced 状态。
- 在 edge 按 `edgeId/CDP` 引入统一任务执行协调器：浏览为低优先级可抢占任务，独占任务按优先级/FIFO 排队；抢占只等待正在执行的原子动作到安全点，未开始的普通浏览命令直接取消，不排空陈旧队列。
- 发布从 `navigate_entry` 到提交后捕获全程持有一个任务租约；发布原子命令必须携带匹配的 `taskId`，没有租约、租约错误或租约过期时诚实失败。
- 评论改为两段边缘占用：搜索/打开/读取为 prepare 租约；云端撰写、模型调用和飞书人审期间释放租约；批准后以 commit 租约重新打开并校验目标，再提交评论。人审等待不占住浏览器。
- 云端新增按 `edgeId` 的统一租约客户端，协调发布、评论及后续通知巡视、加群和系统恢复任务；同优先级人工任务 FIFO，系统恢复高于人工发布/评论，自动排期低于人工任务。
- 浏览恢复改为引用计数/租约收敛语义：只有该 edge 没有当前独占任务及等待接管时才恢复，避免发布和评论重叠时任一 `finally` 过早重启浏览。
- 断线、超时、错误和进程退出均需有界释放；不能确认执行权时不得发送第一条业务命令，也不得伪造成功。

## Capabilities

### New Capabilities

- `edge-task-execution-coordination`: 定义同一 edge/CDP 上浏览、发布、评论、通知巡视、加群和系统恢复任务的任务级租约、优先级、抢占安全点、命令归属、恢复及故障语义。

### Modified Capabilities

- `content-schedule`: 将小红书评论任务从“搜索、撰写、人审、提交全程接管边缘”改为 prepare/commit 两段占用，人审等待期间释放边缘执行权，并在 commit 阶段重新打开和校验目标。

## Impact

- `aidcp-edge`: protocol 定义、`EdgeClient` 路由、`BrowseSession` 命令队列、发布命令入口、主进程装配及新增任务协调器和回归测试。
- `aidcp-cloud`: protocol 定义、任务租约客户端、发布派发器/命令序列器、评论调度器/边缘步骤、浏览接管恢复逻辑、server 装配及协议/集成测试。
- `aidcp-console`: 将桌面客户端下载入口更新到包含本协议实现的 0.3.5 安装包。
- `aidcp`: `docs/protocol.md`、架构说明、OpenSpec 变更与验收记录。
- 兼容性：属于 protocol v2 的增量变更，要求 edge/cloud 同步发布；旧 edge 不会回 `task.acquired`，云端应超时并诚实拒绝任务，而不是回退到无租约写页面。
- 风险：评论 commit 前页面上下文可能已变化，因此必须按稳定 `noteId` 重新打开并复检；已经成功提交发布后仍沿用“不得因后续超时翻成失败”的既有红线。
