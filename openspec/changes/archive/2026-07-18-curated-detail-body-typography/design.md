## Context

精选详情正文由 `.curated-detail-body` 单独承载，灵感库列表正文摘要由 `.curated-card-body` 单独承载；标题、作者、话题、元信息和操作按钮均使用其它选择器。因此可以通过两个局部 CSS 规则精确调整正文层级，不影响其它内容工作区页面。

## Goals / Non-Goals

**Goals:**

- 为精选详情正文应用用户指定的完整字体回退顺序。
- 将正文设置为 `16px`、`font-weight: 400`。
- 为列表正文摘要应用同一字体栈，并设置为较小的 `14px`、`font-weight: 400`。
- 保留现有行高、换行、独立滚动和布局行为。
- 通过静态样式契约测试防止字体声明被缩短、重排或扩散到其它元素。

**Non-Goals:**

- 不调整详情或列表标题、作者、话题、元信息、按钮及稿件审核排版。
- 不改变正文内容、行高、颜色、间距或滚动方式。
- 不加载网络字体或新增字体资源。

## Decisions

### 只在两个正文层级声明字体

字体声明分别放在现有 `.curated-detail-body` 与 `.curated-card-body` 规则中，不放到父容器或内容工作区根节点。这样标题、作者、话题和元信息继续继承原有 UI 字体，变更范围严格限定在详情正文和列表正文摘要。

### 原样保留指定回退顺序

字体栈按用户给定顺序写入 `font-family`，包含系统 UI、彩色 Emoji、跨平台西文字体和中文系统字体。浏览器会使用首个可用字体，并在缺字时继续回退；不引入额外下载或运行时探测。

## Risks / Trade-offs

- [不同系统实际命中的字体不同] → 使用完整跨平台回退链，保持系统原生渲染。
- [较大字号增加正文纵向长度] → 保留现有独立滚动容器，行为不变。
- [列表摘要过大削弱详情层级] → 列表摘要使用 `14px`，低于详情正文的 `16px`。
- [选择器扩大导致标题字体一起变化] → 只修改两个正文选择器，并以测试锁定作用域。

## Migration Plan

纯 CSS 变更，无数据迁移；回滚对应样式与测试即可。
