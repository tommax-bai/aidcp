## Context

角色/分类模型配置的后端契约（`role-llm-config` 已合并 spec）早已成型：模型按四层回落生效（角色覆盖→分类默认→全局默认→代码默认），`provider` 跟模型同行；面板写接口非乐观、`PUT` 的 `model===''`/`null` = 清除该层覆盖（回落），非空 = 建覆盖并先探活。前端 `RolesPage.tsx` 复用这套契约，问题只在**编辑弹窗如何向运营表达「覆盖 vs 继承」**。

旧前端把「模型名输入框」一物两用（既显示值又当覆盖开关，留空=清覆盖），并靠"字符串/厂商有没有变"隐式推断该送什么——这在预填当前生效值后必然产生歧义（预填即非空 → 原样保存会误建覆盖）。

## Goals / Non-Goals

- **Goal**：编辑弹窗能看到当前生效值；「覆盖 vs 继承」由运营**显式声明**而非系统猜；消除三处静默/误导（误钉覆盖、静默丢厂商改动、残留禁用却选中的 `on`）。
- **Non-Goal**：不改任何后端契约与回落语义；不引入新面板字段（继承态对已覆盖行不显示待继承的具体模型名——后端未透出，接受为已知限制）；不做批量 / 筛选 / 权限体系。

## Decisions

- **显式二态选择器（继承 / 自定义）**，而非继续用「留空=回落」的隐式约定。这是级联配置（CSS `inherit`、K8s 默认）的业界通行表达：状态显式后，保存该送 `''` 还是当前值由 `modelMode` 直接决定，不再靠字符串比较推断，一举解决误钉覆盖、支持把继承值固定为覆盖、并让「只改厂商」有确定去向。
- **预填当前生效值作为自定义态起点**：无论开弹窗时是继承还是覆盖，都带出 `effectiveModel`/`effectiveProvider`；继承态输入收起（只读说明呈现），切到自定义即拿到现值微调。
- **诚实闸复用后端契约**：自定义态空模型名前端拦下（无意义空覆盖）；其余交后端探活（无效诚实 400），前端不自行判定模型有效性。
- **思考「开启」可用性上提为组件级派生值** `roleThinkingOnOk`/`catThinkingOnOk`（自定义且填了模型→前端镜像 `thinkingOnSupported`，与云端 `buildThinkingParams` 同源；否则用后端 `thinkingOnAvailable`），并以 `useEffect` 在其变 false 且当前选中 `on` 时收回 `default`，杜绝禁用却选中的误导态与静默存不支持组合。选择器与该派生值同源，不再各算一份。

## Risks / Trade-offs

- **继承态对已覆盖行不显示待继承的具体模型名**：后端行数据只含 `effectiveModel`（= 当前覆盖值），不含「移除覆盖后会落到的上层值」。取舍：继承态用说明文字（「跟随分类默认 / 默认模型」）而非展示一个可能错的值；如需展示具体待继承值，后续可由后端补字段。
- **纯前端改动、无自动化 UI 测试**：靠 `tsc` + `build` + 逐态人工走查 + 一轮对抗性评审兜底（评审揪出的静默丢厂商、残留 `on` 两处已修）。
