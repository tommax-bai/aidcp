## Why

后台「角色配置」页（角色级 + 分类默认两张表）的编辑弹窗有一处编辑体验缺陷：打开编辑时，**厂商下拉是带出当前值的，但模型名输入框在「继承」态（该行未单独覆盖模型、跟随分类默认 / 全局默认）下却是空白**——运营看不到当前实际在用哪个模型，且与已填的厂商不一致、易误判为空配置。

更深一层，旧编辑弹窗**没有「继承 vs 覆盖」的显式表达**：模型名输入框既是「当前值」又是「覆盖开关」（留空=清覆盖回落），全靠"字符串有没有变"来隐式推断，带来三个具体坑：① 把继承值预填进去后原封保存会**把继承悄悄钉成覆盖**（此后不再随上层变动）；② 想把一个继承来的值主动固定成本行覆盖（冻结、不再跟随上层）**做不到**；③ 只改厂商不改模型时改动可能被**静默丢弃**却仍提示已保存（触「绝不静默假成功」红线）。此外思考模式「开启」与模型相互独立，切换来源 / 换模型后可能残留一个**禁用却仍选中的 `on`** 并被静默存库。

## What Changes

- **编辑弹窗预填当前生效模型**：打开角色 / 分类编辑时，模型名与厂商一并带出**当前生效值**（含从上层继承来的值），运营一眼看到现值再改。
- **新增显式「模型来源」二态选择器（继承 / 自定义）**，角色级与分类默认两处一致：
  - **继承**：该行不自设模型、跟随上层默认（角色→分类默认→全局「默认模型」；分类→全局「默认模型」）。厂商 / 模型名输入收起，改为一条说明呈现当前生效值。保存 = 清除本行模型覆盖、回到跟随。
  - **自定义**：为该行单独锁定模型；厂商 / 模型名输入展开并预填当前生效值，可微调。保存 = 按当前值建 / 改覆盖（服务端按厂商探活）。**支持把一个当前继承来的值一键固定为覆盖**（此前不可能）。
  - **诚实闸**：自定义态未填模型名 = 无意义空覆盖，前端拦下并提示，绝不退化成静默回落；只改厂商不改模型不再被静默丢弃（带当前值落库、由服务端探活、无效诚实报错）。
- **思考「开启」自愈**：当「开启」因切换来源 / 换模型 / 换厂商变为不可用时，已选中的 `on` 自动收回 `default`，杜绝「禁用却仍选中」的误导状态、也防止不支持思考的组合被静默存成 `on`。
- **范围裁剪（YAGNI）**：纯前端编辑体验改动；**不改**任何面板 API 契约、不改角色/分类模型解析与回落语义、不改思考三态出口翻译、不碰边-云协议 / 风控 / 边缘。「继承」态对**已覆盖**行只说明「跟随上层」、不显示待继承的那个具体模型名（后端未透出该字段，属已知限制）。

### Modified Capabilities
- `role-llm-config`: 修改既有「后台角色配置页」Requirement——编辑弹窗 SHALL 预填当前生效值、SHALL 提供显式「模型来源」二态（继承 / 自定义）表达覆盖 vs 回落、自定义空模型名 MUST 被拦（不静默回落）、支持把继承值固定为覆盖、思考「开启」不可用时已选 `on` MUST 收回 `default`（不静默存不支持的组合）。仍逐字保留其原「非乐观保存 + 诚实文案 + 纯规则/遗留角色不列 + 判定类不渲染温度」不变量。

## Impact

- **aidcp-console**：仅 `src/pages/RolesPage.tsx`（角色 + 分类两个编辑弹窗：新增 `modelMode`/`catModelMode` 二态 + `Segmented` 选择器 + 继承态说明 Alert + 自定义态输入、`onOk` 按来源送 `model`（继承→`''` 清覆盖 / 自定义→当前值）+ 空自定义拦截、思考「开启」可用性上提为派生值 + 两个 `useEffect` 在不可用时把 `on` 收回 `default`）。
- **不触及**：面板 API（`GET/PUT /api/roles`、`/api/categories`、`/api/roles/:id/prompt`）契约与其后端实现、角色/分类模型解析与四层回落、思考三态出口翻译、边-云 WebSocket 协议、风控单写、边缘端、发布链。后端对 `model===''` 清覆盖、非空探活的既有语义被前端如实复用，未改一行。
