## Why

视频号引擎已经与 Cloud 完成握手、核心进程仍在运行时，若登录会话失效且本地鉴权浏览器启动失败，当前环境栏会因为五分钟没有新的 stdout 而误报“失联”，同时互动工作区长期停留在“鉴权中”。这把“控制面在线但鉴权需要处理”混成了“引擎失联”，既不符合真实运行状态，也掩盖了可操作的本地浏览器失败。

## What Changes

- 为视频号 API-only 运行时增加独立于浏览器、鉴权与业务同步的 Cloud 往返心跳；只有收到匹配的 Cloud 响应才刷新桌面环境栏的运行时鲜活度。
- 保留真实失联语义：心跳失败、WebSocket 断开或核心停止时不得刷新鲜活度，原有超时判定继续如实收敛为“失联”。
- 视频号鉴权浏览器启动失败后退出无限“鉴权中”，转成可恢复、可操作的重新登录状态，并记录脱敏后的具体本地启动诊断。
- 增加回归测试，覆盖“Cloud 在线但鉴权未完成不误报失联”“心跳失败不冒充在线”和“浏览器启动失败不滞留 authenticating”。

### Modified Capabilities

- `edge-fleet-console`: 环境栏的鲜活度必须由真实的运行时/Cloud 往返证据维持，不得把仍在线但尚未完成视频号鉴权的核心因业务日志静默误判为失联。
- `wechat-channels-interaction`: 视频号鉴权浏览器启动失败必须退出进行中状态、保留明确恢复入口，并提供不泄露凭据的可诊断错误信息。

## Impact

- `aidcp-edge` 视频号运行时、鉴权状态机、桌面环境栏状态投影及其测试。
- 复用现有 `ping` / `pong` 协议，不新增协议消息、不修改 Cloud 业务行为、不改变视频号读写授权边界。
- 这是桌面运行时与用户可见状态语义修复；不需要数据库迁移，也不需要构建或发布 Edge 安装包。
