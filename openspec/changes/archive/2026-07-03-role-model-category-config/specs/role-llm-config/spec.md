## ADDED Requirements

### Requirement: 角色分类目录层（配置层，不进运行时注册表）

系统 SHALL 在角色目录之上提供一个**可配置的分类维度**：每个目录角色 SHALL 归属一个稳定的**分类 key**（带中文显示名），用于后台分组查看 / 编辑 / 批量管理。分类清单 SHALL 由代码白名单导出（与 `roleId` 同样的白名单制），系统 SHALL 提供「分类 → 角色」映射与「角色 → 分类」反查，并对写入做未知分类校验。分类是**配置目录层**概念，MUST NOT 进入运行时角色注册表 / 事件编排——运行时角色分发仍按 `roleId`，引入分类 MUST NOT 改变任何角色的注册、调度或事件流。

#### Scenario: 每个目录角色都归属一个分类
- **WHEN** 请求角色目录（`GET /api/roles` 或其分类视图）
- **THEN** 每个现役 LLM 角色都带一个稳定分类 key 与中文显示名，且同分类的角色可被一并取出

#### Scenario: 分类只影响配置层不影响运行时
- **WHEN** 运营在后台调整某分类（如改其默认模型或归类）
- **THEN** 运行时角色注册表 / 事件编排 / 角色分发不发生变化，仅模型解析的回落来源受影响

#### Scenario: 未知分类被拒
- **WHEN** 写接口收到一个不在白名单内的分类 key
- **THEN** 系统拒绝该写入并报因，不落库

### Requirement: 分类级模型默认与四层优先级回落，绝不 brick

系统 SHALL 支持**按分类**设置默认文本模型（落 PostgreSQL，缺 / 空 / 无效一律回落），并把模型解析回落顺序扩为四层：**per-role 覆盖 → 分类默认 → 全局默认（`textModel`）→ 代码默认**。某角色无 per-role 覆盖时 SHALL 继承其所属分类的默认模型；分类亦无默认时回落全局默认；全局缺省时回落代码默认。任一层**缺行 / 为空 / 无效 / 存储不可达**时解析器 MUST 逐级向下回落、MUST NOT 抛错、MUST NOT brick（最坏回落到代码默认）。分类默认 SHALL 在调用时从共享内存镜像解析使 `PUT` 后**无需重启即生效**（热加载），且写入 MUST 先持久化成功再刷新内存镜像。分类默认的写入 MUST 沿用保存前探活：非空模型名探活失败 MUST 诚实拒绝（`model_invalid`）、不落库、不假成功。温度 MUST NOT 引入分类层（仍按角色配，回落构造默认）。

#### Scenario: 角色无覆盖时继承分类默认
- **WHEN** 某角色在 `role_config` 无 `model` 覆盖，但其所属分类设了默认模型
- **THEN** 该角色的文本调用使用分类默认模型，无需重启即生效

#### Scenario: 角色覆盖优先于分类默认
- **WHEN** 某角色既有 per-role `model` 覆盖、其分类也有默认模型
- **THEN** 该角色使用 per-role 覆盖（分类默认仅作用于无覆盖的同类角色）

#### Scenario: 分类无默认时回落全局再回落代码默认
- **WHEN** 某角色无 per-role 覆盖、其分类也无默认模型
- **THEN** 回落到全局默认 `textModel`；若全局也缺省则回落代码默认，全程不报错

#### Scenario: 分类存储不可达不 brick
- **WHEN** 分类默认存储初始化失败或读取异常
- **THEN** 模型解析退化为「per-role → 全局 → 代码默认」三层，系统正常运行不报错

#### Scenario: 分类默认填无效模型名被拒不落库
- **WHEN** 给某分类提交一个保存前探活失败的非空模型名
- **THEN** 系统返回 `model_invalid`，不写库、不刷镜像、绝不假成功

### Requirement: 账号维度模型配置数据缝（NULL=全部账号，本期不接线）

系统 SHALL 在分类配置 schema 预留一个**可空 `account_id`** 列作为账号维度数据缝，其语义为 **`NULL` = 适用全部账号**、非空 = 某账号专属。完整的契约级模型解析优先级 SHALL 文档化为五层（自高而低）：**账号覆盖 → per-role 覆盖 → 分类默认 → 全局默认 → 代码默认**。本期 MUST NOT 把 `accountId` 串到任何 LLM 调用点：解析路径本期恒以 `account_id IS NULL`（全局行）命中，账号专属行本期 MUST NOT 被写入或读取。该缝 SHALL 设计为账号就绪——后续接入按账号绑定时无需改表结构即可启用（先查账号行、miss 再回落全局行）。`role_config` 既有表本期 MUST NOT 改主键引入 `account_id`（账号缝集中在新分类表上验证形态）。

#### Scenario: 本期解析恒走全局账号行
- **WHEN** 任一角色在本期解析模型
- **THEN** 分类默认查询命中 `account_id IS NULL` 的行，账号专属行（若存在）不参与解析

#### Scenario: 账号缝零改表即可启用
- **WHEN** 未来引入按账号绑定，给某账号写入 `account_id` 非空的分类默认行
- **THEN** schema 无需变更即可承载该行，且全局默认行（`account_id IS NULL`）与账号专属行可并存唯一

#### Scenario: 优先级链文档化为五层
- **WHEN** 查阅模型解析契约
- **THEN** 优先级被明确为「账号覆盖 → per-role 覆盖 → 分类默认 → 全局默认 → 代码默认」，其中账号层标注为本期不接线的预留缝
