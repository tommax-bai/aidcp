## Context

当前 Electron 主列在在场感与运行价值卡之间常驻一条七段浏览循环轨道；运行价值卡内部又有三段价值流程和实时进度，形成两套并列流程。今日进展则用无文字的圆形箭头控制窗口详情，虽然已有 `aria-label`，但视觉上无法直接区分展开与收起含义。

改动仅发生在 renderer，既有浏览阶段数据、运行价值视图和今日进展窗口数据继续作为权威来源。

## Goals / Non-Goals

**Goals:**

- 主视图默认只强调当前运行价值和真实进展，不常驻展示内部七段浏览步骤。
- 用户仍可从运行价值卡就地展开七段步骤，并看到真实当前阶段。
- 今日进展折叠控件直接显示“展开 / 收起”及对应方向，视觉权重低于会话生命周期按钮。
- 为两项交互补充 DOM、状态和可访问性回归测试。

**Non-Goals:**

- 不改浏览阶段枚举、阶段推导或云端数据。
- 不改运行价值卡三段流程、配额窗口内容或今日计数。
- 不持久化两个纯展示层的展开状态。
- 不构建或发布桌面安装包。

## Decisions

### 将既有浏览循环 DOM 移入运行价值卡并默认收起

保留现有七段步骤及当前阶段点亮逻辑，只把容器从主列常驻位置移到运行价值卡进度条下方。进度元信息旁增加“查看运行步骤”按钮；展开后按钮改为“收起运行步骤”，并同步 `aria-expanded`。

相比直接删除七段步骤，该方案保留了诊断和解释价值；相比继续缩小常驻轨道，它从根源上消除了与三段价值流程争夺首屏层级的问题。

### 展开状态只保存在 renderer 内存

运行步骤与今日节奏的展开状态都属于当前查看会话，不写设置、不进入协议。运行价值卡消失时关闭七段步骤，避免下一次出现时继承过期上下文。

### 今日进展使用文字加箭头的 ghost disclosure

按钮内部拆成可更新的文字与方向图标。收起态显示“展开 ⌄”，展开态显示“收起 ⌃”；默认无边框和底盘，仅在 hover / focus 时出现柔和背景。既有整卡点击行为和会话控制按钮阻止冒泡的规则保持不变。

## Risks / Trade-offs

- [运行价值卡未出现时无法查看七段步骤] → 此时没有可解释的实时运行进展，继续隐藏内部步骤；在场感仍如实呈现状态。
- [进度元信息在窄窗口变长] → 允许元信息组换行，按钮保持可点击且不挤压进度标题。
- [每秒刷新重建进度头] → 展开状态保存在独立变量中，每次渲染按状态重建按钮文本和可访问属性，阶段容器本身仍复用现有 DOM。

## Migration Plan

1. 更新 renderer DOM、样式和交互状态。
2. 更新 Electron UI 回归测试并运行相关测试与类型检查。
3. 快进合并到 Edge `master`；该纯客户端源码改动不触发 ECS 部署，也不默认构建安装包。

回滚只需回退 renderer 与测试提交，不涉及数据或协议迁移。
