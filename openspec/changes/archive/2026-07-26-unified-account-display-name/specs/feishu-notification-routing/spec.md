## ADDED Requirements

### Requirement: 飞书人类可见账号名称统一从账号目录获取

所有包含当前运营账号的飞书审批卡、告警、指令回执、评论/发布终态通知和委托任务卡 SHALL 在发送前通过 Cloud 账号显示名目录解析账号名称。卡片模板 MUST NOT 自行选择运营别名、平台昵称或运营标签；目录仅能回落账号 ID 时，人类可见位置 SHALL 显示明确的“未获取昵称”，MUST NOT 泄露裸账号 ID。

#### Scenario: 飞书通知显示运营别名
- **WHEN** 账号已有运营别名且触发发布审批、评论结果、验证码告警或委托任务通知
- **THEN** 所有卡片的可见账号字段均显示同一运营别名

#### Scenario: 缺少可读名称不展示账号 ID
- **WHEN** 账号只有机器 ID、没有运营别名、平台昵称或非 ID 运营标签
- **THEN** 飞书可见账号字段显示“未获取昵称”，机器载荷仍保留账号 ID

### Requirement: 飞书路由与回调继续使用稳定键

统一显示名 SHALL 只影响可见文案。飞书目标群路由、客户/团队解析、审批 callback、任务持久化、风控告警归因和发布/评论执行 MUST 继续使用稳定 `accountId`、`requestId` 与既有签名载荷；显示名改变 MUST NOT 改变目标群或重复执行动作。

#### Scenario: 改名不改变通知路由和审批动作
- **WHEN** 账号运营别名在审批卡发出前后发生变化
- **THEN** 后续新通知显示新名字，但既有卡片 callback 仍按原 `requestId/accountId` 完成同一机器动作
