## Context

左侧环境栏由 renderer 根据主进程推送的完整花名册构建，状态分组、紧迫度排序和“全部启动”分别在 renderer 与 Electron 主进程中实现。当前 `fleet:startAll` 没有目标范围，主进程会遍历所有环境，因此仅在界面隐藏非目标环境不足以保证批量启动边界。

## Goals / Non-Goals

**Goals:**

- 提供“全部 / 小红书 / Facebook / 视频号”单选筛选，应用启动时默认“全部”。
- 同一份筛选结果驱动左栏列表、分组计数、空态和“全部启动”目标集合。
- 主进程按 renderer 传入的环境 ID 白名单启动，并忽略不存在或已移出的环境 ID。

**Non-Goals:**

- 不持久化筛选偏好，不改变花名册内容。
- 不改变单环境启动、暂停、恢复、关闭，也不改变“引导处理”的现有全局待处理语义。
- 不改变 Cloud 协议或账号平台事实源。

## Decisions

1. 筛选状态保存在 renderer 的 `fleetView` 中，默认值为 `all`。这是纯展示/操作范围状态，不写入设置，确保每次打开客户端都符合“默认全部”。
2. 使用既有 `normPlatform` 归一化花名册平台值，避免 `fb`、`wechat-channels` 等别名造成漏筛。筛选后的环境数组先交给既有 `fleetRailModel`，继续复用紧迫度排序与状态分组。
3. 切换筛选后若当前选中环境不在结果内，则选中第一个匹配环境；筛选结果为空时保留右侧当前环境但左栏显示该分类暂无环境，且禁用批量启动。
4. renderer 调用 `fleet:startAll` 时始终传入当前筛选结果的 `envIds`；内存确认后的 force 重试复用同一筛选范围，避免确认期间意外扩大到全花名册。
5. 主进程将可选 `envIds` 解析为集合，只从现存且未移除的句柄中选目标。未提供 `envIds` 时保留旧调用方的全量兼容行为；显式空数组则返回零目标。

## Risks / Trade-offs

- [筛选期间花名册刷新导致目标变化] → 每次点击启动时重新从当前筛选结果生成 ID，并由主进程再次对现存句柄求交集。
- [force 二次确认扩大范围] → renderer 在确认态保存首次请求的 ID，force 只重放该范围。
- [收起态空间不足] → 分类筛选仅在展开态显示；收起态仍保持窄图标条，展开后可见并操作筛选。
