# 设计：Command Pacing（指令级节奏）

## 修正记录：一次误判

初版设计是"云端下发系数档案、边缘按真实 DOM 套公式算时长"。否决理由——我当时的核心论据
"云端不知道真实内容、算不准 read_time"**站不住**：协议里 `note.detail` 早已把完整正文 `content`
与计数上报，云端评估角色本来就读它；而且云端评估完本来就要回 `interaction.like`/`navigation.back`，
**那次往返已经发生**。所以内容相关的时长应在云端算决策时一并算出、随指令下发，既不增往返，也更
符合「边轻云重」。教训固化在 §"边界判定的前置检查"。

## 修正后的边界

| 时间 | 归属 | 怎么走 |
| --- | --- | --- |
| **决策耦合的停留 / 思考**（读详情→点赞/返回、返回前 dwell、互动前 think） | **云端算中心值** | 基于已上报 `content`/计数 + 风控状态 `tempo` + 会话进度疲劳，挂在它本来就要发的指令上 |
| **最终抖动**（同一内容不出现字节级相同时序） | 边缘 | 收到中心值后叠 lognormal 噪声（§3.1） |
| **子动作运动时序**（滚动逐帧 / 鼠标贝塞尔 / 打字逐键） | 边缘 | §3.3/§3.5 执行层，云端不碰 |
| **自主微节奏 + 断连兜底** | 边缘 | 内置默认下限，永不零延迟 |

对应仓既有约定（`project.md`「边轻云重」：规划/编排/风控在云、定位/执行/拟人化执行在边）——本边界
与之一致：**"停多久"是思考（云），"怎么停"是执行（边）**。

## 时间指令（timing directive）契约

云端 → 边缘的决策指令新增可选时间字段，全部可选、缺失走边缘默认：

```jsonc
// navigation.back / note.close —— 离开页面前应达到的总停留
{ "reason": "quality_rejected", "targetPage": "feed", "dwellMs": 2200 }

// interaction.like / collect / follow / note.open —— 动作前的犹豫/感知
{ "noteId": "n123", "reason": "高质量内容", "thinkMs": 900 }
```

- `dwellMs`：从进入该页到执行本指令，**总停留**应 ≥ 此值（边缘抖动后判定实际停留是否达标，未达标则补足）。
- `thinkMs`：执行本动作**前**先等待此值（带抖动）。
- 两者均为云端算出的**中心值**；边缘叠 lognormal 抖动，避免确定性指纹。

### 云端如何算（系数收口一处）

```
读详情后的停留中心值 dwell = (base + k_text·textLen + k_img·imgCount) × tempo × fatigue(progress)
  base=1.5s, k_text≈0.18s/100字, k_img≈0.8s/图, cap≈90s      // §3.2
无价值路径：textLen 视作"扫一眼"成本 → dwell 取较小值但仍 ≥ 感知下限（治秒退）
tempo: normal=1.0 / warned≈1.3 / restricted≈1.6              // §7 状态机映射
fatigue(progress): 后段（>0.7）放大停顿                        // §3.4
```

> 系数全部留在云端，不下发。边缘只认 `dwellMs`/`thinkMs` 两个数 + 自己的抖动。

## 边缘消费

```
onCommand(cmd):
  if cmd.thinkMs:  wait( jitter(cmd.thinkMs) ) before execute      // 动作前犹豫
  if cmd.dwellMs:  ensure( pageResidence >= jitter(cmd.dwellMs) )  // 返回/关闭前停够
  else:            ensure( pageResidence >= builtinFloor )          // 无指令兜底，非零
  execute(cmd)
  // 子动作运动时序（贝塞尔/逐帧滚动/逐键）由边缘执行层自带，不受 cmd 时间字段影响
```

- **返回路径**：`navigation.back` 执行前确保详情页实际停留 ≥ `jitter(dwellMs ?? builtinFloor)`；
  有价值阅读已超过则不叠加。**这是治"秒退"的兜底核心。**
- 纯机械连续帧不挂 think/dwell。

## 极薄的会话默认（可选）

`session.budget.pacing`（可选）只放**兜底默认**，供边缘自主动作（feed 间微节奏）与断连用：

```jsonc
{ "tempo": 1.0, "dwellFloorMs": { "min": 1200, "max": 2600 } }
```

缺失则边缘用内置常量。**不放** read/pause/fatigue 系数——那些已收口云端、随指令下发。

## 降级与兼容

- 旧云端不带时间字段 / 边缘断连：边缘用内置默认下限，**绝不零延迟**，仍对返回应用下限。
- 纯增量可选字段，符合 `docs/protocol.md §5` 兼容规则（旧端忽略未知字段）。
- 风控状态变更：下次指令的中心值自带新 `tempo` 即生效；不要求会话中途热更（留后续）。

## 边界判定的前置检查（教训固化）

> 在断言"某一层缺少数据、所以计算只能放在另一层"之前，**先核对协议 / 上报契约里这层到底已经
> 拿到了什么**，以及**那次决策往返是否本就发生**。数据已在手、往返已发生时，把计算就近放到
> "数据 + 决策已经在的地方"通常更对（DRY、不增往返、符合边轻云重）。

## 非目标

- 不重设计 §3 时间模型本身（已设计 / 部分实装），只补"下发管道（指令时间字段）+ 返回兜底 + 边缘抖动收口"。
- 不做跨账号节奏协同、不做会话中途热更、不下发整套系数让边缘套公式（均否决 / 留后续）。
