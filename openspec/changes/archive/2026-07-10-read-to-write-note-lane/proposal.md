# Proposal: 发布与评论创作状态切换

## Why

Electron 客户端的浏览循环目前只呈现「刷 feed -> 选笔记 -> 阅读 -> 互动 -> 返回续刷」。当系统进入发布稿件流程时，客户端仍可能停留在阅读/互动状态，用户看不出此刻正在写笔记并准备发布；当阅读页触发评论发布时，也会被归入泛化互动，无法表达“评论创作”这个创作态。

同时，管理后台精选内容池的 `create-post` 行动作本质是参照精选内容进行洗稿创作，文案叫“写笔记”会误导概念；表格的“纳入原因/更新时刻/操作”列宽也需要调整，避免操作按钮溢出。

## What Changes

- 撤销阅读后自动判定并触发写笔记旁路的行为；普通阅读不因“强参照”自动进入发布链。
- Electron 客户端在发布稿件过程切换到 `写笔记` 状态；发布状态、人审状态和原子发布指令都只投影当前状态，不改变发布审批红线。
- Electron 客户端在阅读页进入发布评论时切换到 `评论创作` 状态；评论成功仍只在真实成功后计数。
- 管理后台精选内容池将 `写笔记` 动作文案改回 `洗稿`，成功/失败提示和确认文案同步调整。
- 精选内容池表格收窄“纳入原因”和“更新时刻”列且不折行，放宽“操作”列避免按钮溢出。

## Non-goals

- 不新增阅读后自动洗稿/自动发帖触发器。
- 不绕过已有发布审批、人审卡、失败回执和发布记录。
- 不新增边云协议字段；Electron 状态通过既有 `[ui-event]`/`loopStage` 投影。
- 不把后台“洗稿”改造成内嵌编辑器；它仍是触发生成草稿并进入人审链路。

## Impact

- **aidcp-cloud**：删除阅读后自动写笔记机会判定角色和 `read_reference` 来源；保留人工/后台参照洗稿路径。
- **aidcp-edge**：Electron loop stage 增加 `写笔记` 与 `评论创作`；发布指令与评论命令更新状态。
- **aidcp-console**：精选内容池动作改为“洗稿”，调整列宽和不折行表现，更新页面测试。
- **OpenSpec/docs**：更新 `read-to-write-note-lane` 能力说明，明确这是状态投影与后台文案修正，不是自动写稿触发器。

## Validation

- `openspec validate read-to-write-note-lane --strict`
- cloud：发布参照链相关测试与 typecheck
- edge：Electron UI event/renderer 相关测试与 typecheck
- console：精选内容池测试、typecheck、build
