## Context

`aidcp-edge` 的稿件审核详情由 `renderer.js` 根据当前账号的待审真态动态重建。配图缩略图位于 `.publish-preview-image`，右上角叠加既有删图按钮和二次确认层；页面本身仍负责审批、发布计划和版本同步。当前缩略图使用 `object-fit: cover`，适合列表浏览但会裁掉细节，也没有任何放大入口。

本变更只扩展客户端本地展示，不需要 Cloud、协议或持久化改动。Electron 当前 Chromium 已支持原生 `<dialog>`，测试基座也为 `showModal()` / `close()` 提供了兼容实现。

## Goals / Non-Goals

**Goals:**

- 双击可用缩略图时打开完整、等比缩放的大图。
- 关闭按钮、点击遮罩和 `Escape` 都能退出大图层。
- 大图层与当前稿件及当前图片绑定；切稿、离开审核页或图片被服务端真态移除后不得残留旧图。
- 不干扰既有删图角标、二次确认和审批动作。
- 用真实 DOM 回归测试覆盖打开、关闭和交互隔离。

**Non-Goals:**

- 不增加轮播、缩放手势、下载、编辑或图片增补。
- 不改变缩略图布局、图片 URL、删图写链路、稿件版本或审批载荷。
- 不构建或发布桌面安装包。

## Decisions

1. **使用单一原生 `<dialog>` 作为大图层。** 页面只保留一个复用实例，打开时写入当前图片 URL、替代文本与稿件记录 ID。相比为每张图片生成独立浮层，单实例减少重复 DOM 和事件监听；相比普通 fixed `div`，`dialog` 原生提供模态焦点与 `Escape` 语义。

2. **双击监听只挂在实际 `<img>` 上。** 删除按钮与确认层是缩略图容器内的独立交互；不在父容器监听可避免双击删图控件时误开大图。缩略图增加 `zoom-in` 光标和“配图 N，双击查看大图”的可访问说明，单击行为保持不变。

3. **大图状态绑定服务端稿件真态。** 打开时记录 `recordId` 与 URL；每次稿件审核重绘时，只要当前稿件变化、图片不再存在或审核上下文消失，就关闭并清空大图。关闭审核页也显式关闭大图层，避免旧图片跨账号或跨稿件残留。

4. **大图使用 `object-fit: contain` 并限制在视口内。** 对话框本身使用深色遮罩，大图最大宽高随窗口收缩；不放大写入新资源，也不改变原图请求方式。加载失败沿用浏览器图片失败真态，不伪造成功占位。

## Risks / Trade-offs

- **[双击与删图控件事件冒泡冲突]** → 只监听 `<img>` 的 `dblclick`，测试断言删除按钮仍只进入既有确认态。
- **[状态推送后仍展示旧稿件图片]** → 以 `recordId + URL` 对当前真态做同步校验，并在审核页关闭时显式清理。
- **[超大图片撑破窗口]** → 使用视口上限和 `object-fit: contain`，对话框内容不产生横向滚动。
- **[原生 dialog 在 jsdom 行为不完整]** → 复用现有测试基座的 dialog polyfill，仅断言项目实际依赖的 open/close 状态和 DOM 内容。
