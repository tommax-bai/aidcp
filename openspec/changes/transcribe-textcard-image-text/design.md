## Context

小红书文字卡笔记的内容渲染在图片里，DOM 正文常薄或空。当前实现（直读坐实）：

- 边缘抓取每图只存 `{index, url, width, height, alt}`（`aidcp-edge/src/browse/note-extractor.ts:37,233-242`），alt 基本为空，**无任何 OCR/视觉**。
- 保真改写只把 DOM 正文喂给文本模型（`aidcp-cloud/src/publish-agent/prompts.ts:106` 的 `referenceNoteBlock` 拼 `referenceNote.body`），图片只经 `reference-image-guidance.ts:29-33` 作为「仅视觉参考、勿复制」的 URL 串进入**出图**路径，文本模型永不见像素。保真链禁新增（`prompts.ts:117-118,197,239-242`），故源薄则输出必薄。
- 精选准入按 DOM 正文判丰富度（`curated-inspiration-corpus` 的「正文进精选评估角色」要求），且**只写非空正文**（`aidcp-cloud/src/cache/curated-content-store.ts:10`）；空正文改写触发返 `empty_body`（`server.ts:2773`），另有拒因 `image_text_only`（`panel-server.ts:1743`）。→ 内容全在图里的文字卡直接被挡在池外，改写永远够不到。
- 系统已有**可复用的云端多模态出口** `OpenAiCompatVisionClient`（`aidcp-cloud/src/llm/vision.ts`，文件头自陈是「后续多模态需求的共享缝」）与**封面形态判定** `cover-form-sensor`（`cover-form-sensor.ts`：判 `text_card/photo/illustration/other`，按抓取锚 `detectedFor===capturedAt` 缓存、诚实降级、可回写素材行，prompt 刻意「不要输出图中的具体文字」防搬运）。
- OSS 转存已作为 merged spec 存在（`cloud-oss-storage`），参照图 `ossUrl` 优先（`cover-form-sensor.ts:92-96`）。

约束：边轻云重、MUST NOT 静默假成功、协议四处同步 + 主动命令白名单、单次模型调用 180s + 发布看门狗、国产 VL 模型下架潮需 env 可换、无 DB 迁移器（schema 启动自建）。

## Goals / Non-Goals

**Goals:**
- 让文字卡笔记的**图内文字**成为系统可见的内容，从而：准入丰富度评估判到真内容（不误杀）、保真改写吃到真内容（不产出薄稿）。
- 复用既有形态判定与视觉出口，**零协议改动、零边缘改动、零新增凭据面**。
- 成本可控：仅文字卡付费、一次批量调用、按锚缓存、旗标 + 影子先行。
- 诚实：转写失败诚实降级，绝不编造、绝不把假内容注入改写。

**Non-Goals:**
- 不做边缘/本地 OCR（准确率与工程成本不划算，见 Decisions）。
- 不改协议、不改边缘抓取结构。
- 不修边缘「>18 静默截断 / 18=平台上界过时」（归属活跃 change `curated-reference-images`，剥离）。
- 不把转写文字直接印到生成的文字卡上（防搬运）。
- 不做历史存量回填（forward-only）。

## Decisions

### D1：OCR 放**云端**，不放边缘
- **选择**：云端视觉大模型转写。
- **理由**：① 边缘/本地开源 OCR（PaddleOCR mobile / tesseract.js）在花体文字卡上准确率从印刷体 ~0.90 塌到 ~0.58，恰好读不准承载信息的花体标题——与「内容要丰富」的目标直接冲突；② 边缘方案要新增上报字段 → 触发协议四处同步 + 主动命令白名单坑，还要往安装包塞识别引擎、占运营机 CPU；③ 云端已有可复用视觉出口、诚实降级、零新增凭据。
- **备选（否决）**：边缘本地 OCR（准确率+协议+包体三重不划算）；专用云 OCR API（百度/阿里/腾讯通用文字识别——花体版面返回碎块乱序、无版面还原、且不支持多图批量，工具不对；至多后续作 bbox grounding 辅助）。

### D2：转写放**准入时**，不只放改写时
- **选择**：在精选观测到达云端、落库前后做转写（准入链）。
- **理由**：空正文文字卡今日在准入即被 `empty_body`/`image_text_only` 挡在池外（`server.ts:2773`、`panel-server.ts:1743`、`curated-content-store.ts:10`），只在改写时补 OCR 根本够不到它们；准入时转写让**评估**与**改写**同时吃到真内容，一次转写两处受益。
- **备选（否决）**：仅改写时转写——省一点钱，但漏掉被准入挡下的整类文字卡，且准入评估仍盲。

### D3：**门控**——仅 `form === 'text_card'` 才转写
- **选择**：复用 `cover-form-sensor` 的形态判定当开关；photo/illustration/other 不转写。
- **理由**：把成本收敛到真正需要的笔记；照片笔记零转写成本。形态判定已缓存，不重复付费。
- **实现要点**：转写与形态判定是**两次独立调用**（保形态判定原有的「不输出图中文字」结构隔离），转写是新角色/新 prompt。

### D4：**模型 `qwen-vl-ocr` 默认**，env 可换，`qwen-vl-max` 升级备选
- **选择**：默认 `qwen-vl-ocr`（VL OCR 专精、性价比最高 ≈¥0.006/note），`AIDCP_TEXTCARD_OCR_MODEL` 覆盖，`qwen-vl-max`（≈¥0.067/note）为难卡升级档。经 `vision.ts` 出口调用（env→代码默认解析在装配处，客户端不回落文本模型）。
- **理由**：门控后成本量级几元/天以内，成本非决策变量、质量才是；真价以百炼控制台为准（~¥0.3/M vs 传闻旧 ¥5/M，均可忽略）。上线前用 20–30 张真卡 A/B ocr vs max 定默认。
- **实现要点**：一条笔记的全部文字卡图**合并成一次调用**（视觉 token 相加、省一次往返）；把输出上限提到 8192，防 9 张密卡撞 4096 默认上限。

### D5：**数据模型**——转写文字并入 `body`，另存 provenance 列（收敛 blast radius）
- **选择**：`curated_content` 新增列承载转写文字 `image_text` 与转写元数据（锚 `transcribedFor===capturedAt`、模型、时刻、来源标记）；**旗标启用后，准入把转写文字并入该行的内容 `body`**（DOM 正文在前、转写文字在后），schema 启动自建（无迁移器）。
- **理由（关键）**：系统里「正文为空 = 无内容」这一等价被烙进多处 merged 要求——改写触发闸（`curated-note-actions` 的「正文为空的壳行 MUST 以 empty_body 拒绝」）、参照模式闸（`curated-inspiration-corpus:203`「参照笔记正文为空时 MUST 拒绝触发」）、空正文壳行清理（`panel-curated-content:58`）。若转写文字只存独立列、让每个消费端各自 `body + image_text` 合并，则上述每处空正文判定都要改、blast radius 大且易漏。改为**在准入把转写文字并入 `body`**，则一条被转写的文字卡「不再是空正文」，所有下游空正文语义**无需改动即自动正确**（评估读全文即读到转写文字、改写读到、闸不再误拒、清理不再误删）。缓存锚沿用 formGuess「重抓必变、零 TTL」范式避免重复付费。
- **provenance / 影子**：`image_text` 列始终保留原始转写（便于观测与影子对比 + 来源可追溯）；影子期只写 `image_text`、**不**并入 `body`（下游零感知）；启用后才并入 `body`。
- **消费**：改写侧转写文字随 `body` 进保真改写**源料**（`referenceNoteBlock`），由既有 分析→规划→改写→忠实审核 链改写去重，**MUST NOT 逐字直贴到生成卡**。
- **备选（否决）**：独立列 + 消费端合并——provenance 更干净，但触及 4+ 处空正文闸/清理判定、blast radius 大、易漏而生矛盾，故否决。

### D6：**诚实降级 + 旗标 + 影子**
- 转写失败/超时/解析失败 → 跳过并标记，绝不编造、绝不用假内容填充改写、绝不阻断准入或发布（沿 `cover-form-sensor` 的「error 绝不持久化、绝不猜、绝不抛」）。
- 默认旗标 off（`AIDCP_TEXTCARD_OCR` 暂名）；影子期先「转写 + 落库 + 观测」不改评估/改写取数，验证后再放量。秒级可回滚。

## Risks / Trade-offs

- **[花体 VL 转写仍可能漏字/幻觉]** → 只走保真改写链（改写 + 忠实审核会拦未支持声明）；A/B 选模型；低置信可在消费端按需过滤（存观测不存策略）。
- **[9 张密卡输出撞 4096 上限]** → max_tokens=8192 或按图分批；密卡估 ~4k 输出。
- **[批量多图调用延迟数十秒、无官方 SLA]** → 后台管线不卡用户；内层超时闸 + 180s 上限 + 看门狗；按锚缓存复用。
- **[qwen-vl-ocr 真价不确定]** → 上线前控制台核实 SKU；即便旧价 ≈¥0.085/note 仍可忽略；token 记账入表监控。
- **[防搬运——转写文字逐字泄漏]** → 转写只入改写源料、经忠实审核改写去重；与形态判定分开调用；绝不进生成卡文案。
- **[URL 过期]** → 转写读的是出图模型同批消费的参照 URL、同一时间窗，不新增暴露；`ossUrl` 优先（OSS 已 merged）。
- **[准入放宽误纳广告文字卡]** → 门控只决定「是否转写」，纳入仍由既有相关性 + 共鸣 + 模型丰富度评估把关，转写只是让评估看到真内容。

## Migration Plan

1. 加列（启动自建）+ 转写服务 + 门控接线，旗标默认 off，全绿再部署 dev。
2. 开旗标进入影子期：转写 + 落库 + 记账，不改评估/改写取数；核花体转写质量与成本/延迟。
3. 影子通过 → 切「有效内容」供评估与改写消费；观察准入纳入率与改写丰富度。
4. **回滚**：旗标 off 即停转写与消费，新列惰性留存无副作用；模型异常 env 换名重启。

## Open Questions

- `qwen-vl-ocr` vs `qwen-vl-max` 谁在花体上更准——研究未定，上线前 20–30 张真卡 A/B 定默认。
- DOM 正文非空但很薄的文字卡：一律按 form 门控转写并合并（倾向此，简单），还是加正文长度阈值只在够薄时转写（省钱但多一个魔数）——影子期数据定。
- 转写接受的置信/质量门槛是否需要，阈值放消费端还是转写端。
- 转写角色是否需登记 `role-catalog` 供后台配模型（倾向仅记账、模型走 env，避免 enum drift 白屏面）。
