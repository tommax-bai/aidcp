## Context

边缘客户端是一个 Electron 外壳（监督者），按 AdsPower 花名册为每个分身派生一个受监督的核心子进程；每个核心在启动时读环境变量 `AIDCP_CLOUD_URL` 决定连哪个云端 WS（`aidcp-edge/src/main.ts:113`，缺省 `ws://121.89.85.150:8787` 即 dev）。外壳派生核心时把自身进程环境整份继承下去（`src/electron/main.cjs:1086-1090` → `fleet.buildEnvSpawnEnv` 内 `{ ...providerEnv, ...processEnv }`），`AIDCP_CLOUD_URL` 不在被剔除的身份键白名单里（`fleet.cjs:79-84`），因此原样流入每个核心。**净效果：整个 GUI 连哪个云由启动该 GUI 时的环境变量一把决定，界面无入口可改。**

现成基建可复用：设置持久化 `userData/settings.json`（`main.cjs:110-186`）、设置抽屉界面（`renderer/index.html:446-516`，内已有「按新设置重启」按钮 `apply-restart` → `edge:restart` → `stopAndRestart`，`main.cjs:2089-2094`）、每环境「云端连接」状态徽标（按核心实际连接如实更新）。

约束：① 云端地址只在核心启动时读一次，运行中无法热切，只能靠重启换云；② dev=测试、ol=生产，误连代价不对称；③ 花名册（分身/edgeId）与云无关、物理浏览器就一套，切云不动本地账号/风控状态（那些在云端侧）；④ 不得破坏「静默假成功」红线——显示的云端必须等于实际连接的云端。

## Goals / Non-Goals

**Goals:**
- 运营人员在设置里自助选择所连云端（dev / ol / 自定义），无需环境变量。
- 界面常驻显示当前连的是哪个云，且与核心实际连接一致。
- 切换云端有明确、诚实的生效路径（显式重启），ol 有防误操作确认。
- 对现有「以 `AIDCP_CLOUD_URL` 启动」的 dev 流程零回归。

**Non-Goals:**
- 不做运行中热切云端（物理不可，核心启动时读一次）。
- 不做同一 GUI 内按分身混连不同云（并行 dev+ol 走既有「两 GUI + 独立数据目录」change `edge-multi-instance-isolation`）。
- 不改协议 / 云端 / 单实例锁 / 分身租约。

## Decisions

### D1 — 存名 + 一处地址映射，而非直接存裸 URL
`settings.json` 存 `cloudEnvKey`（`'dev' | 'ol' | 'custom' | ''`，默认 `''`）+ `cloudUrlCustom`（仅 custom 用）。两个正式地址收在 edge 内一处映射常量（dev/ol），key→URL 由该表解析。
- **为何**：便于界面显示「dev/ol(线上)」友好名与醒目标注；两个 canonical 地址一处真源（现在 dev 缺省散在 `main.ts`）；custom 仍支持任意地址逃生。
- **备选**：只存裸 URL——丢失「这是 dev 还是 ol」的语义，界面无法可靠地对 ol 做醒目/确认，弃。

### D2 — 解析优先级：界面选择 > 启动环境变量 > 缺省 dev
派生核心时解析权威云端地址：`cloudEnvKey` 非空 → 用映射/custom 解析出的 URL，并在 `buildEnvSpawnEnv` 产物上**显式钉** `AIDCP_CLOUD_URL`（压过继承来的同名变量），adspower 与 self 两路都钉；`cloudEnvKey` 为空 `''` → **不注入**，完全走现有「继承环境变量 / 缺省」路径。
- **为何**：留空即零回归（现有 dev 启动脚本设了环境变量、界面没选 → 行为逐字不变）；一旦界面显式选择即以之为权威（运营预期）。开发者想用环境变量逃生阀，把界面留空即可。
- **关键实现点**：因为现有合并是 `{ ...providerEnv, ...processEnv }`（继承的 `processEnv` 会压过 `providerEnv`），所以**不能**只把地址塞进 `providerEnv`——必须在合并之后对最终 spawn env 显式赋值一次，否则界面选择会被继承的环境变量吃掉。
- **备选（弃）**：环境变量硬优先于界面（传统逃生阀语义）——会让打包版运营人员的界面选择在某些启动方式下「点了不生效」，违背此功能初衷。若未来需要锁定部署，可加 `AIDCP_CLOUD_URL_LOCK` 显式强制，YAGNI 暂不做。

### D3 — 保存持久化、显式重启才生效（复用既有范式）
保存云端选择只写盘、不打断在跑核心（与 `main.cjs:2073` 现语义一致）。切换后界面提示「需重启运行中的环境才生效」，并提供「全部重启并连接新云端」一键（复用 `fleet:stopAll` + `startAll`）；每环境的「按新设置重启」也适用。
- **为何**：地址只在核心启动时读，重启是唯一物理生效方式；诚实告知、不假装即时切换。全量重启避免裂脑（见 R1）。

### D4 — 当前云端常驻可见 + 与实际连接一致（红线）
顶部在「云端连接」徽标旁常驻显示「当前云端：dev / ol(线上) / 自定义」。**显示值取「核心实际连接的云端」，不是「已保存的选择」**：已保存新选择但尚未重启时，显示为「目标 X · 待重启生效」，绝不显示成已切换。ol 用醒目色。
- **为何**：防止在 dev 界面误操作到 ol 生产（或反之）；贴合项目「绝不静默假成功」不变量。

### D5 — ol 二次确认
在界面把选择切到 ol 时弹一次确认（「将连接线上生产云端 ol，确认？」）。
- **为何**：ol=生产，误连代价高；贴合项目「ol 只在明确要求时才碰」的一贯谨慎。

## Risks / Trade-offs

- **R1 裂脑（一半核心连 dev、一半连 ol）** → 切换生效走「全环境重启」而非逐个；未重启的环境按 D4 显示为「待重启生效」，其「云端连接」徽标仍如实反映旧连接，操作员一眼可辨。
- **R2 「上次发布」跨云串味**：`ui-state` 的「上次发布」按分身记、不分云，切云后可能显示另一云的旧发布记录 → 低影响；本 change 先不动（可在后续按云清理），登记真机验收观察。
- **R3 custom 地址填错/不可达** → 核心连不上会如实进「未连接」态（现有行为），不静默假成功；界面对明显非法输入（非 `ws(s)://`）做基本校验并诚实回错。
- **R4 环境变量启动 + 界面又选了** → 按 D2，界面选择优先；D4 的「当前云端」常驻显示确保无论谁赢都与实际一致、可见，消除困惑。
- **R5 与多实例并行的交互** → 两 GUI 各自独立 `settings.json`（`edge-multi-instance-isolation` 的 `AIDCP_USER_DATA_DIR`），各自云端选择互不影响；正交无冲突。

## Migration Plan

- 纯 edge、无云端/ECS、无数据迁移。`settings.json` 新增字段默认 `''` → 老配置加载即零回归。
- 回滚：字段留空或回退代码即恢复「纯环境变量决定云端」旧行为；无破坏性数据变更。
- 部署：edge-only，无 ECS 部署步骤；随下次安装包分发。真机验收登记 backlog（切 dev/ol/custom、重启生效、当前云端显示一致、ol 确认、并行两 GUI 各自选择独立）。
