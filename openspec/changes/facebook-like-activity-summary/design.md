## Context

Edge 的 `FacebookBrowseSession` 已为“读”事件把 `NoteDetailPayload` 格式化成作者 + 正文/标题开头，但已确认的点赞仍固定输出“点了个赞”。点赞执行器在后置校验成功后会从被标记的真实目标帖子读取 `FacebookLikeObservation`，其中已有 `author` 与 `textPreviewHead`，因此缺口只在本地 UI 投影。

关键约束是不能用“最近读过的帖子”猜点赞对象：Facebook 支持 feed 就地点赞，且页面可能重排。摘要必须绑定实际被作用帖子，字段缺失时保持通用文案。

## Goals / Non-Goals

**Goals:**

- 已确认 Facebook 点赞的活动流展示作者与正文/标题开头。
- 摘要来源绑定点赞执行器的页面派生见证，避免串稿。
- 与“读”使用相同的空白规范化、单行截断和诚实降级原则。
- 保持成功计数和失败/shadow 不生成成功事件的现有语义。

**Non-Goals:**

- 不改变点赞目标选择、点击、后置校验、归账或风险控制。
- 不新增或修改 edge/cloud 协议字段。
- 不通过历史缓存、原始 ID 或链接补齐缺失文案。
- 不打包或发布 Electron 安装包。

## Decisions

1. **直接使用成功结果的 `FacebookLikeObservation`。** 它是在实际被作用的标记帖子上现读，能同时覆盖 feed 和 detail 作用面。备选方案“缓存最近 `note.detail`”会在就地点赞、页面重排或命令交错时串稿，因此不采用。
2. **在 `FacebookBrowseSession` 内生成活动流文案。** 现有 Facebook “读”和“赞”结构化事件都在这里发射；主进程与渲染器已经透传 `sentence`，无需扩散改动。
3. **复用既有截断规则并单独定义点赞措辞。** 作者限制 18 个字符，正文/标题开头限制 24 个字符；两者齐全时显示 `赞了「摘要」 · 作者`，单字段时部分展示，都缺失时回退 `点了个赞`。
4. **仅在 `ok:true` 后发射。** shadow、失败、已点赞、无目标等路径继续不产生成功活动或本地计数。

## Risks / Trade-offs

- [Facebook DOM 未读到作者或正文] → 使用部分字段或通用“点了个赞”，不展示 ID/链接、不猜测。
- [摘要只是正文开头而非独立标题] → Facebook 帖子通常没有独立标题，与当前“读”保持同一口径；UI 将其作为可辨识的稿件摘要展示。
- [主进程旧日志兜底仍可能产生通用文案] → 本变更只增强当前 Facebook 结构化事件；旧版本兼容路径保持不变。

## Migration Plan

无需数据迁移。Edge 源码通过测试后合入 `master`；若需回滚，只需恢复本地文案格式化与对应测试，不影响云端状态或协议兼容。
