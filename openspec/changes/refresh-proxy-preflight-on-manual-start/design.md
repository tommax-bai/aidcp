## Context

Electron 的代理预检控制器按环境缓存最近一次确定结果两分钟，成功与失败都可被后续 `ensureNetworkPreparation()` 复用。这个策略适合环境选择预热和自动唤醒，但单环境主按钮的 `edge:start` 也是同一个消费入口：用户看到“代理不可用”后再次明确点击“启动”，可能立即命中旧失败，根本没有发起新的网络探测。

一次启动内部会在前置准备和真正 spawn 前重复确认网络。手动点击需要使第一次确认取得新证据，同时仍应让同一次启动的后续确认复用这份结果，避免重复探测。

## Goals / Non-Goals

**Goals:**

- 每次单环境显式“启动”都绕过点击前已经完成的代理预检缓存；点击时已有真实检测在途则等待该单飞结果。
- 只作废该环境的预检证据，不改变代理配置、Cloud 权威 revision 或其他环境缓存。
- 保持同一次启动内部的单飞与短时复用。
- 保持自动唤醒、选择预热和批量启动的既有缓存与退避行为。

**Non-Goals:**

- 不增加代理专用后台轮询、自动重启或新的重试参数。
- 不改变 Active 浏览器出口相等闸、`no_proxy` 旁路或失败分类。
- 不改变 Cloud、协议、数据库或 AdsPower profile 配置。
- 不构建或安装 Edge 客户端。

## Decisions

### 1. 在单环境 `edge:start` IPC 边界作废已完成的预检证据

主进程在解析到目标 handle 后、确认将进入待机唤醒或普通启动分支时检查该环境的预检快照：若没有检测在途，则调用 `proxyPreflight.invalidate(envId)`；若已经是 `checking`，则保留并等待这份真实单飞请求。这是唯一能准确表达“用户这次明确重试”的边界；自动唤醒、排队回调和 spawn 内部不知道最初触发来源，不应自行猜测是否强制刷新。

未选择给 `ensureNetworkPreparation()` 及整条启动调用图增加 `force` 参数，因为启动内部存在多次确认。若每一层都携带或误用 `force`，同一次点击可能重复探测；入口只失效一次后，第一次 `ensure` 取得新结果，后续 `ensure` 自然复用。

未取消点击时已经在途的预热请求。控制器当前的 `invalidate()` 会使旧 promise 返回 `unknown/superseded`；该结果按既有规则不是阻断结论，取消后可能让已经等待旧请求的自动路径继续启动，同时手动路径另起一次检测。保留在途单飞既满足“点击启动时真实重新检测/等待检测”的用户预期，也避免制造并发请求和未知结果旁路。

### 2. 失效只影响预检缓存，不修改代理权威或链路配置

对于已经完成的结果，`invalidate()` 删除该环境的内存预检 entry。下一次 `ensureNetworkPreparation()` 仍按现有流程重新读取当前 Cloud 权威 revision、准备所需代理链并探测。对于点击时已经在途的结果，下一次准备复用相同 promise；若 Cloud authority revision 已变化，既有权威检查仍会按原规则失效旧证据并启动新检测。

不额外失效 Cloud 代理权威或受管链路；用户只是要求重新检测连通性，不代表配置发生变化。配置保存与系统前置代理切换继续使用它们现有的更广失效流程。

### 3. 仅单环境显式启动采用强制刷新

本变更只改变主按钮的 `edge:start`。环境选择预热、Cloud 命令唤醒、定时唤醒和“全部启动”继续按现有 TTL/单飞规则运行，避免批量操作同时绕过缓存造成不必要的代理探测放大。

错误态的“启动”重试与普通停止态的“启动”均走同一 IPC，因此无需按历史失败原因增加兼容分支。`no_proxy` 环境即使 entry 被失效，后续仍由既有规则立即跳过检测。

## Risks / Trade-offs

- [点击时已有选择预热在途] → 手动启动等待同一真实单飞检测；Cloud authority revision 变化仍由既有失效规则触发新检测。
- [用户频繁重复点击可能增加探测] → 生命周期按钮和启动队列已有 pending/幂等保护；每次真正的新显式启动最多强制一轮。
- [批量启动仍可能复用旧失败] → 这是刻意保持的现有批量行为；本需求只授权单环境“启动”按钮。

## Migration Plan

1. 在隔离 Edge worktree 修改单环境启动 IPC并增加聚焦测试。
2. 运行代理预检、生命周期聚焦测试、完整测试和 typecheck。
3. 严格校验 OpenSpec，提交并快进集成 Edge `master` 与 control `main`，随后推送。
4. 不制作安装包；回滚只需回退 Edge 与 control 对应提交。
