## MODIFIED Requirements

### Requirement: 本能力覆盖发帖、评论与群评，声明已知缺口

本能力 SHALL 覆盖定时自动**发帖**、定时自动**评论**与定时自动**群评**（带群组引流码的评论；群评带独占刹车：尝试型持久日上限（硬 ≤10）、一码一号群码闸（**无码硬拒、共用放行 + 风险提示**）、单飞共用评论机器、自动路径配额）。本能力 SHALL 在文档中声明已知缺口：多账号默认共用同一张全局内容格 → 小时级活跃模式逐位相同、协同指纹残留（分钟错峰只在小时内打散）；评论 / 群评目标甄选当前仅首屏、命中率有限（有界翻页归 `comment-search-command` 家族的后续变更）；群码共用放行后（一码一号从硬阻断放松为放行 + 提示），「多账号共用同一码或各自的码在同段时间高频出现」是行为面与指纹面信号，靠小日上限 + 错峰 + 人审 + 开启时明示风险提示压制、诚实声明非零风险。

#### Scenario: 群评带刹车纳入
- **WHEN** 运营为某账号开启自动群评
- **THEN** 开启须过群码闸（无码 → 硬拒；群码与其它账号共用 → 放行但回带风险警告，绝不静默），运行受尝试型日上限 / 错峰 / 人审约束；无码放行、或共用静默放行（不回警告）、或任一运行刹车缺失，均判为违背本能力

#### Scenario: 已知缺口有声明
- **WHEN** 审阅本变更的风控残留
- **THEN** 设计文档已明写「小时级协同指纹」「首屏甄选命中率」「共用群码放行后的指纹残留」为已知缺口及其压制手段
