## ADDED Requirements

### Requirement: 环境栏 SHALL 支持按当前筛选范围全部关闭

客户端左侧环境栏 SHALL 提供“全部关闭”入口，并 SHALL 以当前平台筛选后的环境集合为请求范围。主进程 MUST 以实时环境句柄再次收口目标，并对每个目标执行与单环境“关闭”相同的自动化引擎和本机所拥有浏览器收口语义；MUST NOT 复用“全部暂停”、删除环境、关闭客户端或触碰其他机器 / 外部占用的浏览器。批量回执仅表示关闭请求已受理，MUST NOT 在各环境终态确认前宣称全部关闭完成。

#### Scenario: 在 Facebook 筛选下全部关闭

- **WHEN** 用户选择 Facebook 筛选并点击“全部关闭”
- **THEN** renderer 只提交筛选内 envId，主进程只关闭仍存在且属于该集合的环境，并让其他平台环境保持不变

#### Scenario: 批量关闭包含在途环境

- **WHEN** 目标集合包含运行中、启动排队、暂停和已关闭环境
- **THEN** 主进程逐环境应用单环境关闭语义、清理后续自动复活意图，并由各环境状态分别报告关闭中、已关闭或关闭未确认

## MODIFIED Requirements

### Requirement: 打开真实浏览器窗口为尽力抬前、抬不动 MUST 诚实告知

主界面 / 环境栏 / 引导流的“打开窗口”SHALL 尽力请求该环境的浏览器窗口前置，并以窗口错位摆放 + 行↔窗口同名 / 同色让窗口与环境行可对应。请求成功只证明控制指令已被目标核心接受，界面 SHALL 保持安静且 MUST NOT 展示“已前置”、窗口停放位置或系统窗口切换器说明；请求无法送达时 SHALL 显示该环境的真实失败原因，MUST NOT 假装窗口已抬前。

#### Scenario: 前置请求成功时不展示说明

- **WHEN** 运维对某环境发起窗口前置且目标核心接受控制指令
- **THEN** 界面更新该环境的窗口显示相位但不展示前置成功、停放位置或系统窗口切换器说明

#### Scenario: 前置请求失败时诚实告知

- **WHEN** 运维对某环境发起窗口前置但引擎未运行、浏览器未就绪或指令写入失败
- **THEN** 界面显示目标环境的真实失败原因，MUST NOT 无声假装已抬到最前

### Requirement: 自动化控制与浏览器窗口控制 SHALL 是独立用户意图

客户端 SHALL 分别提供“开始/暂停自动化”和“打开/关闭浏览器”意图；客户登录后的核心在线不再要求点击“启动环境”。非自动化入口 SHALL 只提示其真实绑定、客户鉴权或 Cloud 前置，MUST NOT 显示“请先启动浏览器”“等待浏览器槽位”或把打开浏览器作为修复动作。人工登录/验证等确需页面的场景 SHALL 明确说明其浏览器目的。任务已关闭且浏览器关闭时，用户点击“打开浏览器”后 UI SHALL 在任何客户接口或 Cloud 握手等待前显示处理中状态；主进程 SHALL 后台完成可信绑定 bootstrap、槽位准入和浏览器唤醒，并 MUST NOT 在真实就绪前显示打开成功。

#### Scenario: 浏览器关闭时打开人设向导

- **WHEN** 客户已登录且环境绑定可信、浏览器关闭
- **THEN** 人设向导正常读取和提交，不显示启动浏览器引导

#### Scenario: 人工验证需要浏览器

- **WHEN** 平台 API 或页面身份明确返回需要人工登录/验证码恢复
- **THEN** UI 可提出“打开浏览器完成验证”，并 SHALL 将其标记为鉴权恢复，不得把所有非自动化操作一并阻塞

#### Scenario: 任务关闭后手动打开浏览器

- **WHEN** 当前环境自动化已停止、浏览器已关闭且用户点击“打开浏览器”
- **THEN** 按钮与状态在首个异步等待前显示“正在打开浏览器”，后台链按可信绑定和槽位规则启动，最终以真实就绪或失败状态收敛
