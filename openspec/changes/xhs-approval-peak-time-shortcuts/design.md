## Context

客户端审批详情已经能把 `publishMode/publishTime` 随批准动作提交，并由 Cloud 在同一版本闸内校验；但入口缺少单稿路径的明确契约，也没有常用时间快捷选择。当前待审列表只含 `pending_approval`，一篇稿件批准后即不再是可靠的占用来源，因此“空闲”不能由 renderer 猜测当前列表得到。

这次变更跨 `aidcp-edge` 与 `aidcp-cloud`，但不改变发布协议、数据库结构或平台提交链。Cloud 仍是账号归属和已确认排期真态的权威；renderer 只负责纯时间计算与显式选择交互。

## Goals / Non-Goals

**Goals:**

- 单稿和多稿审批详情稳定展示同一套小红书定时发布入口。
- 用两个紧凑按钮快速回填每日 `08:00 / 12:00 / 18:00` 的北京时间。
- 让“空闲”按账号、北京时间自然小时和真实 `scheduled` 记录判断，并覆盖连续审批中的短暂回写窗口。
- 保持按钮为纯选择动作，批准仍只能由现有主按钮显式触发。
- 在旧 Cloud 或占用读取失败时诚实降级：普通热门时段仍可选，空闲判断不可用时不冒充“空闲”。

**Non-Goals:**

- 自动批准、自动提交或批量安排稿件。
- 改变热门时段配置、引入用户自定义时段或跨账号共享占用。
- 更改 1 小时至 14 天窗口、原生小红书发布序列、对账或风险记账。
- 构建或发布 Electron 安装包。

## Decisions

### 以当前选择为游标计算下一个热门时段

纯逻辑模块新增热门小时常量与选择函数。搜索起点至少为 `now + 1h`；有效输入晚于该起点时，以当前输入为游标。当前输入恰好落在热门整点时，下一次点击前进到后一个时段；输入为 `08:15` 时则前进到 `12:00`。这样既支持一次快速定位，也支持连续点击顺序浏览，且结果始终使用上海时区而不依赖操作系统时区。

候选必须仍在 `now + 14d` 内；无候选时保持原值并显示原因。把算法放在 `publish-review-logic.js` 而不是 DOM 回调中，便于直接覆盖跨日、整点、分钟占用与窗口边界测试。

### 以北京时间小时键统一判占用

占用键使用 `YYYY-MM-DDTHH`，分钟和秒不参与区分，因此 `08:00` 与 `08:15` 同属一个时段。Cloud 返回时间戳，renderer 统一转成上海小时键；避免前后端各自拼装本地时区字符串造成漂移。

“下个热门时段”忽略占用；“下个空闲时段”在同一候选序列上跳过占用键。按钮文案分别为“下个热门时段”和“下个空闲时段”，与已有次级按钮风格一致，不新增弹窗。

### 新增独立的客户只读占用接口

Cloud customer-auth 新增账号归属收口的 `GET /publish-schedule/occupied-hours?envKey=...`。服务端从客户会话与环境绑定解析账号，只查询该账号、小红书、`status='scheduled'`、Cloud 当前时刻至 14 天内的 `scheduled_at`，并通过显式 DTO 只返回时间戳数组。renderer 不得提交 accountId、任意 URL、token 或查询窗口。

采用独立接口而不是扩展待审列表，避免占用读取失败拖垮稿件审批，也避免把已排期记录伪装成待审列表成员。Electron main/preload 只暴露具名 IPC；审批页打开时与稿件读取并行加载。

### 本次会话的已受理排期作为临时保留

Cloud 只有在平台已接受定时任务后才把记录写为 `scheduled`。连续审批时，前一篇“批准受理”到该真态回写之间存在短窗口。renderer 在现有批准请求成功且计划为 scheduled 后，将所选时间加入当前环境的会话保留集合；空闲计算取 Cloud 真态与该集合的并集。

该集合不等同于平台成功证据，也不改变任何状态文案。它只保守地避免本次会话立刻复用同一小时；应用重启后仍以 Cloud `scheduled` 真态为准。

### 读取失败时不伪造空闲

占用接口未提供、失败或返回畸形数据时，“下个空闲时段”禁用并说明暂时无法判断；“下个热门时段”和手动时间输入保持可用。按钮点击只改 `publishTimeInput`、触发现有计划校验与按钮文案同步，不调用 `publishApproval`。

## Risks / Trade-offs

- [Risk] 刚受理的定时发布之后执行失败，会在当前 renderer 会话内留下保守占用。→ 只造成跳过一个时段，不会重复发布；重开页面/客户端后由 Cloud 真态纠正。
- [Risk] `scheduled` 查询增加一次轻量数据库范围读。→ 收口到单账号、单状态、未来 14 天和现有 `scheduled_at` 字段，只返回时间戳；与待审列表独立失败。
- [Risk] 用户误解快捷按钮会直接发布。→ 按钮放在时间输入内作为次级控件，辅助文案明确“仅选择时间，仍需点击批准”，且测试断言不产生审批 RPC。
- [Risk] 旧 Cloud 无新接口。→ 普通热门时段和手动输入继续工作；空闲按钮 fail-closed 禁用。

## Migration Plan

1. 先部署兼容性的 Cloud 客户只读接口和存储查询。
2. 再推送 Edge 源码；新客户端连接旧 Cloud 时按不可用状态降级。
3. 分别运行 Cloud 聚焦测试/全套测试/typecheck 与 Edge renderer/IPC 测试/typecheck，严格校验 OpenSpec。
4. 回滚 Edge 只会移除快捷按钮；回滚 Cloud 只会令新客户端禁用空闲按钮，不影响审批或发布主链。
