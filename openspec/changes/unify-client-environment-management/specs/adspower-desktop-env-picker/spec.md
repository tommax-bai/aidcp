## MODIFIED Requirements

### Requirement: 环境管理经左栏管理入口统一承载、设置抽屉保持精简

多环境下，AdsPower 环境管理 SHALL 经左侧环境栏的“环境管理”入口收口于独立浮层，MUST NOT 回到全局设置抽屉。浮层 SHALL 只使用“环境 / 新建环境”两个一级页签：环境页统一承载本地 API 探测、客户范围内环境列表拉取、加入、移出、代理摘要、代理编辑、平台修正、逐个删除与手动分身 ID 兜底；新建页承载既有单个和 Facebook 批量程序化创建。

环境页 SHALL 使用“已加入 / 未加入 / 加入 / 移出”等简洁文案，MUST NOT 使用“已加入客户端”或暴露内部花名册概念。环境页默认 SHALL 是普通列表，只有显式触发批量动作时才进入临时多选态。稳态首屏 MUST NOT 常驻配置表单或“必填”字样；设置抽屉 SHALL 继续只承载浏览器引擎、AdsPower API 高级配置、窗口停放与开发者开关。

#### Scenario: 稳态首屏无环境配置表单
- **WHEN** 配置齐备且应用处于运行、就绪或暂停稳态
- **THEN** 首屏不出现环境配置表单与“必填”标记，全局设置不出现环境清单；环境管理只经左栏管理入口打开

#### Scenario: 环境页统一承载现有环境动作
- **WHEN** 运维打开环境管理的“环境”页
- **THEN** 系统在同一列表中如实呈现当前客户可见环境、加入状态和代理摘要，并提供加入、移出、单环境代理与低频管理入口，无需先判断“加入现有环境”页签

#### Scenario: 待配置引导打开环境管理
- **WHEN** 状态为待配置或当前花名册为空
- **THEN** 主动引导打开环境管理浮层；若没有环境则展示加入或新建下一步，而不是打开全局设置抽屉

#### Scenario: 拉取失败仍保留手填兜底
- **WHEN** AdsPower 环境列表拉取失败
- **THEN** 环境页诚实说明失败原因并保留手动填写分身 ID 的折叠兜底，MUST NOT 静默显示空清单或回落展示本机非当前客户环境

#### Scenario: AdsPower API 凭据仍在全局高级设置
- **WHEN** 运维需要填写 AdsPower API 地址或 API Key
- **THEN** 该配置继续位于全局设置的浏览器引擎高级折叠中，当前表单值仍可供探测、拉取和建号调用使用
