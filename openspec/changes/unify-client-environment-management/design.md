## Context

当前 Electron 左侧环境栏展开宽度只有 176px，适合切换环境、查看状态和触发少量入口，不适合承载环境勾选、代理池输入和映射确认。由环境栏加号拉起的 460px 浮层已经实际承担环境拉取、加入、新建、平台修正、代理编辑和删除，却仍以“添加环境”命名，并用“加入现有环境 / 新建环境”作为一级信息架构。

已有代理链路具备三个可复用基础：`ads-proxy-config.cjs` 是结构化代理归一真源，Facebook 批量建号支持 `host:port`、`host:port:username:password` 与 `----` 分隔格式，AdsPower 写客户端只允许 `{ user_id, user_proxy_config }` 两键并按至少一秒串行限速。新设计必须保持客户环境可见范围、运行生命周期单写者、代理凭据不落盘和成功口径诚实。

## Goals / Non-Goals

**Goals:**

- 用一个明确的“环境管理”入口收口环境清单、加入、新建、代理和低频环境动作。
- 保持页面与文案简洁：一级页签只保留“环境 / 新建环境”，成员状态只说“已加入 / 未加入”。
- 单环境代理支持粘贴一行后复用现有校验并回填字段。
- 批量代理只在用户显式进入时显示复选框，以明确 ID、稳定顺序和可见映射执行。
- 主进程在任何写入前校验客户归属、目标状态与整批代理输入，并提供可恢复的部分失败回执。

**Non-Goals:**

- 不把启动、暂停、关闭、人设、慢启动或风控证据搬进环境管理。
- 不增加常驻详情页、复杂表格配置器、拖拽排序或代理池资产管理。
- 不自动关闭运行环境，不批量删除，不自动验证真实出口 IP。
- 不改变 Cloud API、数据库或 AdsPower `user/update` 的两键白名单。

## Decisions

### 1. 复用原入口位置，但把动作语义从“添加”提升为“管理”

左栏展开态把加号按钮改为带简洁“管理”文字/滑杆图标的入口，收起态栏尾使用同一图标和“环境管理”可访问名称。入口打开现有独立浮层的升级版；有当前环境时列表保持该环境可见，没有环境时显示“加入 / 新建环境”空态。

不同时保留“添加”和“管理”两个入口，因为两者最终到同一清单会制造选择成本；也不在左栏直接显示复选框，因为状态分组会重排且宽度不足。

### 2. 管理浮层只保留“环境 / 新建环境”两页

“环境”页继续读取客户范围内的 AdsPower 环境，行内直接呈现平台、环境名、运行状态、代理摘要和“已加入 / 未加入”。常用动作使用短文案“加入 / 移出 / 代理”；平台修正与逐个删除作为低频动作保留但弱化。手动分身 ID 仍是拉取失败时的折叠兜底。

默认不显示复选框。点击“批量代理”才进入选择态，显示可选框、“取消”和后续确认动作；退出后清空临时选择。相较常驻多选表格，这让普通管理仍是一眼可读的环境清单。

### 3. 把逐行代理解析下沉为通用纯函数

将 `nonBlankLines`、单行拆分与逐行解析从 Facebook 批量建号模块迁入 `ads-proxy-config.cjs`，形成通用 `parseProxyLines({ proxyType, proxyText })`。Facebook 计划器改为调用该函数，保持既有测试与轮询行为。

单环境编辑增加“快速粘贴”输入，经具名 preload IPC 调主进程纯解析函数，成功后只回填当前四个结构化字段，仍由现有保存 IPC 再次归一校验。选择代理类型仍独立于文本；解析错误只返回行号和字段原因。密码可以包含后续分隔符；既有配置只允许在当前客户作用域精确读取后回填到 `type=password` 遮蔽输入，以便局部修改时原样保留，不能进入列表摘要、消息或日志。

不在 renderer 复制解析器，因为那会让格式和安全错误在两处漂移；也不把原始代理行持久化。

### 4. 批量代理使用明确目标列表和主进程完整计划

renderer 提交 `{ userIds, proxyType, proxyText }`，其中 `userIds` 是选择态冻结的去重有序数组。主进程只接受当前有效客户会话且 `allowedProfileIds` 完整可信时的目标，并要求所有 ID 都属于可见集；空数组、重复项、越权项或已知运行中的目标在第一笔写入前整批拒绝。

代理在主进程一次性解析。第 `i` 个环境使用第 `i mod P` 条代理，renderer 在确认前用同一通用解析结果显示去密映射摘要和复用次数。最终写入仍以主进程重新生成的计划为准，不能由 DOM 顺序或随后变化的平台筛选扩大范围。

### 5. 串行执行并在第一项失败后停止

批量处理逐项调用既有 `updateProfileProxy`，复用 AdsPower 写客户端的串行限速。任一项失败立即停止，返回 `updatedCount`、安全的已更新 ID 摘要、`failedIndex`、失败原因和 `notAttemptedCount`；成功和错误均不携带代理原文或密码。renderer 保留选择和输入供核对，全部成功才退出选择态并清空一次性代理文本。

选择“停止”而非“跳过继续”，是因为代理切换影响账号画像，未知失败后继续扩大写入面不够保守。AdsPower 若因环境已打开而拒绝，错误继续使用“请先关闭”的现有口径。

### 6. 配置写入与运行验证保持分离

列表刷新后的代理摘要只代表 AdsPower 配置。单个或批量成功文案统一说明“下次启动生效”，不得宣称出口 IP、时区或地理已经验证；Facebook 真实出口仍由现有运行证据入口负责。

## Risks / Trade-offs

- [管理浮层内容比原来更多] → 宽度适度增大，但一级页签和默认行操作反而减少；批量表单只在选择后出现。
- [筛选或状态重排造成目标错绑] → 写入只使用进入批量态后冻结的显式 `userIds` 顺序，主进程再次校验归属。
- [运行状态在确认后发生竞态] → renderer 只做便利禁用；主进程检查已知 handle，AdsPower 写结果仍是最终拒绝证据，失败即停止。
- [中途失败留下部分新配置] → 返回成功/失败/未执行计数和安全目标摘要，不自动回滚或伪装原子事务。
- [代理数量少于环境数会复用] → 确认前展示轮询映射与复用次数，不把分配成功表述为防关联安全。

## Migration Plan

1. 先增加通用解析器、批量计划/回执纯函数与主进程归属门禁测试。
2. 改造环境管理浮层和入口文案，再接入单行解析与批量选择态。
3. 运行聚焦 Electron 测试、acceptance、完整测试与 typecheck，严格校验 OpenSpec。
4. 集成并推送到 `aidcp-edge/master`，运行 dev 部署目标预检。该变更仅修改 Edge 桌面源码，没有 dev ECS 运行服务；未经明确要求不构建或发布安装包，因此不执行服务器部署。升级不迁移设置或数据库。

回滚为回退 Edge 源码提交；既有环境、代理配置和设置结构均不迁移。已由用户主动完成的代理更新属于 AdsPower 外部状态，代码回滚不会反向改回代理。
