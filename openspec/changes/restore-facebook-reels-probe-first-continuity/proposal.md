## Why

Facebook Reels browsing currently promotes unstable DOM observations—active-video uniqueness, control geometry, and a uniquely classified horizontal or vertical axis—into authority to decide whether a safe page-level key may run. A live input-safe `/reel/` page was therefore stopped before `ArrowRight` because an unrelated disabled control made the structural axis unresolved, repeating a class of stalls and repairs that bounded probing should absorb.

## What Changes

- **BREAKING** Remove active-video, next-control, and structural-axis resolution as prerequisites for reversible Reels keyboard navigation.
- Admit exactly one trusted keyboard probe per command after stable safety checks: the bound Facebook target is on a Reels route, keyboard focus is not editable, no login/captcha/consent blocker is present, and cancellation/deadline gates remain open.
- Start unknown sessions with `ArrowRight`, alternate the next normally admitted command after an unconfirmed probe, and retain the key that produces a canonically confirmed Reel. Do not dispatch two keys, wheel input, or a control click within one command.
- Keep canonical `/reel/<id>` identity as the only success, view-accounting, cadence, and interaction fact. Input delivery or ambiguous movement remains an honest failure but does not disable the next normally paced probe.
- Stop using broad page-copy restrictions and unstable video/control structure as browsing gates. Preserve stricter exact-target gates for irreversible likes, comments, follows, joins, and publishing.
- Remove the obsolete Reels axis-target router/decoder path from maintained scrolling and add composed regressions for the real disabled `Next items` plus active `Next Card` page shape, missing/ambiguous videos, unsafe focus, and cross-command key learning.

## Capabilities

### New Capabilities

None.

### Modified Capabilities

- `facebook-reels-native-scroll`: make safe keyboard probing independent from active-video and axis recognition while retaining one write per command and canonical-only success.
- `facebook-reels-navigation`: replace structural-axis authorization with a minimal adaptive `ArrowRight`/`ArrowDown` probe state.
- `facebook-reels-browse`: ensure an anonymous or incompletely hydrated Reels entry reaches the keyboard probe after its bounded identity observation instead of terminating on unstable target structure.
- `browse-loop-resilience`: preserve normal pacing and admission while an unconfirmed probe selects the alternate key for the next command.

## Impact

- Owning code: `aidcp-edge` Native Facebook router, Rust session/navigation state, Fake CDP coverage, and router/acceptance tests.
- Control repo: OpenSpec behavior deltas and validation evidence.
- Cloud runtime reuses the existing normally admitted Reels-terminal continuation; only parameterized regression coverage is added there. No protocol-v2, database, policy, Console, deployment, package, installation, or real-account action change is intended.
