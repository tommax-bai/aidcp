## Context

Cloud 主动命令在 `EdgeClient.onMessage` 经过请求响应匹配、协议登记、能力协商和显式路由后进入不同处理器。当前只有 `plan.response` 打印粗略日志；浏览、互动、发布、任务租约和验证码协助没有统一的接收诊断。Electron 主进程已经把每个核心进程绑定到唯一环境，并通过既有 fleet status 向 renderer 投影环境状态，因此本变更可以完全在 Edge 本地闭环。

开发者详情已经默认隐藏并按当前环境显示，但目前只有连接分项和两分钟原始日志。新的诊断必须比原始日志更结构化，同时不得复制命令正文、凭据或原始 payload。

## Goals / Non-Goals

**Goals:**

- 对 Cloud 主动下发命令建立统一、按环境隔离的可视接收记录。
- 区分 `received`、`rejected`、`dispatched` 以及 EdgeClient 能直接证明的 `completed` / `failed`，不把下发或交给处理器解释成平台成功。
- 用逐命令白名单生成有用但无内容泄漏的摘要。
- 复用核心 stdout、Electron 环境 status 和既有 renderer 通道，不扩大 preload IPC 面。

**Non-Goals:**

- 不新增或修改 Cloud→Edge 协议字段，也不要求 Cloud 重发历史命令。
- 不改变命令校验、路由、排队、执行、重试、风控或回执语义。
- 不把命令诊断加入普通活动流，不承诺展示平台最终结果。
- 不持久化命令诊断，不提供导出完整 payload 的入口。

## Decisions

### D1. 在 EdgeClient 主动命令入口生成本地结构化诊断行

新增纯函数构造 `[command-diagnostic] {json}` 单行事件。`EdgeClient.onMessage` 只为主动命令族生成事件：`plan.response`、浏览/互动、发布、任务租约和验证码协助；请求响应、`ui.snapshot`、ping/pong 不进入列表。

事件只包含短关联键、命令类型、阶段、固定原因码和白名单摘要。它经现有 logger/stdout 到 Electron 主进程，不进入 Cloud，也不新增 renderer 可调用的 IPC。

备选方案是在各业务处理器分别打日志。该方案会遗漏新路由、阶段措辞漂移，而且无法统一保证敏感字段过滤，因此不采用。

### D2. 阶段只表达当前层能证明的事实

- `received`：Edge 已解析到主动命令信封。
- `rejected`：协议未登记、能力未协商、payload 非法或本地处理器不可用。
- `dispatched`：同步路由边界已经把命令交给对应处理器；它不等于开始点击，更不等于平台成功。
- `completed` / `failed`：仅 `plan.response` 的 EdgeClient 顺序步骤执行能在同一边界直接观察时更新；文案明确这是“步骤执行结果”，不是整项业务或平台终态。

对返回 `void` 或自行异步执行的 handler，列表停留在 `dispatched`，避免猜测执行结果。备选方案是把 handler 全部改为 Promise 并统一等待，但会改变大量现有执行与并发语义，超出本变更范围。

### D3. 摘要采用逐类型白名单，不做通用对象清洗

摘要构造器从已知安全枚举、布尔值和有界计数中取值，例如发布原子命令 `kind`、租约 `kind/priority`、搜索结果上限、评论或回复字符数。文本只显示长度，不显示内容；URL 只显示“已提供目标地址”，不显示 host/path/query；未知字段全部忽略。

禁止 `JSON.stringify(payload)`、对象展开、递归 redact 或“黑名单字段删除”。黑名单会在协议新增字段时默认泄漏，白名单则默认不展示。

### D4. Electron 主进程负责验证、合并、保留和环境隔离

主进程解析结构化行时再次验证事件形状和长度，以主进程接收时间作为展示时间，并按短关联键更新同一条命令。每个环境最多保留 50 条且最长 30 分钟；新事件到达和 fleet 广播前均裁剪。结构化原文不进入普通原始日志，原始日志只记录固定脱敏占位行。

命令诊断作为 `status.commandDiagnostics` 经既有 fleet status 下发。旧 status 缺少该字段时 renderer 展示空态，不报错。

### D5. 开发者详情增加独立命令列表，原始日志继续保留

开发者详情内依次展示自动化引擎连接、引擎命令、原始日志。命令行展示时间、可读命令名、阶段徽标、安全摘要和短关联 ID；最新更新在上。切换环境直接读取目标环境 status，不复用 renderer 全局桶，因此不会串号。

## Risks / Trade-offs

- [Risk] `dispatched` 容易被理解成已经执行。→ 使用“已交给执行器”文案，并在区域提示中明确“不是平台成功”。
- [Risk] 新命令类型没有摘要映射。→ 仍展示经字符白名单处理的类型和固定“未提供摘要”，payload 默认不展示；测试覆盖未知字段不泄漏。
- [Risk] stdout 分块可能影响结构化行解析。→ 沿用现有逐行处理边界，并为解析器增加非法 JSON、过长字段和多阶段更新测试。
- [Risk] 高频浏览命令造成列表噪声。→ 同一关联键更新、50 条/30 分钟双重上限，普通活动流不受影响。
- [Trade-off] 多数直接命令只能显示到 `dispatched`。这是对现有 void handler 边界的诚实反映；以后若要串联业务终态，应由执行器显式发对应阶段事件，而不是在接收层猜测。

## Migration Plan

1. 先落 Edge 本地事件、主进程投影、renderer 和测试；Cloud 无需同步部署。
2. 更新界面说明与 OpenSpec，严格校验后集成 Edge 默认分支。
3. 本变更只提交源代码，不构建或发布桌面安装包；已安装客户端需后续明确发版才会获得该界面。
4. 回滚时删除本地诊断生成与 UI 投影即可，命令协议和执行路径没有迁移状态。

## Open Questions

无。若后续需要展示平台确认终态，应另行设计执行器到诊断列表的显式关联协议。
