## Context

当前桌面端已经具备标题身份区、运行在场感、循环步骤、发布卡、今日进展、活动流和多环境侧边栏。功能与状态数据均已可用，本次问题来自呈现层逐步叠加：同一个环境头像同时承载平台底色、状态外环、选中外框和抬前外框；会话控制固定悬浮在右下角；卡片之间的圆角、边框、阴影和强调色缺少统一约束。

这次只调整 Electron 外壳与渲染层。既有状态判断、环境排序、环境切换、启动/暂停/恢复/关闭路由、配额计算和发布审批边界全部保持不变。

## Goals / Non-Goals

**Goals:**

- 让交互、平台和状态三类视觉信号互不覆盖。
- 建立清晰的页面层级：标题身份 → 当前状态 → 浏览阶段 → 运行价值 → 发布结果 → 今日进展 → 活动记录。
- 让折叠与展开环境栏属于同一套设计语言，并在窄栏中保持状态可辨。
- 保持小窗口、键盘焦点、减少动态偏好和横向内容溢出的可用性。

**Non-Goals:**

- 不改变任何自动运营、配额、发布或多环境调度行为。
- 不新增远程字体、图标库、网络图片或运行数据字段。
- 不移除待处理徽标、失败状态、失联状态或开发者详情。
- 不在本 change 中制作或发布桌面安装包。

## Decisions

### 1. 三类颜色各司其职

蓝色只用于当前选择、焦点、链接与浏览阶段；平台红/蓝只用于账号头像和平台徽标；绿色、琥珀、红色和灰色只用于运行状态与结果。正常标题栏使用中性白色表面，只有警戒或真正异常时才染色，避免稳态界面长期带告警感。

### 2. 会话控制属于今日进展，而不是全局悬浮层

启动、暂停、恢复和关闭直接放在“今日进展”标题区，与当前账号的统计时间和进度同处一个上下文。小窗口下操作区换到独立一行，时间留在左侧；按钮不再覆盖活动记录。六项指标使用单个分段容器，通过分隔线形成一组，而不是六张相互竞争的小卡片。

### 3. 折叠环境栏使用头像、状态点、选中容器三层关系

头像始终以平台实色呈现账号身份。运行状态使用右下角小圆点，需处理时只让圆点脉冲。当前选择或浏览器已抬前使用浅蓝容器和左侧短蓝线，不再叠加头像外环。该结构让平台、状态和交互可以同时可辨，并减少窄栏里的视觉噪声。

### 4. 运行说明保持价值内容，收敛装饰占位

新鲜运行态使用 CSS 本地图形标记，避免大吉祥物与标题身份、发布卡和进度面板竞争。阶段等待与今日完成仍可使用静态吉祥物，因为这些状态需要更强的解释与完成反馈。所有动效继续受系统减少动态偏好控制。

### 5. 视觉改版不改变业务真相

渲染层继续读取同一份真实状态快照，所有按钮仍走原有环境级路由。样式回归测试锁定控件位置和视觉语义，既有多环境、生命周期、发布与诚实失败测试继续运行。

## Risks / Trade-offs

- [折叠态状态点过小] → 保留高对比颜色、头像外侧留白和待处理数字徽标；悬停仍显示账号与状态文字。
- [平台实色头像抢视觉] → 头像尺寸固定为 30px，选中容器使用低饱和蓝，不再增加外圈。
- [小窗口操作区拥挤] → 允许摘要操作区换行，指标面板降为三列两行，浏览阶段横向滚动。
- [样式改版误伤行为] → 不改变状态模型与 IPC 路由；运行完整 Electron UI 测试、类型检查和开发态窗口验证。

## Migration Plan

1. 在独立 Edge worktree 应用视觉令牌、布局与折叠环境栏样式。
2. 更新 DOM 和样式回归测试，运行 Electron UI 测试与类型检查。
3. 复用 canonical `node_modules` 软链启动 `electron:dev` 做开发态视觉检查。
4. 提交 feature 分支保命；后续迭代继续只在该 worktree 进行。

回滚时可整体撤销本 change 的 renderer、标题栏颜色和测试提交；状态模型、协议与持久化数据不需要迁移。
