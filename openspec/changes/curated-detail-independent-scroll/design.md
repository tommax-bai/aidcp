## Context

桌面客户端精选详情目前由一个外层 `.cw-view` 承担纵向滚动，参考图栏与文字栏只是普通网格子项。两栏高度不同时，共享滚动偏移会把较短栏整体推离视口；剩余滚动距离全部表现为该侧的空白。

详情需要保留“在任意一侧滚轮即可连续阅读”的体验，同时让两侧拥有独立的滚动边界。Electron 内置 Chromium 可直接提供原生滚动容器，不需要引入依赖。

## Goals / Non-Goals

**Goals:**

- 宽屏双栏中，一次纵向滚轮输入同时推进图片栏和文字栏，并由浏览器分别夹紧各栏的合法滚动范围。
- 一栏到底后保持不动，另一栏继续；反向滚动遵循相同边界规则。
- 底部保留固定、有限的舒适留白。
- 小于现有双栏断点的窗口继续使用单栏文档流。
- 切换详情、返回列表和重复渲染时不残留监听器或旧滚动位置。

**Non-Goals:**

- 不按两栏内容高度比例同步滚动。
- 不改变精选数据、图片加载、参考创作或审批流程。
- 不改变管理后台精选页。

## Decisions

### 1. 宽屏详情采用两个原生滚动容器

详情模式给内容工作区一个受视口约束的确定高度，详情外层停止纵向滚动，图片栏和文字栏分别使用 `overflow-y: auto`。两栏各自的 `scrollHeight - clientHeight` 成为独立边界，浏览器自动夹紧，不需要手工计算内容高度。

备选方案是让较短栏使用 `position: sticky`。该方案只能可靠处理“内容短于视口”的侧栏；当该栏本身也长于视口时，纯 CSS 无法同时满足先随页面滚动、到底后再停住，因此不采用。

### 2. 在双栏布局层协调纵向滚轮

布局层监听非被动 `wheel` 事件，把归一化后的纵向增量同时加到两栏的 `scrollTop`。每栏由浏览器独立夹紧，因此先到底的一栏不会继续移动，另一栏仍会推进。只要至少一栏实际移动，就阻止默认滚动，避免事件再次作用到指针所在栏；两栏都无法继续时不吞掉事件。

备选方案是完全独立滚动两栏。它要求客户把鼠标移到未到底一侧才能继续，和“这一侧停、另一侧继续”的连续阅读预期不一致，因此不采用。

### 3. 响应式断点沿用现有 680px

宽度不超过 680px 时恢复单列、外层普通滚动，移除列级高度和溢出约束。滚轮协调器在单列媒体查询命中时直接退出，不干预默认滚动。

### 4. 留白由固定内边距提供

两栏底部各保留 12px 内边距。留白不随另一栏剩余长度增长，因此既有呼吸感，又不会形成持续扩大的空区。

## Risks / Trade-offs

- [嵌套滚动可能产生滚动链] → 仅在至少一栏实际移动时阻止默认行为，并给列容器设置 `overscroll-behavior: contain`。
- [触控板 `deltaMode` 不同导致步幅异常] → 按像素、行和页三种模式归一化滚动增量。
- [窗口从宽屏缩到窄屏后监听器仍存在] → 每次滚轮事件实时查询同一个媒体条件；窄屏直接交回浏览器。
- [JS DOM 不执行布局，难以依赖真实高度测试] → 测试以可控属性桩覆盖 `scrollTop`/`scrollHeight`/`clientHeight`，直接验证边界夹紧、默认事件处理与窄屏旁路。

## Migration Plan

该变更仅影响 Electron 渲染层，无数据迁移。发布新版客户端即可生效；回滚时恢复前一版 `content-workspace.js` 与 `styles.css`。
