## Context

桌面客户端精选详情目前由一个外层 `.cw-view` 承担纵向滚动，参考图栏与文字栏只是普通网格子项。两栏高度不同时，共享滚动偏移会把较短栏整体推离视口；剩余滚动距离全部表现为该侧的空白。

详情需要让客户明确控制正在阅读的一侧，同时让两侧拥有独立的滚动位置与边界。Electron 内置 Chromium 可直接提供原生滚动容器，不需要引入依赖或自定义滚轮算法。

## Goals / Non-Goals

**Goals:**

- 宽屏双栏中，图片栏和文字栏分别使用原生纵向滚动；指针所在栏独立响应滚轮。
- 一栏滚动或到达边界时，另一栏的滚动位置保持不变。
- 底部保留固定、有限的舒适留白。
- 详情标题区在滚动时持续吸顶，以更紧凑的高度保留类型、标题、作者、返回和关闭操作。
- 小于现有双栏断点的窗口继续使用单栏文档流。
- 切换详情、返回列表和重复渲染时不残留旧滚动位置。

**Non-Goals:**

- 不按两栏内容高度比例同步滚动。
- 不改变精选数据、图片加载、参考创作或审批流程。
- 不改变管理后台精选页。

## Decisions

### 1. 宽屏详情采用两个原生滚动容器

详情模式给内容工作区一个受视口约束的确定高度，详情外层停止纵向滚动，图片栏和文字栏分别使用 `overflow-y: auto`。两栏各自的 `scrollHeight - clientHeight` 成为独立边界，浏览器自动夹紧，不需要手工计算内容高度。

备选方案是让较短栏使用 `position: sticky`。该方案只能可靠处理“内容短于视口”的侧栏；当该栏本身也长于视口时，纯 CSS 无法同时满足先随页面滚动、到底后再停住，因此不采用。

### 2. 不接管或联动纵向滚轮

渲染脚本不监听或阻止双栏的 `wheel` 事件。浏览器只滚动指针当前所在的原生滚动容器；另一栏保持原位置。列容器使用 `overscroll-behavior: contain`，当前栏到达边界后不把滚动继续传给详情外层。

备选方案是把同一次滚轮输入分发给两栏。该方案会让客户无法单独停留在某张图片或某段文字，并增加非被动事件处理，因此按用户最终选择不采用。

### 3. 响应式断点沿用现有 680px

宽度不超过 680px 时恢复单列、外层普通滚动，移除列级高度和溢出约束。

### 4. 留白由固定内边距提供

两栏底部各保留 12px 内边距。留白不随另一栏剩余长度增长，因此既有呼吸感，又不会形成持续扩大的空区。

### 5. 详情模式使用紧凑吸顶标题

沿用现有标题 DOM 与返回、关闭按钮，只在 `curated-detail-mode` 下覆盖为吸顶样式：位于应用标题栏下方，缩小网格边栏、间距、内边距、字号和图标按钮尺寸。详情容器使用 `overflow: clip` 保留视觉裁切但不建立新的滚动容器，使窄屏下的 sticky 定位仍相对页面生效。关闭按钮继续占据右侧固定网格列，不通过响应式样式隐藏。

## Risks / Trade-offs

- [客户在已到底一栏继续滚轮时不会自动推进另一栏] → 这是独立控制的明确取舍；客户把指针移到另一栏后继续阅读。
- [嵌套滚动可能传递到详情外层] → 列容器设置 `overscroll-behavior: contain`。
- [吸顶标题遮挡应用标题栏] → sticky 顶部偏移与 46px 应用标题栏高度对齐，并使用低于全局标题栏的层级。
- [JS DOM 不执行原生 CSS 滚动] → DOM 测试验证两栏滚动位置互不改写且脚本不阻止滚轮，样式测试验证两个原生滚动容器与窄屏回退。

## Migration Plan

该变更仅影响 Electron 渲染层，无数据迁移。发布新版客户端即可生效；回滚时恢复前一版 `content-workspace.js` 与 `styles.css`。
