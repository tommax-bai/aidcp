# console-panel-api — spec delta

## ADDED Requirements

### Requirement: 运行控制视图 SHALL 透出写熔断状态且不得与运营暂停混渲

运行控制的对外视图 SHALL 透出账号写熔断状态（至少：是否熔断、熔断起始时刻、连续失败次数）。后台 MUST NOT 在熔断态把该账号渲染成「允许写入」——运营手动暂停与系统熔断是两个独立状态，MUST NOT 共用一个开关或一句结论。熔断态下界面 SHALL 明示恢复路径（解除写暂停即清除熔断并恢复发送），使运营不需要读代码就知道「什么把它拨回来」。

#### Scenario: 熔断态不显示允许写入
- **WHEN** 某账号处于写熔断，且运营暂停开关为「允许写入」
- **THEN** 后台不给出「允许写入」这一单一结论，熔断状态与其起始时刻可见

#### Scenario: 恢复路径可见
- **WHEN** 运营查看处于熔断态的账号
- **THEN** 界面写明解除写暂停会清除熔断并恢复发送

#### Scenario: 正常态渲染不变
- **WHEN** 账号未熔断
- **THEN** 写总闸按运营暂停开关照常渲染，不新增噪音提示
