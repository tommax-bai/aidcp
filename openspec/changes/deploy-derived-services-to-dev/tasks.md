## 4. 三个部署位就位（周期任务全关）

## 7. soak 与逐条验收

- [ ] 7.1 soak **第一段：1 小时**。下限不是拍脑袋——按小时开火的任务每个账号每小时只有固定的
  一分钟窗口，跑不满一小时那个窗口大概率根本没到 ⇒ 什么都没验到，
  而进程全程健康、日志干净、**看着像通过了**。覆盖不到的项如实记未验，
  MUST NOT 用"进程一直活着"替代。
- [ ] 7.1a **停下来看第一段结果再决定是否继续**（无误才挂第二段）。
- [ ] 7.1b soak **第二段：8–12 小时（挂一晚）**。第一段回答"闹钟真会响吗"，
  第二段才覆盖得到多轮判定、以及内存 / 连接池 / 日志量这类**渐进型**问题——
  它们跑五分钟全都是正常的。
- [ ] 7.2 soak 记录 SHALL 能回答"周期任务醒了几次、每次判定是什么、原因是什么"。
  **"一次都没醒"与"醒了但每次都判跳过"是两件事**，要分得开。
- [ ] 7.3 逐条走 `docs/real-machine-acceptance-backlog.md` 簇 60 的验收项，每条记三态之一：
  **已验（附证据）/ 未验（附为什么没覆盖到）/ 不适用（附理由）**。
  重点是上一个 change 登记的 5 条 + 既有的 `runAutomationMain` 从未真跑、飞书 `/delegate` 从未真跑。
- [ ] 7.4 **禁止出现"三进程已验证"这类概括**。概括性的验收结论会以最快速度过期——
  本 change 立项时就当场推翻了一条这样的记载。
