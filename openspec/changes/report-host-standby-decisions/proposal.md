## Why

**宿主层握着「要不要关掉一个正在被人使用的浏览器」的决定权，而这个决定对云端完全不可见。**

2026-08-05 的真机故障就是这个形状：云端每 60 秒推一次「这个账号接下来 33 分钟没活干」，
客户端**连续 32 分钟每次都拒绝**，浏览器一直占着两个槽位之一。云端那侧只知道自己在推，
不知道对面收到没有、判了什么、为什么不动。

change `admit-browser-standby-on-live-facts` 已经补上了**本地**可见性（具名拒绝原因、连续拒绝次数、
开发者详情两行、按首次+每 5 次节流的日志）。但那只解决了「有人坐在那台机器前面」的情况。
**车队是跨机器的**：运营在一处看不到另一台机器上某个环境已经卡了半小时。

这条缺口有一条**结构性理由**，不只是「顺手加个遥测」：

> 分层判据（规格 `edge-addressing-layers`）把槽位调度判给宿主层，**因为槽位不跨机器**。
> 但宿主层拥有决策权的**代价**是必须向上可见——否则它就退化成这次故障：
> 一个没人能质询的本地决定。**可见性是遥测，不是审批权**：云端读得到、但 MUST NOT 据此否决。

**这条 MUST 先于「把等待门槛的权威还给宿主层」那个 change 落地。** 先装眼睛，再交权；
反过来做等于把这次故障的成因扩大之后再补监控。

**现成通道不可复用（已实读代码坐实）**：边缘→云端唯一那条浏览器真态上报只接受
`absent` / `ready` 两个值，其诊断字段明写「不参与云端会话状态判定」，而云端处理函数
**第一行就是「状态没变直接返回」**——让位被拒时浏览器一直是 `ready`，状态永远没变，
整条消息连同诊断字段一起被丢弃。**且整张消息表里没有任何一条通用的边缘→云端遥测通道。**

## What Changes

- **新增一条 edge → cloud 协议消息**，承载宿主层的槽位让位决策事实：判决（让位 / 拒绝）、
  具名原因、连续拒绝次数、首次拒绝时刻、以及该决策对应的提示标识。
- **上报由外壳发起、经核心转发**：决策在 Electron 外壳做，而云端连接在核心子进程里，
  因此需要一条新的外壳→核心本地消息 + 核心侧的转发。
- **发送按事件节流，不按提示节拍**：判决**变化**时发（首次拒绝、原因变化、由拒转让），
  持续拒绝按与本地日志一致的节流补发。**MUST NOT** 每 60 秒一条把链路灌满。
- **云端持有并呈现**：新增消息 MUST 有真实消费方——按环境/账号留存最近一次决策与连续拒绝态，
  并在面板侧可读。**只读、只呈现**：云端 MUST NOT 因此获得对槽位决策的否决权。
- **能力位协商 + 纯增量**：新消息经握手能力位启用；旧客户端不声明该能力时云端不期待它，
  且**现有 `browserStandby` 载荷的字段一个都不减**（见 Impact 的兼容红线）。

## Capabilities

### New Capabilities

- `host-standby-decision-telemetry`: 宿主层槽位让位决策的向上回执——上报什么、何时报、
  云端如何持有与呈现，以及「可见不等于可否决」这条权限边界。

### Modified Capabilities

- `browser-cold-standby`: 补一条要求——宿主层每一次让位判决 SHALL 向云端回执，
  且该回执 MUST NOT 成为准入的输入或否决通道。

## Impact

- **协议**：新增一条消息类型。**三份 `protocol.ts` 必须逐字一致**（`aidcp-edge` / `aidcp-cloud` /
  `aidcp-automation`——`scripts/land-change` 的跨仓对账门现在查三份，不是两份），外加
  `docs/protocol.md` 的头部计数与 §2 表。
  - **不涉及**动作↔消息映射表（那是 cloud→edge 命令用的）与边缘 onMessage 主动命令白名单
    （那是 cloud→edge 独立下发命令用的）；本消息是 edge→cloud 单向上报。
- **边缘**：Electron 外壳新增上报触发点与节流；新增一条外壳→核心本地消息与核心侧解析、转发。
- **云端**：新增消息处理与按环境/账号的留存；面板侧读取。
- **⚠️ 兼容红线（贯穿实现）**：边缘收到待机提示时**先验格式**——「是否够格让位」不是布尔、
  或「门槛值」小于 1 秒，**整条提示当场判无效丢弃**。故云端侧**任何字段都只能加、不能减**；
  且**不能靠版本号灰度**：客户端会被从源码重新编译装机而**不抬版本号**，版本号认不出装的是哪份代码。
- **并行冲突**：`protocol.ts` 是 CLAUDE.md §7 的热点文件，**须标记需串行**。
  立项时已核：edge / cloud 两侧均无在开分支改动协议（cloud 侧唯一命中的
  `codex/add-managed-automation-runtime` 属 2026-07-30 已撤出计划的 change，非活跃占用）。
