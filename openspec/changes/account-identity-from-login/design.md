## Context

`multi-account-node-support`（已部署）把云端改成按连接多租户、按账号过诚实人设就绪闸、按账号风控/去重。但账号身份的**来源**是启动器外部指派的环境变量标签（`AIDCP_ACCOUNT_ID`），握手携带、缺失即拒。这个标签与"该节点浏览器里实际登录的账号"解耦：错配静默、且要求运营预先管标签、漏设即被拒。

现状里有两个**已经成立**的事实，使"身份从登录读出"几乎是顺水推舟：① 边缘时序已是"登录在前、握手在后"（`main.ts` 先 `launchChrome`（含等登录）再 `client.connect()`）；② 握手消息本就带 `accountId` 字段、云端门禁/运行时本就按它判。所以把身份来源从"环境变量标签"换成"登录态读出的真实稳定 id"，**不动协议、云端近零改**，只新增边缘"登录后读身份"一步。

约束（项目铁律）：边轻云重、状态单写、**绝不静默假成功 / 绝不静默以默认账号或默认人设跑**、协议 v2 改动须四处同步（本 change 不动协议）。

## Goals / Non-Goals

**Goals:**
- 把账号身份**钉死到实际登录的那个账号**，错配从根上消失；运营只需"起节点 + 扫码登账号"，不管标签。
- 给出一套清晰的**节点生命周期口径**（登录前/后 = 身份是否确立），让"哪些操作账号无关、哪些必须账号绑定"有据可循。
- 身份**诚实**：读不出稳定 id 就停手，绝不猜、绝不回落 default。
- 身份**可翻转可重确立**：掉登录/换号能正确退回无身份态、重新确立，不重跑节点初始化。

**Non-Goals:**
- 不动边-云协议（`HelloPayload.accountId` 字段已存在）。
- 不改云端按连接多租户/风控/去重内核（仅换身份来源）。
- 不引入指纹浏览器（同机防关联非本次）。
- **同一真实账号被多个节点并发登录** 是否触发平台侧异地/多端关联或风控——本次**有意识不管**（不是漏掉）；同账号 N:1 的额度/去重安全由 `multi-account-node-support` 已部署内核保证，平台侧并发关联另议。

## Decisions

### D1. 分界线是「身份是否确立」，不是「登录」这个动作
登录前/后的本质分界是**系统知不知道自己此刻是哪个账号**；登录只是确立身份的那个事件。判定任一操作归属的测试：「不知道自己是哪个账号时，这操作还成立、还正确吗？」成立=账号无关（登录前），不成立=账号绑定（登录后）。**分类按操作本质、不按方便**——不得为绕过就绪闸把账号作用域操作挪到登录前（否则=未绑账号在默认人设上空跑红线）。

### D2. 三态生命周期；把"节点初始化"与"身份确立"分开命名
- **无身份态**：账号无关，绝不替任何账号做事。内含两件**本质不同、生命周期不同**的事——
  - **节点初始化**：一次性、基础设施层（拉浏览器、分配端口/用户数据目录、连云端传输）。登出不会重来。
  - **身份确立**：可反复发生的**态**（非一次性步骤），本质是"系统从不知道我是谁 → 知道了"。
- **已确立身份 · 就绪闸**：知道是谁了 → 过人设绑定闸（default 豁免）。未绑→停手+飞书，已绑→放行。
- **运行态**：账号作用域操作，受人设/风控/配额/去重约束。
**理由**：不把整个"登录前"叫"初始化"——"初始化"是按时序命名且暗示一次性，会误导实现（掉登录时该重跑的是"身份确立"而非重启浏览器/重分目录）。分开命名后"一次性 vs 可反复"自明。

### D3. 身份 = 登录态读出的**稳定 id**（非昵称），读不出即诚实失败
账号主键用稳定标识（小红书内部 userid，即 `/user/profile/<id>` 路径段那个不可变 token），**不用昵称**（昵称可改、当主键会漂）。昵称 + 小红书号一并读、但仅作显示名/副标识。读取来源与定序见 **D8**。**读不出稳定 id → 诚实失败、停手**，绝不猜一个、绝不回落 `default`——身份错了，后面人设/配额/归因全错，比不动更糟。

### D4. 身份可翻转、要持续校验；翻转只退回到"身份确立"，不退回"节点初始化"
登录态会丢（登出、session 过期、profile 换登别的号）。身份是**要持续校验的状态**，不是握手时定死一次：
- 失效检测到 → 节点退回**无身份态**，停掉账号作用域操作；
- 重新走"登录 → 读身份 → 就绪闸"；
- **不重跑节点初始化**（浏览器不重启、端口/目录不重分）。
profile 换号场景：同一节点（同 edgeId、同用户数据目录）登了不同账号 → 身份从 A 翻成 B → 云端须把旧账号会话拆掉、按新账号重过就绪闸（状态单写、不串味）。

### D5. 边缘侧为主、不动协议、**云端零改**
边缘：登录后读身份 → 用真实 id 当握手身份（取代 env 标签）；身份失效则退回无身份态重连。握手字段与时序不变。
云端：经查实，`accountId` 在云端**全程是不透明字符串、无任何格式/形态校验**（仅查空）——handler 原样落连接、按连接运行时 / 风控控制器 / accounts 主表主键 / 人设存储全都直接消费它（`connection-runtime.ts`、`risk-controller.ts`、`account-store.ts`、`persona-store.ts`）。故把身份**来源**从 env 标签换成真 userid，对整条云端**透明**：协议零改、迁移零改、内核零改。云端**唯一需验证**的是"同 `edgeId` 换账号重连"经已部署的顶替机制正确重绑（拆旧账号会话、起新账号就绪闸）。

### D8. 身份读取来源与定序（已查实，复用现成）
经代码查实：边缘浏览时**早已在读这个 userid**——`browse-session.ts:1589` 用 `location.href.match(/\/user\/profile\/([A-Za-z0-9]+)/)` 抽作者 userid（URL 结构性、生产已验）；登录探测又**已定位到导航栏自己的头像**（`chrome-launcher.ts:409-415`），其 href 即 `/user/profile/<自己id>`。故读自己的 userid = 复用同一条正则、换个对象。读取来源按"结构性优先（DOM-first 漂移纪律）"定序：
1. **导航栏自己头像的 `href`**（`/user/profile/<id>`，**结构性、就地读、不跳转**）—— 首选；
2. **进"我的主页" → 读 `location.href`**（确定，但有一次跳转副作用）—— 兜底；
3. **不读 cookie 当 id**：`web_session`/`a1` 是会话/设备不透明 token、无可解 userid（这正是"cookie 值 ≠ 页面值"的来源）；**不读 class 文本拼 id**（改版即漂）。
昵称/小红书号另读（DOM 文本即可），作显示名/副标识。读出的 userid 应**校验形态**（像不像那个 token），读不出/不像 → 诚实失败（D3）。

### D6. 启动器只分配节点槽位；env 标签降级为可选覆盖
多节点启动器只分配**节点槽位**（端口 / 用户数据目录 / `edgeId`），**不再分配 accountId**；用户数据目录按 `node-<n>` 命名（账号未在登录前已知，是"谁登进这个槽位"的产物）。`AIDCP_ACCOUNT_ID` 保留为**可选显式覆盖**（预置/特殊场景）：设了则用它、不设则走登录推导。

### D7. 与已部署 change 的关系 / `default` 的新含义
迭代 `multi-account-node-support` D4，复用其门禁/通知/风控；与 `account-real-nickname` 正交（昵称=显示，稳定 id=主键）。**`default` 的含义收窄**：真实登录的账号一律拿到真实 userid、不享豁免（真实账号本就不该跑默认人设）；`default` 实际只剩"env 覆盖显式声明 default"这一条路（兼容旧单账号），其打包默认人设回落语义不变。

## Risks / Trade-offs

- **[成败手——已查实可行，降级]** 稳定 id 读取：核心可行性已坐实（`browse-session.ts:1589` 早已用 URL 正则抽作者 userid、生产已验，自己只是换对象；登录探测已定位到自己头像）。**仅剩一次性现场校准**——确认导航栏自己头像的 `href` 是否就是 `/user/profile/<id>`。读不出/不像 → 诚实失败（不退化成静默 default）。
- **[`default` 地雷]** 字面量 `default` 在云端约 15 处 + ws-server 兼容分支 + 面板 needsPersonaSetup 闸 + accounts seed 都当 catch-all/seed。**真 userid 万一读成空，绝不能塌回 `default`**（会把一个真账号并进大杂烩账号 = 跨账号污染）。守住"读不出即诚实失败、握手缺 id 即拒、绝不偷映射 default"。
- **[换号重绑残窗] profile 换登别的账号** → 身份翻转期间若云端未及时拆旧账号会话，可能短暂串账号。缓解：身份失效即退回无身份态、断连重连触发云端按新 id 重建运行时（状态单写）。
- **[env 覆盖误用] 显式覆盖与实际登录不一致** → 又回到错配。缓解：覆盖是逃生阀、默认登录推导；可在边缘对"覆盖值 ≠ 读出的真实 id"诚实告警。
- **[无身份态可观测性弱] 节点已连未登录在后台看不见** → v1 接受（无身份不上报、不占账号视图）；后续如需"节点已上线待登录"再补。

## Migration Plan

1. **校准 id 读取**（apply 第一项）：核心已查实可行（复用 `browse-session.ts:1589` 的 URL 正则 + 登录探测已定位的自己头像）；只需一次性现场确认"自己头像 href = `/user/profile/<id>`"，再选定"就地读 href" 或 "进我的主页读 URL"。
2. **边缘改造**：登录后读身份 → 握手用真实 id；env 降级为可选覆盖；身份失效退回无身份态重连；启动器改按节点槽位。
3. **云端**：确认"同 edgeId 换账号重连"正确重绑（多为复用，必要时小补）。
4. **平滑性**：当前 ECS 仅 `default` 账号、persona_config 空——新模型上线后，节点登录真实账号即按真实 id 登记进主表、过就绪闸（未绑→飞书叫人去后台设人设）。现有"default 节点"可用 env 覆盖 `AIDCP_ACCOUNT_ID=default` 继续工作。
5. **回滚**：边缘身份来源可回退为纯 env 标签（保留覆盖路径即天然回滚阀）。
