# Proposal: 保真参照洗稿角色链

## Why

现有精选页「洗稿」与普通 `/publish` 共用发布创作链，只是在输入里多带一条 `referenceNote`。其 prompt 明确要求「借选题/结构/要点、以人设口吻重新创作、补充自己的经验判断」，更接近借题再创作；这会把原文的身份、事实、时间线和论证重心改掉。

运营现在明确要求洗稿只做**保真改写**：不做解读二创，不做借题重写。系统需要把参照路径从常规自由创作链中分出来，用专门角色先解析原文、规划保留边界、生成改写稿、再审核忠实度，通过后才进入既有配图 / 标题 / 话题 / 人审 / 下发链路。

## What Changes

- `referenceNote` 触发的参照洗稿改为保真改写模式：不得主动新增未在原文出现的事实、数据、实测、身份经历或结论。
- 新增发布侧 LLM 角色：
  - `publish:ReferenceAnalyzer`：抽取原文事实、论点、结构、不可改写约束。
  - `publish:FaithfulRewritePlanner`：生成段落级保真改写计划。
  - `publish:FaithfulDraftWriter`：按计划写小红书体裁草稿。
  - `publish:FidelityAuditor`：对比原文与草稿，审核事实覆盖、未授权新增、视角漂移和结构偏离。
- 参照路径旁路 `ContentScout` / `ContentCreator` 的自由创作；只有 `FidelityAuditor` 通过后才写 `createdContent`，下游既有链路继续复用。
- 四个新角色加入角色目录和管理后台可配置范围；判定/审核类不开放温度，写作类开放温度。
- 普通常规发布保持原有角色编排与自由创作逻辑，不受参照保真链影响。

## Non-Goals

- 不做解读二创模式。
- 不做借题重写模式。
- 不新增前端新页面；后台角色配置页继续消费角色目录。
- 不绕过既有 AC-PUB 人审、发布下发、配图收口或来源快照。
