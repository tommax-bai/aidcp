## Context

浏览器执行槽按内存计（约 700MB 一格），一台机器的格数有限。今天有一整类环境可以**无限期**占着一格：需要人介入才能解除的阻塞。

云端待机提示的准入判据是「解除这个阻塞需不需要浏览器」。需要的那一类（验证码、登录失效、风控未识别、尚未就绪）**刻意不产出可让位提示**——这条是红线，立它的代价付过：关掉一个正等运营去解验证码的浏览器，等于把资源回收做成了自残。

但红线只写了"不许关"，没写"人一直不来怎么办"。于是：

- 该环境的浏览器一直开着、零工作量、占满一格，直到有人想起它；
- 宿主层的连续拒绝记账**覆盖不到这一类**——那套记账只记"云端说可以让、本地却拒了"；云端说不该让时计数被清零、不留痕，所以界面上连"卡了多久"都看不到；
- 已有的遥测回执同理，只在有让位判决时才发。

本 change 给红线补上它缺的那一半：**有界的滞留上限**。

## Goals / Non-Goals

**Goals:**

- 需人介入的阻塞持续滞留超过门槛后，该环境**主动终止自己**并释放槽位，不再无限期占位。
- 终止是**终态**：不自动重启、不进等槽位队列，必须运营手动重新启动——因为阻塞本身没被解决，自动重来只会立刻回到同一个状态。
- 终止事实在客户端界面**持久可见**，写明是哪一类阻塞、从什么时候开始滞留。
- 触发条件足够窄，误配的部署不会被一次清场。

**Non-Goals:**

- **不动既有红线**：这类阻塞仍然 MUST NOT 产出可待机提示，仍然不走冷待机（保核心保云连、可自动醒）。本 change 走的是语义不同的另一条路——终止。
- **不做槽位借调 / 驱逐**（`browser-slot-scheduling` 5.8 明确否决）：这里没有受益人被指定，是被阻塞的环境**自己**按上限停手，不是替谁腾位、更不碰任何正在干活的会话。
- 不改冷待机的任何既有让位路径（配额 / 冻结 / 受限 / 排期），一字不动。
- 不新增飞书通知或云端记档（用户已选定：只留客户端界面持久卡片）。

## Decisions

### D1. 滞留计时归宿主层，云端不参与

计时与处置都在客户端外壳。理由与既有编址分层一致：槽位不跨机器、环境绑死本机分身，没有任何槽位决策是云端能做而宿主做不了的。技术上还有两条：云端每跳都是**无状态重算**、不持有"这个原因从何时开始"；且连接断开时云端根本无从判断阻塞是否仍在。

**Alternative（否决）**：云端算滞留时长、下发"该关了"的指令。这会让两层各出一个决策、必然漂移，正是既有遥测规格里"可见性 MUST NOT 转化为否决权"要防的那类问题。

### D2. `not_ready` 必须拆成具名子原因（唯一的云端改动）

`not_ready` 今天是一个**兜底桶**，至少三件处置完全不同的事共用它：

| 实际情况 | 人来了能解决吗 | 该不该按滞留上限关掉 |
| --- | --- | --- |
| 人设未绑（`needs_persona_setup`） | 能（去绑） | **该** |
| 云端读不到该账号的人设（副本陈旧） | 不必——只读副本会自己追上 | **绝不该** |
| 其他配置副本陈旧 | 同上 | **绝不该** |
| 该平台不具备浏览能力（`platform_no_browse`） | 无从"解决"，这是该平台的常态 | **绝不该**——该账号很可能正在跑排期发帖 / 评论，关掉它等于把那些也停了 |
| 调度未激活（`dispatch_inactive`）＝**运营的显式全局停机** | 与单个环境无关 | **绝不该**——全局停机时每个环境都报这个，照关即全场清光，且没有受益人（大家都停了，位子腾给谁），运营重开调度时反而要逐个手动重启 |
| 续场配置提供者缺席＝该部署没开这个特性 | 不能，与这个环境无关 | **绝不该**——同样是全场清光 |

边缘拿到的只有 `not_ready` 三个字，分不出是哪一种。若照单全收，一次全局停机或一个没配续场的
部署就会把**全部**环境逐个自动关掉——这正是本仓"跨层翻译 MUST NOT 有兜底桶"红线所说的：把没
认出来的原因折进一个已有名字，跨层传下去就成了终局判决。

`hard_blocker` 是**第二个兜底桶**，同样必须拆：它既装着「该边缘正处于验证码暂停态」（用户点名
要治的那一类），也装着「风控拦住且原因不以配额开头」这个**取反得来的补集**——补集里将来会落进
什么，今天没有人知道。

因此云端 SHALL 把两个桶都拆成互相可分辨的具名取值（原因字符串取值扩展，不改协议结构、不改消息
类型）。

**采用白名单制，不是黑名单制**：宿主层持有一份「明确该终止」的具名清单，**清单之外的一切原因
一律不计时**。清单初始只有两项——验证码暂停、人设未绑。黑名单（"排除已知不该关的几种"）在这里
是错的方向：上面这张表是我逐条读代码才拼出来的，而且比第一版判断多出三种"绝不该关"；将来云端
新增任何原因，黑名单的默认后果是**关掉它**，白名单的默认后果是**多占一会儿槽位**。

**Alternative（否决）**：纯本地的整机护栏（"同一原因滞留的环境超过 N 个就不关"）。不需要云端
改动，但会误伤真正该关的场景——批量建号后一批环境同时等着绑人设，那恰恰是最该释放槽位的时候。
用比例做判据也无法区分"批量待绑"与"全局误配"。

**关于人设未绑与既有复判链的关系**：云端对"人设未绑"已挂了一条 2s→60s 退避的自动复判链（人设
可能正被自动补齐、或运营正在客户端里设）。本 change 的门槛（15 分钟）比该链的稳定间隔大一个数
量级，因此**只会在自动补齐确实没发生时才触发**，两者不冲突。

### D3. 触发条件是四条合取，不能只看原因字符串

同时满足才开始计时：

1. 云端提示判定不让位，且原因**在宿主层的具名白名单内**（初始：验证码暂停、人设未绑）；
2. 该环境**此刻真的占着一格执行槽**（活核心持有的浏览器，排除冷待机中、临时通道、以及从未开过浏览器的控制面环境）——不占槽的环境关掉它一无所获；
3. 自动化意图为**已启用**（运营手动暂停 / 关闭的环境走的是别的路，不归本机制管）；
4. 云端连接**处于连接态**——提示能到达本身就是这条的证据。

第 2、3 条是关键护栏：它们把"这个环境正在浪费一格"从原因字符串的推断变成**当场可验证的事实**，与既有准入闸"MUST 只读当场可验证的事实"同源。

### D4. 换原因即重置，断连即重置

- **换原因即重置**：与既有连续拒绝记账"换因即复位"口径一致。原因变了说明情况变了，不该继承上一段的时长。
- **断连即重置**：连接断开期间收不到提示，**不等于阻塞仍在**。若只按"首次出现时刻"算差值，断连 20 分钟后重连的第一跳就会立刻越过门槛——那等于让断连时间替阻塞背书。重连后重新计满门槛，最坏情况只是多占一个门槛的时长，方向安全。

### D5. 处置复用运营手动「关闭」那条路径，只换归因

不新造终止路径。既有的手动关闭路径已经处理了生命周期代次推进、启动队列释放、等槽位队列清理、槽位记账收敛、界面四轴与在场感收敛——新写一条必然漏项，而漏项在这里的形态是"关了但槽位没还"或"关了却又被自动拉起"。

只有一处不同：停止归因不是"运营关闭"，而是一个具名的系统归因，界面据它呈现持久卡片、并与运营手动关闭区分开。**MUST NOT 复用运营关闭的归因**——否则事后没人分得清这个号是人关的还是系统关的。

### D6. 门槛与开关

默认门槛 15 分钟，环境变量与客户端设置可覆盖；另有一个默认开启的功能开关，关掉即回到今天的行为（秒级回滚）。门槛下限需大于提示节拍（约 60 秒）的若干倍，避免一两跳抖动就触发。

## Risks / Trade-offs

- **[关掉后运营就没浏览器可解验证码了]** → 用户已确认接受：15 分钟没人来，判定为"短期内没人管"，释放槽位的收益大于保留现场。缓解：持久卡片写明是验证码类阻塞，运营重新启动环境后阻塞状态仍在云端、会再次呈现，**不会丢失"这个号需要人处理"这件事**。

- **[全局性原因被误当成单个环境的问题，导致集中关闭]** → 这是本 change 最贵的失败模式，有三条路径通向它（运营显式全局停机、该部署没开续场特性、配置副本整体陈旧）。D2 的白名单制把它们全部挡在触发之外：清单只有两项，且都是**账号级**的事实。缓解还有秒级回滚开关 + 每次关闭都留持久卡片，集中发生时在界面上一目了然。

- **[把一个马上就要被解决的阻塞关掉]** → 门槛 15 分钟远大于人从看到告警到动手的常见时长；且关闭前的每一跳提示都在界面上可见。

- **[与 `browser-slot-scheduling` 并行改同一个文件]** → 桌面外壳主文件是双方热点。实装前确认单写者，必要时串行。

- **[新的原因取值边缘不认识]** → 边缘对未知原因**默认不计时**（保守方向：多占槽位，绝不误关）。这条必须写成断言，否则将来云端新增任何需人介入的原因都会悄悄落进"不认识就当可以关"。

## Migration Plan

1. 云端先落 `not_ready` 的原因拆分并部署 dev——**这一步单独可上线**，行为零变化（边缘此时还不认新取值、按未知原因不计时）。
2. 边缘再落滞留计时与终止处置，默认开启，带回滚开关。
3. dev 观察一轮：确认没有环境被误关、卡片呈现正确、槽位确实回到池子里。
4. 回滚：关掉功能开关即恢复今天的行为，无需回退部署。
