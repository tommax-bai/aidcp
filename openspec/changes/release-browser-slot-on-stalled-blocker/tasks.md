- [ ] 1.2 坐实「需要浏览器才能解除」的来源：阻断浮层暂停态（确认验证码与未识别弹窗两种载荷都落到同一个暂停集合），以及「风控拦住且原因不以配额开头」这个取反补集里实际会出现的取值
- [ ] 1.3 把两个桶都拆成互相可分辨的具名取值，**只扩展取值、不改消息结构**；全局性来源（显式停机 / 特性未开）与会自愈的来源（副本陈旧）必须与账号级来源明确区分
- [ ] 1.4 待机提示构造处按新取值透传原因，确认既有「不让位」判定与 `eligible` 取值一字不变（本步行为零变化）
- [ ] 1.5 补单测：每个来源各自产出可分辨的具名原因；断言互不相等，且都仍然 `eligible=false`
- [ ] 1.6 补**穷举断言**：会话启动裁决的取值集合若新增成员而未在原因映射里具名，测试失败——复用既有那张穷举分类表的做法，防止新原因默默折进已有名字

## 2. aidcp-edge — 滞留计时（纯判定函数）
