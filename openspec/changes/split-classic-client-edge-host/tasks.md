## 0. In-place prerequisites, completed inside the existing `aidcp-edge`

No new repository may be created until every gate in this section is green. All of this work stays in
`aidcp-edge` and moves with the engine at split time, so none of it is throwaway.

**0.A — Windows self-contained packaging (separate change; a hard gate here, not implemented here)**

- [ ] 0.A.1 Land the separate Windows self-contained packaging change and build one real Windows installer from it. Today's Windows CI job does not stage the fingerprint-browser runtime and does not restore the baked runtime key, and electron-builder only *warns* on a missing `extraResources` source, so the job goes green and uploads an installer whose browser cannot start. Fix the job, then add the missing gate so the failure mode becomes a red build rather than a silent pass.
- [ ] 0.A.2 Correct the two places that assert the opposite of the truth: the workflow comment and `docs/release-desktop.md` both say the Windows build "would fail on missing extraResources". It does not fail; that is the whole problem. Also correct `docs/release-desktop.md` §2A: cross-building a Windows package on macOS is now structurally impossible (the native page engine target map and electron-builder's platform macro both key off the *host* platform, and the post-pack manifest assertion then throws), so Windows must be built on a Windows host.
- [ ] 0.A.3 Record the current published Windows artifact version against the current source version and decide what happens to the stale published installer. `[需用户操作]` — the published Windows build predates the packaged-subprocess-working-directory fix, so installed Windows clients most likely cannot start the core at all; whether to withdraw the download entry now or wait for the replacement is the user's call.
- [ ] 0.A.4 Admission gate: the same one command produces macOS ×2 plus Windows ×1 before the split, so that the identical command after the split is a real acceptance criterion. Without this, split acceptance silently degrades to "macOS still builds".

**0.B — Machine-level exclusion (implemented in `aidcp-edge`, moves with the engine)**

- [ ] 0.B.1 Implement the machine-level runtime reference count: a starting instance that finds a healthy, version-compatible daemon MUST adopt it and MUST NOT stop or restart it. Current behaviour is the opposite — the first successful runtime preparation of each application session stops whatever registered daemon it finds, with no ownership, health or in-use check inside that branch.
- [ ] 0.B.2 Implement the physical-profile lease on atomic exclusive file creation, and place its decision point **before the debug port is read**, so that it covers both entry doors: the already-active attach path and the orphan-debug-port adoption path. A guard placed only on the start call covers neither, because neither door calls start.
- [ ] 0.B.3 Implement lease reclamation with the two-condition rule: reclaim only when the previous holder process is proven dead **and** the browser side proves that browser is gone. Holder-dead alone is an orphan lease and MUST be refused. Do not use an OS lock that releases on process death — the browser outlives the client process, so automatic release hands the second client a lease over a live browser.
- [ ] 0.B.4 Implement the cross-process Local API rate gate as a short critical section over a timestamp file, stacked behind the two existing in-process queues, which are retained. Bounded timeout takeover is safe here and only here; write that difference down next to the code so the lease rule is never copy-pasted from it.
- [ ] 0.B.5 Present refusals with the existing vocabulary — "环境被其它端占用" for the reason, "不可重起终局" for the disposition — and extend the standing red line so it also binds the attach decision itself, not only the handling of an already-classified rejection. Do not introduce a competing outcome class.
- [ ] 0.B.6 Add tests for: two instances on different profiles both run; a second instance is refused before reading the debug port on an active profile; a second instance is refused on the orphan-port path; holder dead with browser alive is refused as an orphan; holder dead with browser proven gone is reclaimed; a healthy compatible daemon is adopted rather than restarted.

**0.C — In-place main-process split (no new repository)**

- [ ] 0.C.1 Split the Electron main process in place. It is currently one 7396-line file registering 82 runtime IPC channels from 81 handler call sites, with a matching 82-channel preload surface and 4 main→renderer push channels. Separate product-side modules from engine-side modules inside the existing repository first; the split into two repositories is a move of already-separated files, never a first separation.
- [ ] 0.C.2 Assign all 82 IPC channels to Classic or Host, one owner each, with no "undecided" entries. Use the measured shape rather than assumptions: only two non-lifecycle channels actually command the running engine (show the driven browser; reset browser parking). Re-login and restart are stop-and-restart; open/close browser are wake/standby; environment creation and proxy edits go straight to the fingerprint-browser local API; environment deletion, persona, publish approval, inbox and content workspace all go straight to the cloud over HTTPS.
- [ ] 0.C.3 Assign all five cross-boundary transports, not just the log stream: the stdout/stderr line stream (with its four structured line prefixes, and the standing rule that stderr is not a failure signal); the stdin JSON-lines bridge; the Node IPC channel; the spawn-time environment variables; and POSIX signals. Two of these carry operations that exist nowhere else — environment deletion with credential wipe is delivered only by spawning a cleanup-only engine process with environment variables, and the terminate signal is the authoritative way to enforce "pause means the engine disconnects" when the IPC channel is already unusable.
- [ ] 0.C.4 Do not re-route product operations back through the engine. Persona and publish approval used to ride the stdin bridge and were deliberately moved to direct client-to-cloud HTTPS so that they keep working while the engine is stopped; their client-side senders are now dead code with zero call sites and there are tests forbidding their return. Confirm those tests still pass at the end of this section.
- [ ] 0.C.5 Produce the ownership list **by file and line range**, not by category. A category list cannot be checked; a file/range list can be diffed against the two repositories after the move.
- [ ] 0.C.6 Admission gate — every one of these must hold before any repository is created: the Electron main file is under 1500 lines; every module assigned to the engine has zero renderer, window or navigation imports, enforced by a boundary test; all 82 channels carry an owner with no "undecided"; the three suites (`npm run test:acceptance`, `npm test`, `npm run typecheck`) are green.

## 2. Independent repository foundations

**Ordering is load-bearing: the helpers are taught the new names before anything is renamed.** The only
hard admission gate in the fleet skips a repository whose directory is missing instead of failing, so at
the instant of the rename the old path disappears, becomes a silent skip, and the gate goes blind to the
two new repositories. The incident that gate exists to prevent — a canonical execution-side checkout left
on a release branch for about a day, with the locally launched desktop client running the release tree —
is exactly what a blind gate allows to recur.

- [ ] 2.1 Teach every control-repo helper both the old and the new repository names, before any rename. This is a four-site edit, not one: the iteration list in `scripts/task-preflight`, the identical iteration list in `scripts/fleet-status`, the default-branch table in `scripts/lib.sh`, and the sibling allow-list in `scripts/lib.sh`. Also update the usage strings in `new-change` / `spawn-change` / `land-change`, the hardcoded GitHub slug and the five `aidcp-edge` path references in `scripts/release-desktop-macos`, and `scripts/README.md`. Both layouts must be accepted for the whole transition window.
- [ ] 2.2 Harden the admission gate so a rename cannot narrow it silently: keep reporting a genuinely un-cloned repository as skipped, but fail admission when a project checkout exists beside the control repository under a name the roster does not know. Do not convert "missing" into a blanket failure — a machine that legitimately holds only some repositories must still be able to start tasks (CLAUDE.md §0 explicitly contemplates that case).
- [ ] 2.3 Verify 2.1 and 2.2 by dry run before the rename: with the current layout admission still passes; with a simulated post-rename layout both new checkouts are branch-checked; with an unregistered project checkout present admission fails and names it.
- [ ] 2.4 Rename/migrate the existing `aidcp-edge` remote to `aidcp-edge-host` while preserving full Git history, issues/releases and `master`, then verify existing clones receive the intended hosting redirect.
- [ ] 2.5 Create `aidcp-classic-client` from the same `split-base`, retain relevant Classic file history, set `master` as its canonical branch and verify it is independently cloneable without the Host source checkout.
- [ ] 2.6 Add repository-local AGENTS, ownership, branch protection, dependency install, focused/full test and typecheck rules to both repositories. Secret rule: **no secret in source in either repository, and release secrets exist only in the Classic repository's CI.** Do not write "neither repository has secrets" — signing and notarization require them, and forbidding them outright would forbid the only way to ship.
- [ ] 2.7 Update protocol and architecture references so Cloud↔Edge v2 synchronization names `aidcp-cloud` and `aidcp-edge-host`, while Classic is explicitly excluded from protocol command routing ownership. Do not introduce any post-Cloud-split repository name (`aidcp-api` / `aidcp-content` / `aidcp-automation`); those repositories do not exist and pointing a CLAUDE.md §2 protocol-sync slot at a non-existent repo is exactly how commands were silently dropped twice before.
- [ ] 2.8 Validate control repo changes with `openspec validate split-classic-client-edge-host --strict` and helper dry-runs against physical, non-symlinked dependency installs in both new repositories. Note that `--strict` passing is not evidence the change can be archived; see 8.7.
