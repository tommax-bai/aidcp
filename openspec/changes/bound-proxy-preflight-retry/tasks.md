## 1. aidcp-edge — 失败原因分类

- [ ] 1.1 在预检模块中加入失败原因的可恢复性分类：返回「可恢复 / 不可恢复」两态，映射表按 design 决策二逐条落地（超时、连接被拒、主机解析失败、代理连接建立失败、未归类请求失败、中继端口占用 / 启动过慢 / 提前退出 / 孤儿清理失败 → 可恢复；配置不完整、协议不匹配、认证不通过、系统代理未配置 / 不受支持 / 重复、权威读不到 / 格式无效 / 版本已变 → 不可恢复）
- [ ] 1.2 分类函数对**未识别原因**默认返回可恢复，并为此单独写一个用例锁住（传入一个分类表里不存在的原因串，断言结果是可恢复）
- [ ] 1.3 「无法确认」（检测设施自身异常、配置读不到的非阻断态）保持既有语义：既不进重排通道，也不显示成代理失效

## 2. aidcp-edge — 重排通道（手动 / 批量启动路径）

- [ ] 2.1 在环境句柄上加重排计数与上限（默认 2，环境变量可调；设为 0 时逐字退回今天的立即终结行为）
- [ ] 2.2 预检确定失败的分支改为分流：不可恢复 → 走既有终结处理；可恢复且预算未尽 → 安排重排；可恢复但预算已尽 → 终结并写明「重试预算耗尽」
- [ ] 2.3 重排实现为**延迟重入既有启动入口**（间隔 20s / 60s 递增），确保调用发生在当前启动流出栈之后，否则会被启动入口的幂等闸挡掉、静默无效
- [ ] 2.4 重排回调必须复核生命周期代次与停止意图：环境已被暂停 / 移出 / 停止 / 退出时一律作废，MUST NOT 把一个已被叫停的环境重新拉起来
- [ ] 2.5 重排计数在预检成功、用户手动点击启动这两处清零；随生命周期代次自然作废
- [ ] 2.6 确认重排等待期间不持有启动排队名额（当前启动流出栈时已归还），只在真正重新入场那一刻重新占用

## 3. aidcp-edge — 重试前作废缓存结论（两条路径）

- [ ] 3.1 重排重新入场前作废该环境已完成的预检结论，使这次重排真的发出新探测
- [ ] 3.2 冷待机唤醒的退避重试到点、真正重探之前作废旧结论（修掉 60s 那一跳复用旧失败、不发探测的空跑）
- [ ] 3.3 确认作废不影响在途单飞：已有真实探测在途时仍等待并复用，MUST NOT 产生可被其他启动路径当作「无法确认」消费的 superseded 结果

## 4. aidcp-edge — 诚实呈现

- [ ] 4.1 重排等待期间的状态与文案：显示代理不通 + 已重排第 N 次，MUST NOT 显示成普通「启动中」，MUST NOT 提前显示成终态失败
- [ ] 4.2 预算耗尽终结的回执写明「重试预算耗尽」，与不可恢复类的配置原因文案明确区分（两者不得压成同一句「代理不可用」）
