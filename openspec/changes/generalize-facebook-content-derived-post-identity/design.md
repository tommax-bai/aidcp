## Context

### 现状：身份只有一种，且群组帖拿不到

云端识别一条帖子靠**平台永久链接**。取不到就整张卡丢掉（`20-feed.js` 的 `cardOf`：无地址即返回 null），云端因此什么都收不到——不评估、不计数、不互动。

2026-07-29 真机实测（两台，均为越南语号）确认地址来源分两类：

- **主页帖**：地址挂在时间戳上，**可信指针悬停**后才写进 DOM（5/5）。已由 change `acquire-facebook-feed-post-identity-by-hover`（edge `78f89cf`）覆盖。
- **群组帖**：时间戳悬停给不出（0/1）；**点击评论按钮**后地址出现在 URL 上（2/2，形如 `/groups/<群>/permalink/<帖>/`）。页面上**不存在**任何现成的可接受链接（6/6 卡为 0）。

Vo Tu 这类账号首页几乎全是群组帖 ⇒ **浏览链路 100% 阻塞**。

### 已有但被限死的机制

`00-shared.js:215-249` 已实现一套内容派生身份：

```
证据 = 作者名 + 作者主页(归一) + 正文 + 稳定链接 + 图片/视频标识
引用 = "aidcp:facebook-group-feed-post:v1:" + SHA-256(证据)
```

配套齐全：DOM 打标记（`data-aidcp-native-first-post-target`）、会话内 Map、取用时**重新算证据比对**（`boundFirstPostRoot`，证据变了就判失效）、歧义检测（同引用命中多个元素 ⇒ `ambiguous_target`）。协议侧也已写明它可作 noteId 且「不得当作 permalink 展示」。

唯一的限制是作用域：`firstPostGroupScope()` 要求当前 URL 是 `/groups/<gid>`，首页信息流直接返回空 ⇒ 整套机制不生效。

## Goals / Non-Goals

**Goals**

- 让取不到平台地址的信息流卡**能被上报、被评估、被计入浏览、被就地点赞**。
- 复用既有内容派生机制，**不新造第二套**。
- 两类身份的能力边界在协议与规格上显式分档，不靠调用方自觉。
- 老边端 / 字段缺省时行为逐位等于今天。

**Non-Goals**

- 不让"打开详情""定向评论"在群组帖上免交互——那两件事仍需真地址。
- 不改哈希算法与证据构成。
- 不做任何"猜地址"的回落。
- 不把会话内引用写进任何持久化存储或交付给人工。
- 不在扫卡路径上点击弹窗（用户已否决：代价摊在最高频路径上）。

## Decisions

### D1：复用既有引用机制，只放宽作用域

作用域从「群组页」改为「当前列表面 URL + 文档代」。同面同代内有效，换面或换代即失效。

- **为什么不新造**：既有实现已含歧义检测、证据复校、DOM 标记生命周期，且协议侧已有"不得当作 permalink"的书面约束。新造等于把这些都重做一遍并重新踩坑。
- **为什么绑文档代**：文档代变了说明列表已换批，旧引用指向的元素可能已被虚拟化复用给别的帖子。绑代是防止"引用漂到别的帖子上"的结构性手段。
- **前缀是否要改**：现前缀写死 `facebook-group-feed-post`。语义上已不止群组，但**改前缀会让云端既有的评论链路判据失配**（`facebook-edge-steps.ts:90` 按该前缀匹配）。决定：**保留前缀不动**，在规格里注明它是历史命名、语义为"内容派生的会话内帖子引用"。改名单独立项，不与本 change 混。

### D2：身份分档必须显式，不靠"看 noteId 长什么样"猜

协议新增一个可选分档字段（缺省 = 平台地址），而不是让云端去正则匹配 `aidcp:` 前缀。

- **为什么不靠前缀**：靠前缀等于把一条契约藏在字符串格式里，任何一处忘了判就会把会话内引用当地址用——那正是"静默假成功"的形态。显式字段让漏判在类型层暴露。
- **缺省语义**：字段缺省 ⇒ 平台地址 ⇒ 老边端逐位等于今天，零回归。
- **协议四处同步**（CLAUDE.md §2 铁律）：两份 `protocol.ts` 逐字一致 + `command-bridge.ts` 映射 + `docs/protocol.md`。本字段不新增消息类型，不涉及第 4 处主动命令白名单。

### D3：能力边界按身份分档硬切

| 动作 | 平台地址 | 会话内引用 |
| --- | --- | --- |
| 内容评估 | ✅ | ✅ |
| 计入浏览 | ✅ | ✅ |
| 就地点赞 | ✅ | ✅（边缘按引用重定位，按钮状态变化校验） |
| 打开详情 / 导航 | ✅ | ❌ **必须诚实失败**，绝不猜 |
| 定向评论 | ✅ | ❌（需先取真地址，见 D4） |
| 交付人工作线索 | ✅ | ❌（交不出去的东西不许交） |
| 跨会话去重 | ✅ | ❌（换会话即失效，不得落库） |

- **点赞为什么可以**：点赞不需要地址——按钮就在卡里。校验也不依赖 id：按钮状态由「赞」变为「已赞」是比 id 比对更直接的证据。边缘按引用重定位时会重算证据，命中不唯一即 `ambiguous_target`（既有行为）。
- **导航为什么必须失败而非猜**：`validated_facebook_content_url` 会拒绝非 URL 的引用——这条已经是诚实失败。本 change 要保证云端**不下发**这类命令，而不是依赖边缘兜住。

### D4：真地址在"要动手时"才取，且与本 change 解耦

当决策端判定这条值得评论 / 值得留线索时，才点开评论弹窗取真地址，并补 `/groups/<群>/permalink/<帖>/` 格式。

- **为什么不在本 change 做**：那是交互路径，涉及弹窗开关、滚动位置复原、被抢占后的遗留清理，风险与本 change 完全不同源。混在一起会让"浏览恢复"这件事被交互风险拖住。
- **为什么顺序上可以在后**：浏览与点赞不依赖它。它只在评论 / 线索这条低频路径上是前置。

### D5：不引入任何"半成品卡"的第三态

卡只有两种：可上报（持平台地址或会话内引用）、不可上报（两者皆无 ⇒ 不上报，走今天的 `present_unreportable`）。

- 不新增"有内容但无身份"的上报形态。会话内引用的存在正是为了消灭这个中间态。

## Risks / Trade-offs

- **[引用漂到别的帖子]** → 三重防护：证据含作者+正文+链接+媒体、取用时重算比对、绑文档代。仍需真机复核（虚拟化复用是最可能的漂移源）。
- **[云端某处忘了判分档，把引用当地址用]** → D2 的显式字段 + 规格里逐条列出禁止项；实装须加断言：对会话内引用下发导航类命令即测试失败。
- **[同模板刷屏帖碰撞]** → 证据不止正文，还含作者主页与媒体标识，抗碰撞强于纯文本。但**招聘/租房群是最坏场景**，须真机采样碰撞率。碰撞的后果是"少读一条"（被误判成已读），不是"操作错帖子"——因为动作都要重新定位并复校证据。
- **[浏览量口径变化]** → 会话内引用不跨会话去重，同一条帖子在两次会话里会各记一次浏览。这是真实的口径放宽，须在规格中写明，避免日后被当成计数 bug 反复排查。
- **[前缀名不副实]** → 保留历史前缀是刻意取舍（见 D1），规格中注明，避免后人以为它只用于群组。

## Migration Plan

1. 边缘：放宽作用域 → 普通卡签发引用 → 按引用重定位（点赞路径）→ Rust 侧透传分档。
2. 协议：新增可选分档字段，四处同步，`npm run typecheck` 双仓暴露漂移。
3. 云端：准入分档 + 禁止对会话内引用下发导航类命令 + 浏览记账接受引用。
4. 真机验证：Vo Tu（群组帖为主）上，可上报卡数应从 0 变为正数；就地点赞应能命中并通过按钮状态校验；导航类命令应从不下发。
5. 本 change 改的是编入 Rust 二进制的引擎与注入脚本 + 云端，**边缘侧须重打客户端包才生效**，云端侧需部署 dev。
6. 回滚：协议字段可选、缺省即旧行为；回退提交并重打包 / 重部署即可。
