# tasks — lease-strict-preemption

> **串行标记**：本 change 改动边缘执行权协调器与各平台会话的页面写记账。
> **占用中的文件，本 change 不碰**：`aidcp-edge/src/main.ts`（用户并行占用中——FB 租约闸节奏档位豁免）。抢占接线全部落在协调器与各平台会话侧；若发现确需动 `main.ts`，先与用户协调，不得擅自改。

## 1. aidcp-edge — 安全取消点与让路（解死锁的核心）

- [ ] 1.1 新增接管取消令牌：命令入口拍下接管世代号存为字段 + 一个「检查并抛出」的私有方法 + 一个专用的接管异常类型
  - **判据必须是「接管世代号」，不能是「浏览已冻结」标志** —— 独占任务自己的命令就跑在冻结期内（交接一开始就置冻结、只有恢复时才清）。用后者，评论 / 巡视的每条命令要么在自己的等待里当场自尽，要么直接跳过浮层闸对着验证码墙点击
- [ ] 1.2 阻断浮层等待（`src/browse/browse-session.ts:3145-3181`）：循环条件加第三个出口（世代号已变）；把闸内的不可打断 sleep 换成同文件已有的可打断 sleep
- [ ] 1.3 离页停留两处（`:472-502`）与动作前统一闸（`:550-556`）：同样换成可打断 sleep，醒后检查世代号
  - 可打断等待机制本仓已有（唤醒集合，`:568-590`），今天只认「停机」和「终止命令」两个触发源，对「任务接管」全盲 —— 补这一个触发源即可，**不引入超时、不改 sleep 语义**
- [ ] 1.4 主循环（`:1241-1250`）：取到命令先拍世代号，再进页面写记账；捕获接管异常 → 发诚实回执 → `continue`（不记账、不重放）
  - **不新建边缘侧动作名映射表** —— 那是 CLAUDE.md §2 点名的第 5 处 typecheck 抓不到的漂移点；云端入口已有归一函数（`aidcp-cloud/src/comm/handler.ts:96` 定义 / `:478` 调用），直接回协议消息名
- [ ] 1.5 回归：确认新原因码不落进云端的「可重试白名单」、交互类动作已在「不补发兜底滚动」名单内（否则云端会误重试 / 白发一条兜底滚动）

## 2. aidcp-edge — 交接有界 + 未收敛绝不授予（解锁体）

- [ ] 2.1 交接函数（`src/browse/browse-session.ts:883-893`）：世代号自增后**立刻唤醒全部可打断等待**；无界的裸等待换成同文件已有的有界排空（预算 30s，env 可覆盖）
- [ ] 2.2 未排空 → **按世代号守卫回滚自己置的冻结标志** + 抛出交接超时错误
  - 不回滚 = 把停摆从「让位态」搬到「浏览冻结态」：协调器看着完全健康，云端浏览命令逐条被静默丢弃，且没有任何事件会再来清它
- [ ] 2.3 协调器（`src/execution/edge-task-coordinator.ts:288-334`）：交接抛错的分支改为「不授予 + 排队任务以诚实终态终结 + 解除浏览冻结 + 返回」；顺带修掉今天「交接抛错却仍继续授予」的既有隐患
- [ ] 2.4 Facebook 会话（`src/facebook/facebook-session.ts:294-310`）用它已有的有界排空实现同一契约
- [ ] 2.5 诚实终态复用现有原因码，**不得复用 `cdp_unhealthy`**（本仓已明文认定那是假话，且云端会据此对运营发出「请重启浏览器客户端」的误导指令）

## 3. aidcp-edge — 抢占路径（协调器）

- [ ] 3.1 协调器新增抢占：更高档位申请到达 + 当前有活跃低档位持有者 → 向持有者发取消信号 → 有界等它真停 → 授予
  - 现有的提前返回分支（见 `:191-196` / `:288-334`）会挡住这条路，逐个梳理
- [ ] 3.2 **同档位 MUST NOT 抢占**（仍 FIFO）；**低档位 MUST NOT 抢占高档位**
- [ ] 3.3 持有者必须能告诉协调器「我在不可逆提交之前 / 之后」——决定回执走哪一档（依赖 0.1）
- [ ] 3.4 防抖动护栏：同一任务被抢占 N 次后暂缓重排（防「验证码反复弹 → 反复抢占发布 → 发布永远做不完」）
- [ ] 3.5 系统恢复任务租期 60s / 受理超时 20s —— 抢占引入后重估这两个数（依赖 5.1）

## 4. aidcp-edge — 发布执行流纳管（防双写）

- [ ] 4.1 把发布执行流接进统一的页面写记账（依赖 0.4）——今天它跑在主进程一个独立上下文里，协调器的交接对它完全无感
- [ ] 4.2 发布认同一个取消令牌：每一步之间、以及**逐字输入的字符间隙**插检查点
- [ ] 4.3 分档回执：不可逆提交之前 → 「未提交，已中止」；之后 → 「已提交，结果未知」
- [ ] 4.4 **重开发布前确保干净起点**：被抢占时页面上留着半截草稿，而且此刻浮层挡着、清不了 ⇒ 清理不能放在抢占时，要放在**发布流程重新开始时**（无条件确保编辑器为空 / 丢弃残留草稿），否则会写出「半截 + 完整」的双份正文

## 5. aidcp-cloud — 失败语义与提示

- [ ] 5.4 「已提交，结果未知」→ **不自动重试** + 向运营发需人工确认的提示（飞书按账号路由 / 客户端）

## 6. 测试

- [ ] 6.1 【核心】让路：阻断浮层常驻 + 一条浏览命令在飞（翻页 / 开笔记 / 点赞各一例）→ 发起接管 → 交接 MUST 在一个轮询周期内收敛（< 200ms）；该命令回诚实失败回执；接管信号之后 MUST 记录到**零次**页面改写调用
- [ ] 6.2 【核心】停留让路：关闭 / 返回命令停在离页停留（下发 90s 预算）时发起接管 → 交接 MUST 毫秒级收敛
- [ ] 6.3 【边界不能画错，既有三条必须继续绿】`test/browse/browse-session.test.ts:350 / :1941 / :1984` —— 真实页面写在途时，交接 MUST NOT 提前收敛。这三条变红 = 把红线保护的东西也一起扔了
- [ ] 6.4 【唯一「写错了会更糟」的一格】持权任务不自尽：评论准备租约内的搜索 / 开笔记命令 MUST 正常执行，且 MUST 仍在阻断浮层前停手（不跳闸）。即：让路判据是接管世代号，不是「浏览已冻结」标志
- [ ] 6.5 交接有界且不撒谎：注入一个永不收敛的真实页面写 → 交接 MUST 在预算内抛出 → 协调器 MUST NOT 授予、MUST 给排队任务诚实终态、MUST NOT 停在让位态；随后普通浏览 MUST 恢复、冷待机 MUST 可再次进入（现有协调器测试 `test/execution/edge-task-coordinator.test.ts:91-115` 的形状恰好绕开了这个分支）
- [ ] 6.6 抢占矩阵：风控抢人工 ✓ / 人工抢系统 ✓ / 同档不抢 ✓ / 低档不抢高档 ✓
- [ ] 6.7 抢占发布不双写：系统恢复抢占一个正在逐字输入的发布 → 在系统恢复的第一次页面写之前，发布 MUST 已停止向控制端口派发任何输入
- [ ] 6.8 分档回执：提交前被抢 → 「未提交，已中止」+ 熔断计数不变；提交后被抢 → 「已提交，结果未知」+ **不自动重试**
- [ ] 6.9 【参数一致性】断言常量关系：云端验证码协助受理预算 > 边缘交接上界 + 往返余量
- [ ] 6.10 `npm run test:acceptance` → 全量 `npm test` → `npm run typecheck`，edge / cloud 两侧（安全红线 `AC-PROTO-*` / `AC-PUB-*` / `AC-RISK-*` 必须全过）

## 7. 真机验收（dev，登记 backlog）

- [ ] 7.1 【最终验收，用户原话】浏览中人工制造验证码浮层 → 运营点协助 → 协助点击**落地**（不再回租约不匹配 / 租约申请失败）、浮层被清除、浏览自动恢复
- [ ] 7.2 抢占进行中的发布：填了标题正文时弹验证码 → 协助抢占 → 发布诚实终结为「未提交，已中止」、熔断不 +1；验证码清掉后稿件可重发且**正文不重复**（验 4.4 的干净起点）
- [ ] 7.3 零副作用假设的真机证伪项（0.2 的转项）：自动存草稿 / 图片入素材库 / 评论草稿残留 / 未读被清成已读
