# image-postcheck-vision-model

## Why

当前参照洗稿虽然把原笔记图片传给生图模型，但存在三个会让“参考了原图”失真的结构性问题：

1. 所有槽位共享整组参考图，源图与生成图没有一一绑定；
2. 提示词组装仍优先套内容品类的通用风格档，没有先理解整组原图的视觉语言；
3. 生成后只相信 prompt 约束，没有对构图、色彩、风格、主体及高风险文字/真人做视觉核验。

因此 provider 即使真实消费了图片，也可能选错参照、平均化整组风格或发生明显风格漂移。审计中的 `referenceStatus='used'` 只能证明“请求使用了参考图”，不能证明“生成结果保持了参考关系”。

## What Changes

- 新增整组视觉反推角色 `VisualReferenceAnalyzer`：先做整组分类、序列和风格聚类，再按摄影、插画/3D、文字卡、UI/文档、图表信息图、拼贴/混合等类型使用独立分析维度，汇总为 `setStyleBible + styleClusters + frameSpecs`。摄影类才反推相机、镜头、景深和光线；非摄影类使用版式、媒介、造型、信息层级、网格、图形语法等对应字段。
- 视觉反推只描述视觉结构和风格，不 OCR、不逐字提取原图文案；文字卡图内文字转写仍归独立 change `transcribe-textcard-image-text`，防止视觉模仿与内容搬运耦合。
- 按源图顺序为每个生成槽建立显式绑定。每槽只传该槽主参考图及经策略授权的风格/身份锚；Wan 多图请求明确图片角色并保证主参考图最后输入，避免所有槽共享整组参考图。
- 提示词优先使用源图 `frameSpec + styleBible`；现有内容品类风格档仅在反推关闭、不可用或低置信时兜底。
- `ImageSetPlanner` 同时承担分类内容视觉导演职责：读取有界但覆盖正文首/中/尾的语义摘录，为每个生成槽产出公共 `contentVisualBrief`，再按人物、文字卡、图表信息图、场景摄影、静物、插画/3D、UI/文档、混合拼贴附加判别式 `categoryBrief`。参考图负责视觉形式与风格，正文 brief 负责具体表达内容；两者冲突时正文语义优先。
- 文字卡继续走确定性渲染，但在源风格可用时由反推结果派生受限设计令牌（内部色板、背景网格/渐变、信息卡形态、分页标记、密度和层级），不再固定使用账号哈希模板；渲染器仍不得接收原图 URL、像素、坐标或 OCR 文本。UI/文档、图表和混合类保留诚实路由状态，首版在没有结构化重绘器时使用类型专用生成提示，不冒充“已确定性重绘”。
- 新增产后 `VisualFidelityAuditor`：比较主参考图与生成图，并按本槽公共 brief + 分类 brief 核验人物表演、文字信息结构、图表关系、场景事件、静物使用状态、插画隐喻、UI 任务状态或拼贴分区是否与正文一致；同时检查形态、主体、构图、色彩、风格以及乱码、可识别真人、水印、逐字复制/原创风险。生成式和确定性文字卡都必须进入核验，失败有界重生成/重渲染，重试用尽后丢弃该槽；若上一轮已失败，下一轮模型不可用不得以 `unverified` 放行。
- 视觉反推结果按图片抓取锚、模型和 schema 版本缓存到精选素材行；发布元数据与控制台展示风格来源、槽位绑定、路由和逐槽审计，历史记录 null-safe。
- 新能力使用默认关闭的旗标分阶段上线：反推影子 → 槽位绑定/源风格生效 → 产后审计生效；关旗标时保持现版行为。

## Impact

- Affected specs: `publish-multi-image`、`panel-curated-content`。
- Affected code:
  - `aidcp-cloud`: 视觉模型角色、缓存字段、管线接线、按槽参考图契约、Wan 请求、产后视觉审计、发布审计元数据。
  - `aidcp-console`: 精选素材视觉分析与发布视觉审计的可解释展示，包括逐槽公共 brief、分类 brief 与内容一致性分数。
- No protocol / edge change：继续消费现有 `referenceNote.images`，不新增边缘字段或命令。
- Cost / latency：反推按抓取锚缓存；整组一次轻量分类 + 按类型小批量调用，不按每图无界调用；大图集 specialist 分批并发，避免单次七至九图输出在固定超时内失败；产后审计仅在旗标开启且存在主参考图的参照洗稿执行。

## Model Decision

- 复用云端 `OpenAiCompatVisionClient`；默认 provider 为 DashScope、模型为 `qwen3.7-plus`，均可由独立 env 覆盖，并进入现有 token usage 记账。
- 图片生成继续使用当前 provider/model；Wan 多参考图遵循图序并显式声明图角色。
- 模型不可用或严格 JSON 解析失败均诚实降级，不写“已分析/已通过”的假状态。

## Out of Scope

- 不做 OCR、原文转写或把原图文字复制到生成图。
- 不在本 change 新建 UI/图表确定性渲染引擎；只保留类型识别、专用提示与诚实路由状态。
- 不声称仅凭自动评分已完成真实视觉 A/B；上线前后仍需用真实 1/3/8/9 图素材抽样验收。
