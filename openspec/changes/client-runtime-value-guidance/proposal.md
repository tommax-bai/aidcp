## Why

现有客户端会在自动浏览与节奏间隔之间切换，但用户只能看到状态或计数，难以理解首页浏览、互动与等待分别在为内容创作带来什么。配额完成也容易被理解为限制，而不是一个已完成的阶段成果。

这次改动需要在不重做 Edge 主界面的前提下，把真实的运行节奏转成用户可理解的价值与下一步，同时保持“没有进度就不假装有进度”的边界。

## What Changes

- 在现有在场感下方加入紧凑的运行价值说明区，只在真实的运行、本轮间隔、小时级间隔或今日计划完成时展示。
- 运行时说明正在为用户寻找内容灵感；本轮和小时级间隔说明已记录的灵感、自然间隔与下一轮会更聚焦的收益；今日计划完成说明成果已沉淀。
- 使用吉祥物的执行、观察、庆祝状态作为该说明区唯一的吉祥物位置，并仅在真实运行且事件新鲜时允许持续动效。
- 单项评论、点赞、收藏等节奏完成仍只在“今日进展”的展开详情中呈现，不触发“浏览已暂停”或全局等待卡。
- 保留既有发布卡与“今日进展”位置和职责；不新增审批操作、不改动协议与云端数据形状。

## Capabilities

### New Capabilities

- `runtime-value-guidance`: 将真实浏览节奏以成果、原因和下一步的方式嵌入 Edge 客户端主运行区。

### Modified Capabilities

- `edge-companion-ui`: 在场感与今日进展需与新的运行价值说明区协同，继续遵守真实事件和静默诚实的边界。

## Impact

- Edge renderer: `index.html`、`renderer.js`、`styles.css` 与其 DOM 集成测试。
- Edge renderer assets: 打包三张透明背景吉祥物 PNG。
- 无协议、主进程、云端服务或发布审批链路变更。
