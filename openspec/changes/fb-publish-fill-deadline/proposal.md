## Why

Facebook 发帖的正文填写是 **O(正文长度)** 的逐字符输入，却被云端用一个**与长度无关的常数 30s 窗口**去等——这是一天前刚引入的结构性回归，dev 上**每一篇由内容管线自动生成的 FB 帖子都会踩中**。

- 上一批把 FB 正文从「一次性 `Input.insertText`」改成逐字输入（edge `4e466ca`，编辑器要求），实测每字约 150–165ms（拟人节奏 + CDP 往返）。
- 云端 `fill_field` 的等待窗口是常数 30s（只有传图放宽到 60s），无 env 旋钮。**约 175 字即中位数超时，200 字几乎必爆。**
- 当前内容管线已为 Facebook 使用专用 prompt，并将正文目标明确为「全文 100–500 字（Facebook 最佳阅读区间）」；但该要求仍是模型软提示，**正文没有任何确定性长度校验**。执行侧的 `content_too_long` 只能诚实拒绝，不能替代生成侧合同。

后果**不止「发不出去」**，而是三重错位：

1. **孤儿打字循环**：云端判超时 → 中止序列 → 记录落 `failed` → 租约以 `completed` 释放 → 边缘排空并**恢复浏览循环**，而被放弃的打字循环**仍在往活着的编辑器里逐字写入**，与浏览循环共用同一个 CDP session。
2. **脏 composer 污染下一篇**：失败留下的残稿不会被清理；下一篇的 composer 会**复用已存在的编辑区**，而输入是**在光标处追加**——只靠整页跳转顺带冲掉，纯属侥幸。
3. **验收闸本身就是个「静默假成功」洞**：正文校验只检查**前 20 个字符**是否出现在编辑器里。正文被吞掉 90% 也照样判成功。今天它没爆，**只是因为 30s 硬墙让长正文根本走不到提交**——任何「让长正文跑得完」的修法都会**给这颗雷上膛**。

（相邻代价：同账号连续 2 次序列失败即触发熔断，**整条已审发布队列停摆**、需人工重新审批；`failed` 是终态，稿件与配图直接烧掉。）

## What Changes

**核心是把语义反过来：让边缘永远先答。** 云端按正文长度算出这一步的**执行预算**随指令下发；边缘据此自我掐表、超时即停手清场并诚实回报；云端只在预算之上多等一点点兜底。于是「孤儿打字循环 / 迟到回执被丢 / 租约提前释放 / 浏览循环抢占同一页」这一整条级联**由构造消失**——而不是靠再加一道补丁去追。

- **云端按正文长度下发单步预算**（`base + 每字 × 字数`，上限硬钳）。复用协议里**早已声明、无人读写**的 `PublishCommandPayload.timeoutMs`——**不改协议、不新增消息类型、不碰主动命令白名单**。
- **云端等待窗口 = 下发预算 + 兜底余量**；该 timer 从「正常路径」退化成「边缘真的失联」的兜底。**不带预算的指令（小红书全路径）逐字节沿用旧常数窗口**，零回归。
- **预算上限按发布租约 TTL 收敛**（≤0.4×）：否则边缘会在打字途中单方面过期租约、恢复浏览循环去驱动半写的编辑器。
- **正文超出可打完的上限 → 诚实 `content_too_long`，绝不截断**、一条指令都不下发。
- **边缘自我掐表**：预算耗尽即停止输入、清空编辑器、诚实回报；清不干净则如实标 dirty（绝不谎报干净页）。逐字符的拟人节奏**一个字节不动**。
- **验收闸换成全文回读**：确认编辑器完整包含终稿正文；额外内容超容差（如打字途中被 typeahead 劫持）亦判失败。
- **打字前先清空编辑器并校验为空**，斩断脏稿拼接。

**已核实不需要做的**（避免过度设计）：身份监测体在发布期间**不必挂起**——FB 身份从 `c_user` cookie 读取，与编辑器弹层无关，抬预算不会新增其射程；XHS 侧则由 `creator-app` 页面上下文闸豁免。

**评估后否掉的三条路**：**边缘分块插入**押注在从未验证的 FB 编辑器行为上，且把一个响亮的失败换成可能静默的失败（吞掉的块 → 截断的帖子真发出去）；**云端拆多条 fill 命令**要跨仓改协议 + 强制出一次桌面安装包，并独有一条「新云端配旧客户端 → 把打乱的帖子真发出去」的最坏路径；**调快打字节奏**只能把悬崖从约 180 字挪到约 250 字，而管线默认产出 200–500 字，照样爆（且直接削弱拟人度）。

## Impact

- `aidcp-cloud`: `src/publish-agent/fill-budget.ts`（新增）、`src/publish-agent/platform-profile.ts`、`src/publish-agent/command-sequencer.ts`、`src/publish-agent/prompts.ts`、`src/server.ts`

- **协议不变**：`PublishCommandPayload.timeoutMs` 是既有可选字段，消息类型数仍为 74，`AC-PROTO-*` 不动。
- **向后兼容**：旧边缘忽略下发的预算、按旧行为跑（不劣化）；新边缘在云端未下发预算时用 25s 兜底（**小于**云端 30s 常数窗口 → 即使对端未升级也是边缘先答，诚实失败而非孤儿执行）。
- **小红书零回归**：不带预算的指令等待窗口逐字节不变；逐字输入辅助不传截止时刻即行为完全不变（XHS 搜索/评论、FB 评论均不受影响）。
