## 2. 接口进程构造并启动排期器

- [ ] 2.1 接口仓手写入口：读部署目标 → 缺失或非法则**不启动该定时器**并留具名 fail-closed 日志

- [ ] 2.2 把接口侧现成的依赖接上：排期配置现读、小时格占位、账号平台、

- [ ] 2.3 结构断言：**自动化侧的启动装配 MUST NOT 构造这个调度器**（同一后台任务绝不两处各跑一份）。

- [ ] 2.4 用例：部署目标合法 → 调度器真在跑；缺失 → 不启动但接口其余能力照常；

## 4. 失败方向：逐条定死并做变异实测

- [ ] 4.1 按规格逐条落实失败方向：在线清单问不到 → 整个心跳跳过；风控状态问不到 → 跳过该账号；
  三个是否在跑问不到 → 判为在跑；委托占用问不到 → 判为占用；素材数问不到 → 判为 0。
- [ ] 4.2 把「未注入」与「问不到」在代码与日志上分开：前者是既定零回归跳过，
  后者是具名失败。两者今天在外部同形，正是本项目反复点名的静默假成功形态。
- [ ] 4.3 每条方向各配一条**喂失败输入**的用例。
- [ ] 4.4 **变异实测，逐条给出是哪条用例抓住的**：把每条方向改反（如在线清单失败回空数组、
  是否在跑失败回 false），确认当场有用例红。**没红的那条说明用例是空的**——
  上一个 change 实测过一次「桩把陈旧态置了空，而真实现会保留上一份，于是那条用例什么都没测」。
