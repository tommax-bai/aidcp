## Why

三进程拆分完成后，**定时发帖 / 定时评论没有任何一个进程在跑**。负责「到点该发了」的内容排期调度器按分工归接口服务，类也确实在接口仓里，但接口服务的手写启动入口**从不构造它**——今天不出事只因为还是单体在跑。真拆开的那天，到点什么都不会发生，**且没有任何一行日志说为什么**：队列里暂时没活与永远没人来处理，在外部完全同形。

同一条链的另一半也断着：自动化服务已有客户端在调「排期名额回程」（本槽没能开始 → 归还小时格），而接口服务**压根没提供这条口**。账面上这条能力标着已接线，真跑起来就是跨进程 404，而 404 会被读成「对面版本落后」——一个本该留给版本落后的具名原因，被一次纯接线遗漏冒名顶替。

顺带结掉一处**过度约束**：自动发帖今天把「触发那一刻账号在哪个浏览器环境」冻进稿件，之后只允许从同一个环境发；账号换了环境在线，稿件就一直不投。用户 2026-08-03 裁定：**账号连着引擎才执行排期这条闸保留，但不必管是哪个浏览器环境**。

## What Changes

- **接口服务真正构造并启动内容排期调度器**：读配置 → 组装依赖 → 每分钟心跳。部署目标按本机部署配置注入，缺失或非法即**不启动该定时器**（fail-closed，不是降级跑）。
- **接口服务注册「排期名额回程」路由**，落点与本进程内的调度器**共用同一个方法**——小时格账本只有调度器自己那一本，MUST NOT 造第二条路径。缺调度器时**响亮抛具名错误，绝不回 false**：回 false 读作「调度器看过了、没接管」，与「这个进程根本没有调度器」完全同形。
- **调度器所需的自动化侧事实改走跨进程端口**：在线账号清单、风控状态、发布/评论/加群三类触发、三个「在跑吗」单飞判定、委托任务占用判定。方向与既有的运营指令端口一致，不是新方向。
- **BREAKING（生产行为变更）**：**去掉自动发帖的浏览器环境绑定**，三处同批：
  - 调度器不再因「解析不出环境身份」跳过发帖；
  - 下发前的归属形状校验不再要求环境标识，**部署目标（dev/ol）判断原样保留**；
  - 下发时不再要求在线环境与冻结值精确匹配，账号在哪个环境在线就从哪个发。
  小时格占位的唯一键是「账号 + 动作」，环境标识只是记录列 ⇒ **幂等强度不变**，重启与跨进程同格仍不重复触发。
- **不改的**：账号必须连着引擎才执行排期（在线闸保留）；dev / ol 数据隔离；「同一个后台任务绝不在两个服务里各跑一份」；单体形态下的行为逐位不变。

## Capabilities

### New Capabilities
- `api-process-content-scheduling`: 内容排期调度器在接口进程内的承载——构造、启动闸、部署目标注入、跨进程取用自动化侧事实，以及「排期名额回程」的服务端落点与缺席语义。

### Modified Capabilities
- `content-schedule`: 自动发帖的执行归属去掉浏览器环境维度——触发前不再因环境身份不完整而静默关闭自动发帖，下发前不再按环境精确匹配；部署目标绑定与在线闸不变。

## Impact

- **aidcp-cloud**（事实源，先落这里再派生）：接口段的组装与路由注册、调度器的环境身份闸、发布下发的两处环境匹配、小时格占位的入参校验。
- **aidcp-api**（主）：手写启动入口构造调度器、注册回程路由、新建面向自动化的跨进程客户端。
- **aidcp-automation**：新增被调路由（在线账号清单、风控状态、三类触发、单飞与占用判定）。
- **数据**：`content_schedule_hour_claims` 的环境列退化为纯记录，并**随本 change 放宽其 NOT NULL**（expand 类迁移一条，表属主 api）——拿不到环境标识时写 NULL 而非空串占位。唯一键是「账号 + 动作」，不含环境列，故幂等强度不变。`publish_log` 已落库稿件里冻结的环境标识**保持可读、不再参与判定**（历史稿件不迁移、不作废）。
- **文档**：`docs/cloud-service-decomposition-proposal.md` §4.6.5 第 12 项那条「MUST 改为按排期表扫描、MUST NOT 以 Edge 在线为前置」与本次裁定相左，**须按用户裁定更正**（保留在线闸）。
