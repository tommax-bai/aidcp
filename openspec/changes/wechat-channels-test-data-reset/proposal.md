## Why

视频号测试账号的真实评论和私信样本很少，而 Cloud 与 Edge 都会记录已读数据和增量游标，同一条平台数据正常情况下不会再次进入待处理收件箱。开发、验收每测试一次就消耗一个真实样本，导致列表、详情和后续回复流程难以反复验证。

## What Changes

- 增加仅在 `dev` 开放的“重置测试数据”能力，允许当前环境所有者按评论或私信清空当前账号的 Cloud 入站互动副本、同步批次和游标。
- 重置后通过既有 Edge 同步通道清除对应本地读取检查点并从头重新拉取，使微信平台上仍存在的一两条真实数据可以再次进入 Cloud。
- 在 Electron 视频号工作区“开发者详情”中提供高风险入口、明确影响说明和二次确认；按评论/私信分别操作，不提供跨账号或批量环境删除。
- 重置严格保持只读：不删除微信平台原评论/私信，不发送回复，不修改授权、读取开关、回复配置、风险状态或账号写闸。
- 当环境不是 `dev`、Edge 不在线、账号未暂停写入或所选通道已有发送记录时拒绝操作；Cloud 记录不含消息正文的审计结果，并对清空成功但重新拉取未送达的部分完成状态如实返回。

## Capabilities

### New Capabilities

- `interaction-test-data-reset`: 定义开发环境内按账号、按通道清理 Cloud 入站副本、重置 Edge 读取检查点、重新拉取及审计/失败真态的完整契约。

### Modified Capabilities

- `client-customer-auth`: 增加当前环境所有者可调用、仅 dev 可用且受安全前置约束的互动测试数据重置 API。
- `edge-companion-ui`: 在视频号工作区开发者详情中增加带影响说明、二次确认和诚实进度/结果的测试数据重置入口。

## Impact

- `aidcp-cloud`: customer-auth 路由、互动存储事务、同步请求下发、审计和测试。
- `aidcp-edge`: 视频号同步请求协议、本地检查点清理、连接器串行化、Electron IPC/客户端界面和测试。
- `aidcp`: OpenSpec 契约与 `docs/protocol.md` 的 `interaction.sync.request` 原因枚举说明。
- 不新增生产能力，不修改微信平台数据，不放开任何写 capability，不构建或发布 Edge 安装包。
