## Why

Facebook 环境当前虽可把多行账号资料依次导入 AdsPower，但仍复用单环境表单：模板只能手选一次、代理只能填一条，无法按账号批量分配不同代理，也没有清晰区分单建与批量建。运营需要一个 Facebook 专用的批量入口，在一次粘贴账号与代理后按确定规则完成多个环境创建，同时继续保持凭据不落盘和失败结果诚实可见。

## What Changes

- 仅在新建环境的平台选择为 Facebook 时展示“单个新建 / 批量新建”方式；其他平台不出现也不能调用批量模式。
- 批量模式接受多行 Facebook 账号资料，每行沿用现有 `email----password----2FA----cookie` 格式，一行对应一个待创建环境。
- 批量模式只选择一次代理类型，并接受多行代理资料；所有代理使用同一类型，代理按账号顺序循环分配，账号数超过代理数时从第一条代理开始下一轮。
- 批量模式不允许选择环境模板；每个账号由主进程从现有、已通过一致性护栏的整机模板中独立随机选择一套完整模板。
- 在创建前完整校验账号、代理、平台与账号上限；创建期间保持串行与单飞。中途失败时停止后续创建并如实返回已成功条数，不自动批量删除已建环境。
- Facebook 账号、2FA、cookie 与代理账密继续只在本次 IPC/AdsPower `user/create` 内存链路中使用，不写设置、台账或日志，回执不回显敏感原文。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `adspower-environment-provisioning`: 增加 Facebook 专用批量创建入口、多行账号/代理校验、整套模板随机选择、代理轮询分配和部分失败回执要求。

## Impact

- `aidcp-edge` Electron 渲染层的新建环境表单、样式与 IPC 入参。
- `aidcp-edge` 主进程 AdsPower 创建编排，以及新增的批量代理解析/分配纯逻辑。
- 现有 `user/create` 写客户端、一次性 Facebook 账号导入、预置 `aidcp` 分组、客户归属意图和创建后花名册确认链路继续复用；不新增云端 API、持久化表或依赖。
