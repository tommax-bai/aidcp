## Context

当前 renderer 已完成左侧零环境创建卡和环境管理表单重排，但实际客户端截图显示右侧仍在渲染旧选中环境留下的身份、Facebook 徽标、代理状态、待命工作区、发布空态、今日进展、浏览器/启动按钮和 `environment_not_owned`。这使“环境 0”与“已有一个可运行 Facebook 环境”两种语义同时出现。环境管理浮层已统一承载加入、新建和代理配置，创建能力及安全门禁完整，本次补充把同一权威零环境状态扩展到整个 shell。

环境栏的权威空态继续来自 `railEnvList()` 的完整运行花名册，而不是当前平台筛选结果、DOM 行数或 AdsPower 探测结果。创建成功仍以现有主进程回执、花名册落盘和 fleet 快照为准；UI 不提前构造虚假环境行。

## Goals / Non-Goals

**Goals:**

- 让已确认零环境的新用户一眼看到唯一下一步，并直接进入创建页。
- 仅在全量运行花名册为零时隐藏无效的筛选、汇总和批量运行区域；筛选结果为空但仍有其他环境时保持现有能力。
- 让环境管理导航和新建表单具备清晰的标题、字段、渐进式代理配置和底部主操作层级。
- 让右侧工作区与左栏共享同一个权威零环境判断，只呈现一条清晰的首次使用路径，不泄漏旧选中环境或内部原因码。
- 在现有客户端蓝色圆角卡片语言内解释“创建环境 → 登录账号 → 开始运行”，让用户理解下一步和创建后的价值。
- 保持加载、失败、创建中、成功和失败口径诚实且可测试。
- 让客户端启动先等待权威 fleet 全量快照，再决定空态或日常态，消除老用户登录时的空态闪烁。

**Non-Goals:**

- 不增加第二套 onboarding 状态机、主进程 IPC、Cloud API 或数据库字段。
- 不改变环境创建、客户归属、代理解析、Facebook 批量建号、花名册落盘或运行生命周期语义。
- 不把占位卡做成真实环境行，不赋予平台头像、状态点、离线状态或可启动 ID。
- 不重做有环境时的环境列表、批量代理、设置抽屉或右侧业务工作区。
- 不自动创建、启动浏览器、登录账号或触发自动化；首次引导只说明路径并打开既有创建页。

## Decisions

### 1. 用全量运行花名册判定专用零环境态

`renderRail()` 继续以 `allList.length === 0` 作为 `rosterEmpty`，并把该布尔值放入渲染签名和环境栏类名。CSS 仅在该类名存在时隐藏平台筛选、Facebook 批量人设、汇总、收起按钮、收起态管理入口和栏尾运行操作；当前平台筛选结果为空但 `allList` 非空时仍渲染筛选器与“暂无该平台环境”。

不用 AdsPower 列表、当前筛选行或 DOM 数量判空，因为这些值可能处于读取中、失败或局部筛选状态，不能代表客户确实没有运行环境。

### 2. 占位卡是创建按钮，不是虚构环境

空态按钮保留在 `rail-list` 内，但使用加号图形、主标题“创建第一个运行环境”、辅助说明“创建后可在这里切换账号并查看运行状态”。它没有 `.rail-row`、平台色、状态点或环境 ID，点击直接调用 `openEnvAddPanel('create')`。

栏头“管理”仍保留作为已有环境/高级入口；零环境时点击它也直达创建页。这样主入口不绕路，同时没有删除加入已有环境的“环境”页。

### 3. 环境管理使用文字页签和纵向创建表单

浮层头增加简短副标题，页签改为内容宽度文字导航和底部激活线，不再把两页伪装成并列主按钮。新建页按“选择平台 → 浏览器系统 → Facebook 条件字段 → 代理设置 → 创建回执”排序：

- 平台仍使用现有 `select` 值和事件链，视觉上包装为具名字段，不新增平台状态源。
- 操作系统使用全宽字段；Facebook 批量模式继续隐藏该字段并由主进程随机分配。
- 代理默认显示“无代理（可稍后配置）”摘要；选择非 `no_proxy` 或展开按钮后才呈现结构化代理字段。Facebook 批量代理继续按原条件显示。
- “创建环境”从字段行移到底部动作区，成为唯一蓝色主按钮；取消只关闭浮层，不修改输入。

优先复用现有 DOM ID 和事件监听，避免改 IPC 和测试桩；新增包装结构、辅助文案和 CSS class，不复制创建逻辑。

### 4. 创建反馈保持现有回执权威并补齐交互锁

创建期间给新建页加 `is-creating` 状态、禁用页签切换/关闭/重复提交，并让按钮显示“正在创建…”；创建完成后按现有回执更新花名册和列表。单个成功后切回“环境”页，使新加入的离线环境可见；批量或部分失败保留当前页及输入/错误，避免用户丢失核对上下文。

若实际创建请求无法取消，遮罩点击和 Escape 在 `is-creating` 期间不关闭；这只是一层 renderer 交互锁，不声称请求具备取消能力。

### 5. 零环境状态扩展为完整 shell 引导态

`renderRail()` 计算出的同一个 `rosterEmpty` 同步切换 shell 的零环境类名和右侧引导容器，避免左栏、标题栏和工作区各自猜测状态。零环境时：

- 标题栏只保留应用标识、全局 Cloud 环境和设置入口；隐藏旧环境名、平台徽标、代理运行摘要及环境生命周期状态，改为中性的“开始使用”。
- 隐藏当前环境标题、发布摘要、今日进展、活动流、开发者详情、浏览器和自动化生命周期按钮；这些区域依赖真实选中环境，不用零值或禁用态占位。
- 在原工作区位置展示一个单一首次引导面板，主标题为“创建你的第一个运行环境”，说明每个环境独立保存浏览器账号、代理与运行状态，并用三步卡片呈现“创建环境 → 登录账号 → 开始运行”。唯一蓝色主按钮“创建运行环境”调用 `openEnvAddPanel('create')`。
- 引导不显示 `environment_not_owned` 等内部错误码；这些诊断仍可在真实环境的开发者详情中按既有规则出现。

引导容器使用语义化标题、说明和原生按钮，不自动抢焦点；键盘聚焦有清晰 focus ring，`prefers-reduced-motion` 下不依赖动效传达步骤。重复点击左栏创建卡、栏头管理或右侧主按钮均打开同一创建页，不产生不同状态源。

### 6. 第一个真实环境进入花名册后原位恢复

首次引导退出仍只认 `allList.length > 0`。创建回执本身不提前隐藏引导；只有环境进入权威运行花名册并触发 `renderRail()` 后，shell 才恢复环境身份、平台、工作区和生命周期控制。若创建失败或仅收到不完整回执，继续停留在零环境引导，避免出现半初始化工作区。

### 7. 首次引导视觉主次不伪造进度

右侧引导承担解释价值与唯一高强调主操作，应在常见桌面窗口中靠近内容区上方呈现，避免垂直居中产生大段无意义顶端留白。卡片顶部不使用只填充一部分的色条或其他没有运行事实支撑的装饰，避免用户把它理解为加载或完成进度。

左侧占位卡继续作为固定导航入口，但缩小图形、间距和文字对比度，不使用实心主按钮样式；右侧“创建运行环境”仍是整页唯一高强调 CTA。三步卡片保持当前步骤提示，但辅助说明使用可在支持宽度内完整阅读的短句，第三步改为“查看进展与真实状态”，避免孤立单字换行。布局调整只改 CSS 与静态文案，不改变点击路由、花名册判断或创建状态。

### 8. 第一个环境创建完成后直接交接到主界面

点击创建时只在“非批量、权威运行花名册为空且设置花名册也为空”时记录首次创建候选。创建接口成功不是关窗条件；renderer 先按既有流程回读主进程 `settings.environments`、刷新物理环境列表，再主动读取一次 fleet 快照。只有回执中的精确 `userId` 已在设置花名册和 fleet 环境中出现时，才选中该环境、关闭环境管理并展示正常主界面。

若 fleet 快照稍后才到，保留环境管理窗口和已创建回执，待 `applyFleetSnapshot()` 或该环境状态进入后再完成交接；不得关闭后回到零环境空态。创建第二个及后续环境仍切回环境列表供管理，批量创建、部分成功、失败、需要管理员分配或未进入花名册时继续留在原窗口。

### 9. 主界面使用一次性“启动环境”接续提示

首次交接完成后，在“启动”按钮旁展示短提示：“下一步 / 启动运行环境 / 系统会打开浏览器，请完成平台登录”，并给按钮三次柔和扩散光环。它只绑定刚创建环境的 `envId`，只有该环境仍被选中且生命周期动作真实为 `start` 时可见；不自动聚焦、不自动点击，也不改变按钮颜色所表达的未启动状态。

提示是本次 renderer 会话内的临时交互态，不写设置、不跨重启重放。用户点击启动、主动关闭提示、切换环境，或权威状态变为启动中、运行、暂停等非 `start` 动作时立即清除。`prefers-reduced-motion` 下取消扩散动画，但保留静态描边和文字提示；这样动效只是注意力辅助，不是理解下一步的唯一方式。

### 10. fleet 未决时先展示中性加载态

renderer 从 HTML 首帧即带 `environment-roster-loading`，环境栏展示无平台、无状态语义的骨架行，主区域展示“正在读取运行环境”与骨架卡。`getStatus()` 或单环境状态推送不得提前把加载态改成零环境，因为它们不是当前客户的权威全量花名册。

只有格式有效的 `fleetGet()` / `onFleetUpdate` 全量快照能把 roster phase 收敛为 `ready`：快照为空进入首次引导，快照非空进入日常工作区。读取失败进入独立错误态并提供重试，MUST NOT 用零环境空态兜底；不支持 fleet API 的旧主进程继续按既有兼容路径收敛，不永久停在 loading。

### 11. 大窗口余量只做非语义化视觉收口

首次引导卡保持靠上但使用随视口高度收敛的间距和最大宽度；主区域下方以低对比径向光晕和点阵纹理承接大窗口留白。装饰层 `aria-hidden`、不含环境行、数字、状态点或分段路径，也不响应点击，避免被理解为真实环境或加载进度。矮窗取消多余装饰并缩短外边距，内容自然滚动；`prefers-reduced-motion` 下环境光和骨架扫光均静止。

## Risks / Trade-offs

- [隐藏栏尾后空态卡可能显得过高] → 空态列表使用紧凑居中卡，不改变有环境时固定高度和滚动规则。
- [CSS 包装影响 Facebook 条件字段] → 保留全部既有 ID、`hidden` class 和 `updateFacebookImportVisibility()`，测试单个/批量两种 DOM 可见性。
- [创建成功立即切页可能掩盖批量回执] → 只对确认成功的单个创建切回环境页；批量和任何失败留在创建页。
- [零环境与读取失败混淆] → 零环境只看权威运行花名册；AdsPower 探测/列表失败仍在浮层中显示错误，不参与环境栏判空。
- [弹窗变宽或内容变高] → 保持 620px 现有宽度和 `max-height` 内滚，不引入新的桌面窗口尺寸假设。
- [首次引导与左侧创建卡重复] → 左栏承担稳定导航入口，右侧承担解释价值与主路径；两者调用同一创建函数，视觉上只保留一个右侧主按钮。
- [初始渲染短暂闪现空态或旧工作区] → HTML 首帧进入 loading，只有权威 fleet 全量快照才能原子切到 empty/ready；失败保持未知并可重试。
- [靠上布局在矮窗口中拥挤] → 使用响应式 `clamp()` 上边距和现有滚动容器，不写死窗口高度，也不依赖垂直居中。
- [创建回执早于 fleet 快照导致关窗后仍为空态] → 交接同时校验设置花名册和精确 fleet 环境；证据不足时保持窗口，不用超时猜成功。
- [启动提示误导其他环境或持续打扰] → 临时态绑定精确 `envId`，只在真实 `start` 动作可见，并在点击、切换或状态变化时清除。

## Migration Plan

1. 新增 renderer DOM/CSS、完整工作区空态路由测试和可复现视觉预览，再调整样式与交互。
2. 在独立 `aidcp-edge` worktree 运行聚焦 Electron 测试、完整测试和 typecheck。
3. 回写提交与验证证据，严格校验 OpenSpec，串行 fast-forward 到 `aidcp-edge/master` 并推送。
4. 本变更不改服务器运行时，不部署 dev/ol，不构建安装包；源码回滚为回退 Edge 提交。
