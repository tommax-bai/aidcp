## Context

`aidcp-edge` 已能通过 AdsPower 本地 API 启动指定 profile，并使用现有 CDP client 驱动 Chromium。Facebook 与小红书已有手动探针，但 TikTok 尚无平台模块或真实页面证据。本变更必须在不接入生产协议、Cloud 调度和风险计数的前提下，回答四个窄问题：网页信息流能否稳定浏览、一次点赞能否由页面状态确认、评论文本能否只填入编辑器而不提交、合成素材能否进入发布编排器并停在最终发布之前。

TikTok 信息流采用客户端渲染与虚拟化复用，页面结构会因语言、地区、登录状态和 A/B 实验变化。探针不能缓存长期 DOM node，也不能把鼠标事件派发或页面静止误判为业务成功。

## Goals / Non-Goals

**Goals:**

- 复用现有 AdsPower + CDP 基础设施连接明确指定的本地 profile。
- 对浏览、点赞和评论输入分别产生可测试、可回查且不含敏感数据的证据。
- 参考 Facebook 与小红书现有探针，以独立、语义定位的 no-submit 路径验证 TikTok 上传和编排器状态。
- 真实点赞必须双重显式授权、目标唯一、状态前后闭环；评论路径必须在代码层没有发送能力。
- 登录失效、挑战页、页面歧义、虚拟列表换项和确认超时均诚实失败。

**Non-Goals:**

- 不注册 TikTok 为正式生产平台，不接 Cloud 自动浏览、发布、评论或风控计数。
- 不绕过验证码、登录验证、风控限制或平台安全措施。
- 不实现批量点赞、批量评论、关注、最终发布、数据抓取或私有接口调用。
- 不保证当前探针选择器可长期跨 TikTok 页面版本稳定工作。

## Decisions

### 1. 使用独立的手动探针模块，不接入生产命令路由

在 `src/tiktok/probes/` 放置可单测的页面探测与动作逻辑，由 `scripts/tiktok-interaction-probe.ts` 负责 AdsPower 生命周期和运行编排。这样可以复用 CDP 原语，同时避免尚未验收的 TikTok 能力被 Cloud 或客户端误调用。

备选方案是直接增加 `PlatformId`、协议消息和生产 driver；当前没有足够页面证据，也会扩大风险与验证范围，因此不采用。

AdsPower 本地 API 是首选 profile→debug port 绑定来源。如果 API 暂时不可用而已启动浏览器仍存活，手动探针允许显式传入 debug port，但必须从 `/json/list` 找到 `start.adspower.net` 且 `id` query 与目标 profile 精确一致的 marker 自证归属；否则拒绝连接。该 fallback 不拥有浏览器生命周期，也不能请求关闭浏览器。

### 2. 每一步重新读取当前视频稳定标识

探针从当前可见视频的规范链接中提取 `/@<author>/video/<id>`，并在滚动、点赞前、点赞后和评论输入前重新探测。任何多目标、无目标或目标变化都中止当前动作。探针不持有跨滚动 DOM node，以适配虚拟列表节点复用。

备选方案是缓存首次找到的按钮或使用列表序号；TikTok 虚拟化可能令同一节点承载新视频，存在点错内容风险，因此不采用。

### 3. 点赞采用双重运行门和单向动作

真实点赞同时要求 `AIDCP_TIKTOK_PROBE_LIKE=1`，以及 `AIDCP_TIKTOK_PROBE_CONFIRM_PROFILE` 与实际 AdsPower profile 精确相等。未开闸时只报告可操作性。目标已经点赞时返回 `already_liked`，绝不点击取消；未点赞时只点击一次，随后要求同一视频按钮状态变为 liked，否则报告 `ambiguous`，不得算成功。

备选方案是单一布尔开关或盲点后看计数；前者容易误用其他环境，后者会受延迟和计数缩写影响，因此不采用。

### 4. 评论探针只有 fill API，没有 submit API

评论探针定位当前视频的可见评论编辑器，聚焦后使用 CDP 文本输入，并回读编辑器的 `textContent`/`value` 校验。实现中不查询发送按钮、不派发 Enter、不调用 form submit，也不暴露提交参数。运行结束默认保持浏览器打开，以便人工观察“已输入未发送”状态。

备选方案是复用生产评论 executor 的 dry-run 分支；该 executor 通常仍包含提交能力，配置错误可能造成真实发送，因此不采用。

### 5. 输出最小化脱敏证据

报告只记录 profile id、页面 host/path、视频 id、作者 handle、动作状态、挑战分类和时间戳。不得读取或输出 cookie、localStorage 内容、token、请求/响应正文或评论列表数据；评论报告只记录输入文本长度和匹配布尔值，不回显完整文本。

### 6. 发布探针只到编排器，不拥有最终提交能力

发布探针使用 TikTok 页面暴露的语义上传入口和唯一文件输入，先只读记录路由、接受类型、编辑器和页面阻断状态。只有调用方显式提供合成测试素材时，才通过 CDP 文件输入能力选择该精确路径，等待页面自身给出上传完成或可编辑证据，再可选填写无敏感测试文案并回读。

实现不查询或点击最终发布控件，不派发 Enter、Ctrl+Enter 或 Meta+Enter，不调用 form submit，也不暴露启用发布的开关。选择文件可能把合成素材传输到 TikTok 并形成平台草稿，因此报告必须区分 `file_selected`、`upload_acknowledged`、`composer_ready_not_submitted` 与 `published`；本探针永远不得产生或宣称 `published`。

备选方案是复用未来生产发布 executor 的 dry-run 分支；这会让最终提交能力进入探针代码并扩大误触风险，因此不采用。也不为本次探测新增平台注册、协议、Cloud 编排或持久化模型。

## Risks / Trade-offs

- [TikTok DOM/可访问性标签随语言或实验变化] → 使用结构、规范链接和多语言语义组合，无法唯一确认时失败，并以真机观测更新 fixture。
- [点赞 UI 乐观更新但服务器未确认] → 本探针只能证明同页 UI 状态确认，报告明确标为 `ui_confirmed`，不宣称服务器持久化；正式接入前仍需设计更强回查。
- [虚拟列表滚动时目标被回收] → 每次动作前后重探 stable video id，目标不一致立即停止。
- [评论文本可能被浏览器草稿机制暂存] → 不发送仍是硬边界；探针不宣称页面刷新后不会保留本地草稿，且默认留给操作员观察和手工清理。
- [选择文件会把素材传到 TikTok 或形成服务端草稿] → 只使用可丢弃的无敏感合成素材，明确报告上传/暂存事实，不把它描述为公开发布。
- [上传页面和控件因 TikTok Studio 实验变化] → 使用 route、`data-e2e`、role、accept 等语义组合；候选不唯一或上传状态不明确时失败关闭。
- [本地 profile 已被其他进程占用] → 复用 active debug port 或由 AdsPower 返回明确失败，不做跨机器强占。

## Migration Plan

1. 在隔离的 Edge 工作树实现模块、脚本与聚焦测试。
2. 先以默认只读模式在 `k1eu5amn` 运行，确认登录状态、当前视频和滚动变化。
3. 显式打开点赞双门，最多执行一次未点赞到已点赞的转换并记录 UI 证据。
4. 设置无敏感内容的测试文本，只填入评论编辑器并保持浏览器打开，确认没有发送动作。
5. 只读探测 TikTok 上传入口和编排器；如结构明确，选择临时生成的合成视频并填写无敏感测试文案，停在最终发布之前。
6. 不部署、不迁移数据库；回滚只需移除探针文件和分支，不影响生产运行时。平台侧可能保留的素材草稿由操作员在该测试环境中观察或清理。

## Open Questions

- TikTok 当前账号页面实际暴露的点赞状态语义、评论编辑器 role/placeholder 和挑战页结构，需要由首次只读真机探针确定。
- 如果未来进入正式接入，点赞服务器确认、用户授权、平台条款评估和 Cloud 风控记账需另立 OpenSpec，不能由本探针结论直接推导。
