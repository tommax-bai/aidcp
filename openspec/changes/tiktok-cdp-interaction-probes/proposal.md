## Why

AIDCP 目前没有经过真实浏览器验证的 TikTok 网页端能力，无法判断现有 AdsPower + CDP 基础设施能否可靠完成信息流浏览、单次点赞和评论编辑器输入。需要先用本地测试环境建立一组默认安全、证据可回查的探针，再决定是否进入正式平台接入。

## What Changes

- 新增 TikTok 网页端 CDP 交互探针，支持登录/挑战页识别、当前视频稳定标识、信息流滚动和滚动后内容变化验证。
- 新增一次性点赞探针：默认只读，只有显式动作开关打开且目标仍唯一匹配时才点击；已经点赞时不反向取消，点击后必须由同一视频的 UI 状态确认。
- 新增评论输入探针：只定位并填写当前视频评论编辑器，代码路径不包含提交点击或回车提交，并回读编辑器内容确认输入成功。
- 探针输出脱敏的结构化证据，不读取或打印 cookie、token、原始账号标识、请求正文或其他敏感数据。
- 使用本地 AdsPower 环境 `k1eu5amn` 做受控真机验证；浏览和一次点赞可真实执行，评论停在已输入未发送状态。
- 本变更仅交付开发/验收探针，不把 TikTok 宣称为已接入的正式生产平台，也不修改 Cloud 风控、协议或自动运营调度。

## Capabilities

### New Capabilities

- `tiktok-cdp-interaction-probes`: 规定 TikTok 网页端浏览、受控点赞、评论只输入不发送、挑战页中止和脱敏证据的探针行为。

### Modified Capabilities

无。

## Impact

- 代码：`aidcp-edge` 新增 TikTok 探针模块、手动运行脚本和聚焦测试。
- 运行环境：本地 AdsPower API 与 `k1eu5amn` profile；不访问 Cloud，不部署到 dev/ol。
- 协议/API：无生产协议变更，无数据库变更，无新增第三方依赖。
- 风险：TikTok 页面布局、语言和 A/B 实验可能导致探针诚实失败；验证码、登录失效、目标歧义或点赞后状态不明确时必须中止，不得推断成功。
