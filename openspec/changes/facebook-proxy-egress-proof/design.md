## Context

AdsPower 的本地 API 只能说明环境保存了哪类代理配置，不能证明正在运行的 Facebook 页面实际从哪个公网出口访问。当前 Edge 也没有按浏览器代际维护网络接收字节数，因此运行页既缺少运行时证据，也容易把“已配置”误读为“已生效”。

实现横跨 Cloud 的公网回显端点、Edge 核心的 CDP 观测与 Electron 运行页。必须保持三个边界：探测必须由目标指纹浏览器自己的网络上下文发出；未知结果不得变成绿色成功；界面只呈现非敏感配置摘要和聚合接收字节，不采集 URL、Cookie、正文或代理密码。

## Goals / Non-Goals

**Goals:**

- 为每一代运行中的 Facebook 指纹浏览器生成可追溯的浏览器出口证据，并与同一 Edge 子进程的直连出口比较。
- 从 CDP 已完成请求事件累计本次浏览器会话可观测的接收字节。
- 在选中账号的运行页顶栏以紧凑状态呈现，并在详情中区分配置、浏览器出口、本机出口、检测时间与流量口径。
- 探测失败、浏览器与本机出口相同、配置缺失等情况诚实降级，但首版不阻断既有运行流程。

**Non-Goals:**

- 不实现代理商计费流量、上传流量、请求数或整机所有进程流量。
- 不持久化逐请求网络记录，不采集 URL、Cookie、请求/响应正文。
- 不校验代理 IP 的国家、城市、ASN 或账号策略匹配，不自动停号或切换代理。
- 不在 Cloud 建立代理台账或新增数据库表。

## Decisions

### 1. Cloud 提供无状态公网回显端点

Client Auth HTTP 服务新增公开只读 `GET /egress`。端点从受信 nginx 以 `$proxy_add_x_forwarded_for` 追加的最右侧 `X-Forwarded-For` 地址（无有效地址时使用 socket 地址）得到 nginx 实际观察到的最近连接出口，拒绝采信可由客户端或上游代理伪造的左侧前缀；响应体和响应头返回来源 IP、服务端时间与随机请求标识，并设置 `Cache-Control: no-store` 与允许无凭据跨域读取的 CORS 头。端点不接收账号、环境或代理参数，不读写数据库。

选择复用既有 Client Auth 公网基址，是因为 Edge 已按 dev/ol 注入该基址，部署面已有 nginx 转发与健康检查。备选方案是第三方 IP 服务，但会引入可用性、隐私和响应格式依赖；另一个备选是仅由 Node 发请求，但它无法证明浏览器代理路径。

### 2. 浏览器探测使用当前 page 的 CDP Network 上下文

Edge 为 AdsPower Facebook 会话启用 `Network` domain，从当前顶层 frame 调用 `Network.loadNetworkResource`，参数关闭缓存且不携带凭据。探测结果从响应头读取出口 IP；该请求不得包含环境 id、账号 id 或 Cookie。若当前 Chromium 不支持该命令、端点不可达或响应不完整，则状态为无法确认，不回退成“已验证”。

选择 CDP 网络上下文是为了让探测与该指纹浏览器使用同一代理栈，同时避免导航当前 Facebook 页面。备选的页面内 `fetch` 会受 CSP、页面脚本环境与站点 Cookie 策略影响；导航到检测页会破坏正在运行的业务页面。

### 3. 用浏览器出口与 Edge 直连出口形成状态，而非仅看配置

同一子进程还通过 Node 直连访问回显端点。浏览器出口与本机出口都成功且不同时，运行证据为“已验证”；两者相同时为“疑似直连”；仅配置存在但尚无完整证据为“待验证”；浏览器探测失败或证据超出当前浏览器代际为“无法确认/已失效”；配置明确为空时仍显示“未配置代理”。配置态只影响文案，不覆盖运行证据。

状态及证据通过既有 `[ui-event]` 结构化行进入 Electron fleet 投影。IP 只保留在当前运行态内，不落盘。浏览器每次新启动和冷待机唤醒均开启新代际：接收字节清零，旧出口证据立即失效，再异步探测；普通 CDP 重连不重置同一浏览器代际。

### 4. 会话流量只累计 CDP 已完成请求的接收字节

观测器订阅 `Network.loadingFinished`，对有效非负的 `encodedDataLength` 求和，并以节流后的聚合事件推送到 Electron。统计从 Edge 接管并启用 Network 后开始，包含受管 page 网络目标可观测的响应编码字节；它不是代理商账单，也不保证覆盖接管前加载、浏览器扩展、其他 profile 进程或未受管 target。

选择 `loadingFinished.encodedDataLength` 是因为它提供已完成请求的总接收字节，且无需记录 URL。备选的 OS/代理层计数覆盖更广，但无法在现有架构中可靠归属到单个 AdsPower 环境；逐个 `dataReceived` 累加会增加事件量且仍不等于供应商计费口径。

### 5. 顶栏紧凑入口承载结论，详情承载证据

仅在当前选中 Facebook 环境的账号身份区显示代理状态入口。紧凑态显示结论和本次会话接收流量；详情显示非密代理类型/地址摘要、浏览器实际出口、本机出口、最后检测时间、流量值和口径说明。代理密码永不进入渲染数据。异常状态使用明确警示色但不自动停止环境；主环境列表不铺完整 IP。

## Risks / Trade-offs

- [Chromium 版本不支持实验性 CDP 命令] → 以“无法确认”降级并保留本机出口证据，绝不显示已验证。
- [nginx 转发头配置错误导致来源 IP 不可信] → 聚焦测试覆盖首个转发地址与 socket 回退，部署验收实际请求端点并核对响应；端点只部署在既有受控反代链路。
- [高频 Network 事件增加 UI 压力] → 核心只累计数字并节流推送，不传 URL 或逐请求事件。
- [统计低于浏览器/代理商账单] → UI 固定标注“从本次接管开始的受管页面可观测接收流量”，不使用“总流量/计费流量”措辞。
- [一次探测受短暂网络波动影响] → 失败保持无法确认且不阻断运行；新浏览器代际和冷唤醒自动重新探测。

## Migration Plan

1. 先部署 Cloud 回显 route 并验证 dev 公网路径、CORS、no-store 与真实来源 IP。
2. 再发布 Edge 源码变更；旧 Cloud 未部署或不可达时 Edge 仅显示无法确认，运行不被阻断。
3. 回滚 Edge 时 Cloud route 可安全保留；回滚 Cloud 时 Edge 自动诚实降级。无数据库迁移。

## Open Questions

- 首版不做地区/ASN 策略校验；若后续需要“出口地区符合账号策略”或异常自动暂停，另立带风险控制契约的变更。
- 首版在每个新浏览器代际自动探测，不提供持续定时探测；是否增加人工重检或周期复检由实际故障频率决定。
