## Context

桌面外壳（`aidcp-edge/src/electron`）为每个环境监督一个核心子进程。启动是一条几十秒的流水线，取消（暂停 / 关闭 / 移出 / 客户端退出）在流水线的多个站点被复核：

- `enqueueStartFlow` / `startFlowForEnv` / `startAdsPowerFlow`：每个 await 之后都复核代号与 `stopRequested`（`main.cjs:5765`、`:5794`、`:5798`、`:5800`）。
- `startEdge` 的队列任务体：出队时复核一次（`main.cjs:4394-4408`）。
- `spawnEdgeChild`：进门复核一次（`main.cjs:4439-4441`）。

**缺口在最后一段**：`spawnEdgeChild` 进门复核之后还要 `await adsBrowserStartupState()`（`:4460`）与 `await ensureNetworkPreparation()`（`:4465`），这两步在真机上跑了十几到几十秒，之后一路同步走到 `spawn()`（`:4626`）**不再复核**。2026-08-04 20:10 的真机事故正落在这段缝里：20:10:06 关闭（走「无子进程 → 无事可停」分支并宣布已确认关闭），20:10:15 同一趟启动把核心拉了起来。

该核心随后无人认领，原因是三个机制各自成立、叠起来失效：

1. 关闭路径已经收工，`stopAutomation` 不会再被调用，没有任何一方向它发关闭指令。
2. 它带的是关闭前的操作代号（关闭时 `advanceLifecycleGeneration` 已 +1），而 `handleEdgeOutput`（`main.cjs:5907`）与 `onChildMessage`（`:4796`）都以「代号一致」为丢弃判据 → 它的输出与消息**全量静默丢弃**，真机上 13 分钟零日志。
3. `occupiedSlots()`（`:2748`）按「子进程活着」计数 → 它永久占一格；`lifecycleAxes`（`:6725`）把「点过关闭且子进程还在」投影成 `stopping` → 界面永久「关闭中」。

约束：不得改动浏览器并发名额的统计口径（放掉卡住核心的名额会超额开浏览器打爆内存）；不得引入协议 / 云端 / 数据库改动；改完的客户端要用户重新出包才生效。

## Goals / Non-Goals

**Goals:**

- 取消意图与「拉起核心子进程」之间**不存在中间地带**：取消要么阻止拉起，要么被关闭路径看见。
- 「无人认领的核心子进程」成为结构上不可能，而不是靠每条启动路径各自记得复核。
- 故障可观测：仍归本环境所有的子进程，其输出必须留下痕迹，绝不因操作代号变化而整段消失。
- 就绪超时对运营如实可见。

**Non-Goals:**

- 不改浏览器并发名额的统计口径、不改串行启动队列与槽位 FIFO 语义（属活跃 change `browser-slot-scheduling`）。
- 不改「代号门控界面运行态投影」这条既有保护（它防的是旧代把界面写回去，目的正确）。
- 不为卡住但确实持有浏览器的核心增加自动回收（放掉名额风险大于收益，见 Non-Goals 上一条）。
- 不加任何开关 / 环境变量旁路：这是红线违规修复，不留可绕过口。

## Decisions

### D1：提交点原子化用「同步函数」表达，而不是「多加一句复核」

把 `spawnEdgeChild` 拆成两段：

- **准备段（可 await）**：分身 active 状态、网络 / 代理准备、身份与 env 构造、Native 产物校验等，产出一个纯数据的启动方案。
- **提交段（同步、不带 `async`）**：复核取消闸 → `spawn()` → `initializeOwnedCoreChild()` 登记所有权 → `prepare()` 写入启动态。

选同步函数而不是「在 spawn 前补一句 if」：JS 单线程下，同步段内不可能有其它任务插入，取消要么在复核之前到达（不拉起），要么在所有权登记之后到达（关闭路径看得见）。**中间地带被语言层面消掉，而不是变窄。** 更重要的是它抗回归：日后有人要在这段里插一个网络检查，必须先把函数改成 `async` 并改调用点，改动一眼可见；而「补一句 if」的版本，插入一个 await 就静默恢复原状，源码扫描与既有用例全绿。

**被否的方案**：① 只在 `spawn()` 前补一次复核——本次能修好，但没有任何机械手段防止它被重新打开；② 用一把「启动锁」让关闭等待在途启动结束——把用户的关闭变成阻塞等待（最长几十秒），且关闭本就是最高优先的意图，不该排在启动后面。

### D2：兜底闸落在「所有权登记」这一处，且判据按启动意图分档

`initializeOwnedCoreChild`（`core-child-startup.cjs:69`）是 `handle.child = child` 的唯一入口，所有启动路径（常规启动 / 崩溃重起 / 待机唤醒 / 排期任务 / 无浏览器控制面 bootstrap / 受限离场清理）都必经此处。准入闸放这里，不变量就从「每条路径都要记得复核」变成「不管从哪来，进门必查」。

三个实现细节是有意为之：

- **先登记所有权与观测者，再终止**。不登记就杀 = 我们手上有一个不归自己管的进程，它的退出没人处理、名额没人归还——那是把一个 bug 换成另一个。登记后终止，走的是既有的退出路径：清 `handle.child`、归还名额、放行等槽位队列。
- **判据由调用方按启动意图提供，但调用点唯一**。受限离场清理核心与无浏览器控制面 bootstrap 核心是特殊会话（不开浏览器、且可能正是在环境已被移出/停止的语境下运行），它们的取消条件不是 `stopRequested`。因此闸的**判据**分档，闸的**位置**不分档。判据参数设为必填：新增启动路径时不写判据会当场报错，而不是默默放行。
- **被拒不投影为失败**。这是用户主动关闭的正常结果，界面上关闭路径已经写过正确的话；被拒只落一行原始日志（谁、为什么被拒），不弹错误、不消耗重起预算。

### D3：日志按所有权全量落，代号只门控界面投影

`handleEdgeOutput` 现在一句 `if (代号不一致) return;` 同时管两件事：写原始日志 与 写界面运行态。为保护后者，把前者一起扔了——这正是本次故障 13 分钟不可见的直接原因。

改法取最小血径：代号不一致时**不再直接 return**，而是把该行原样写入原始日志并标注它来自已被取代的操作代次，然后返回；代号一致时行为逐字不变。其余所有副作用（人设回执、发布审批回执、浏览器窗口回执、引擎命令诊断、状态投影）**一概保持现状的代号门**——它们的关联语义超出本 change 范围，动它们会把一个可观测性修复变成行为改动。

### D4：停止意图的持久性不新增机制

`stopRequested` 本就持续有效直到显式启动重新建立（`queueStartEnv` / `stopAndRestart` 才清），D1+D2 之后它已经能覆盖在途启动：提交点复核读它，所有权登记闸也读它。因此关闭路径的「无子进程」分支不需要改代码——它宣布的「浏览器已确认关闭」在 D1+D2 之后才第一次成为真话。这条写成规格不变量而非新机制，是为了让后续任何人删掉 D1 或 D2 时，规格上有东西被违反。

### D5：就绪超时如实呈现，但不得写成失败

`awaitLaunchReady` 超时（默认 180s）的语义是「放行启动队列的下一个，**不杀它、它可以继续自己起**」。现状只 `console.warn`。改为同时写入该环境状态：已超就绪预算、启动队列已放行下一个、本环境仍在继续启动。MUST NOT 写成失败态或终态——它既没失败也没停手，写成失败就是另一条方向相反的静默假失败。

## Risks / Trade-offs

- **[受限清理 / 控制面 bootstrap 被兜底闸误杀]** → 判据按启动意图分档（D2），且判据参数必填；实装时逐条读这些路径的真实取消条件，用例覆盖「已 removed 的环境仍允许起离场清理核心」。
- **[准备段与提交段之间事实变陈旧]**（代理准备完成到 spawn 之间用户改了代理）→ 该窗口现状即存在，本 change 只缩短它、不扩大；不在本 change 内处理。
- **[原始日志变多]**（被取代代次的输出不再丢弃）→ 只在代号不一致时多写，正常运行不产生额外行；日志文件已有轮转（`edge.log` / `edge.log.1`）。
- **[提交段拆分改动面偏大]**（`spawnEdgeChild` 约 200 行，含 adspower / self / cleanup / control-plane / transient 五条分支）→ 拆分只搬动语句顺序、不改分支语义；先补齐锁住现有行为的用例再拆，逐分支验证。
- **[打包后才生效]** → 客户端改动本身不改变云端行为，dev 上无部署动作；用户手上生效需显式出包（默认不做）。
