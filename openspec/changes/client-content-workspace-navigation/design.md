## Context

Electron 伴随窗口目前只有运行首页和少量覆盖层。精选语料已经在 Cloud 的 `curated_content` 中按账号持久化，内部 Console 也已有分页查看与参照创作能力，但客户令牌域没有相应出口；客户端只能看到一个数量。稿件审批则继续使用固定宽度抽屉，正文、多图、逐图删除和审批状态挤在同一窄容器内。

本变更跨 `aidcp-cloud` 客户鉴权服务与 `aidcp-edge` Electron 主进程、preload、渲染层。安全边界是：渲染层不直连 Cloud；客户 JWT 不能访问内部面板；每次内容请求都必须以当前客户在数据库中的环境归属校验账号；创建委派任务只表示已排队，不表示生成或发布成功。

## Goals / Non-Goals

**Goals:**

- 在一个 Electron `BrowserWindow` 内建立可返回、可关闭的内容页面栈，保留全局标题栏、账号和运行状态上下文。
- 为当前账号提供一致总数的分页灵感库、详情与两种参照创作方式。
- 在客户鉴权域提供最小字段、按环境归属隔离的精选内容接口。
- 把稿件预览迁移为主内容区全页审核，同时完整保留现有 CAS、非乐观删图与 first-writer-wins 审批语义。
- 账号切换和异步回包都不得造成跨账号内容闪回。

**Non-Goals:**

- 不创建新的系统级窗口，不改变主窗口关闭到托盘的生命周期。
- 不修改 `curated_content` 表结构、精选准入算法或浏览/互动行为。
- 不为客户开放精选删除、治理筛选、跨账号统计或内部面板接口。
- 不改变稿件生成、飞书审批、发布编排和图片编辑的 Cloud 协议。
- 本独立分支不合并默认分支、不部署 Cloud、不构建 Electron 安装包。

## Decisions

### 1. 使用同一主窗口内的页面栈

渲染层新增 `home → library → detail → create` 和 `home → draft-review` 两条页面路径。标题栏、环境栏和运行健康区属于全局壳层；内容页替换主内容区域。`Back` 恢复上一页快照，`Close` 回到运行首页。

采用应用内页面而非多个 `BrowserWindow`，因为内容页面必须共享当前账号、客户会话、核心状态和审批忙态。多系统窗口会额外引入窗口间同步、焦点、托盘关闭语义和过期账号上下文问题。未来若需要跨屏对照，可把同一数据模型投影到独立窗口，但不作为本期基础交互。

### 2. 灵感库状态按环境保存，页面请求使用代次令牌

每个 `envKey` 保存自己的筛选、页码和列表滚动位置。账号切换时立即隐藏旧详情与确认态，递增请求代次并加载新账号第一页；只有 `envKey` 与代次仍匹配的回包可以落 UI。返回列表时恢复原筛选、页码和滚动位置，不重新解释为新导航。

这一方案比全局单例列表更能避免切账号残留，也比取消所有请求更可靠：即使底层网络请求无法真正取消，迟到回包仍会被丢弃。

### 3. 客户内容接口留在独立客户鉴权域

Cloud 新增：

- `GET /curated-contents?envKey=&mode=creatable|all&limit=&offset=`
- `GET /curated-contents/:id?envKey=`
- `POST /curated-contents/:id/create-post`，body 为 `{envKey, useReferenceImages}`

所有路由先完成客户 JWT、撤销和启用态校验，再从 `client_env_scope` 回读当前归属；不接受 `accountId`。列表限制 `limit` 上界并只返回客户 UI 所需字段，详情以 `id + envKey` 同时查询，未命中和跨账号统一返回 404。

不复用内部 `/api/curated/*` HTTP 端点，因为其面板 JWT、跨账号运营能力和 DTO 都不属于客户安全域。底层可以复用 `CuratedContentStore` 的账号约束查询和 `DelegatedTaskService`，但路由与输出白名单独立。

### 4. 可创作筛选在 SQL 层完成

`mode=creatable` 的确定性条件为 `content_type = image_text` 且正文去空白后非空。筛选必须进入数据库 `WHERE`，再执行 `COUNT(*) OVER()`、`LIMIT`、`OFFSET`，使分页总数与当前页一致；不能先分页后在内存过滤，否则会出现空页和错误总数。

缺失计数保持 `null`，真实零保持 `0`。没有参考图不影响文字参照创作；“图文一起参考”仅在存在可用参考图时可选。

### 5. 参考创作复用结构化委派任务入口

创建接口从账号约束的精选行生成 `publish_post` 委派任务，来源固定为 `edge`，参照正文、话题和可选参考图以服务端读取的快照写入 `sourceConstraints`。客户端不能提交原文、图片 URL、账号 id 或任务状态。结构化 Edge 入口由现有 `DelegatedTaskService` 自动确认并进入 `queued`，响应文案必须表达“已排队”，任务终态仍由既有创作、审核和发布链路决定。

服务端再次验证行是 `image_text` 且正文非空。`useReferenceImages=true` 只复制该行已经持久化的参考图/视觉分析；文字模式显式写入 `false`。

### 6. 主进程持有会话并提供窄 IPC

Electron 主进程继续持有客户令牌、解析当前环境到裸 `envKey`，并向 preload 暴露 `curated:list`、`curated:get`、`curated:create-post` 三个窄 IPC。渲染层只传筛选/分页/id/参照模式，不传任意 URL 或鉴权头；主进程统一处理会话失效和可读错误。

### 7. 稿件审核只改变容器，不改变写路径

稿件审核页面复用现有主进程稿件真态和 IPC：发布/取消仍创建审批决定，删图仍带版本号走边云 WS，成功后由主进程写回新图片列表和版本。迁移过程中把确认态、忙态、具名失败映射保存在页面控制器状态中，不能依赖会随快照重绘的 DOM。

账号切换时关闭稿件页和局部确认态；如果在途请求随后返回，只允许更新其真实主进程状态，不得重新打开旧账号页面。

### 8. 灵感库入口收口为标题栏储备条

运行首页不再放置大卡片入口。标题栏把灵感入口放入**右侧控制区**，位于弹性留白之后、环境名左侧；账号名与平台标识继续独立留在左侧。入口高 26–28px，固定呈现“✦ 灵感 {精选池总数} · 已成稿 {参照稿总数}”及 3px 储备条；整个控件可点击并进入同一主窗口内的灵感库。它不承载等级、连续签到、任务、奖励或悬浮运营面板，避免为低频能力制造持续干扰。

该入口与灵感页面只对平台明确为 `xiaohongshu` 的环境开放。视频号与 Facebook 环境隐藏入口且不发起精选汇总请求；如果客户在灵感页打开期间切换到这两个平台，页面栈立即回到对应平台的运行首页，旧灵感页不得继续显示。这个门禁只约束灵感库，跨平台共用的稿件审核入口与审核语义不因此改变。

两个数字都只读权威数据：“灵感”取客户鉴权接口按当前 `envKey` 查询的 `mode=all` 精选池总数；“已成稿”取同账号 `publish_log.source_reference IS NOT NULL` 的真实行数，表示确实形成过参照稿。仅排队的委派任务不得提前计入成稿。任一来源不可用时显示 `—`，不得以零或前端缓存猜测补全。

储备条表达“内容储备丰富度”，不表达使用率、任务完成率或剩余量，也不会因创作而扣减。客户端以 30 条为视觉饱和阈值，宽度为 `min(count / 30, 1)`，不展示百分比或“目标”文案；达到阈值后继续显示真实总数。普通态使用浅蓝容器 `#EEF5FF`、边框 `#D7E5FF`、主数字 `#2F6FE4`、轨道 `#DCE8F7` 和填充 `#4F83E8`；达到饱和阈值时填充才轻微过渡为蓝绿 `#3F7CE0 → #2AA57A`。低储备不使用黄/红告警，避免与账号健康状态争夺语义。

## Risks / Trade-offs

- **[列表 DTO 复用了完整存储投影而意外泄漏运营字段]** → 客户路由使用显式映射白名单，测试断言没有 `accountId`、`admitReason`、视觉内部字段等非 UI 字段。
- **[切账号时旧网络回包覆盖新页面]** → `envKey + requestEpoch` 双重校验，切换先清局部状态再发请求。
- **[可创作内存过滤导致 total 与页不一致]** → 条件下推 SQL，并为 total/offset 增加存储测试。
- **[重复点击产生重复任务]** → 按钮在途禁用，并沿用委派任务 `sourceRef`/去重语义；服务端回真实 `created` 与任务 id。
- **[全页迁移破坏既有删图安全语义]** → 只改展示容器，保留主进程真态、版本 CAS、非乐观刷新和现有失败码测试，补充页面导航测试。
- **[主窗口尺寸较小时内容拥挤]** → 页面采用可滚动主区和响应式双栏；不通过扩大最小窗口尺寸强迫用户。
- **[标题栏把储备条误解成消耗比例或任务完成率]** → 不展示百分比/目标/剩余量，辅助说明明确“进入灵感库”，成稿数独立呈现且不驱动条宽。

## Migration Plan

1. 先在 Cloud 增加向后兼容的客户内容接口与测试；未升级 Edge 不会调用。
2. 再发布 Edge 页面栈与 IPC；客户鉴权接口不可用时展示可重试空态，不回落内部面板接口。
3. 合并默认分支后按既有安全流程部署 Cloud 到 `dev`，健康检查通过后再发布 Edge；本独立分支阶段不部署、不打包。
4. 回滚 Edge 时旧版仍使用原运行首页与稿件抽屉；回滚 Cloud 时新版 Edge 得到明确不可用错误，不影响边云主链。无数据库回滚。
