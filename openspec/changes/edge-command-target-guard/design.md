## Context

云端对每个 edge 连接建立独立的「私有事件通道 + 角色调度器 + 会话状态」（`connection-runtime.ts:117-141`），入站帧按会话号（sessionId）路由到本连接的私有通道（`ws-server.ts:256` → `handler.busFor(session)`）。这层是**结构性隔离**：一台 edge 的上报在对象图层面就到不了另一台的调度器。

出站定向下发**不是结构性隔离**：调度器本身与 edge 无关（命令载荷不含节点号），靠握手时闭包捕获的 `ctx.edgeId` 作第二参传给出口 `pushToEdges(envelope, ctx.edgeId)`（`server.ts:1063-1065`），出口在共享在线表里按节点号过滤（`ws-server.ts:170-184`）。

当前约束与缺口：
- 握手对账号号已强校验（缺 / 空 / `default` 一律 `onConfigError` 拒绝，`connection-runtime.ts:79-95`），但**节点号全程当可选、从不校验**（`session.edgeId?`）。
- 出口的过滤条件是 `if (edgeId && conn.session.edgeId !== edgeId) continue;`（`ws-server.ts:176`）——目标为空值时该分支不成立，**退化为向所有在线 edge 广播**。
- 两者叠加：某连接握手漏带节点号 → `ctx.edgeId=undefined` → 其决策命令广播给所有 edge（含他人）。违反核心红线「绝不静默假成功 / 绝不误伤」。
- 现有先例：发布路径 `resolveEdgeIdForAccount` 已确立「无在线节点返回 null，调用方据此**诚实失败、绝不广播**」（`ws-server.ts:236-252`）。本次是把该纪律补齐到握手层与浏览调度出口，不引入新机制。
- 已确认无任何调用点故意用空目标广播（单参 `pushToEdges` 调用为零），故收紧行为对现有路径零回归。

## Goals / Non-Goals

**Goals:**
- 握手治本：无可路由节点身份的连接不得进入在线集合。
- 出口纵深防御：定向投递在无目标时诚实失败（命中 0、返回 0、记警告），绝不隐式广播。
- 保持并显式化「广播须走独立操作」这一不变量。
- 补安全红线级回归断言，锁死上述两条行为。

**Non-Goals:**
- **不修**同节点号重连瞬间的双活连接窗口（见 Risks）——本次仅记录、留扩展缝。
- **不重构**出站路由从「按节点号」改为「按唯一会话号」（更彻底但更大，另案收敛）。
- 不改动入站结构性隔离、不改动同账号多连接的账号级共享态（风控 / 冷却 / 互动闸）。
- 不改 edge 端（edge 一直携带节点号）。

## Decisions

**D1：握手缺 / 空节点号 → 判配置错误拒绝（复用 `onConfigError`）。**
与账号号校验对称。无节点号 = 无可路由的出站身份，放行只会制造「注册在册但下发即广播」的危险连接。
- 备选：为缺失连接合成一个默认节点号 → 否决：违反「真实身份、绝不偷映射」（与 `default` 账号退役同理），且会掩盖配置错误。
- 备选：只在出口修、不动握手 → 否决：无身份连接仍会被登记进在线表，纵深防御虽拦住广播，但根因（无路由身份的连接存活）未除；两层都做才彻底。

**D2：出口空目标不广播——命中 0、返回 0、记警告。**
沿用 `resolveEdgeIdForAccount` 已确立的「0 = 诚实失败信号」语义，调用方已按投递计数做诚实失败处理（`edge-steps.ts` 注释「送达 0 → 该步空 / 失败，不假成功」）。
- 备选：空目标时抛异常 → 否决：多个调用点把返回值当数值做诚实失败判断，改抛异常需全链 try/catch 改造，且与既有「返回 0」语义不一致。返回 0 更平滑、语义统一。

**D3：广播须显式（YAGNI，本次不建）。**
当前无任何广播需求，故不预建广播方法。规范上确立「广播只能经专用显式操作」这一不变量；将来真需要时再新增语义明确的独立方法（如全网停机通知），杜绝「省略目标参数」隐式广播复活。

**D4：在线表仍按会话号索引、出站仍按节点号过滤（本次不动）。**
出站按节点号是当前实现，够用；改为按唯一会话号定向能顺带免疫 D 中的重连双活窗口，但属更大重构，留待后续单独评估。

## Risks / Trade-offs

- **[同节点号重连瞬间双活窗口]** 顶替旧连接调用 `closeEdge`，但 `ws.close` 异步，旧 socket 的 `close` 事件 + `edges.delete`（`ws-server.ts:275`）触发前，短窗口内两条活连接共享同一节点号，定向命令会瞬时扇给两个。→ **缓解**：本次不修，记录在案；根治路径是 D4（定向按唯一会话号）或顶替时同步移除旧连接。影响面小（仅重连瞬间、同节点号自连），不属本次核心红线。
- **[强制节点号可能误拒历史连接]** 若存在不带节点号接入的老 edge 版本会被拒。→ **缓解**：已核实 edge 客户端握手恒带节点号（构造时固定），风险极低；且「无身份连接被拒」正是期望行为。
- **[出口返回 0 被误读为「已尝试但边端离线」]** 空目标的 0 与「目标离线」的 0 同值。→ **缓解**：空目标额外记警告以区分；根因经 D1 在握手层消除，运行期几乎不会再出现空目标下发。

## Migration Plan

- 纯 aidcp-cloud 改动，无数据迁移、无协议版本变更（不触 `PROTOCOL_VERSION`、不改两份 protocol.ts）。
- 部署走既有 ECS 安全序列：sub-repo 测试全过（先 `test:acceptance` 再全量 `test` 再 `typecheck`）→ 备份 → rsync → 重启 → healthcheck → 失败回滚。
- 回滚：还原提交即可，行为回到「空目标广播 + 握手不校验节点号」的旧态。
