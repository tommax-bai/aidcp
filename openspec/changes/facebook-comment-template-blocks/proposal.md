## Why

运营把整段 13 行的招聘广告粘进后台"评论模板"框，期望它作为**一条**评论发出去。但该框的语义是
"每行一条模板、发送时随机挑一条"，于是广告被切成 13 条，账号每次只发其中一行——2026-07-28 12:53
真机发出的就是残句 "👉 Chuyên cần: 400.000 VNĐ"（FB 活动日志与 `facebook_comment_audit` 的 `text_length=26` 互证）。

同时，模板正文走的是给**无人值守 LLM 生成文**设计的确定性内容校验：链接 / 联系方式 / @提及 / 垃圾短语 /
相关性。运营自己写的投放素材天然带电话与营销措辞，整段作正文必被 `contains_contact` 拒掉。
用户 2026-07-28 决定：**模板正文由人工负责，系统不再对其做内容审查；联系方式与正文并存由人工保证**。

## What Changes

- 后台评论模板编辑框的分隔符由**换行**改为**单独一行 `------`（6 个及以上连字符）**；单条模板因此可以跨行。
  账号模板与区域通用模板两个编辑框口径一致。存储形态不变（仍是模板字符串数组），故无数据迁移必需项。
- 运营手写的模板正文不再走内容政策类校验（链接 / 联系方式 / @提及 / 垃圾短语 / 相关性）——这些校验是为
  无人值守的模型生成文设的，作者是模型不是人；模板的作者是运营本人，内容由其负责。
- 结构类校验对模板**仍然全部保留**：空、无实义字符、过短、过长。其中"过长"不是政策而是物理约束——
  超长正文在拟人逐字输入下打不完平台步预算（真机实测 431 字符约 17.6 秒，而引擎节奏更慢），
  会以超时收场而不是发出去。
- 生成式评论（`generated` 模式）的校验一条不动。

## Capabilities

### Modified Capabilities

- `facebook-scheduled-comment`：模板分隔符语义与多行模板；模板正文的校验通道与生成文分离。

## Impact

- Console：账号评论模板编辑器与区域通用模板编辑器的解析/回填改为按 `------` 分块。
- Cloud：确定性校验器新增"运营手写正文"通道；评论调度在模板模式下启用该通道。
- 无协议、无数据库迁移、无 Edge 改动。**现有已存成 13 条碎片的区域配置需运营在后台重存一次**
  （或由本次一并合并），否则仍会随机发单行。
