## Context

左侧环境栏已经通过 `fleetLevel` 为每个环境生成稳定的 `level`、`needsAction` 与用户可读标签，渲染层再用分组谓词生成标题和行列表。当前 `idle` 分组同时接收暂停环境和离线 / 失联环境，造成视觉语义合并。

## Goals / Non-Goals

**Goals:**

- 复用现有状态真相，将普通环境清晰分成运行中、暂停、离线三组。
- 保留“需处理”浮顶优先级以及组内原有排序。
- 以聚焦 DOM 回归测试锁定标题、归属与顺序。

**Non-Goals:**

- 不修改 `fleetLevel` 的状态判定、标签或协议字段。
- 不调整环境生命周期动作、云端状态或环境栏视觉样式。
- 不改变“需处理”环境的检测与浮顶行为。

## Decisions

1. 在渲染层分组定义中新增独立 `paused` 组。暂停归属直接使用 rail row 已携带的稳定会话态 `status.session=paused`，因为 `level=offline` 还同时覆盖已关闭和已停止，不能仅按 level 区分。
2. 离线组继续接收非需处理的 `offline` / `stale` 行，但明确排除“已暂停”。这样保留已有失联投影，不重写状态模型。
3. 分组顺序固定为“需处理、运行中、暂停、离线”；空组沿用现有不渲染行为。

## Risks / Trade-offs

- [Risk] 旧快照若缺少 `status.session` 会无法识别暂停 → 按现有离线级别安全回落到“离线”，新鲜快照仍准确进入“暂停”。
- [Risk] 需处理环境本身可能处于暂停态 → `needsAction` 继续优先，确保此类环境只出现在“需处理”组。
