## MODIFIED Requirements

### Requirement: 面板写端点校验目标存在性与输入格式，绝不静默假成功

面板写端点 MUST 校验其操作目标的存在性与外部输入的格式，杜绝「对不存在目标返回假成功」与「不可信输入直达副作用」（承本项目「MUST NOT 静默假成功」红线于面板写路径）。

账号相关写端点（暂停 / 恢复 / 设风控状态 / 设配额）MUST 在写库前校验账号存在，不存在 SHALL 返回 404 `account_not_found`、MUST NOT 经底层 `INSERT ... ON CONFLICT` 凭空造出幽灵账号行并返回成功。

发布审批端点接收的 `requestId` MUST 经格式白名单校验（仅允许受控字符集，如 `publish-<数字>` 或 `[A-Za-z0-9_-]+`）后方可作为持久授权记录的主键与接口路径段使用，MUST NOT 把白名单外字符原样带入下游标识符或路径段；非法格式 SHALL 返回 400、不触发任何授权写入。

#### Scenario: 对不存在账号的写返回 404 而非假成功
- **WHEN** 以一个不存在的账号 ID 请求暂停 / 恢复 / 设风控状态 / 设配额
- **THEN** 端点返回 404 `account_not_found`、不写库、不制造幽灵账号或幽灵风控状态行

#### Scenario: 非法审批 requestId 被拒
- **WHEN** 审批请求的 `requestId` 含 `../` 或白名单外字符
- **THEN** 端点返回 400、不写入任何授权记录

## ADDED Requirements

### Requirement: 发布投影暴露授权的下发进度与阻塞原因

面板发布队列与待审详情投影 SHALL 为每条已授权记录增量返回下发进度（待下发 / 下发中 / 已消费 / 已作废）、可读阻塞原因、决策时间与自决策起的等待时长。已批准待下发的行 MUST 与待审批行**可区分地**呈现。投影 MUST 来自持久授权记录，MUST NOT 依赖任何进程内在途集合——进程重启或执行侧不可达时该区分必须依然成立。字段缺省（尚未升级的服务端）时前端 MUST 回落为既有呈现，MUST NOT 白屏或报错。

#### Scenario: 待下发行带原因与等待时长
- **WHEN** 某稿已被批准但下发侧因边缘离线尚未执行
- **THEN** 投影返回下发进度为待下发、阻塞原因为边缘离线、决策时间与等待时长，前端据此与待审批行区分呈现

#### Scenario: 进程重启后区分依然成立
- **WHEN** 服务进程重启，进程内在途集合被清空
- **THEN** 已批准待下发的行仍呈现为「已批准·待下发」，MUST NOT 退回为「待审批」

#### Scenario: 字段缺省安全回落
- **WHEN** 服务端尚未返回下发进度字段
- **THEN** 前端按既有方式呈现，不白屏、不报错
