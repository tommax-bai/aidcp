## Context

获得感卡片当前有四类常规状态（运行中、场次间隔、小时间隔、今日完成）以及首帖创作状态。普通运行态同时渲染价值说明、三段流程和浏览进度；其中流程里的浏览数字重复进度区，“持续判断中 / 持续筛选中”也没有可验证的阶段结果。间隔、完成和首帖状态则确实需要用三段流程解释“刚完成什么、为什么等待、下一步是什么”。

实现限定在 Edge renderer，不改变协议或运行节奏。所有数字继续只来自现有运行状态，缺少证据时不补写结果。

## Goals / Non-Goals

**Goals:**

- 让普通运行态首先呈现真实浏览进度，并在有明确灵感汇总时呈现真实收获。
- 移除普通运行态重复且含糊的三段流程，降低卡片高度和视觉噪声。
- 保持间隔、完成和首帖状态的阶段解释能力以及既有客户端视觉语言。
- 让推荐流返回动作保留真实文字，同时把流光强调移到下方创作方向标题，并让获得感卡片的吉祥物作为静态视觉锚点。
- 保证窄屏、动态更新、无障碍进度语义和减少动态偏好不退化。

**Non-Goals:**

- 不改变浏览、判断、收集、创作或发布行为。
- 不改变运行状态、窗口计数或灵感汇总的数据契约。
- 不重做整张卡片或引入新的组件库、图标和动画。
- 不把收藏、候选等近似计数冒充已记录的创作灵感。
- 不调整首次设立好人设后的恭喜弹窗；该弹窗的吉祥物缩放动画和文字流光继续保留。

## Decisions

### 1. 运行态不提供 `steps`，其他状态维持现有流程

`runtimeGuidanceView()` 在普通运行态不再返回三段 `steps`。renderer 已把空步骤数组处理为隐藏流程容器，因此复用现有条件渲染，不增加状态分支或新 DOM。场次/小时间隔、今日完成和首帖状态继续返回原有流程。

替代方案是所有状态一起移除流程。它会让用户失去对自然间隔和首帖“浏览 → 筛选 → 创作”路径的解释，因此不采用。

### 2. 真实灵感结果进入进度元信息，不新增结果卡

运行态继续使用现有进度标题、计数和进度条。当 `dailyUsage.inspirationSummary.count > 0` 时，进度元信息显示“已记录 N 条创作灵感”并使用克制的绿色结果色；缺少汇总或数量为零时仍显示中性的“进展实时记录”。不使用 `collect`、候选数或其他近似动作推断灵感结果。

替代方案是在运行态复用完整的收获面板。该面板会重新增加卡片高度，并与“运行仍在继续”的语义争夺注意力，因此不采用。

### 3. 用分隔和间距承接流程移除后的视觉层级

运行态进度区增加轻量顶部细分隔和紧凑留白，让“价值说明”和“真实进度”仍然形成清晰两层；不保留空流程占位。结果元信息只改变文字颜色，不增加徽章、底色或额外动效，避免小尺寸客户端卡片显得拥挤。窄屏允许进度标题自然换行，计数与结果保持可读。

### 4. 测试按状态职责拆分

纯逻辑测试断言运行态无 `steps`、真实汇总存在时显示结果、无汇总时不制造结果。DOM 测试断言运行态流程容器隐藏且为空、进度语义完整；间隔、完成和首帖测试继续保证三段流程、连接器、窄屏与减少动态样式存在。

### 5. 返回推荐流事件只迁移流光区域，不改文字

主进程发送 `返回推荐流，继续逛…` 时，presence 视图继续原样显示这个真实动作。若事件仍在实时流光窗口内，renderer 不再给顶部 `#presence-text` 添加 `shimmer`，而是把同一流光 class 加到下方 `#runtime-guidance-title`，其文字仍为“正在缩小创作方向。”。事件时间戳、“刚刚更新”和活动圆点保持不变；其他 presence 动作仍按既有规则在顶部显示流光。

### 6. 获得感卡片吉祥物统一静止，恭喜弹窗明确隔离

`runtimeGuidanceView()` 不再为普通运行态或首帖命中灵感态请求吉祥物动画，`.rg-mascot` 也不再定义位移或缩放动画。运行、间隔、完成与首帖各状态仍按既有数据选择对应图片，但图片固定不动。

首次设立好人设后的恭喜弹窗使用独立的 `.pg-mascot` 与 `pg-mascot-scale`，不属于 `.rg-mascot`。本次保留该选择器、关键帧及其减少动态降级，防止静止运行卡片时误伤新手完成反馈。

## Risks / Trade-offs

- [运行态与其他状态不再结构完全一致] → 以状态职责一致性替代机械布局一致性，并通过相同卡片外壳、字体、色彩和间距保持整体视觉连续。
- [灵感汇总更新晚于浏览进度] → 没有汇总时只显示中性进度，不用动作计数推断收获。
- [移除流程后卡片显得松散] → 给运行态进度区增加轻量分隔与精确垂直间距，并覆盖窄屏测试。
- [旧测试把运行态连接器当作全局动效样本] → 将连接器连续性断言放到仍有流程的状态，运行态改验隐藏与真实进度。
- [统一静止吉祥物误伤首次恭喜弹窗] → 只移除 `.rg-mascot` 动画，并增加 `.pg-mascot` 动画仍存在的回归断言。

## Migration Plan

1. 更新视图模型和 renderer 进度元信息样式。
2. 更新纯逻辑、DOM 和 CSS 契约测试，运行聚焦测试及 typecheck。
3. 完成 OpenSpec strict 校验并按 worktree 集成规范提交。

回滚时恢复运行态 `steps` 及原 CSS/测试即可；没有数据迁移或协议回滚。

## Open Questions

无。当前 `inspirationSummary` 足以作为是否展示真实灵感结果的保守证据。
