## Why

Facebook 法语界面下出现的软阻断弹窗——

> Cette fonctionnalité n'est pas disponible.
> Un contrôle de sécurité est requis pour continuer.
> Si vous pensez que ceci ne va pas à l'encontre des Standards de la communauté, dites-le nous. [OK]

——**对系统当前是全静默的**：边缘判为「无事发生」，连上报都不发，云端风控态停在 `normal`，继续按原节奏点赞发评论；零告警、零 `alerts` 记录。这与 change `fb-throttle-popup-zh-frequency-copy`（2026-07-17 归档）治的是**同一种故障的另一个语种实例**。

**已用现役模块实证**（直接调 `classifyFacebookOverlayFromSignals` 与 `isFacebookThrottleText`，非复刻）：

| 输入 | 边缘分类 | 云端限流词库 |
| --- | --- | --- |
| 法语原文 + 普通群页 URL | `none`（当作无事，零上报） | 不命中 |
| 法语原文 + `/checkpoint` URL | `unknown`（地址判据兜住） | 不命中 |
| **同一弹窗的英文界面文案** | `unknown` | **命中 → 一次刹车到 `restricted`** |

断点只有一处：**识别是纯文字匹配，两仓词库只有英文与中文两套短语，法语零命中**。这张卡片的每一句在英文界面下都已在词库内（`this feature isnt available` 在限流词库、`security check` 在安全检查判据），所以并非「没见过这种弹窗」，而是**只认得它的英文与中文版本**。

**为什么是现在**：限流是账号已经受损的信号，越晚发现继续操作越久、损伤越深；而修复面极小（无协议改动、无 DB 迁移、不动任何分级逻辑），没有理由继续让它静默。

## What Changes

- **两仓识别归一化补入「去变音符」一步**（`é→e`、`ô→o`、`à→a`），与既有的小写化、去撇号、折叠空白并列。此举使拉丁语系词条可用纯 ASCII 形式书写，一次性吃掉三种转录差异：Unicode 预组合 vs 组合序列（NFC/NFD）、页面文字与截图转录的重音丢失、地区变体的重音差异。对既有英文与中文词条**行为完全不变**（两者均不含变音符）。
- **两仓限流词条集合补入两条法语句片段**（归一后的 ASCII 形式），两侧逐条一致：
  - `controle de securite est requis` —— 「要求你做一次安全检查」，`est requis` 是必需的限定，使其区别于 Facebook 安全设置页里作为功能名出现的同一短语；
  - `cette fonctionnalite nest pas disponible` —— 英文对等条目已在词库内，本条只是补齐同一语义的法语面。
- **显式不加第三句**（`ne va pas à l'encontre des Standards de la communauté`）：这是 Facebook 的**申诉入口话术**，出现在一切违规告知中，包含通知中心里的**陈年**内容删除通知——一条旧通知就能把账号打进 `restricted`。这与云端删除 `we removed your` 的理由完全一致。
- **补单元测试**：两侧各锁一份法语词条集合（任一侧新增/删除而另一侧未同步即失败，沿用既有的两仓防漂移模式）；用带完整重音与撇号的**真实法语原文**断言命中；用申诉话术、Facebook 法语安全设置页措辞断言**不**命中。

**不改的（刻意）**：

- **不动任何分级逻辑**。安全检查 / checkpoint 走软信号逐级升（正常→降速→受限，两轮才刹车）是**刻意设计**——checkpoint 可能只是身份确认或设备确认，两轮确认是为了不误伤；限流词库命中一次直接刹车。本 change 只让法语走上英文今天已走的那条路，两条路径的分级各自维持原样。
- 不改协议（零消息类型增删）、不改风控状态机迁移表与终态云端单写、不改遮罩快照的 DOM 可信阈、无 DB 迁移、不碰小红书侧（词条为 Facebook 法语专属措辞，换平台零命中）。

## Capabilities

### New Capabilities

（无）

### Modified Capabilities

- `captcha-incident-handling`: 新增一条需求——平台限流文案的识别覆盖面必须及于 Facebook 法语界面的软阻断措辞，且识别归一化必须消解变音符差异；同时把「不得引入申诉话术这类跨语境泛化短语」的词条纪律扩展到拉丁语系。

## Impact

**aidcp-edge**（1 文件 + 1 测试）
- Facebook 遮罩分类模块：新增法语词条集合常量 + 归一函数（小写 / 去撇号 / 去变音符 / 折空白），接入既有阻断判据分支，判定结果与中英文一致为阻断态
- 对应单测：词条集合锁定、真实法语原文命中、申诉话术与设置页措辞不命中

**aidcp-automation**（1 文件 + 1 测试）
- Facebook 限流词库：归一化补去变音符 + 补两条法语词条
- 对应单测：同上，并锁两仓集合一致

**不受影响 / 明确不碰**
- 边-云协议、风控状态机、告警类型与冷却、遮罩快照可信阈、证据文案回填、评论回执语义、小红书侧

**风险面**：词条误报使账号迁入 `restricted` 并钉住恢复窗、不自动回滚、只能人工恢复；漏报仅维持现状。**代价严重不对称 ⇒ 宁可漏不可错**。故两条词条均为长专属句片段，且刻意排除申诉话术。失败方向是安全的：词条不命中即回落今天的静默行为，不误伤。

## Non-Goals

- **模型兜底未命中的弹窗**（不靠词表追语言）→ 属 `fb-cross-language-recognition` 的 L4，另一 change 量级。本 change 只把这一张已知卡片接上，跨语言脆性只被推后一格，不假装解决。
- **扩充其他语种词条**（西 / 葡 / 越 / 德…）→ 未见过的变体不凭空扩充，沿用既有纪律。本 change 的去变音符归一为将来的拉丁语系留了干净的缝，但**不预先填充**。
- **存量号 Facebook 界面语言归一为英文** → 治本方案 `facebook-locale-pin-en-us` 只作用于新建号的指纹层；登录后界面语言由账号服务端设置决定，存量号需逐个登入改设置页，流程脆、属独立工作。
- **调整安全检查 / checkpoint 的两轮确认分级** → 经查证为刻意设计（见 What Changes），本 change 不触碰。
- **两仓词库共享模块** → 无跨仓共享基建，成本 > 收益；用两侧单测锁对齐即可（既有结论）。
- **`restricted` 恢复窗自动回滚策略** → 正交。
