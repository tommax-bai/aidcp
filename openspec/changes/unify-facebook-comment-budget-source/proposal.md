## Why

Facebook 评论提交的时间预算，**两个仓各写了一份同样的公式**：

| | 云端 `src/comment-agent/facebook-edge-steps.ts` | 边缘 `src/native-page-engine/browse-session.ts` |
| --- | --- | --- |
| 下限 | `FACEBOOK_STEP_TIMEOUT_MS = 42_000` | `FACEBOOK_COMMENT_TIMEOUT_FLOOR_MS = 42_000` |
| 基数 | `..._SUBMIT_BASE_MS = 27_000` | `..._TIMEOUT_BASE_MS = 27_000` |
| 每字符 | `..._SUBMIT_PER_CHAR_MS = 330` | `..._TIMEOUT_PER_CHAR_MS = 330` |
| 上限 | `..._SUBMIT_MAX_MS = 180_000` | `..._TIMEOUT_MAX_MS = 180_000` |
| 计入的串 | `groupChatCode ? text + "\n" + code : text` | `groupChatCode ? body + "\n" + code : body` |

四个数字 + 一条「算哪一串」的口径，各写两遍。**没有任何机械手段能发现它们分叉** —— 两个仓不共享包、任一侧的测试都读不到另一侧的源码。

**危害是具体的**：云端是判定方（等待窗口），边缘是执行方（命令预算）。判定方的窗口一旦短于执行方的预算，一次**慢但成功**的提交会被云端判成 `timeout` ⇒ 去重标记不打 ⇒ 下一轮同帖再发一条**真评论**（平台可见的重复）。已上线规格 `facebook-comment-idempotency` 把这条写成了硬要求，而且它的最后一条场景写的是一条**人工复核义务**：「边缘的提交后确认预算一旦变大，必须回头对这个超时重新核算」。**一条人工义务加上两份可以各自漂移的公式，等于没有义务。**

**必须如实说明一件事**：摘出文档（`docs/cloud-orchestration-residuals-descoped-2026-07-31.md` B 节）说云端「仍只把正文传给预算函数」⇒ 算短了 ⇒ 带联系方式的长评论会被误判超时。**这条已经不成立了** —— 云端在 2026-07-29（`aidcp-cloud 9013a5f`，比那份文档早两天）已经改成按「正文 + 换行 + 群聊码」的完整串算，且就地写了注释说明为什么。**今天两份公式的取值是一致的。**

所以本 change 的立论要重述：**它不再是在修一个正在发生的缺陷，而是在消除一个只能靠人记住的约束。** 优先级因此低于 A 节那批（迁移闩），但立论比原来更清楚 —— 上一次分叉是被人**偶然**发现并修掉的，没有任何机制保证下一次也会。

**为什么不能靠 drift-guard 测试解决**：本仓确有跨仓词表漂移守卫的先例（`facebook-group-join-resilience` 的「云端判定词表须与边缘词表对齐」）。但实读那条守卫，它是一条**行为测试 + 手抄夹具**：它能发现「云端不再认某个语种」，发现不了「边缘加了一个云端不认的语种」。数字比词表更糟 —— 两个常量取值不同**不产生任何可观测的行为差异**，直到真机上一条长评论超时。**行为测试原理上看不见第二份实现。**

## What Changes

- **确定计算方为云端，预算随命令下发**：`interaction.comment` 载荷新增一个可选的提交预算字段（毫秒），由云端按完整串算出并带上。
- **边缘改为据传输值派生**，删掉自己那四个常量与那份公式；边缘只保留「传输余量」这一个自己的量（它表达的是「边缘要比云端早一点收口」，是边缘自己的职责，不是公式的第二份）。
- **字段缺席时的兜底必须响亮，且不得是公式的第二份副本**：回落到既有的默认命令超时（一个与评论长度无关的常量），并在回执上标出「本次预算未由云端下发」。**MUST NOT** 在边缘保留一份按长度算的兜底公式——那正是本 change 要消除的东西。
- **协议同步**：新增可选字段属于载荷形状变更，两份 `protocol.ts` 须逐字一致，`docs/protocol.md` 同步。**不新增消息类型**（`MessageType` 穷举不变）、**不动动作↔消息映射**、**不进主动命令路由白名单**（它是既有命令的一个字段，不是独立下发的新命令）。
- **把「人工再核算」那条义务改写成结构性保证**：规格里那条「边缘确认预算变大时须回头核算云端超时」在单一事实源下自动成立，改为要求单一事实源本身。

## Capabilities

### Modified Capabilities

- `facebook-comment-idempotency`: 「慢提交不得被误判超时成重复评论」这条今天靠两份各自维护的公式取值相等来保证，且其最后一条场景是一条无法机械执行的人工复核义务；改为要求单一事实源（判定方算、随命令下发、执行方派生），并要求兜底路径响亮。

## Impact

- **aidcp-cloud**
  - `src/comm/protocol.ts`：`InteractionCommentPayload` 增可选预算字段（与边缘逐字一致）。
  - `src/comment-agent/facebook-edge-steps.ts`：把算出的提交步超时随命令带下去（公式与常量**留在这里**，这是计算方）。
- **aidcp-edge**
  - `src/comm/protocol.ts`：同上，逐字一致。
  - `src/native-page-engine/browse-session.ts`：删四个常量与那份公式，改为据传输值派生；保留传输余量常量；兜底路径加显式回执标注。
- **控制仓**
  - `docs/protocol.md`：载荷字段说明同步。
- **不涉及**：console、Native IPC 协议版本、协议消息类型数、动作↔消息映射、主动命令路由白名单。
- **部署顺序两个方向都安全**：云端先上 —— 老边缘忽略未知字段，行为不变；边缘先上 —— 走响亮兜底。**但两边都上线之前，保证不成立**，须在 tasks 里记为「本 change 的效果要等下一次边缘出包才完整」。
