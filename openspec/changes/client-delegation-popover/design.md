## Context

`aidcp-edge` 的委派任务入口刚以常驻卡片落到陪伴主视图。卡片复用了现有委派任务 IPC、结构化确认和真实进度列表，但其 200px 以上的固定高度打断了“在场感 → 运行价值 → 发布结果 → 今日进展”的阅读顺序。当前在场感行已经代表当前选中环境，并在右侧留有自然的次级操作空间，因此可作为委派入口的稳定锚点。

该客户端没有前端构建框架或外部图标依赖，渲染器使用静态 HTML/CSS/JS；实现必须继续按当前选中 `envId` 路由，不能把 A 环境的未确认操作带到 B 环境。

## Goals / Non-Goals

**Goals:**

- 把常驻委派卡从主文档流移除，让默认首屏高度恢复到委派功能加入前的层级。
- 在在场感行最右侧提供始终可辨、但视觉权重低于会话主操作的入口。
- 用锚定入口的非模态浮层完整承载现有表单、动作、任务真态和控制。
- 支持鼠标、键盘、窗口边界、减少动态偏好和环境切换的可靠行为。
- 保持现有委派任务 API、确认 dialog、轮询与诚实计数不变。

**Non-Goals:**

- 不修改委派任务模型、调度、协议、数据库或云端实现。
- 不改变各快捷动作的平台能力边界及二次确认规则。
- 不构建或发布 Electron 安装包。
- 不把委派入口改成固定于窗口角落的全局悬浮按钮。

## Decisions

### 1. 入口内嵌在在场感行右端

在场感容器改为相对定位，状态文案区域占满剩余宽度；右端放置 36px 圆角方形按钮。按钮使用内联 SVG 的“托盘 + 向前箭头”线性图标：托盘表示任务承接，箭头表示交付给 AIDCP。存在非终态任务时，仅在按钮右上角显示小蓝点，并通过可访问名称说明有进行中任务。

选择这一位置是因为在场感与委派都绑定当前环境，用户不必在页面上寻找第二个账号上下文。替代方案包括标题栏全局按钮和今日进展标题区入口；前者容易让人误解为跨账号全局任务，后者会与启动/暂停等生命周期主操作争夺空间。

### 2. 使用锚定的非模态浮层，不使用第二个 modal dialog

原 `#delegated-card` DOM 移到在场感容器内部并改为绝对定位浮层：右对齐入口、宽度约 420px，最大高度受视口约束，头部固定、内容区独立滚动。浮层使用现有白色表面、浅边框、交互蓝和柔和阴影，并以小箭头建立与入口的视觉归属。

浮层本身使用 `role="dialog"`、`aria-modal="false"`、`aria-labelledby`；结构化确认继续使用现有 modal `<dialog>`。未采用原生 Popover API，以避免依赖当前 Electron/Chromium 版本差异，也避免其 top-layer 行为干扰已有确认 dialog 和抽屉层级。

### 3. 明确维护打开状态与焦点

渲染器集中提供打开、关闭和切换函数，同步 `hidden`、`aria-expanded` 与可访问名称。打开后刷新当前环境任务并把焦点放到浮层关闭按钮；按钮再次点击、关闭按钮、外部点击或 Escape 均可关闭，Escape 关闭后焦点回到入口。确认 dialog 打开时，外部点击/Escape 交由 dialog 自己处理，浮层保持上下文。

环境切换和全量快照导致选中环境变化时先关闭浮层，再渲染新环境。这样旧环境表单值即便仍在 DOM，也不会以打开态留在新账号旁；任务列表仍由既有按 `envId` 的刷新结果覆盖。

### 4. 保持真实任务刷新和写入边界

现有 15 秒低频轮询继续只读当前选中环境，以便浮层关闭时仍能更新进行中指示点。每次打开浮层额外触发一次刷新，减少用户看到陈旧列表的窗口。所有写操作仍先生成 `awaiting_confirmation` 草稿，再由现有确认 dialog 排队；布局变化不增加任何直接网络访问或乐观成功状态。

### 5. 回归测试覆盖结构、交互和真态连续性

在现有 jsdom companion UI 测试中增加以下断言：默认无常驻委派卡占位；入口位于在场感容器内；点击后同步可见性/`aria-expanded` 并刷新；再次点击、外部点击和 Escape 关闭；环境切换关闭；进行中任务显示指示点；原有草稿、确认、任务真态和 Facebook 能力闸测试继续通过。

## Risks / Trade-offs

- [浮层遮住下方运行卡片] → 限定宽高、保持非模态、支持一键/外部/Escape 关闭，内容只在浮层内部滚动。
- [浮层与确认 dialog 的关闭事件冲突] → 确认 dialog 打开时暂停外部点击/Escape 的浮层关闭逻辑，确认结束后保留原操作上下文。
- [环境切换后误操作旧账号] → 在两条选中环境变化路径中同步关闭浮层，写请求仍以点击当下的 `currentEnvId()` 和确认回执中的 envId 为准。
- [小图标含义不清] → 使用任务交付语义的 SVG、悬停提示和明确的 `aria-label`，打开态同时呈现完整标题“交给 AIDCP”。
- [窗口过矮导致操作不可达] → 浮层最大高度按视口计算，头部固定、主体滚动；窄屏宽度按视口收缩。

## Migration Plan

1. 在独立 `aidcp-edge` worktree 修改静态渲染层和测试。
2. 运行 companion UI 针对性测试、完整 `npm test` 与 `npm run typecheck`。
3. 将变更 fast-forward 集成到干净的 `aidcp-edge/master` 并推送。
4. 不触发桌面打包；回滚只需回退本次渲染层提交，委派 API 与数据无需迁移。
