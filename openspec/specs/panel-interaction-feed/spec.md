## Requirements
### Requirement: 互动流记录四类动作，按真实账号归属，笔记动作按笔记、关注按作者

面板互动流 SHALL 记录点赞、收藏、评论、关注四类真实发生的动作。笔记类动作（点赞 / 收藏 / 评论）SHALL 以被互动笔记的 id 为目标；关注 SHALL 以被关注作者的 id 为目标（不依赖笔记 id）。每条记录 MUST 归属到发起动作的真实账号；账号缺失时 MUST 回退到保留键而非误并入真名账号。`comment_like`（按评论锚点、无按笔记 / 作者语义）MUST NOT 进入本流。

#### Scenario: 评论进入互动流并带笔记归属
- **WHEN** 某账号在一条笔记详情页成功发出评论
- **THEN** 互动流出现一条 `action=comment`、目标为该笔记 id、归属该账号的记录

#### Scenario: 关注进入互动流并按作者归属
- **WHEN** 某账号成功关注一位作者（发生在作者主页、无当前笔记）
- **THEN** 互动流出现一条 `action=follow`、目标为该作者 id、归属该账号的记录

#### Scenario: 点赞与收藏照常进入互动流
- **WHEN** 某账号成功点赞或收藏一条笔记
- **THEN** 互动流出现对应 `action=like`/`collect`、目标为该笔记 id 的记录

#### Scenario: 同一目标同一动作去重为一行、保留首次时间
- **WHEN** 同账号对同一笔记 / 作者重复同一动作
- **THEN** 互动流仍只有一行，其时间为**首次**发生时间，不被后续重复刷新为「刚刚」

### Requirement: 笔记动作显示标题并可跳转真实笔记详情页

对笔记类动作，互动流 SHALL 显示该笔记的标题；当持有带 `xsec_token` 的真实详情页链接时，标题 SHALL 渲染为可点击、在新标签打开真实笔记的链接。界面 SHALL 提示链接含时效令牌、较旧的可能失效。缺标题或缺真实链接时按诚实置空要求处理（见诚实置空红线）。

#### Scenario: 有标题且有真实链接
- **WHEN** 一条笔记动作记录持有标题与带 token 的详情页链接
- **THEN** 该行显示笔记标题，且点击标题在新标签打开该笔记真实详情页

#### Scenario: 有标题但无真实链接
- **WHEN** 一条笔记动作记录持有标题但无带 token 的链接
- **THEN** 该行显示纯文本标题、不可点击，且界面 MUST NOT 用裸笔记 id 拼一个打不开的链接

### Requirement: 关注显示作者昵称并可跳转作者主页

对关注动作，互动流 SHALL 显示被关注作者的昵称；当持有作者主页链接时，昵称 SHALL 渲染为可点击、在新标签打开作者主页的链接。缺昵称时 SHALL 回落显示作者 id，MUST NOT 编造昵称；缺主页链接时显示不可点击的昵称 / id。

#### Scenario: 有昵称且有主页链接
- **WHEN** 一条关注记录持有作者昵称与主页链接
- **THEN** 该行显示作者昵称，且点击昵称在新标签打开该作者主页

#### Scenario: 无昵称
- **WHEN** 一条关注记录抓不到作者昵称
- **THEN** 该行回落显示作者 id，MUST NOT 显示编造的昵称

### Requirement: 诚实置空——绝不伪造链接或标题（红线）

当无法获得带 `xsec_token` 的真实笔记链接、无法获得标题或昵称时，系统 MUST 诚实置空：边缘上报 MUST NOT 用裸 id 拼接打不开的链接、地址栏读取失败 MUST 归一为空而非空串；云端 MUST 以 `NULL` 持久化缺失值；前端 MUST NOT 渲染死链，只渲染纯文本或回落标识。本要求贯穿全链路、不可妥协。

#### Scenario: 边缘抓不到带 token 的链接
- **WHEN** 边缘在详情页读取地址栏但其中不含 `xsec_token`
- **THEN** 边缘上报该笔记的链接字段为空（不带、或 `undefined`），MUST NOT 用 `https://www.xiaohongshu.com/explore/<裸id>` 充数

#### Scenario: 云端持久化与前端渲染缺失值
- **WHEN** 某记录的标题或链接缺失
- **THEN** 云端落 `NULL`（非空串），且前端该单元格回落为纯文本 / 裸 id，不出现可点击的死链

### Requirement: 边缘在浏览时诚实捕获真实详情页 / 主页链接与作者昵称

边缘 SHALL 在进入笔记详情时读取真实地址栏链接（含 `xsec_token`）随详情上报；SHALL 在进入作者主页时读取主页链接、并从主页页面抓取作者真实昵称，随主页上报。这些字段 SHALL 为可选，且遵守诚实置空红线。此能力 MUST NOT 新增消息类型或 cloud→edge 命令（仅给既有上报追加可选字段），两份协议定义 MUST 逐字一致。

#### Scenario: 进入笔记详情带回真实链接
- **WHEN** 边缘打开一条笔记详情且地址栏链接含 `xsec_token`
- **THEN** 详情上报带上该真实链接

#### Scenario: 进入作者主页带回链接与昵称
- **WHEN** 边缘打开一位作者主页
- **THEN** 主页上报带上主页链接与从页面抓取的作者真实昵称（任一抓不到则该字段诚实置空）

### Requirement: 动作按类型着色以便区分

互动流的动作列 SHALL 按动作类型呈现可区分的颜色标签，点赞 / 收藏 / 评论 / 关注各自颜色不同。未知动作 MUST 安全回落为默认样式，不得崩溃。

#### Scenario: 四类动作颜色可区分
- **WHEN** 互动流同时展示点赞、收藏、评论、关注
- **THEN** 四类动作的标签颜色互不相同、可一眼区分

### Requirement: 互动流存储与去重台账解耦，写入为纯观测

互动流 SHALL 以「事件表 + 元数据旁表、读时合并」的形式存储：事件表记录账号 / 动作 / 目标 / 时间，元数据旁表按目标记录标题 / 链接，二者读时按目标合并。元数据 SHALL 在「看到笔记 / 看到作者」的上报到达时独立写入、与互动事件解耦，使元数据迟到不致事件丢失标题。写入互动流 MUST NOT 改写风控终态（纯观测账本）。既有按笔记去重台账 MUST 保持行为不变、不被本能力改写。

#### Scenario: 元数据迟到不致事件丢标题
- **WHEN** 某互动事件先落库、其目标的标题 / 链接元数据稍后才到
- **THEN** 面板再次读取时该行已能合并出标题 / 链接（读时 join 取当前元数据），无需事件携带标题

#### Scenario: 写入互动流不触碰风控终态
- **WHEN** 一条互动写入互动流
- **THEN** 账号风控最终状态与计数不因此被改写（仅由风控控制器单写）

#### Scenario: 去重台账行为不变
- **WHEN** 本能力上线后发生点赞 / 收藏
- **THEN** 既有按笔记去重台账的写入与去重语义与上线前完全一致
