## Requirements
### Requirement: 桌面外壳前置探测 AdsPower 本地 API 可用性

`adspower` 模式下，Electron 桌面外壳 SHALL 在面板加载、切到指纹浏览器选择项、或运维点「刷新」时，经本地指纹浏览器服务的**根级**健康检查接口（`/status`，不在 `/api/v1/` 前缀下）**只读探测**其是否可达，用于填充环境列表。该探测 SHALL 按端点显式构造 URL，MUST NOT 因把请求误加 `/api/v1/` 前缀而把一个本可达的服务谎报为不可达。探测 SHALL **静默进行**——MUST NOT 提供独立「检测」按钮、MUST NOT 呈现「已就绪 / 未就绪」状态徽标：可达即自动拉取并列出环境；不可达 SHALL 在环境区诚实提示（说明启动后应用会自动拉起内置运行时、并保留「手动填写」分身 id 兜底），MUST NOT 谎报就绪、MUST NOT 因探测不可达就假装可启动、且提示中 MUST NOT 引导下载或暴露底层方案名。探测 SHALL 为低频触发（面板加载 / 切换 / 刷新），MUST NOT 引入后台常驻轮询。「是否已安装」无独立探测手段，SHALL 由不可达状态反推去引导（启动后自动拉起内置运行时或手填分身 id），MUST NOT 猜测本机安装路径而谎报。

#### Scenario: 本地服务可达时静默列出环境
- **WHEN** 桌面外壳在 `adspower` 模式下面板加载、切到指纹浏览器选择项或点「刷新」，且本地指纹浏览器服务可达
- **THEN** 桌面外壳静默探到可达并**自动列出环境**，界面 MUST NOT 出现「检测」按钮或「已就绪」徽标

#### Scenario: 本地服务不可达时环境区诚实提示不谎报
- **WHEN** 探测健康检查接口不可达
- **THEN** 环境区诚实提示「暂未连接到本地指纹浏览器服务」并说明启动后应用会自动拉起内置运行时、运维仍可手填分身 id 继续（诚实降级）；MUST NOT 谎报就绪、MUST NOT 引导下载或暴露底层方案名

### Requirement: 桌面外壳拉取并下拉选择 AdsPower 浏览器环境

`adspower` 模式下，桌面外壳 SHALL 经 AdsPower 本地 API 的环境列表接口（`user/list`）**只读拉取**可用的浏览器环境，并以下拉列表供运维选择，每项 SHALL 至少展示环境名称与其分身 id，并 SHOULD 展示分组与代理配置摘要（`user/list` 返回的代理类型 / host 及配置 `ip` / `ip_country`）以便**初步**核对防关联绑定契约（1 环境 = 1 指纹 = 1 独立 IP = 1 账号）；该 `ip` SHALL 明示为环境的**配置值**、对无代理或动态分配代理可能为空 / 占位，实测出口 IP 以 AdsPower 内『检测代理』为准，MUST NOT 把防关联核对的可信度绑死在该字段。运维选中某环境后，**其 `user/list` 返回的 `user_id`**（非 `serial_number` 序号）SHALL 写入既有持久化设置的分身 id 字段（即注入核心的 `AIDCP_ADS_USER_ID`，下游 `browser/start` 只认 `user_id`）；`serial_number` / 名称仅供下拉展示，MUST NOT 写入分身 id 字段（否则 `browser/start` 找不到该 user 而失败）。下游启动路径 MUST NOT 因引入下拉而改变。需鉴权的拉取 SHALL 支持取渲染层传入的**当前表单 api-key / api-base 作调用级参数**（仅本次调用用、不持久化、不落日志），以支持「新填 key 未保存即刷新」而不陷入「填了仍被要求去填」的回环。**手敲分身 id 的输入方式 SHALL 始终保留为兜底**：当环境列表拉取失败时，桌面外壳 SHALL 诚实降级为手填分身 id 并如实说明拉取失败原因，MUST NOT 把启动的唯一入口绑死在列表拉取成功上。最终以写入分身 id 字段的值为准，保存时 SHALL 校验其非空。

#### Scenario: 拉取成功时下拉选择写入分身 id
- **WHEN** 桌面外壳在 `adspower` 模式下拉取环境列表成功
- **THEN** 面板以下拉列表展示各环境（名称 / 分身 id / 分组 / 代理配置摘要），运维选中一项后其 `user_id`（非 `serial_number`）写入持久化设置的分身 id 字段，注入核心的目标 profile env 与手敲同等生效、下游零改动

#### Scenario: 新填未保存的 api-key 刷新即生效不陷回环
- **WHEN** 运维在表单新填了 api-key 但尚未「保存并启动」，即点「刷新环境列表」，且 AdsPower 开启了 API 校验
- **THEN** 拉取用表单当前填写的 api-key（调用级、不持久化、不落日志）发起，key 正确则拉出环境列表；若仍失败其提示 MUST NOT 反过来要求运维去填一个他已填的 key 框

#### Scenario: 拉取失败时诚实降级为手填
- **WHEN** 环境列表接口调用失败（本地 API 不可达 / 开了 API 校验致鉴权失败 / 返回错误）
- **THEN** 面板如实说明拉取失败原因（疑似鉴权失败时提示去填 API key），并保留手填分身 id 的入口让运维继续，MUST NOT 谎报有环境、MUST NOT 禁死启动

#### Scenario: 环境未登录仍走核心诚实退出
- **WHEN** 运维选中或手填了某环境并启动，但该环境未登录目标账号、身份读不出
- **THEN** 沿用既有红线由核心诚实非零退出并弹窗提示去 AdsPower 登录，桌面外壳 MUST NOT 在面板侧假判为成功或以「运行中」外观空跑

### Requirement: 桌面外壳对 AdsPower 本地 API 的调用只读且在主进程侧自持限速节流

桌面外壳为探测与环境拉取而对 AdsPower 本地 API 发起的所有调用 SHALL **只读**（仅健康检查与环境列表查询），MUST NOT 触及浏览器启动 / 停止 / 生命周期接口，MUST NOT 改动核心 provider 的启动与生命周期层。因面板探测 / 拉取运行在 Electron 主进程、而核心的启动 / 停止 / active 调用运行在被 `spawn` 拉起的**独立子进程**内（节流状态为其进程私有、且探测常发生在核心尚未启动之时），二者分属不同 OS 进程、无法共享同一内存节流队列——**故本 change 不要求跨进程共享节流**。桌面外壳的这些只读调用 SHALL 在 Electron 主进程内经其**自持的同一条 ≥1 秒间隔串行节流**按序发出（复用与核心相同的最小间隔逻辑、但为独立实例），且探测 / 刷新触发按钮 SHALL 在请求在途时禁用；跨进程残余并发窗口极小（探测为人工低频、核心仅在启动 / 回收瞬间打本地 API），一旦真撞上本地 API 每秒一次限速 SHALL **诚实降级**（如实提示、允许 ≥1 秒后重试 / 手敲），MUST NOT 谎报限速合规、MUST NOT 假成功。开启 API 校验时环境列表查询 SHALL 携带 api-key（优先取渲染层传入的调用级当前值、否则回落持久化值），且 api-key MUST NOT 被写入日志或文档。

#### Scenario: 只读调用不触碰启动生命周期层
- **WHEN** 桌面外壳执行探测或拉取环境列表
- **THEN** 仅调用本地 API 的健康检查与环境列表查询接口，不调用启动 / 停止接口，核心 provider 的启动与生命周期逻辑零改动

#### Scenario: 主进程侧自持节流按序发出、撞限速即诚实降级
- **WHEN** 面板的探测 / 刷新连续触发，或与运行中核心的浏览器启动 / 回收调用在同一秒内相近发生
- **THEN** 主进程侧的只读调用经其自持的同一条串行节流按 ≥1 秒间隔发出、按钮在途禁用；因主 / 核心分属不同进程无法共享内存队列，若跨进程碰撞触发本地 API 每秒限速，则如实提示并允许 ≥1 秒后重试，不谎报合规、不假成功

### Requirement: 环境列表就绪即自动加载并以可点列表直接呈现

`adspower` 模式下，当探测到 AdsPower 本地 API 就绪时，桌面外壳 SHALL **自动拉取一次**环境列表（无需运维先点「刷新」），并以**可点选的列表 / 行**（非下拉）直接呈现，每行 SHALL 展示名称与分身 id，并 SHOULD 展示序号 / 分组 / 代理配置摘要。「刷新」SHALL 仅用于更新该列表。自动加载 SHALL 复用同一串行节流与诚实降级：探测未就绪或拉取失败时 SHALL 不静默留空、而是给出与手动刷新一致的诚实提示，并保留手填分身 id 的兜底。

#### Scenario: 就绪即自动列出环境、无需先点刷新
- **WHEN** `adspower` 模式面板加载或切到 AdsPower 且本地 API 探到就绪
- **THEN** 桌面外壳自动拉取一次环境列表并以可点列表直接展示，运维无需先点「刷新」即可看到并选择环境

#### Scenario: 未就绪 / 拉取失败不静默留空
- **WHEN** 自动加载时本地 API 未就绪或拉取失败
- **THEN** 面板如实提示原因（与手动刷新一致）并保留手填分身 id 兜底，MUST NOT 呈现一个空列表却不说明原因

### Requirement: 分身 id 默认由选中环境带出、手动填写为可切开关

`adspower` 模式下，分身 id **默认不需要手敲**。多环境模式下，环境列表 SHALL 支持**多选**：运维可勾选一个或多个环境加入**运行花名册**，每个花名册成员 SHALL 各自携带其环境的 `user_id`（只读呈现）作为该环境将写入的分身 id；花名册 SHALL 持久化为一个环境列表。桌面外壳 SHALL 另提供「手动填写」开关，**默认关闭**（此时分身 id 取所选环境的值）；打开后 SHALL 呈现手敲输入框作为兜底（列表拉不到等场景，用于加入单个环境）。无论来自选中还是手敲，加入 / 启动前 SHALL 校验每个成员的最终分身 id 非空，且写入的 SHALL 始终是环境的 `user_id`（非序号）；同一分身 / 账号 MUST NOT 被重复加入花名册（防 edgeId 撞车 / 串号）。既有单分身设置（`adsProfileId` 单值）SHALL 向后兼容加载为**单元素花名册**。分身 id 的只读展示、「手动填写」开关与手敲输入框，连同 API 地址、API Key，SHALL 默认折叠于「高级设置」中、点开才呈现；当探测未就绪或环境拉取失败等需要手动兜底时，桌面外壳 SHALL 自动展开「高级设置」使「手动填写」即时可达。

#### Scenario: 多选环境加入运行花名册
- **WHEN** 运维在环境列表勾选多个环境并加入
- **THEN** 每个被选环境成为花名册成员、各带其 `user_id`，花名册持久化为环境列表，各成员可独立启动 / 停止

#### Scenario: 重复加入同一分身被拦
- **WHEN** 运维试图把一个已在花名册中的分身 / 账号再次加入
- **THEN** 外壳诚实拦阻并提示已加入，MUST NOT 让同一分身 / 账号在花名册中出现两次（防 edgeId 撞车）

#### Scenario: 打开手动填写开关作兜底
- **WHEN** 运维打开「手动填写」开关
- **THEN** 面板呈现手敲输入框，运维可自行填分身 id 加入单个环境；关闭开关则回到取选中环境的值

#### Scenario: 旧单分身设置向后兼容
- **WHEN** 载入历史保存的单值 `adsProfileId` 设置
- **THEN** 该值被兼容加载为单元素花名册，既有单环境使用不受影响

### Requirement: 无独立保存按钮——保存并入启动；会话由悬浮三态按钮控制

桌面外壳 SHALL **不提供独立的「保存」按钮**；浏览器设置的持久化 SHALL 并入以下两个动作：
- **启动**（悬浮按钮「启动」态）SHALL 先持久化当前设置、再启动核心；`adspower` 模式启动前 SHALL 校验最终分身 id 非空，缺则诚实提示、MUST NOT 启动。
- **按新设置重启** SHALL 先持久化当前设置、再有序重启核心，且 SHALL 仅在「设置相对已应用有改动、且核心在运行」时呈现，用于把改动显式应用到在跑核心。
- 持久化写盘失败 SHALL 诚实回报（沿用既有红线），MUST NOT 谎报已保存。
- **会话控制** SHALL 由窗口内一个显著（悬浮）主按钮承载，随边缘 / 会话状态呈**三态**：停止 / 异常时为「启动」、运行时为「暂停」、已暂停时为「恢复」，分别触发启动 / 暂停 / 恢复；顶部不再另设重复的暂停 / 恢复控件。两 provider（`adspower` / `self`）语义一致，`self` 的启动同样先写盘再起、无分身校验。

#### Scenario: 启动先保存再启动
- **WHEN** 运维选好环境（或手填分身 id）后点悬浮「启动」
- **THEN** 桌面外壳先把当前设置写盘、再启动核心；无独立「保存」按钮

#### Scenario: 缺分身 id 时诚实提示不启动
- **WHEN** `adspower` 模式未选环境也未手填分身 id 即点「启动」
- **THEN** 面板诚实提示先选环境 / 填分身 id，MUST NOT 写盘或启动

#### Scenario: 改动且运行中才现「按新设置重启」
- **WHEN** 核心在运行且运维改了环境 / 高级项
- **THEN** 面板呈现「按新设置重启」入口；点击它先写盘、再有序重启把改动应用到在跑核心；未改动或核心已停止时不呈现该入口

#### Scenario: 悬浮按钮随状态三态切换
- **WHEN** 边缘处于停止 / 运行 / 已暂停三种状态之一
- **THEN** 悬浮主按钮相应呈现「启动」/「暂停」/「恢复」并触发对应动作；顶部不再另设重复的暂停 / 恢复控件

### Requirement: 桌面外壳「创建环境」程序化建号入口 + 是否配代理提示

`adspower` 模式下，桌面外壳的「创建环境」入口 SHALL 触发 `adspower-environment-provisioning` 的程序化建号流程（而非仅拉起 AdsPower 客户端），运维 SHALL 只需挑一个「整机模板」，MUST NOT 被要求在面板内逐字段手配指纹。触发控件 SHALL 在创建在途时禁用（配合主进程单飞互斥）。**唯一的运营提示 = 「是否配置了代理」**：环境列表 SHALL 对每个环境如实呈现其代理配置状态，无代理（`user_proxy_config.proxy_soft` 为 `no_proxy` / 空）SHALL 给出「未配置代理」提示；该提示为纯提醒、MUST NOT 阻止任何操作（代理由运维手动在 AdsPower 侧配）。桌面外壳 MUST NOT 自动做运行时自检 / 投产硬闸 / 就绪判定——创建成功即如实呈现「已创建」，是否可用由运维登录时自行确认。本地 API 不可达或程序化创建失败时 SHALL 诚实降级（如实说明原因），MUST NOT 谎报已创建（不再提供「打开 AdsPower 手动新建」外链）。环境列表每行 SHALL 提供**删除入口**，其行为按 `adspower-environment-provisioning` 的「删除环境仅经界面逐个二次确认」需求（点两次确认、警示不可恢复）。

#### Scenario: 挑模板一键程序化创建，不必手配指纹
- **WHEN** 运维在「创建环境」入口选定一个整机模板并确认
- **THEN** 桌面外壳触发程序化建号流程，运维无需在面板内逐字段配指纹；创建在途时该控件禁用；成功后如实呈现「已创建」

#### Scenario: 无代理给提示但不拦
- **WHEN** 环境列表刷新，其中某环境未配置代理（`no_proxy` / 空）
- **THEN** 该环境如实标「未配置代理」提示，运维仍可对其做任何操作，MUST NOT 因无代理而拦截

#### Scenario: 创建失败诚实降级
- **WHEN** 本地 API 不可达或 `user/create` 返回错误
- **THEN** 桌面外壳如实说明失败原因，MUST NOT 谎报已创建

#### Scenario: 每行删除入口二次确认
- **WHEN** 运维点击某环境行的删除按钮
- **THEN** 第一次仅进入「确认删除?」待确认态、第二次才真删；删除后刷新列表

### Requirement: 恰好一个环境时自动选中

未启用客户鉴权时，探测就绪并拉取环境列表后，若恰好存在一个环境、运行花名册为空**且核心未在运行**，桌面外壳 SHALL 自动把该环境加入花名册并明示「已自动加入」；存在多个环境时 MUST NOT 自动替运维决定加入哪些——运维经**多选**把想跑的环境加入花名册。外壳 MUST NOT 在有环境正在运行时按该便利规则自动改写花名册。

启用客户鉴权时，桌面外壳在有效会话下成功取得**完整且非空**的本机环境列表、并经权威归属收窄后，SHALL 默认把所有尚未入册、未处于撤权清理且未被当前客户手动移出的环境加入并持久化运行花名册；该默认加入只建立离线环境行，MUST NOT 启动、重启、暂停或中断任何环境。客户手动移出某归属环境后，普通刷新和应用重启 MUST NOT 自动加回；客户再次点选加入 SHALL 撤销该排除。客户身份变化 MUST NOT 继承上一客户的排除选择。列表失败、截断、空响应或归属真态不可信时 MUST 保持花名册与排除选择不变。

#### Scenario: 唯一环境自动加入花名册
- **WHEN** 客户鉴权未启用、核心未在运行、花名册为空且拉取到恰好 1 个环境
- **THEN** 该环境被自动加入花名册、其分身 id 自动带出，界面明示已自动加入，无需运维手动勾选

#### Scenario: 非客户模式多环境不代选、由运维多选加入
- **WHEN** 客户鉴权未启用且拉取到 2 个及以上环境
- **THEN** 外壳不自动替运维选择，等待运维多选把想跑的环境加入花名册

#### Scenario: 客户归属多环境默认全部入册但不启动
- **WHEN** 客户鉴权启用，有效会话取得完整非空的本机环境列表并按当前客户权威归属收窄，其中多个环境尚未入册且未被手动移出
- **THEN** 外壳把这些环境一次性加入并持久化花名册、立即显示离线环境行，MUST NOT 自动启动或中断任何环境

#### Scenario: 手动移出在刷新和重启后保持
- **WHEN** 客户把一个已归属且已默认入册的环境手动移出，随后刷新列表或重启应用
- **THEN** 该环境仍出现在客户可加入列表但不在运行花名册，MUST NOT 被默认规则重新加回

#### Scenario: 手动重新加入撤销排除
- **WHEN** 客户点选一个此前手动移出的归属环境
- **THEN** 该环境重新加入并持久化花名册，客户端撤销其排除记录，使后续刷新保持已加入

#### Scenario: 运行中新增归属只增加离线行
- **WHEN** 已有环境正在运行，完整权威列表出现一个新的当前客户归属环境
- **THEN** 外壳可把新归属环境加入花名册并建立离线行，但 MUST NOT 重启、暂停或启动任何环境

#### Scenario: 不完整结果不改花名册
- **WHEN** 环境列表拉取失败、被截断、返回空响应或客户归属真态不可信
- **THEN** 外壳 MUST NOT 据此默认批量加入、批量移出或清理手动排除记录

### Requirement: 环境管理收口于左栏浮层、设置抽屉精简、稳态首屏不常驻表单

多环境下，AdsPower **环境管理**（本地 API 探测 / 环境列表拉取 / 多选加入运行花名册 / 手动填分身 id 兜底 / 程序化「创建环境」）SHALL 收口于**左侧环境栏**的「＋ 添加环境」拉起的独立浮层（非设置抽屉），浮层以「加入现有环境」/「新建环境」两页承载。设置抽屉 SHALL 精简为「浏览器引擎（`provider` 切换；AdsPower API 地址 / API Key 收进其高级折叠）+ 窗口停放 + 显示开发者详情开关」三项，MUST NOT 再常驻环境列表 / 创建入口 / 分身 id 表单。稳态首屏 MUST NOT 常驻任何配置表单或「必填」字样。既有探测 / 拉取 / 手填兜底 / 保存并入启动 / 「按新设置重启」等要求在新位置 SHALL 原样成立。

#### Scenario: 稳态首屏无配置表单
- **WHEN** 配置齐备且应用处于稳态（运行 / 就绪 / 暂停）
- **THEN** 首屏不出现配置表单与「必填」标记；点击标题带齿轮打开的设置抽屉只含浏览器引擎 / 窗口停放 / 开发者开关，环境管理经左栏「＋ 添加环境」完成

#### Scenario: 待配置时主动步骤引导开左栏添加面板
- **WHEN** 状态为待配置（如 AdsPower 模式花名册为空）
- **THEN** 首屏呈现一条醒目的主动引导（而非灰色告示），点击即打开**左栏「添加环境」浮层**（不再打开设置抽屉）定位到加入 / 新建

#### Scenario: AdsPower API 凭据仍可配、收在浏览器引擎高级折叠
- **WHEN** 运维需填 AdsPower API 地址 / API Key（多数情况留空）
- **THEN** 在设置抽屉「浏览器引擎」卡的「指纹浏览器高级设置」折叠内填写，探测 / 拉取 / 建号调用按当前填写值生效

### Requirement: 环境展示名保真于 AdsPower 实时名并随列表刷新同步

写入运行花名册（并经主进程 `syncEnvHandles → fleetSnapshot / status.envName` 投影到左侧环境列表 / fleet rail）的**环境展示名**，SHALL 忠于该环境在 AdsPower `user/list` 返回的名字（`name`，缺则回落 `username`），使**左侧列表**与**「添加环境」面板**对同一环境呈现一致的名字，MUST NOT 让二者因来源不同而长期漂移。

- **创建路径 MUST NOT 以空名入册**：桌面外壳经程序化创建环境后自动选中该环境时，SHALL 把创建流实际写入 AdsPower 的环境名（`name`，缺省为模板名）经创建返回体带回渲染层并写入花名册，MUST NOT 因返回体漏带名字而以空字符串入册。此保真 SHALL 即时生效、不依赖后续任何列表刷新。
- **拉列表时以实时名回填花名册**：桌面外壳**成功且完整**地拉取 AdsPower 环境列表时（`user/list` 返回 `ok` 且未截断、且列表非空），SHALL 用实时名回填 / 更新花名册中对应成员的名字：仅覆盖**本次列表在场**、且实时名**非空**、且与花名册现存名**不同**的成员；有回填即落盘一次以令左侧列表随即刷新。名字为纯展示字段，回填 MUST NOT 引入「人工标注优先」之类的例外。
- **缺数据不自残**：拉取失败 / 截断 / 空列表时 SHALL NOT 回填任何名字（沿用剔孤儿同款守卫 `r.ok && !r.truncated && live.size>0`），MUST NOT 因一次不完整的拉取把在用环境的名字误清或误改；宁可暂留旧名、绝不据缺数据改写。

#### Scenario: 创建环境后左侧列表与面板显示同一真名
- **WHEN** 运维经「创建环境」建出一个环境并被自动选中，随后创建动作触发的列表刷新拉回该环境
- **THEN** 左侧环境列表对该环境显示其 AdsPower 环境名（默认为模板名），与「添加环境」面板对同一环境显示的名字一致，MUST NOT 显示「环境 …末4位」这类占位名

#### Scenario: AdsPower 端改名后刷新即同步到左侧列表
- **WHEN** 某已加入花名册的环境此后在 AdsPower 端被改名，运维再次成功且完整地刷新环境列表
- **THEN** 桌面外壳用实时名回填该成员的花名册名并落盘，左侧列表随即显示新名，与面板一致

#### Scenario: 拉取不完整时绝不误改环境名
- **WHEN** 环境列表拉取失败、被截断、或返回空列表
- **THEN** 桌面外壳不回填任何花名册成员名，在用环境的名字保持不变，MUST NOT 因缺数据把其名字清空或改错
